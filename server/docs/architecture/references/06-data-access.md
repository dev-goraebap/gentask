# 06. 데이터 접근

본 문서는 스키마의 소유권과 코드 생성 경로, 그리고 저장소 구현이 지켜야 하는 규약을 정의합니다.

## 1. 마이그레이션이 스키마의 원본

**버전이 붙은 SQL 파일이 스키마의 단일 원본이고 생성 코드는 그로부터 파생됩니다.** 반대 방향(코드에서 스키마를 만들거나 대조하는 구성)을 쓰지 않습니다.

```text
src/main/resources/db/migration/
└── V1__create_tasks.sql
```

| 항목 | 규약 |
| :--- | :--- |
| **파일명** | `V<번호>__<설명>.sql`. 번호는 되돌리지 않고 말번으로 붙입니다 |
| **적용 이력** | Flyway 가 데이터베이스에 기록합니다 |
| **적용된 파일** | **고치지 않습니다.** 이미 적용된 환경과 어긋납니다 |
| **되돌리기** | 새 마이그레이션으로 되돌립니다. 내려가는 스크립트를 두지 않습니다 |

되돌리는 스크립트는 검증되지 않은 채 쌓입니다. 그래서 두지 않습니다. 실제로 실행할 일이 드물어 작성 시점에만 맞고, 정작 필요한 순간에 동작하지 않습니다.

## 2. 코드 생성

**실행 중인 데이터베이스 없이 마이그레이션 SQL 에서 직접 생성합니다.**

```text
V1__create_tasks.sql  ──(파서)──▶  build/generated-sources/jooq/
```

| 항목 | 결정 |
| :--- | :--- |
| **생성 입력** | `db/migration/*.sql`. Flyway 순서로 적용합니다 |
| **생성물 위치** | 빌드 산출물 디렉터리. **커밋하지 않습니다** |
| **생성 시점** | `compileJava` 앞. 마이그레이션이 바뀔 때만 다시 돕니다 |

생성물을 커밋하지 않는 이유는 **단일 원본을 두 벌로 만들지 않기 위해서**입니다. 커밋하면 재생성을 잊은 커밋이 스키마와 어긋난 생성물을 저장소에 남깁니다. 어긋남을 막으려면 CI 가 재생성 후 차이를 검사해야 하는데, 그럴 바에는 커밋하지 않는 편이 단순합니다.

빌드가 외부 상태에 의존하지 않는 것이 이 방식의 이점입니다. 개발자마다 로컬 데이터베이스 상태가 달라 생성 결과가 갈리는 일이 없고, CI 가 컨테이너를 먼저 띄우지 않아도 됩니다. **컨테이너가 필요한 것은 통합 테스트뿐입니다.**

> [!WARNING]
> **파서가 이해하는 범위가 제약입니다**
>
> 기준이 실제 데이터베이스가 아니라 SQL 파서입니다. 데이터베이스 고유 구문 중 일부는 생성기가 해석하지 못하며, 그 경우 구문을 피하거나 생성 대상에서 제외해야 합니다. **파서를 통과했다고 실행까지 보장되지는 않으므로**, 실제 적용 여부는 컨테이너를 띄우는 통합 테스트가 확인합니다.

생성기는 인메모리 데이터베이스를 쓰므로 스키마 이름이 대문자로 잡힙니다. PostgreSQL 의 실제 스키마는 소문자이므로 매핑을 걸어 두었으며, 그러지 않으면 렌더링된 SQL 이 런타임에 문법 오류를 냅니다.

## 3. 컬럼 타입

시각 컬럼의 타입이 둘로 갈립니다. **그 값이 절대 순간인지 아닌지가 기준입니다.**

| 성격 | 타입 | 예 |
| :--- | :--- | :--- |
| 실제로 일어난 순간 | `timestamptz` | 만든 시각, 완료한 시각 |
| 사용자가 고른 "그 날 그 시각" | `timestamp` | 미리 알림 |
| 날짜만으로 판정이 끝남 | `date` | 기한, 나의 하루에 담은 날 |

미리 알림에 시간대를 붙이면 사용자가 고른 값과 저장된 값이 달라져 화면에 낼 때마다 되돌려야 합니다. 그 대가로 절대 순간이 아니게 되며, 실제로 알림을 보내는 구현이 사용자 시간대를 알아야 합니다.

**길이 제약은 값 객체와 같은 값을 씁니다.** 도메인이 200자를 막는데 컬럼이 100자면 도메인을 통과한 값이 저장에서 실패합니다.

## 4. 저장소 구현

**jOOQ 에는 변경 감지가 없습니다.** 애그리거트를 고친 뒤에는 항상 명시적으로 저장합니다.

```java
Task task = tasks.findById(id).orElseThrow(TASK_NOT_FOUND::raise);
task.complete(clock.instant());
tasks.save(task);                    // 이 호출이 없으면 아무 일도 일어나지 않는다
```

| 규약 | 내용 |
| :--- | :--- |
| **`save`** | 삽입과 갱신을 하나로 다룹니다. 호출부가 존재 여부를 알 필요가 없습니다 |
| **변환** | 저장소 구현 안의 비공개 메서드가 담당합니다. 매퍼 클래스를 따로 두지 않습니다 |
| **SQL 의 자리** | `infrastructure` 뿐입니다. 다른 계층에서 jOOQ 타입이 보이면 위반입니다 |
| **접근 제어** | 구현 클래스는 패키지 전용입니다. 바깥은 인터페이스로만 씁니다 |

재구성은 `restore` 만 씁니다. 저장된 값이 현재 불변식을 통과하지 못할 수 있으므로 생성 경로와 나누며, 그 경로를 저장소만 호출합니다([04. 계층](04-layers.md) 4절).

## 5. 트랜잭션

경계는 서비스의 public 메서드입니다. 저장소는 트랜잭션을 시작하지 않습니다.

**애그리거트 경계를 넘지 않는 것을 기본으로 합니다.** 하나의 트랜잭션이 여러 애그리거트를 바꾸기 시작하면 그 둘의 수명이 묶이고, 나중에 분리할 때 경계가 아니라 트랜잭션을 먼저 풀어야 합니다.

조회 경로는 `readOnly = true` 로 선언합니다([05. 조회와 명령](05-query-command.md) 2절).
