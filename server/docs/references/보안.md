# 보안

본 문서는 서버가 지키는 보안 규칙을 정의합니다.
인증 계약(토큰 전달 방식·OTP 흐름)은 [API 설계](API-설계.md) §5·§6이 소유합니다.

## 1. 인가

인가 원칙은 **기본 거부(deny-by-default)** 입니다. 보호가 필요한 리소스를 기본으로 막고 예외적으로
엽니다. 열어 둔 경로는 인증 없이 접근할 수 있어야 하는 것들뿐입니다 — 가입·로그인·복구처럼
**아직 세션이 없는 사용자를 위한 경로**이며, 그 보호는 OTP와 시도 제한이 담당합니다.

## 2. 입력 검증

모든 요청 DTO는 컨트롤러 진입 시점에 Bean Validation으로 검증합니다.

## 3. 시크릿

시크릿(DB 비밀번호, OAuth 클라이언트 시크릿, VAPID 키)은 소스·설정 파일에 평문으로 두지 않고
환경변수로 주입합니다. 키트의 예시 설정에는 값이 아니라 **변수 이름만** 둡니다.

> **주의: 시크릿에 기본값을 두지 않습니다**
> `auth.secret`처럼 없으면 안 되는 값에 기본값을 주면, 주입을 잊었을 때 조용히 약한 키로 동작합니다.
> 기본값을 두지 않아 **기동 자체가 실패하는 편**이 안전합니다.

## 4. CSRF

쿠키 경로의 CSRF 방어는 Spring의 토큰 방식 대신 **Origin 검증 필터 + `SameSite=Lax` 쿠키**로 합니다.
세션을 서버 렌더 폼 없이 API로만 쓰므로 토큰 왕복이 필요 없습니다.

검사는 **상태를 바꾸는 요청 전반**에 겁니다. "세션 쿠키가 있을 때만"으로 좁히면 세션
고정(session fixation)이 열립니다 — 로그인하지 않은 피해자의 브라우저에 공격자 세션을 심는
교차 출처 POST가 옛 조건에는 걸리지 않기 때문입니다(검토 #32-2).

## 5. 시도 제한

시도 제한은 IP·이메일·계정 축으로 나누어 겁니다. 두 가지가 규칙입니다.

- **비대칭 방향을 뒤집지 않습니다.** IP는 촘촘히, 이메일은 넉넉히 겁니다. 이메일별을 조이면
  공격자가 남의 주소로 한도를 소진시켜 정상 가입과 재발송을 막는 서비스 거부가 됩니다.
- **제한은 비싼 계산보다 먼저 겁니다.** bcrypt는 의도적으로 느리므로, 검증을 뒤에 두면 해시 비용
  자체가 자원 고갈 수단이 됩니다.

이 층의 위·아래에 무엇이 오는지는 [결정-0021](../../../docs/결정기록/결정-0021-남용-방지-계층.md)이
정의합니다. 엣지(요청률)와 사람 증명(캡챠)은 배포 시점에 도입합니다.

## 6. 업로드

업로드 파일은 서버가 생성한 식별자로만 접근하고, 파일명의 경로 조작 문자를 제거합니다.
확장자·MIME 화이트리스트를 둡니다.

## 7. 검토 절차

보안 민감 기능(인증·세션·업로드·프로필)은 머지 전에 `security-reviewer` 페르소나 검토를 거칩니다.
