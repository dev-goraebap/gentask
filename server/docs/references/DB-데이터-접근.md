# DB · 데이터 접근

본 문서는 저장소 구현, 스키마 관리, SQL 안전성 규칙을 정의합니다.
접근 경로의 분리(조회와 명령)는 [조회와 명령](조회와-명령.md)이, 테이블별 스키마 명세는
[설계/데이터베이스.md](../../../docs/설계/데이터베이스.md)가 소유합니다.

## 1. 저장소

- 인터페이스는 도메인 언어로 선언합니다(`UserRepository.findByEmail`). 구현 기술은 인터페이스에
  드러나지 않습니다.
- 구현은 `infrastructure/repository`에 두고, jOOQ 레코드를 도메인 엔티티로 변환합니다.
- 트랜잭션 경계는 명령 서비스의 public 메서드입니다(`@Transactional`).

## 2. SQL 안전성

jOOQ DSL은 바인딩이 타입 세이프하므로 인젝션이 구조적으로 차단됩니다. plain SQL API(`DSL.field(String)`
등)를 쓸 때만 문자열 결합에 주의하고, 사용 시 사유를 주석으로 남깁니다.

## 3. 스키마와 코드 생성

마이그레이션은 **Flyway**(`src/main/resources/db/migration/V*.sql`)가, jOOQ 코드 생성은
**DDLDatabase**(마이그레이션 SQL에서 직접 생성, 실행 중 DB 불필요)가 담당합니다 —
[결정-0013](../decisions/결정-0013-마이그레이션과-코드생성.md).

- 마이그레이션 파일이 **스키마의 단일 원본**입니다. 생성 코드는 항상 그로부터 파생되며 커밋하지
  않습니다.
- 생성 코드는 코딩 표준의 대상이 아닙니다(Spotless·Checkstyle·SpotBugs에서 제외).
- `./gradlew build`는 Docker 없이 동작합니다. Docker가 필요한 것은 통합 테스트(`test`)뿐입니다.

## 4. 시각은 주입된 Clock으로 채운다

시각을 DB 기본값(`now()`)으로 채우지 않고 전역 `Clock` 빈에서 받습니다. 도메인과 통합 테스트가
시각을 통제할 수 있어야 만료·수명 관련 불변식을 검증할 수 있기 때문입니다.

## 5. 비밀은 원문으로 저장하지 않는다

세션 토큰과 OTP는 앱 시크릿을 키로 하는 HMAC-SHA256으로 저장하고, 비밀번호는 bcrypt로 저장합니다.
용도별로 HMAC 라벨을 분리하므로 한 용도로 만든 값이 다른 용도의 조회에 걸리지 않습니다.
상세는 [보안](보안.md)과 [설계/데이터베이스.md](../../../docs/설계/데이터베이스.md) §1.4에 있습니다.
