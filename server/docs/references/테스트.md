# 테스트

본 문서는 무엇을 어떤 방식으로 검증하는지, 그리고 구조 규칙을 강제하는 수단을 정의합니다.

## 1. 대상과 방식

| 대상 | 방식 |
|---|---|
| 도메인 모델(엔티티·불변식) | 단위 테스트 — Spring 컨텍스트 없이 순수 객체로 |
| 명령 서비스 | 단위 테스트 — 저장소·포트를 가짜 구현으로 대체 |
| 조회 서비스, 저장소 구현 | **통합 테스트** — Testcontainers로 1회용 PostgreSQL |
| 컨트롤러 | 선택 |

단위 테스트는 복잡도와 도메인 중요도가 모두 높은 코드에 집중합니다. 조회 서비스는 로직이 거의 없는
매핑 코드라 단위 테스트의 회귀 방지 효과가 낮고, 정작 검증해야 할 "SQL·스키마 정합성"은 가짜
객체로는 잡히지 않습니다.

공유 개발 DB는 쓰지 않습니다. 통합 테스트는 `IntegrationTestSupport`를 상속해 1회용 PostgreSQL
컨테이너를 공유합니다.

## 2. 이름

- **테스트 메서드명은 한국어를 허용합니다** — 테스트 이름은 "무엇을 검증하는가"를 사람이 읽는
  문장입니다. Checkstyle 명명 규칙은 `config/checkstyle/suppressions.xml`에서 테스트 소스에 한해
  완화합니다(프로덕션 코드는 그대로).
- **완화는 메서드명에만 적용됩니다.** 지역변수·파라미터는 프로덕션과 같은
  규칙(`^[a-z][a-zA-Z0-9]*$`)을 따릅니다 — 완화의 근거가 "이름이 곧 명세 문장"인데 변수는 그 대상이
  아니기 때문입니다.
- **요구사항 ID는 `@DisplayName`에 씁니다** — `@DisplayName("AUTH-06 미검증 사용자는 저장할 수 없다")`.
  메서드명에는 하이픈을 넣을 수 없어 `AUTH_06`이 되는데, 그러면 하이픈=요구사항 ID라는 구분이 깨져
  `AUTH-06` 전체 검색에 걸리지 않습니다. 추적성을 유지하려면 하이픈 형태가 소스에 남아야 합니다.
- 한국어 메서드명을 `{@link #메서드()}`로 참조하면 Checkstyle의 Javadoc 파서가 깨집니다.
  `{@code 메서드()}`를 씁니다.

## 3. 테스트가 결과가 아니라 메커니즘을 봐야 하는 경우

동시성·잠금처럼 창이 수 밀리초인 결함은 **결과를 관찰하는 방식으로는 재현되지 않습니다.**
잠금을 지워도 통과하는 테스트가 실제로 있었습니다. 그런 경우에는 결과 대신 **메커니즘**을
확인합니다 — 테스트가 행을 잠근 채 붙들고 대상 경로가 진행하지 못하는 것을 봅니다.

> **주의: 결함이 있는데도 통과하는 테스트는 없느니만 못합니다**
> 방어 장치를 검증하는 테스트를 쓸 때는 **그 장치를 지우면 실패하는지**를 반드시 확인합니다.

## 4. ArchUnit 강제

구조 규칙을 ArchUnit 테스트로 인코딩하고 CI 게이트에 포함합니다. **규칙 위반은 빌드 실패입니다.**

1. 다른 모듈의 하위 패키지(internal) 참조 금지
2. `domain`은 `application`·`infrastructure`·Spring·jakarta 의존 금지
3. `application`은 `infrastructure` 의존 금지 (포트로만)
4. 피쳐 슬라이스 간 순환 금지
5. `shared`는 피쳐를 의존하지 않는다
6. 컨트롤러는 저장소·조회 포트를 직접 의존하지 않는다
7. 명령 서비스(`~Service`)는 조회 포트(`~Queries`)를 의존하지 않는다
8. `common`은 어떤 모듈도 의존하지 않는다

규칙 3이 조회에도 그대로 적용되므로, 영속성 라이브러리를 application에서 허용하는 예외 규칙은 두지
않습니다.
