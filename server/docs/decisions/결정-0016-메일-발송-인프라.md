# 결정-0016: 메일 발송은 Gmail SMTP로 하고 비동기로 보낸다

- 상태: 승인됨
- 날짜: 2026-07-27

## 맥락

MAIL-01(트랜잭션 이메일 발송)에 두 가지가 미결로 남아 있었다 — **발송 인프라**(SMTP vs 외부 서비스)와
**동기·비동기 여부**. [결정-0015](../../../docs/결정기록/결정-0015-이메일-소유-증명.md)로 이메일 소유 증명을 OTP로 정하면서
메일이 가입 흐름의 임계 경로에 들어왔으므로 함께 정할 시점이 됐다.

당시 전제: 키트는 파생 프로젝트의 출발점이며 초기 트래픽 규모를 가정하지 않는다. MAIL-01이 이미
**발송을 포트 뒤에 둘 것**을 요구하고 있어(도메인이 발송 수단을 모른다) 인프라 교체는 어댑터
교체로 끝난다.

## 검토한 대안

### 발송 인프라

- **Gmail SMTP (선택)**: 별도 계약·API 키 발급 없이 시작할 수 있다. 키트를 복제한 사람이 즉시
  동작을 확인할 수 있는 것이 가장 큰 값이다. 제약이 분명하다(아래 결과 참조).
- **외부 서비스(SES·Resend 등)**: 도달률·발송량·이벤트 웹훅이 우수하다. 다만 계정 생성·도메인 인증
  (SPF·DKIM·DMARC)·샌드박스 해제가 선행되어야 하며, 키트의 첫 실행 경험을 무겁게 만든다.
- 포트 뒤에 있으므로 이 선택은 **되돌리기 쉬운 결정**이다. 되돌리기 쉬운 결정은 가장 빨리 시작할 수
  있는 쪽으로 정한다.

### 동기 vs 비동기

- **동기**: 발송 결과를 응답에 반영할 수 있다. 그러나 SMTP는 TLS 핸드셰이크와 릴레이로 수백 ms~수 초가
  걸리고, 그 지연이 그대로 가입 API의 응답 시간이 된다. 외부 인프라의 지연을 우리 SLA로 들이는 셈이다.
- **비동기 (선택)**: 응답을 먼저 돌려준다. OTP 흐름에서는 사용자가 이미 "코드 입력" 화면으로 넘어가
  메일을 기다리는 중이므로, 응답을 먼저 주는 편이 흐름에 맞는다.
- **outbox 테이블 + 워커**: at-least-once 전달을 보장한다. 다만 OTP 유실은 **재발송**으로 복구되므로
  현 단계에서 지불할 복잡도가 아니다. 필요해지는 시점의 업그레이드 경로로 둔다.

## 결정

1. **발송 어댑터는 Gmail SMTP로 구현한다.** MAIL-01이 요구하는 포트 뒤에 두어, 파생 프로젝트가
   SES·Resend 등으로 교체할 때 어댑터와 설정만 바꾸면 되게 한다.
2. **발송은 비동기로 한다.** 전용 executor를 두고(공용 풀을 쓰지 않는다) 유스케이스 응답이 발송을
   기다리지 않게 한다.
3. **발송은 트랜잭션 커밋 이후에 트리거한다.** 트랜잭션 안에서 보내면 롤백 시 유령 메일이 나간다.
4. **실패는 유스케이스를 중단시키지 않는다**(MAIL-01 인수조건). 실패를 로그와 지표로 남기고,
   사용자 측 복구 수단은 **재발송**이다. 재시도는 짧은 횟수로 제한한다.
5. **자격증명은 환경 변수로 주입한다.** 앱 비밀번호를 저장소에 넣지 않는다.
6. **본문·제목은 템플릿으로 조립하고 사용자 입력을 이스케이프한다**(MAIL-01 인수조건 — 헤더·내용
   인젝션 방지). 수신자 주소에 개행이 들어갈 수 없게 검증한다.

## 재검토 조건

- **발송량이 Gmail 한도에 접근하거나 도달률이 문제가 되는 경우** — 어댑터를 외부 서비스로 교체한다.
  포트가 있으므로 도메인 코드는 바뀌지 않는다.
- **메일 유실이 재발송으로 감당되지 않는 종류의 알림이 생기는 경우**(예: 결제 영수증) — outbox
  테이블과 워커를 도입한다.
- **발신 도메인을 서비스 도메인으로 바꿔야 하는 경우** — Gmail SMTP는 발신자가 계정 주소로 고정되므로
  그 시점에 외부 서비스로 옮긴다.

## 결과

- 키트를 복제한 사람이 계정 하나와 앱 비밀번호만으로 메일 흐름을 끝까지 확인할 수 있다
- 가입 API의 응답 시간이 SMTP 지연과 분리된다
- 감수하는 것
  - **앱 비밀번호가 필요하다** — 2단계 인증이 켜진 계정이어야 한다
  - **발신자 주소가 그 계정 주소로 고정된다** — 서비스 도메인 발신은 외부 서비스로 옮겨야 한다
  - **일일 발송 한도가 있다**(무료 Gmail 약 500통, Workspace 약 2000통). 프로덕션 규모에는 부족하다
  - 발송 실패를 사용자에게 즉시 알릴 수 없다. 재발송 수단이 항상 열려 있어야 한다
  - at-least-once 보장이 없다. OTP·검증 메일에 한정해 재발송으로 갈음한다
