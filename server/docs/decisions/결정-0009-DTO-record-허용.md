# 결정-0009: DTO·값 객체에 Java record 허용 (가변 컴포넌트는 방어복사 의무)

- 상태: 승인됨
- 날짜: 2026-07-24

## 맥락

팀 프로젝트(safety-solution)는 DTO·값 객체를 record가 아닌 Lombok class로 통일하는 규칙을
운영한다. 근거는 SpotBugs의 `EI_EXPOSE_REP`(가변 객체 참조 노출) 경고 회피와 팀 컨벤션 일치였다.
우리도 SpotBugs를 쓰므로([결정-0004](결정-0004-server-정적분석-도구.md)) 이 규칙을 승계할지
판단해야 했다.

한편 jOOQ는 생성자 기반 매핑으로 record 프로젝션을 1급 지원하고, 도메인 엔티티와 생성 레코드가
분리되는 구조([결정-0007](결정-0007-서버-모듈-구조.md))에서 DTO는 대부분 불변 값이다.
record를 금지하면 보일러플레이트가 늘고 조회 결과 매핑에 변환 단계가 추가된다.

## 검증

기억이나 문헌이 아니라 **우리 환경에서 직접 측정**했다 (SpotBugs 4.10.3, Java 21, 2026-07-24).

| 프로브 | 결과 |
|---|---|
| `record(String, List, Map, byte[])` — 방어복사 없음 | `EI_EXPOSE_REP` **4건** |
| `record(String, int, UUID, Instant, List)` — 컴팩트 생성자에서 `List.copyOf` | 경고 **0건** |

결론: SpotBugs와 record는 근본적으로 충돌하지 않는다. 경고는 **가변 컴포넌트를 방어복사 없이
노출할 때만** 발생하며, 이는 오탐이 아니라 실제 결함(외부에서 내부 상태를 바꿀 수 있음)이다.
컴팩트 생성자 한 줄로 해소되고, 그 결과 진짜 불변성이 확보된다.

참고로 class 전환이 이 경고를 없애는 이유는 문제를 고쳐서가 아니라 Lombok 생성 메서드가
분석에서 제외되기 때문일 가능성이 높다 — 경고를 가리는 쪽에 가깝다.

## 검토한 대안

- **record 금지, Lombok class 통일 (선례 승계)**: 기각 — 경고를 가릴 뿐 불변성 문제는 남고, 보일러플레이트와 jOOQ 매핑 변환 비용이 든다
- **record 허용 + SpotBugs exclude로 EI_EXPOSE 억제**: 기각 — 검증 결과 억제가 불필요했다. 실제 결함까지 함께 눈감게 되므로 더 나쁘다
- **record 허용 + 방어복사 의무 (선택)**: 설정 변경 없이 경고 0건, 진짜 불변성 확보

## 결정

- DTO·값 객체·조회 프로젝션 타깃은 **record를 기본으로** 한다.
- **가변 컴포넌트(컬렉션·배열·가변 객체)를 가지는 record는 컴팩트 생성자에서 방어복사**한다(`List.copyOf` 등). SpotBugs가 이를 강제하므로 별도 리뷰 항목으로 두지 않는다.
- SpotBugs 제외 필터에 `EI_EXPOSE_REP`를 추가하지 않는다.
- Jackson 역직렬화가 필요한 요청 DTO도 record로 쓴다(Spring Boot 기본 구성이 record 바인딩을 지원한다). 프레임워크 제약으로 불가능한 사례가 나오면 그때 class를 쓰고 사유를 주석으로 남긴다.

## 결과

- 조회 결과를 jOOQ에서 DTO로 바로 프로젝션할 수 있어 변환 코드가 줄어든다
- 정적분석 설정을 느슨하게 만들지 않고도 record를 쓴다 — 게이트의 신뢰가 유지된다
- 감수하는 것: 컬렉션을 가진 record마다 컴팩트 생성자 한 줄
