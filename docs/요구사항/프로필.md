# 요구사항 — 프로필

상태 정의: `제안` → `확정` → `구현됨` / `폐기`

| ID | 요구사항 | 상태 |
|---|---|---|
| PROF-01 | 프로필 닉네임을 변경할 수 있다 | 제안 |
| PROF-02 | 프로필 이미지를 변경할 수 있다 (FILE-* 의존) | 제안 |
| PROF-03 | 비밀번호를 변경할 수 있다 | 제안 |
| PROF-04 | 소셜 로그인 연동을 추가·해제할 수 있다 | 제안 |
| PROF-05 | 이메일을 변경할 수 있다 | 제안 |

## PROF-01 닉네임 변경

인수조건 (확정 단계에서 상세화):
- [ ] 닉네임을 조회·변경할 수 있다
- [ ] 닉네임 규칙(길이·문자)이 검증된다

## PROF-02 프로필 이미지 변경

인수조건 (확정 단계에서 상세화):
- [ ] 파일 업로드(FILE-01~03)를 통해 프로필 이미지를 설정·교체할 수 있다

## PROF-03 비밀번호 변경

인수조건 (확정 단계에서 상세화):
- [ ] 현재 비밀번호 확인 후 새 비밀번호로 변경할 수 있다
- [ ] 변경 시 기존 세션 처리 정책이 적용된다 (정책은 설계에서 결정)

## PROF-04 소셜 연동·해제

인수조건 (확정 단계에서 상세화):
- [ ] 로그인된 계정에 소셜 인증 수단을 추가·해제할 수 있다
- [ ] 마지막 남은 인증 수단은 해제할 수 없다 (계정 잠김 방지)

## PROF-05 이메일 변경

인수조건 (확정 단계에서 상세화):
- [ ] 새 이메일의 소유를 OTP로 증명한 뒤에 변경이 반영된다
- [ ] **미완료 변경 요청이 계정에 남지 않는다** — 만료되거나 취소되며, 비밀번호 재설정(AUTH-07) 시
      함께 취소된다
- [ ] 변경 후에도 `user` 식별자는 바뀌지 않는다 — 이메일은 `user`의 속성이며 결제·권한의 앵커가 아니다
- [ ] 변경 사실이 이전 주소로도 통지된다

미완료 변경을 남기지 않는 것은 pre-hijacking 변종 4번(공격자가 이메일 변경을 시작해두고 피해자의
계정 복구 이후에 완료하는 공격)에 대한 방어다. 근거는
[결정-0015](../결정기록/결정-0015-이메일-소유-증명.md).
