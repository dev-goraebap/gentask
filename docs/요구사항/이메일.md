# 요구사항 — 이메일 발송

상태 정의: `제안` → `확정` → `구현됨` / `폐기`

| ID | 요구사항 | 상태 |
|---|---|---|
| MAIL-01 | 서버에서 트랜잭션 이메일(인증·알림 등)을 발송할 수 있다 | 확정 |

## MAIL-01 이메일 발송

- [ ] 템플릿 기반으로 이메일을 발송할 수 있다
- [ ] 발송은 **포트 뒤에 두어** 인프라(SMTP·외부 서비스)를 교체할 수 있다 — 도메인이 발송 수단을 모른다
- [ ] 발송 실패가 기록되며, 실패가 호출한 유스케이스를 중단시키지 않는다
- [ ] 이메일 본문·제목에 사용자 입력이 그대로 들어가지 않는다 (헤더·내용 인젝션 방지)
- [ ] 인증 메일(AUTH-01의 이메일 검증)에 사용된다

미결(설계 단계에서 결정): **발송 인프라**(SMTP vs 외부 서비스)와 **동기·비동기 여부**.
가입 응답이 메일 발송을 기다리지 않아야 하므로 비동기가 유력하나, 실패 처리·재시도 정책과 함께 정한다.
