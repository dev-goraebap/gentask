# 요구사항 — 이메일 발송

상태 정의: `제안` → `확정` → `구현됨` / `폐기`

| ID | 요구사항 | 상태 |
|---|---|---|
| MAIL-01 | 서버에서 트랜잭션 이메일(인증·알림 등)을 발송할 수 있다 | 구현됨 |

발송 인프라와 동기·비동기 여부는 [결정-0016](../결정기록/결정-0016-메일-발송-인프라.md)을 따른다.

## MAIL-01 이메일 발송

- [x] 템플릿 기반으로 이메일을 발송할 수 있다
- [x] 발송은 **포트 뒤에 두어** 인프라(SMTP·외부 서비스)를 교체할 수 있다 — 도메인이 발송 수단을 모른다
- [x] 발송은 **비동기**이며 전용 executor를 쓴다 — 유스케이스 응답이 발송을 기다리지 않는다
- [x] 발송은 **트랜잭션 커밋 이후에** 트리거된다 — 롤백 시 메일이 나가지 않는다
- [x] 발송 실패가 기록되며, 실패가 호출한 유스케이스를 중단시키지 않는다
- [x] 사용자가 **재발송을 요청할 수 있다** — 발송 실패·유실의 복구 수단이다 (발급 API 재호출이 곧 재발송이다)
- [x] 이메일 본문·제목에 사용자 입력이 그대로 들어가지 않는다 (헤더·내용 인젝션 방지).
      수신자 주소에 개행이 포함될 수 없다
- [x] 발송 자격증명은 환경 변수로 주입되며 저장소에 포함되지 않는다
- [x] 인증 흐름의 OTP 발송에 사용된다 — AUTH-01에서 사용 중이며, AUTH-05·07·08은 해당 기능 구현 시 같은 포트를 쓴다
