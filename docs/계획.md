# 계획

프로젝트의 목표·범위·마일스톤을 정의한다. 이 문서가 계획의 원본이며, 실행 추적은 GitHub 이슈·마일스톤으로 한다.
계획이 어긋나면 이 문서를 수정하고 커밋한다 — 수정 이력이 곧 계획 조정의 기록이다.

## 목표

새 웹앱 프로젝트를 시작할 때 복제해서 바로 쓰는 개발 키트를 만든다.
일반 웹앱에 공통으로 필요한 기능(인증, 이메일, 파일 업로드, 알림, 프로필)을
프로세스 체계(요구사항 상태 관리·결정기록·CI 게이트·검토 페르소나·베이스라인 감사)와 함께 제공한다.

## 범위 / 비범위

**범위**: 인증(이메일/비밀번호 + 구글·카카오 소셜, 이메일 키 통합), 이메일 발송,
파일 업로드(R2 presigned URL, Active Storage식 구조, 이미지 처리), 웹 푸시 알림(VAPID),
프로필 관리, 그리고 이를 뒷받침하는 문서·CI·에이전트 프로세스 자산.

**비범위**: 스택 교체(Angular 또는 Spring이 바뀌면 별도 프로젝트) · 결제 · 관리자 도구 ·
다국어 — 필요해지면 계획 변경으로 편입한다.

## 마일스톤

일정은 약속하지 않는다. 순서와 완료 조건으로 정의한다.

| # | 이름 | 내용 | 완료 조건 |
|---|---|---|---|
| M0 | 기반 (완료) | 문서 체계, 린트 구성, CI 게이트, 페르소나 에이전트, 부트스트랩 스크립트 | CI에서 빌드+린트 통과 강제 (테스트는 web만 — server 테스트 게이트 편입은 #7 해결과 함께 M1로 이관, 2026-07-24 조정: 회고 참조) |
| M1 | 아키텍처 + 인증 + 이메일 | ① 아키텍처 확립(설계 문서·결정기록) ② 기반 배선(마이그레이션·jOOQ·헬스체크·Testcontainers) ③ 이메일/비밀번호, 소셜 2종, 이메일 키 통합, 4테이블 구조, 비밀번호 재설정·이메일 복구, 이메일 발송 | AUTH-*(폐기 제외), MAIL-* 인수조건 충족, server 테스트 CI 게이트 편입(#7), 베이스라인 v0.1 |
| M2 | 프로필 | 닉네임·비밀번호 변경, 이메일 변경, 소셜 연동·해제 (이미지 변경은 M3 이후) | PROF-01, 03, 04, 05 충족 |
| M3 | 파일 업로드 | R2 presigned URL, Active Storage식 테이블, 이미지 변환·지배적 색상, 프로필 이미지 연결 | FILE-*, PROF-02 충족, 베이스라인 v0.2 |
| M4 | 알림 | VAPID 웹 푸시, 알림 설정 | NOTI-* 충족, 베이스라인 v0.3 |

의존 관계: M1의 인증 메일 → 이메일 발송 선행. M2의 프로필 이미지 → M3 선행. M4의 알림 설정 → M2 선행.
