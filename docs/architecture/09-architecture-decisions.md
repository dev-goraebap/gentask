# 9. 아키텍처 결정 (Architecture Decisions)

본 문서는 이 저장소의 아키텍처 결정을 시간순으로 나열합니다. 결정의 본문은 각 파일이 소유하고 여기에는 상태와 한 줄 요약만 둡니다.

**결정 기록은 승인 후 불변입니다.** 결론이 바뀌면 새 결정을 발행해 이전 것을 대체하며, 옛 문서를 고치지 않습니다. 기록의 역사성이 사라지면 다음 작업자가 같은 논의를 반복합니다.

## 파일명

`NNNN-<축>-<요약슬러그>.md` 형식입니다.

| 자리 | 규격 |
| :--- | :--- |
| **`NNNN`** | 네 자리 순번. **축과 무관하게 하나의 수열**을 씁니다. 저장소 전체에서 결정이 내려진 순서입니다 |
| **`<축>`** | `shared` · `frontend` · `backend` 중 하나. 그 결정이 어느 축의 규칙을 바꾸는가입니다 |
| **`<요약슬러그>`** | 영문 케밥 케이스. 제목이 아니라 식별을 위한 것이므로 짧게 씁니다 |

축을 순번보다 뒤에 두는 이유는 목록이 시간순으로 정렬되게 하기 위해서입니다. 축으로 묶어 보려면 파일명 가운데를 읽습니다.

두 축에 함께 걸리는 결정은 `shared` 입니다. 한쪽에서 시작했더라도 반대쪽 규칙을 함께 바꾸어야 성립하면 `shared` 로 발행합니다.

## 작성 판별식

**구조 · 비기능 특성 · 의존성 · 인터페이스 · 구축 기법 가운데 하나에 영향을 주는가.** 하나라도 해당하면 결정 기록이고, 아니면 참조 문서 본문에 직접 적습니다. 업계 표준, 취향, 앞선 결정에서 자동으로 따라오는 규칙은 대상이 아닙니다.

형식은 [Michael Nygard 의 ADR](https://cognitect.com/blog/2011/11/15/documenting-architecture-decisions.html)을 따릅니다. **검토했다 기각한 길은 별도의 절을 두지 않고 맥락 절에서 서술합니다.** 다투는 힘을 제대로 적으면 왜 그 결론인지가 따라 나오며, 대안을 절로 못 박으면 형식을 채우느라 검토하지 않은 안이 자리를 메웁니다.

템플릿은 [0000-template.md](./decisions/0000-template.md)입니다.

## 대체 절차

한 커밋으로 처리합니다.

1. **새 결정 작성**: 무엇을 왜 대체하는지 맥락 절에 적습니다.
2. **목차 갱신**: 아래 표에서 이전 결정의 상태를 `대체됨 (→ NNNN)`으로 바꿉니다.
3. **참조 교체**: 참조 문서가 걸어 둔 링크를 새 결정으로 바꿉니다.

## 발행 예정

아래는 판별식을 통과하지만 아직 작성되지 않은 결정입니다. 해당 참조 문서를 이식하거나 그 규칙을 처음 적용할 때 함께 발행합니다.

**프론트엔드**

- **모듈 분할 방법론** — FSD 를 택한 선택. 대안은 기능별 폴더, 계층별 폴더, Nx 라이브러리 경계
- **UI 킷 조달** — Spartan 의 brain + helm 조합. 대안은 완제품 킷 채택, 자체 구현
- **적응형 판정 축** — 뷰포트 폭으로 컴포넌트를 교체하는 선택. 대안은 포인터 정밀도, 사용자 설정
- **서버 상태 조회 수단** — `httpResource` 를 조회의 단일 수단으로 두는 선택. 대안은 리졸버, 외부 상태 라이브러리
- **데이터 로딩 모델** — 화면 진입 후 조회하고 대기를 베일로 덮는 선택. 대안은 리졸버로 데이터를 받은 뒤 진입
- **폼 구현 수단** — 시그니처 폼과 그 위의 검증 배치. 대안은 리액티브 폼 유지
- **신선도를 맞추는 단계** — 화면 진입과 변경 뒤 조회에 머무는 선택. 캐시와 무효화로 올라가면 속도를 사고 정확성을 팝니다
- **생성 타입을 화면까지 그대로 쓰는 선택** — 변환 계층을 두지 않습니다. 백엔드 리팩터링이 화면까지 전파되는 대가로 매핑 유지 비용을 없앱니다
- **문서 배치** — 참조 아키텍처를 저장소 루트 한 트리에 모으는 선택. 대안은 축마다 자기 패키지 안에 두는 방식이며, 이식 단위가 축에서 저장소로 바뀌는 대가를 감수했습니다

**백엔드**

- **모듈 그룹 패키지** — 루트 아래에 `module` · `shared` 를 두는 선택. 대안은 업무 모듈과 공용 기반을 루트 직계에 나란히 두고 모듈이 아닌 것을 제외 목록으로 관리하는 방식
- **조회와 명령의 클래스 분리** — 서비스를 하나로 두고 저장소와 조회 포트를 함께 참조하는 선택. 대안은 명령 서비스와 조회 서비스를 나누고 "명령이 조회 포트를 주입받지 못한다"를 도구로 강제하는 방식이며, 그 강제를 포기하는 대가를 감수했습니다
- **저장소와 조회 포트의 경계** — 반환 타입으로 가르는 선택. 대안은 메서드의 성격으로 가르는 방식이며, 판정이 사람마다 갈리고 강제할 수 없어 기각했습니다
- **에러 코드의 표현** — 모듈별 열거형과 인터페이스 default 메서드. 대안은 실패마다 예외 클래스를 두는 방식, 문구를 `MessageSource` 로 외부화하는 방식
- **도메인 모델과 영속 모델의 분리** — 두 모델을 분리하고 저장소 구현이 변환하는 선택. 영속성 기술 선택에서 따라오는 부분이 있어 판별식 통과 여부를 재확인해야 합니다
- **정적 분석 도구 조합** — 구조 규칙과 버그 패턴, 포맷을 각각 어느 도구가 맡고 무엇을 빌드 실패로 둘 것인가
- **값 객체의 재구성 경로** — 저장된 값을 읽을 때 검증하지 않는 선택. 데이터베이스를 신뢰 경계 안으로 보는 전제이며, 규칙을 강화한 날 옛 데이터를 읽지 못하는 문제를 그 대가로 피합니다
- **생성 코드를 커밋하지 않는 선택** — 단일 원본을 두 벌로 만들지 않는 쪽. 대안은 커밋하고 CI 가 재생성 후 차이를 검사하는 방식
- **마이그레이션의 단일 원본과 down 스크립트 부재** — SQL 파일이 스키마의 원본이고 되돌리기를 새 마이그레이션으로 하는 선택. 대안은 코드에서 스키마를 만들거나 대조하는 방식
