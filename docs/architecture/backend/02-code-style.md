# 백엔드 02. 코드 작성 규약

백엔드 애플리케이션의 패키지, 클래스, 메서드, 변수의 명명 규약과 서비스 클래스 멤버 배치 순서, 주석 작성 규격 및 검증 기준을 정의합니다.

계층 구조는 디렉터리 경로뿐 아니라 클래스 명명과 애너테이션으로도 식별되므로, 본 명세의 명명 규약은 아키텍처 배치 규칙의 일부로 적용됩니다.

본 문서의 표와 코드 블록에 기재된 클래스명과 변수명은 규약의 형태를 설명하기 위한 대표 예시이며, 프로젝트의 전체 목록을 전수 나열한 것이 아닙니다.

## 1. 패키지

| 대상 | 규약 |
| :--- | :--- |
| **모듈** | 단수 소문자 한 단어 |
| **계층** | `contract` · `application` · `domain` · `infrastructure` 로 고정 |
| **세그먼트** | 복수형 명칭 사용 금지 |

모듈 패키지명에 복수형 사용을 금지합니다. 모듈은 애그리거트를 소유하는 단위이므로 단수형 명칭을 적용합니다.

패키지명은 소문자 알파벳만을 사용하며 언더스코어(`_`)나 대문자를 사용하지 않습니다.

## 2. 클래스 접미사

`application` 패키지 내부에는 프레젠테이션 계층과 애플리케이션 계층의 구성 요소가 함께 배치됩니다. 두 계층의 역할은 클래스 접미사와 애너테이션으로 식별하며, ArchUnit 정적 검증 도구가 이 규칙을 기반으로 아키텍처 준수 여부를 판정합니다.

| 역할 | 식별 기준 | 배치 패키지 |
| :--- | :--- | :--- |
| **컨트롤러** | `@RestController` + `Controller` 접미사 | `application` |
| **서비스** | `Service` 접미사 | `application` |
| **조회 서비스** | `QueryService` 접미사 | `application` |
| **조회 포트** | `Query` 접미사 | `application` |
| **요청 DTO 묶음** | `Requests` 접미사 | `application` |
| **응답 DTO 묶음** | `Views` 접미사 | `application` |
| **에러 코드** | `ErrorCode` 접미사 | `application` |
| **저장소 인터페이스** | `Repository` 접미사 | `domain` |
| **포트 구현체** | 기술 접두사 + 포트 명칭 | `infrastructure` |

**조회 포트에 `QueryRepository` 명칭 사용을 금지합니다.** 애그리거트 영속성을 관리하는 저장소(`Repository`)와 화면 표현 데이터를 조립하는 조회 포트(`Query`)의 역할을 명확히 분리하기 위함입니다.

**포트 인터페이스 명칭은 제공하는 기능을 기준으로 명명합니다.** 조회 포트는 조회(`Query`), 발송 포트는 발송 등 수행하는 역할을 명시하며, 구현 기술이나 저장 위치를 명칭에 포함하지 않습니다.

**인터페이스 명칭에 복수형 사용을 금지합니다.** 프로젝트 내 복수형 명칭은 복수 DTO 타입을 중첩하여 정의한 묶음 클래스(`*Requests`, `*Views`)로 용도를 한정하며, 인터페이스는 단수형 명칭을 적용합니다.

## 3. DTO

요청(`Requests`) 및 응답(`Views`) DTO는 모듈당 하나의 묶음 클래스(Holder class) 내부에 중첩 `record`로 선언합니다.

```java
public final class TaskRequests {

    private TaskRequests() {}

    public record CreateTask(
            @NotBlank(message = TaskTitle.REQUIRED)
            @Size(max = TaskTitle.MAX) String title) {}

    public record ChangeDueDate(LocalDate dueDate) {}
}
```

DTO 묶음 클래스는 인스턴스화를 방지하기 위해 `final` 클래스로 선언하고 `private` 기본 생성자를 정의합니다. 관련 DTO의 응집도를 높이고 모듈이 처리하는 입출력 계약의 가시성을 확보하기 위함입니다.

단일 묶음 클래스가 비대해질 경우 피쳐 단위로 분할하며, 분할 기준은 [5.3.3 하위 패키지 승격](../05-building-block-view.md) 규격을 따릅니다.

**목록 및 상세 조회의 반환 구조가 동일한 경우 응답 record를 분리하지 않고 단일 record를 공유합니다.** 상세 조회 전용 필드가 추가되는 시점에 별도 record로 분리합니다.

## 4. 에러 코드 문자열

에러 코드 문자열은 `<모듈>_<사유>` 형식의 `SCREAMING_SNAKE_CASE`를 적용합니다.

```java
TASK_NOT_FOUND
TASK_ALREADY_DONE
COMMON_INVALID_REQUEST
```

**식별자 구분 원칙**: 요구사항 및 유스케이스 식별자에는 하이픈(`-`)을 사용하고, 시스템 에러 코드에는 언더스코어(`_`)를 사용하여 전역 텍스트 검색 시 두 식별자 간 혼선을 방지합니다.

## 5. 메서드

| 대상 | 규약 |
| :--- | :--- |
| **도메인 생성 팩토리** | 업무 낱말(`create` · `register`). 생성자(`new`) 직접 공개 금지 |
| **도메인 재구성** | `restore` 명칭으로 고정. 영속성 저장소에서만 호출 |
| **명령 메서드** | 동사로 시작하며 `void` 또는 식별자 반환 |
| **조회 메서드** | `find`는 대상이 없을 수 있음(`Optional` 또는 컬렉션 반환), `get`은 대상이 없으면 예외 발생 |

**접근자에 `get` 접두사를 붙이지 않습니다.** 도메인 객체와 `record`는 필드명을 그대로 메서드 명칭으로 사용합니다.

**Lombok 플루언트 접근자 설정**: `lombok.config` 파일에 `lombok.accessors.fluent = true`가 선언되어 있어 `@Getter` 애너테이션 사용 시 `get` 접두사 없는 플루언트 스타일 접근자 메서드가 자동 생성됩니다.

**`@Setter` 사용을 금지합니다.** `lombok.config` 설정을 통해 `@Setter` 사용 시 빌드 오류가 발생하도록 강제합니다. 상태 변경은 도메인 비즈니스 규칙과 불변식을 검증하는 명시적 업무 메서드를 통해서만 수행합니다.

## 6. 메서드 배치

서비스 클래스(`application` 계층) 본문의 멤버는 아래 6개 블록 순서로 배치합니다. 각 블록 앞에 구분선 주석을 배치하고, 해당하는 멤버가 없는 블록은 구분선 주석을 포함하여 생략합니다.

| 순서 | 블록 | 대상 |
| :--- | :--- | :--- |
| 1 | 상수 | `static final` 상수 |
| 2 | 의존 | 의존성 주입 필드 |
| 3 | 생성 | 명시적 생성자 (`@RequiredArgsConstructor` 사용 시 생략) |
| 4 | 조회 | `@Transactional(readOnly = true)` 적용 메서드 |
| 5 | 명령 | `@Transactional` 적용 상태 변경 메서드 |
| 6 | 보조 | `private` 보조 메서드 |

구분선 주석은 `// --- <블록명> ` 뒤에 대시(`-`)를 채워 들여쓰기를 포함한 총 **120 컬럼**으로 작성합니다 (들여쓰기 포함 폭, 한글 2컬럼 계산, `palantirJavaFormat` 줄 폭 기준).

```java
    // --- 조회 --------------------------------------------------------------------------------------------------------
    @Transactional(readOnly = true)
    public MeView me(UUID userId) { ... }

    // --- 명령 --------------------------------------------------------------------------------------------------------
    @Transactional
    public void changeNickname(UUID userId, String rawNickname) { ... }
```

**조회 메서드 블록을 명령 메서드 블록보다 앞에 배치합니다.** 서비스 클래스 내부에서 읽기 트랜잭션과 쓰기 트랜잭션의 경계를 시각적으로 명확히 구분하기 위함입니다.

블록 내부의 메서드 정렬 순서는 별도로 강제하지 않으나, 명령 메서드의 경우 유스케이스 생애주기 순서(생성/추가 → 수정/편집 → 상태 변경 → 삭제)로 배치할 것을 권장합니다.

컨트롤러(`@RestController`)와 도메인 객체는 본 배치 규약의 적용 대상에서 제외합니다. 컨트롤러는 엔드포인트 단위로 구성되며, 도메인 객체는 팩토리 메서드·상태 변경 메서드·접근자의 형태가 명확히 구분되기 때문입니다.

본 배치 순서는 Checkstyle 등 자동 린트 도구로 검증되지 않으므로 코드 리뷰 단계에서 준수 여부를 확인합니다.

## 7. 변수

필드와 파라미터의 명칭은 대상 **타입명의 로워 카멜케이스(lowerCamelCase)**를 적용합니다.

| 대상 | 규약 |
| :--- | :--- |
| **주입 의존성 필드** | 대상 타입명의 카멜케이스 |
| **파라미터** | 대상 타입명의 카멜케이스. 동일 타입 파라미터가 2개 이상이면 역할 접두사 부가 |
| **컬렉션** | 담긴 요소 타입의 복수형 명사 |
| **상위 시그니처 준수 파라미터** | 재정의 대상 인터페이스/상위 클래스에 선언된 파라미터 명칭 유지 |

**임의 축약을 금지합니다.** 1~2글자로 줄인 축약 변수명 사용을 금지합니다. 저장소 인터페이스 주입 필드는 단수형 카멜케이스(예: `taskRepository`)로 선언하여 컬렉션 변수명과의 혼동을 방지합니다.

## 8. 주석

본 절은 설명 주석의 작성 규약을 정의합니다 (6절의 구조 구분선 주석 제외).

**주석 서식 태그 사용 금지**: `<p>`, `<b>`, `{@code}`, `{@link}` 등 렌더링을 위한 서식 태그 사용을 금지합니다.

### 8.1 설계 근거의 소스 코드 기술 금지

설계 의도, 아키텍처 결정 사유 및 기각된 대안에 대한 설명은 소스 코드 주석에 기술하지 않고 아키텍처 문서 및 결정 기록([9. 아키텍처 결정](../09-architecture-decisions.md))에서 관리합니다.

| 제외 항목 (금지) | 기술 항목 (허용) |
| :--- | :--- |
| 설계 선택의 근거 및 배경 | 해당 코드의 도메인 업무적 의미 |
| 기각된 기술 대안 및 사유 | 유스케이스 식별자 및 흐름 번호 |
| 다른 방식과의 비교 및 결과 예측 | 팩토리 메서드 호출 방법 등 코드 사용법 |
| 아키텍처 및 참조 문서에 기재된 규칙의 중복 설명 | 미인지 시 런타임 오류를 유발하는 동작상 주의사항 |

### 8.2 도메인 엔티티 필드의 한글 주석 명시

도메인 엔티티의 필드 선언 상단에는 `//` 단일행 주석으로 **도메인 업무 용어(한글)**를 명시합니다.

```java
// 나의 하루에 담은 날짜
private LocalDate myDayOn;
```

영문 식별자와 도메인 업무 서술서 및 UI 화면 용어 간의 명확한 대응 관계를 제공하기 위함입니다.

## 9. 테스트

테스트 클래스명은 **테스트 대상 클래스명 + `Test`** 접미사를 적용합니다. 검증 대상 클래스가 아닌 특정 기능 또는 성공 조건을 검증하는 테스트 명명 규약 및 슬라이스 ID 부여 규칙은 [프로세스 문서](../../process.md)를 따릅니다.

## 10. 강제 수단 및 검증 방식

| 규칙 | 검증 주체 및 강제 수단 |
| :--- | :--- |
| 패키지 구조 및 계층 의존성 참조 규칙 | ArchUnit 아키텍처 테스트 자동 검증 (빌드 차단) |
| 클래스 접미사에 따른 계층 판정 | ArchUnit 아키텍처 테스트 자동 검증 (빌드 차단) |
| 식별자 형식(타입 · 멤버 · 파라미터 · 메서드 · 상수) | Checkstyle 정적 분석 자동 검증 (빌드 차단) |
| 플루언트 접근자 강제 및 `@Setter` 사용 금지 | `lombok.config` 컴파일 시점 자동 차단 |
| 소스 코드 포맷팅 및 줄 폭(120) | Spotless (`palantirJavaFormat`) 자동 교정 |
| 서비스 클래스 멤버 배치 순서 및 구분선 폭 | 코드 리뷰 검증 (정적 분석 미지원) |
| 임의 축약 금지와 역할 접두사 | 코드 리뷰 검증 (형식만 검사되므로 의미는 판정되지 않음) |
| 주석 태그 배제 및 설계 근거 미포함 규약 | 코드 리뷰 검증 |
