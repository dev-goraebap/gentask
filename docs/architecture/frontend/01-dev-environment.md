# 프론트엔드 01. 개발 환경

프론트엔드 애플리케이션의 구성 파일 명세, 실행 명령, 경로 별칭 및 줄바꿈 정책, 자동화 강제 수단의 적용 범위와 예외 규정을 정의합니다.

본 문서는 규칙이 빌드 및 린트 도구에서 강제되는 지점과 그 예외 기준을 명시합니다.

## 1. 구성 파일

설정값을 문서에 중복 기술하지 않고 구성 파일을 단일 진실 공급원(Single Source of Truth)으로 참조합니다. 문서는 규칙과 판정 기준을 정의하고, 구성 파일은 해당 규칙의 구체적인 실행 형태를 관리합니다.

| 파일 | 역할 |
| :--- | :--- |
| `package.json` | 의존성 및 패키지 버전 관리 |
| `tsconfig.json` | 컴파일러 옵션, 경로 별칭(`paths`) 정의 |
| `angular.json` | 빌드 설정, 번들 예산, 전역 스타일 경로 등록 |
| `steiger.config.ts` | FSD 계층 구조 및 슬라이스 의존성 규칙 강제 |
| `eslint.config.js` | 코드 규약, 전역 프로바이더 위치 제한, 임포트 제한, 템플릿 접근성 검사 |
| `.postcssrc.json` | Tailwind CSS 플러그인 등록 |
| `.prettierrc` · `.editorconfig` | 코드 포맷팅 및 에디터 기본 서식 설정 |
| `proxy.conf.json` | 로컬 개발 서버의 백엔드 API 프록시 설정 |
| `.gitattributes` (저장소 루트) | 줄바꿈 정책(EOL) 및 바이너리/생성 파일 처리 지정 |

## 2. 명령

| 명령 | 용도 |
| :--- | :--- |
| `npm start` | 로컬 개발 서버 실행 (`proxy.conf.json`을 통해 API 요청을 백엔드로 프록시) |
| `npm run build` | 운영 빌드 수행 (번들 예산 초과 시 경고/에러 처리) |
| `npm test` | 단위 및 컴포넌트 테스트 실행 |
| `npm run lint` | ESLint 기반 코드 규약 검사 |
| `npm run lint:fsd` | Steiger 기반 FSD 계층 규칙 검사 |
| `npm run check` | 린트(`lint`, `lint:fsd`), 테스트, 빌드를 순서대로 실행 |
| `npm run api:generate` | 백엔드 OpenAPI 명세로부터 프론트엔드 TypeScript 타입 생성 |

`npm run check` 검증을 통과하지 않은 코드는 코드베이스에 병합할 수 없습니다. 지속적 통합(CI) 환경에서는 `npm run check` 단일 명령을 통해 프론트엔드 전체 검증을 수행합니다.

## 3. 경로 별칭

```json
// tsconfig.json
{ "compilerOptions": { "paths": { "@/*": ["./src/*"] } } }
```

`baseUrl` 설정의 사용을 **금지**합니다. TypeScript 컴파일러에서 폐기 예정으로 지정되어 있으며, 설정 시 `TS5101` 오류가 발생하여 빌드가 차단됩니다. `paths` 매핑만을 정의하고 상대 경로를 값으로 지정합니다.

계층 간 임포트에 상대 경로를 사용하는 것은 ESLint `no-restricted-imports` 규칙으로 차단합니다. Steiger는 상대 경로로 작성된 참조 위반도 검출하므로, 별칭 규칙 적용의 주된 목적은 **파일 이동 내성(Refactoring Resilience)** 확보입니다. 슬라이스를 다른 계층으로 이동할 때 상대 경로는 모두 수정이 필요하지만 경로 별칭은 그대로 유지됩니다.

## 4. 줄바꿈 정책

모든 텍스트 파일은 저장소와 로컬 체크아웃 환경 모두에서 **LF** 줄바꿈을 적용합니다. 저장소 루트의 `.gitattributes`에 선언된 `* text=auto eol=lf` 설정이 개발자 로컬 환경의 `core.autocrlf` 설정보다 우선합니다.

해당 정책을 명시하지 않을 경우 Windows 환경에서 체크아웃 시 CRLF로 자동 변환되어 불필요한 변경 이력이 발생하고 줄바꿈 차이로 인한 머지 충돌을 유발합니다.

| 대상 | 처리 규격 |
| :--- | :--- |
| 텍스트 파일 전반 | LF |
| `*.bat` · `*.cmd` | CRLF (`cmd.exe` 실행 환경 호환) |
| 이미지 · 폰트 · 문서 바이너리 | 개행 변환 금지 (`-text`) |
| `package-lock.json` | `linguist-generated=true` 지정 (수동 리뷰 대상에서 제외) |

**OpenAPI 생성 타입 파일은 `linguist-generated`로 지정하지 않습니다.** 생성 코드를 형상 관리에 커밋하는 목적은 API 계약 변경 사항을 풀 리퀘스트(PR)의 diff에서 명시적으로 확인하기 위함입니다. diff 표시가 축소되면 백엔드 API 변경에 따른 필드 누락이나 타입 불일치를 병합 전에 검증할 수 없습니다.

## 5. 전역 스타일 배치 및 테마 관리

전역 스타일 파일은 `src/app/styles.css`에 배치하며, `angular.json`의 `styles` 항목에 해당 경로를 등록합니다. 이는 FSD 아키텍처에서 전역 스타일을 최상위 `app` 계층에 배치하도록 규정함에 따른 조치입니다.

**`src/styles.css` 기본 파일을 루트에 잔존시키지 않습니다.** Spartan CLI의 스타일 진입점 자동 탐지 로직은 `angular.json` 설정을 우선 확인하지 않고 `<sourceRoot>/styles.{css,scss,sass,less}` 파일의 존재 여부를 먼저 검사합니다. 기본 경로에 파일이 남아 있는 경우 `angular.json`이 참조하지 않는 파일에 테마 스타일이 잘못 작성될 수 있습니다. UI 컴포넌트 생성기 실행 시 `--stylesEntryPoint` 옵션을 명시하여 탐지 순서와 무관하게 진입점 경로를 고정합니다.

**테마 스타일은 스타일시트에서 단독으로 제어합니다.** 라이트 모드 및 다크 모드 전환은 HTML 루트 요소의 클래스 속성으로 제어하므로, 스타일시트 외부에서 배경색이나 `color-scheme`을 직접 정의할 경우 시스템 테마 설정에만 종속되어 애플리케이션의 테마 전환 제어가 무효화됩니다. 따라서 진입점 문서(`index.html`) 내 인라인 스타일로 색상이나 테마를 선언하는 것을 **금지**합니다.

## 6. 강제 수단의 적용 범위

아키텍처 및 코드 규약의 검증 주체를 자동화 도구와 코드 리뷰로 명확히 분리하여 관리합니다. 자동 강제되지 않는 규칙은 코드 리뷰 단계에서 필수로 검증합니다.

| 자동 차단 (빌드 / 린트 도구) | 코드 리뷰 검증 대상 (수동 확인) |
| :--- | :--- |
| 계층 간 임포트 방향 위반 (`fsd/forbidden-imports`) | `shared` 계층 내 비즈니스 로직 유입 여부 |
| 공개 API (`index.ts`) 우회 참조 (`no-restricted-imports`) | 적응형 컴포넌트의 뷰포트별 테스트 케이스 작성 여부 |
| 동일 계층 슬라이스 간 크로스 임포트 | 단일 파일 내 복수 도메인/책임 혼재 여부 |
| 미검증 조기 추출 슬라이스 (`insignificant-slice`) | 디자인 토큰 대신 임의의 매직 넘버/하드코딩 값 사용 여부 |
| 번들 예산(Bundle Budget) 초과 | 시각 디자인 세부사항(디자인 시스템 소유)의 아키텍처 문서 혼입 여부 |
| 잘못된 계층에서의 전역 프로바이더(`providedIn: 'root'`) 선언 | |

## 7. 규칙의 예외

도구별 린트 및 규칙 완화 설정은 각 구성 파일에서 관리하며, 본 절에서는 해당 예외의 승인 사유와 적용 범위를 정의합니다.

| 대상 | 완화 규칙 | 적용 사유 |
| :--- | :--- | :--- |
| 테스트 파일 (`*.spec.ts`) | ESLint 브라우저 API 직접 접근 제한 | 테스트는 jsdom 환경에서 실행되며 서버 렌더링 경로를 거치지 않음. 브라우저 API를 다루는 단위 검증을 위해 대상 API 직접 호출이 필요함 |
| 서버 진입점 (`main.server.ts`) | ESLint `no-console` | Node.js 서버 런타임 진입점의 표준 로깅 채널이 `stdout`이므로 브라우저 콘솔 정보 유출 방지 규칙의 적용 대상에서 제외함 |
| `pages` 계층 | Steiger `excessive-slicing` | 슬라이스 수가 적은 초기 개발 단계에서의 과분할 경고 노이즈 방지. 슬라이스가 3개 이상으로 확장되는 시점에 예외 설정을 해제함 |
| OpenAPI 생성 타입 | ESLint 전체 규칙 | 자동 생성 파일은 수동 수정이 불가능하므로 린트 검사 노이즈 방지를 위해 검사 대상에서 제외함 |
| 외부 UI 킷 복사본 (Spartan) | ESLint 선택자 접두사, `no-input-rename`, `Injector` 임포트 제한 | 라이브러리 원본 규약 유지 및 재생성 호환성 보장. 표준 HTML 속성명 바인딩을 위한 별칭 사용 허용 및 `runInInjectionContext` 인자 전달 목적의 `Injector` 참조 허용 |
| 외부 UI 킷 복사본 (Spartan) | Steiger `public-api`, `no-reserved-folder-names` | 외부 라이브러리 코드 생성기가 정의한 내부 디렉터리 구조 유지 |
| 프로젝트 전역 | Steiger `no-public-api-sidestep` | 컴포넌트별 개별 진입점 참조를 우회로 오탐지하는 문제 대응. 슬라이스 내부 비공개 파일 직접 임포트는 ESLint `no-restricted-imports` 규칙으로 차단함 |

## 8. 실측으로 확인한 도구 동작 특성

아키텍처 및 개발 환경 규격의 근거가 되는 빌드·린트 도구의 검증 완료된 동작 특성입니다.

| 항목 | 검증 결과 |
| :--- | :--- |
| Steiger의 경로 별칭 인식 여부 | 정상 인식함. TypeScript 경로 별칭(`@/*`) 기반 임포트를 FSD 계층 구조로 해석함 |
| Steiger의 참조 규칙 위반 검출 여부 | 정상 검출함. 하위 계층에서 상위 계층으로의 역방향 참조는 `fsd/forbidden-imports`, 슬라이스 내부 직접 참조는 `fsd/no-public-api-sidestep`으로 차단됨 |
| Steiger의 상대 경로 참조 검출 여부 | 정상 검출함. 상대 경로로 작성된 계층 위반도 동일하게 차단됨 |
| Steiger의 슬라이스 그룹 명명 제한 여부 | 제한함. 그룹 디렉터리명이 `shared`의 세그먼트 명칭과 중복될 경우 `fsd/ambiguous-slice-names` 에러로 빌드가 차단됨 |
| 프레임워크 진입점 파일의 미분류 경고 여부 | 경고 발생하지 않음. 의도를 명확히 하기 위해 `steiger.config.ts`의 `ignores` 목록에 등록하여 관리함 |
| `baseUrl` 설정 사용 가능 여부 | 사용 불가. TypeScript 컴파일러에서 `TS5101` 오류가 발생함 |
| 배럴 파일의 지연 로딩 청크 분리 방해 여부 | **동일 배럴 파일을 즉시 임포트와 지연 임포트(`loadComponent`)가 동시에 참조할 경우 번들 분리를 방해함.** 라우트 설정에서 배럴을 통해 프로바이더를 즉시 가져오면서 `loadComponent`로 동일 배럴을 호출할 경우, 지연 청크는 91 바이트의 껍데기 파일만 생성되고 실제 컴포넌트 코드가 초기 번들로 병합됨. 즉시 참조 심볼을 별도 진입점으로 분리 시 초기 번들이 517 kB에서 377 kB로 감소하고 지연 청크가 91 바이트에서 141 kB로 정상 분리됨 |
| 단일 방식(즉시 또는 지연) 배럴 참조 시 동작 | 번들 분리 간섭 없음. 사용되지 않는 재수출(re-export) 심볼은 트리 셰이킹(Tree-shaking)을 통해 정상 제거됨 |
| 배럴 파일의 `@defer` 의존성 분리 방해 여부 | **번들 분리를 방해함.** 동일 배럴 파일에서 즉시 로딩 심볼과 `@defer` 블록 내부 전용 심볼을 동시에 가져올 경우 모듈이 정적으로 바인딩되어 지연 청크가 생성되지 않음. 컴포넌트별 개별 파일 경로로 임포트를 분리한 결과 초기 번들이 544 kB에서 275 kB로 감소함 |
| 동적 주입 토큰의 정적 구문 규칙 검출 여부 | 정적 구문 분석으로 검출 불가. 정상적인 `Map.get` 호출과 문법적으로 구분되지 않으므로 ESLint의 `Injector` 임포트 제한 규칙으로 대체 강제함 |
| 생성 파일의 수동 편집 린터 차단 여부 | 차단 불가. 린터는 파일 수정을 직접 차단하지 못하므로 CI 파이프라인의 재생성 일치 검증 단계로 대체 강제함 |
| 비ASCII(한글) 경로의 정적 파일 서빙 여부 | 정적 파일(`index.html`) 생성은 완료되나 **웹 서버 서빙 단계에서 404 에러 반환됨.** 따라서 라우팅 경로 정의 시 영문 슬러그(Slug) 규칙을 적용함 |
