# 프론트엔드 02. 코드 스타일 가이드

## 1. 목적과 적용 범위

`web/src` 아래의 TypeScript · HTML · CSS 에 적용합니다. 외부 UI 킷 사본과 생성된 API 타입은 대상이 아닙니다.

규칙은 세 수준으로 나눕니다. 이 구분이 없으면 리뷰에서 취향 논쟁이 반복됩니다.

| 수준 | 뜻 |
| :--- | :--- |
| **필수** | 어기면 병합하지 않습니다. 대부분 도구가 막습니다 |
| **권장** | 다르게 할 이유를 말할 수 있으면 따르지 않아도 됩니다 |
| **취향** | 규칙을 두지 않습니다. 리뷰에서 지적하지 않습니다 |

기존 코드에 소급하지 않습니다. **손대는 파일만 고칩니다.** 규칙이 바뀔 때마다 전체를 훑으면 변경 이력이 규칙 적용으로 덮여 실제 변경을 찾을 수 없습니다.

각 규칙은 `FE-STY-NNN` 으로 참조합니다. 번호는 부여 뒤 바꾸지 않으며 삭제는 결번, 추가는 말번입니다.

## 2. 포매팅

**FE-STY-001 (필수)** 포매팅은 도구가 강제하며 `.prettierrc` 가 유일한 기준입니다. 들여쓰기 · 줄 길이 · 따옴표 · 세미콜론을 이 문서에 적지 않습니다. 설정과 설치는 개발 환경 문서가 갖습니다.

## 3. 네이밍

### 3.1 파일

**FE-STY-002 (필수)** 파일명은 케밥 케이스입니다.

**FE-STY-003 (필수)** 파일이 클래스를 내보내면 파일명은 그 클래스명을 옮긴 것입니다. 클래스명이 바뀌면 파일명도 바뀝니다.

| 대상 | 클래스 | 파일 |
| :--- | :--- | :--- |
| 컴포넌트 | `TaskRow` | `task-row.ts` |
| 라우트 진입 컴포넌트 | `TaskListPage` | `task-list.page.ts` |
| 서비스 | `SessionService` | `session-service.ts` |
| 가드 · 인터셉터(함수) | — | `auth-guard.ts` · `auth-interceptor.ts` |

**FE-STY-004 (필수)** 한 파일이 클래스 둘을 내보내지 않습니다. 파일명이 한쪽만 가리켜 나머지를 이름으로 찾을 수 없습니다.

**FE-STY-005 (필수)** `pages` 슬라이스의 라우트 진입 컴포넌트는 `.page` 접미사를 갖고 클래스명은 `Page` 로 끝냅니다. `ui/` 가 평면이라 진입점과 표현 컴포넌트가 나란히 쌓이면 구분이 사라집니다. 선택자에는 붙이지 않습니다 — 템플릿에 나타나지 않습니다.

**FE-STY-006 (필수)** 세그먼트 안의 파일은 다루는 도메인으로 이름 짓습니다.

```
model/task.ts        lib/format-due-date.ts     api/fetch-tasks.ts      // Good
model/types.ts       lib/utils.ts               api/api.ts              // Bad
```

역할이 불명확한 자리에는 서로 다른 관심사가 쌓입니다.

**FE-STY-007 (필수)** 요청 함수 파일은 동사로 시작합니다 — `fetch-tasks.ts` · `create-task.ts` · `delete-task.ts`.

### 3.2 심볼

**FE-STY-008 (필수)** 클래스는 파스칼 케이스이며 `Component` · `Directive` · `Pipe` 접미사를 붙이지 않습니다. 파일 위치가 이미 역할을 드러냅니다.

**FE-STY-009 (필수)** 서비스만 `Service` 로 끝냅니다. 근거는 역할 표시가 아니라 FE-STY-011 입니다 — 복수형 명사 클래스는 주입 변수가 목록 변수와 충돌합니다.

**FE-STY-010 (필수)** 함수는 하는 일을 접두사로 드러냅니다.

| 성격 | 접두사 | 예 |
| :--- | :--- | :--- |
| 주입 헬퍼 | `inject` | `injectViewportClass` |
| 조회 요청 | `fetch` | `fetchTasks` |
| 변경 요청 · 계산 | 동사 | `completeTask` · `formatDate` |
| 판정 | `is` · `has` · `can` | `isExpired` |

**FE-STY-011 (필수)** 주입 결과를 그대로 담는 필드는 클래스명의 로워 카멜 케이스입니다. 축약하지 않습니다.

```ts
private readonly httpClient = inject(HttpClient);   // Good
private readonly http = inject(HttpClient);         // Bad — 파일마다 이름이 갈립니다
```

주입값을 변환한 결과는 그 값의 의미로 이름 짓습니다(`isServer`).

**FE-STY-012 (필수)** 타입에 `I` 접두사나 `Type` 접미사를 붙이지 않습니다. 생성된 서버 타입은 생성기가 정한 이름을 그대로 씁니다.

**FE-STY-013 (필수)** 컴포넌트 선택자는 `app` 접두사와 케밥 케이스, 디렉티브 선택자는 접두사를 붙인 카멜 케이스 속성입니다. 접두사의 원본은 `angular.json` 의 `prefix` 입니다.

**FE-STY-014 (필수)** 상수는 대문자 스네이크 케이스입니다.

### 3.3 슬라이스

**FE-STY-015 (필수)** 슬라이스명은 케밥 케이스이며 계층에 따라 품사가 다릅니다. **품사 차이가 `features` 와 `entities` 의 판정 기준입니다** — 동사구가 자연스러우면 `features`, 명사면 `entities` 입니다.

| 계층 | 품사 | 예 |
| :--- | :--- | :--- |
| `pages` | 화면을 나타내는 명사구 | `task-list` |
| `features` | 사용자 동작을 나타내는 동사구 | `file-upload` |
| `entities` | 도메인 개념을 나타내는 명사 | `task` |

**FE-STY-016 (필수)** `pages` 슬라이스명은 라우트와 대응시키고 접미사를 `-list` · `-detail` · `-edit` · `-create` 로 통일합니다.

**FE-STY-017 (필수)** 금지하는 이름 — 계층명을 포함한 이름, 포괄적인 이름(`common` · `misc` · `management`), 축약어, `shared` 의 세그먼트명과 겹치는 그룹명.

## 4. 코드 구조

계층과 슬라이스의 정의, 임포트 방향, 공개 API 규칙은 빌딩 블록 뷰가 갖습니다. 이 절은 **새 코드를 어디에 두는가**를 정합니다.

### 4.1 배치 판정

**FE-STY-018 (필수)** 위에서부터 순서대로 판정하고 먼저 해당하는 항목에서 멈춥니다.

```text
1. 애플리케이션 전역 설정인가?            → app/
2. 비즈니스 로직이 없는 인프라인가?        → shared/<세그먼트>/
3. 한 화면에서만 쓰는가?                  → pages/<화면>/
4. 여러 화면이 이미 쓰는 사용자 동작인가?   → features/<동작명>/
5. 여러 화면이 이미 쓰는 도메인 모델인가?   → entities/<도메인명>/
6. 확신이 없는 경우                       → pages/<화면>/
```

**FE-STY-019 (필수)** 6번이 기본값입니다. 화면 간 중복은 허용하며 중복 자체는 추출의 근거가 아닙니다. 가설적 재사용을 근거로 하위 계층에 두지 않습니다 — 되돌리는 비용이 승격하는 비용보다 큽니다.

**FE-STY-020 (필수)** 4번과 5번의 "이미 쓰는"은 **현재 두 곳 이상에서 실제로 호출됨**을 뜻합니다. 앞으로 그럴 것 같다는 판단은 조건을 만족하지 않습니다.

### 4.2 승격과 강등

**FE-STY-021 (필수)** 승격은 같은 코드가 두 번째 화면에서 실제로 필요해진 시점에 합니다. 사용자 동작이면 `features`, 도메인 모델이면 `entities` 입니다.

**FE-STY-022 (권장)** 강등은 규칙 위반이 아닙니다. 한 화면에서만 쓰이는 슬라이스는 그 화면으로 되돌립니다. 재사용 예측이 빗나가는 것은 정상이며 되돌리는 것이 방치보다 낫습니다.

### 4.3 클래스 멤버 순서

**FE-STY-023 (필수)** 클래스 본문은 여덟 블록 순서로 배치하고 각 블록 앞에 구분선 주석을 둡니다. 없는 블록은 주석째 생략합니다.

| 순서 | 블록 | 대상 |
| :--- | :--- | :--- |
| 1 | 상수 | `static`, 템플릿에 재노출하는 심볼 |
| 2 | 계약 | `input` · `model` · `output` |
| 3 | 의존 | `inject` |
| 4 | 질의 | `viewChild` · `contentChild` |
| 5 | 상태 | `signal` · `linkedSignal` · `form` |
| 6 | 파생 | `computed` · `resource` · `httpResource` |
| 7 | 생성 | 생성자 · 라이프사이클 훅 |
| 8 | 동작 | 공개 메서드 먼저, `private` 나중 |

**참조 방향이 곧 읽는 방향입니다.** 파생은 상태를, 상태는 의존을 참조하므로 참조 대상이 항상 위에 있습니다.

**FE-STY-024 (필수)** 구분선은 `// --- ` 뒤에 블록명을 두고 대시로 100 컬럼까지 채웁니다. 들여쓰기를 포함한 폭이며 한글은 두 컬럼으로 셉니다.

**FE-STY-025 (필수)** 한 블록은 파일당 한 번만 등장합니다. 뒤에서 앞 블록으로 되돌아가 멤버를 추가하지 않습니다.

**FE-STY-026 (필수)** 템플릿에 재노출한 상수는 클래스 안에서도 그 필드로 참조합니다. 원본을 직접 참조하면 한 파일에 같은 값이 두 이름으로 존재합니다. 템플릿이 쓰지 않는 상수는 필드로 얹지 않습니다.

**FE-STY-027 (권장)** 멤버 분산의 부담이 크면 원인은 순서가 아니라 컴포넌트 크기입니다. 컴포넌트를 나눕니다.

## 5. TypeScript · Angular 관용구

**FE-STY-028 (필수)** `any` 를 쓰지 않습니다. 타입을 모르면 `unknown` 으로 받고 좁힙니다.

**FE-STY-029 (필수)** 열거는 `enum` 대신 `as const` 객체와 유니온 타입입니다. `enum` 은 런타임 코드를 만들고 `isolatedModules` 에서 제약이 있습니다.

```ts
export const TASK_STATUS = { todo: 'TODO', done: 'DONE' } as const;
export type TaskStatus = (typeof TASK_STATUS)[keyof typeof TASK_STATUS];
```

**FE-STY-030 (필수)** 템플릿과 호스트 바인딩에 노출되는 식별자는 영문입니다. 템플릿 파서가 한글 식별자를 `NG5002` 로 거부하며 컴파일 단계에서야 드러납니다. 한글은 `private` 멤버와 지역 변수에만 씁니다.

**FE-STY-031 (필수)** `providedIn: 'root'` 는 `shared` 와 `app` 에서만 선언합니다. `pages` 가 전역 싱글턴을 만들면 서비스 수명이 화면 수명과 어긋나 화면을 떠나도 상태가 남습니다. 화면 범위 서비스는 라우트의 `providers` 에 둡니다.

**FE-STY-032 (필수)** 계층 간 임포트는 `@/*` 별칭입니다. 상대 경로는 같은 슬라이스 내부에서만 씁니다. 근거는 검출 가능성이 아니라 **파일 이동 내성**입니다.

**FE-STY-033 (권장)** 조회는 라우트 스코프의 `httpResource`, 명령은 명령 전용 서비스로 나눕니다.

## 6. 주석

**FE-STY-034 (필수)** 주석은 무엇이 아니라 **왜** 를 적습니다. 코드를 읽으면 아는 것을 되풀이하지 않습니다.

**FE-STY-035 (필수)** 설계 근거를 소스에 적지 않습니다. 그것은 아키텍처 문서와 결정 기록이 갖습니다. 특히 **하지 않은 선택을 변호하는 문장**을 넣지 않습니다 — 읽는 사람은 지금 있는 것을 이해하려는 것입니다.

| 뺍니다 | 남깁니다 |
| :--- | :--- |
| 설계 선택의 근거, 기각한 대안 | 이 코드가 업무에서 무엇인가 |
| 문서에 이미 있는 규칙 설명 | 유스케이스 ID 와 흐름 번호 |
| 다른 방식의 결과 예측 | 모르면 깨지는 동작상 주의 |

**FE-STY-036 (필수)** `TODO` 는 `// TODO(작성자): 내용` 형식입니다. 주인 없는 TODO 는 지워지지 않습니다.

## 7. 에러 처리와 로깅

**FE-STY-037 (필수)** 401 을 화면마다 개별 처리하지 않습니다. 여러 화면이 동시에 로그인 이동을 시도합니다. 인터셉터가 한 곳에서 처리합니다.

**FE-STY-038 (필수)** 인터셉터에서 토스트를 띄우지 않습니다. 화면이 표시를 통제할 수 없게 됩니다.

**FE-STY-039 (필수)** 조회 실패를 빈 상태로 표시하지 않습니다. 사용자가 데이터 없음으로 오해합니다.

**FE-STY-040 (필수)** 변경 요청을 자동 재시도하지 않습니다. 중복 처리가 발생합니다.

**FE-STY-041 (필수)** 스택 트레이스와 내부 식별자를 화면에 노출하지 않습니다.

**FE-STY-042 (필수)** 응답 객체 전체를 콘솔에 출력하지 않습니다. 개인정보와 토큰이 함께 나갑니다. 필요한 필드만 골라 출력합니다.

**FE-STY-043 (필수)** `console.log` 를 커밋하지 않습니다. ESLint `no-console` 이 막으며 `console.error` 와 Node 진입점은 예외입니다.

**FE-STY-044 (권장)** 400 · 403 을 관측 도구로 보내지 않습니다. 정상적인 입력 오류가 쌓이면 실제 장애가 그 안에 묻힙니다.

## 8. 테스트 코드 스타일

**FE-STY-045 (필수)** 테스트 파일은 대상 파일 옆에 둡니다. `__tests__` 디렉터리를 만들지 않습니다 — 코드를 옮길 때 테스트가 따라오지 않습니다. E2E 는 계층에 속하지 않으므로 저장소 루트에 둡니다.

**FE-STY-046 (필수)** 분기가 있는 코드는 테스트합니다. 분기 없는 위임 함수는 대상이 아닙니다.

**FE-STY-047 (필수)** 프레임워크 동작과 생성된 타입을 검증하지 않습니다. 우리가 쓴 코드가 아니며 버전이 오를 때마다 깨집니다.

**FE-STY-048 (필수)** CSS 클래스로 요소를 선택하지 않습니다. 스타일 변경에 테스트가 깨집니다. 역할과 접근 가능한 이름으로 찾습니다.

**FE-STY-049 (필수)** 고정 시간 대기를 쓰지 않습니다. 느리고 불안정합니다.

**FE-STY-050 (필수)** 불안정한 테스트를 재시도로 통과시키지 않습니다. 실제 결함을 숨깁니다.

**FE-STY-051 (필수)** 응답 목을 임의 객체로 만들지 않습니다. 생성된 타입을 써야 계약 변경이 검출됩니다.

**FE-STY-052 (권장)** 커버리지 수치를 게이트로 쓰지 않습니다. 통과만 시키는 테스트를 유도합니다.

## 9. 예외 처리 절차

**FE-STY-053 (필수)** 규칙을 어겨야 하면 그 자리에 사유를 남깁니다. `eslint-disable` 에는 어느 규칙을 왜 끄는지 함께 적습니다. 사유 없는 억제는 리뷰에서 되돌립니다.

**FE-STY-054 (필수)** 도구 설정으로 예외를 두는 경우 **완화한 규칙의 근거가 왜 그 대상에 적용되지 않는지**를 개발 환경 문서의 예외 절에 적습니다. 선언은 설정 파일이, 사유는 그 문서가 갖습니다.

**FE-STY-055 (필수)** 규칙 자체를 바꾸려면 이 문서를 고칩니다. 도구 설정만 완화하는 변경은 허용하지 않습니다. 규칙과 강제가 어긋나면 문서가 거짓이 됩니다.

**FE-STY-056 (권장)** 대안을 검토하고 트레이드오프를 한 문단 이상 쓸 수 있으면 결정 기록으로 발행합니다. 쓸 수 없으면 이 문서 본문에 직접 적습니다.
