# 참조 아키텍처

본 문서는 이 저장소의 아키텍처 규칙 체계의 진입점입니다. 개별 세부 규칙의 본문을 직접 기술하지 않고, 문서 구조와 도입 순서 및 분류 체계를 정의합니다.

분류는 [arc42](https://arc42.org/) 섹션 체계를 차용하되 필요한 섹션만 사용합니다.

## 세 축

| 축 | 폴더 | 담는 것 |
| :--- | :--- | :--- |
| **공통** | `shared/` | 두 축에 걸치는 계약. 어느 한쪽만 고쳐서는 성립하지 않는 규약이 여기 옵니다 |
| **프론트엔드** | `frontend/` | Angular · FSD · 화면 |
| **백엔드** | `backend/` | Spring Boot · 모듈 · 계층 |

`shared/` 는 아직 비어 있습니다. API 의 전송 형식과 실패의 전송 표현처럼 지금 두 축이 각자 서술하는 것들이 그 자리의 후보이며, 내용을 떼어낼 때 채웁니다.

**시각 언어는 이 트리에 두지 않습니다.** [web/docs/design/DESIGN.md](../../web/docs/design/DESIGN.md)가 소유하며 프로젝트마다 새로 작성합니다. 분리의 근거는 [결정-0001](decisions/0001-frontend-design-outside-architecture.md)에 있습니다.

## 파일명과 번호

참조 문서는 `<축>/NN-이름.md` 형식으로 명명하며 `NN`은 **아키텍처 도입 순서**를 의미합니다. 단순 열람 순서가 아닌 **초기 구축 및 타 프로젝트 이식 시 선행되어야 하는 의존성 순서**이며, 사후 변경 시 기존 코드에 미치는 영향도(파급 범위)를 기준으로 정의되었습니다.

번호는 축마다 따로 셉니다. `frontend/03` 과 `backend/03` 은 다른 문서이며, 둘 다 코드 작성 규약인 것은 두 축이 같은 자리에 같은 성격의 규칙을 두기로 한 결과입니다.

| 축 | 구간 | 번호 | 시점 |
| :--- | :--- | :--- | :--- |
| **프론트엔드** | 기반 | 01~04 | 첫 코드를 작성하기 전에 확정되어야 합니다 |
| | 화면 | 05~13 | UI 프로토타입 단계에서 필요해집니다 |
| | 연결 | 14~16 | 백엔드 연동 시점에 필요해집니다 |
| | 검증 | 17~18 | 검증 게이트 이후 단계에서 필요해집니다 |
| **백엔드** | 기반 | 01~04 | 첫 코드를 작성하기 전에 확정되어야 합니다 |
| | 구현 | 05~08 | 슬라이스 구현 단계에서 필요해집니다 |
| | 검증 | 09 | 검증 게이트 이후 단계에서 필요해집니다 |

프로세스 단계와의 대응은 [프로세스 문서](../process.md)가 원본입니다.

**용어의 정의는 그 용어를 도입하는 문서가 소유합니다.** 각 참조 문서 하단에 그 문서가 도입한 용어를 두며, 별도의 용어집 문서를 두지 않습니다.
