# 백엔드 02. 코드 스타일 가이드

## 1. 목적과 적용 범위

`server/src` 아래의 Java 에 적용합니다. jOOQ 생성 코드는 대상이 아닙니다.

규칙은 세 수준으로 나눕니다. 이 구분이 없으면 리뷰에서 취향 논쟁이 반복됩니다.

| 수준 | 뜻 |
| :--- | :--- |
| **필수** | 어기면 병합하지 않습니다. 대부분 도구가 막습니다 |
| **권장** | 다르게 할 이유를 말할 수 있으면 따르지 않아도 됩니다 |
| **취향** | 규칙을 두지 않습니다. 리뷰에서 지적하지 않습니다 |

기존 코드에 소급하지 않습니다. **손대는 파일만 고칩니다.** 규칙이 바뀔 때마다 전체를 훑으면 변경 이력이 규칙 적용으로 덮여 실제 변경을 찾을 수 없습니다.

각 규칙은 `BE-STY-NNN` 으로 참조합니다. 번호는 부여 뒤 바꾸지 않으며 삭제는 결번, 추가는 말번입니다.

## 2. 포매팅

**BE-STY-001 (필수)** 포매팅은 [Spotless](https://github.com/diffplug/spotless) 의 [`palantirJavaFormat`](https://github.com/palantir/palantir-java-format) 이 강제하며 그 설정이 유일한 기준입니다. 들여쓰기 · 줄 폭 · 임포트 순서를 이 문서에 적지 않으며 `./gradlew spotlessApply` 가 수정합니다.

**BE-STY-002 (필수)** 별표 임포트(와일드카드)와 미사용 임포트를 쓰지 않습니다. Checkstyle 이 차단합니다.

## 3. 네이밍

### 3.1 패키지

**BE-STY-003 (필수)** 모듈 패키지명은 단수 소문자 한 단어입니다. 모듈은 애그리거트의 소유자이지 그것의 컬렉션이 아닙니다.

**BE-STY-004 (필수)** 계층 이름은 `contract` · `application` · `domain` · `infrastructure` 로 고정합니다. 세그먼트에 복수형을 쓰지 않습니다.

### 3.2 클래스

**BE-STY-005 (필수)** `application` 안에서 프레젠테이션과 애플리케이션의 구분은 폴더가 아닌 **접미사이며 [ArchUnit](https://www.archunit.org/) 이 이 이름으로 판정합니다.**

| 역할 | 식별 | 자리 |
| :--- | :--- | :--- |
| 컨트롤러 | `@RestController` + `Controller` | `application` |
| 서비스 · 조회 서비스 | `Service` · `QueryService` | `application` |
| 조회 포트 | `Query` | `application` |
| 요청 · 응답 DTO 묶음 | `Requests` · `Views` | `application` |
| 에러 코드 | `ErrorCode` | `application` |
| 저장소 인터페이스 | `Repository` | `domain` |
| 포트 구현 | 기술 접두사 + 포트 이름 | `infrastructure` |

**BE-STY-006 (필수)** 조회 포트를 `QueryRepository` 로 명명하지 않습니다. 저장소는 애그리거트를 다루는 계약이고 조회 포트는 화면 응답 구조를 만드는 계약입니다.

**BE-STY-007 (필수)** 포트 이름은 제공하는 역할로 짓습니다. 구현 기술이나 저장 위치를 이름에 담지 않습니다.

**BE-STY-008 (필수)** 인터페이스 이름에 복수형을 쓰지 않습니다. 복수형은 **여러 타입을 담은 묶음 클래스**(`Requests` · `Views`)를 뜻하며 이름의 대상이 모호해집니다.

### 3.3 메서드와 변수

**BE-STY-009 (필수)** 도메인 생성은 비즈니스 어휘를 가진 팩토리 메서드를 사용하고 생성자를 공개하지 않습니다. 영속성 재구성은 `restore` 로 고정하고 저장소만 호출합니다.

**BE-STY-010 (필수)** `find` 는 대상이 없을 수 있음(`Optional`)을, `get` 은 없으면 예외가 발생함을 뜻합니다.

**BE-STY-011 (필수)** 접근자 메서드에 `get` 접두사를 붙이지 않습니다. `lombok.config` 의 [`lombok.accessors.fluent`](https://projectlombok.org/features/experimental/Accessors) 가 `@Getter` 도 같은 형태로 생성합니다.

**BE-STY-012 (필수)** 필드와 파라미터는 타입명의 로워 카멜케이스입니다. 같은 타입이 둘 이상이면 역할을 앞에 붙이며, 재정의 대상이 정한 파라미터 이름은 그대로 유지합니다.

```java
TaskRepository taskRepository;   // Good
TaskRepository tasks;            // Bad — 컬렉션인지 포트인지 사라집니다
```

**BE-STY-013 (필수)** 변수명을 축약하지 않습니다. 축약된 이름은 선언 위치에서 타입을 다시 확인하게 만듭니다.

**BE-STY-014 (필수)** 컬렉션 변수명은 담긴 원소 타입명의 복수형입니다.

### 3.4 에러 코드 문자열

**BE-STY-015 (필수)** 에러 코드 문자열은 `<모듈>_<사유>` 형식의 SCREAMING_SNAKE_CASE 입니다. **하이픈은 요구사항 식별자, 언더스코어는 에러 코드**로 구분하여 전체 검색 시 혼재를 방지합니다.

## 4. 코드 구조

모듈과 계층의 정의, 참조 방향, `shared` 의 입장 조건은 빌딩 블록 뷰가 갖습니다. 이 절은 **새 코드를 어디에 두는가**를 정합니다.

### 4.1 하위 패키지 승격

**BE-STY-016 (필수)** 신규 모듈은 각 계층 아래에 파일을 직접 두고 하위 패키지를 만들지 않습니다. 승격은 **계층마다 따로 판정**합니다.

| 계층 | 분할 축 | 승격 기준 |
| :--- | :--- | :--- |
| `domain` | 애그리거트 | 애그리거트 2개 이상 |
| `application` | 피쳐(입구) | 입구 2개 이상 |

`application` 의 분할 축은 **입구(inbound adapter)가 잡은 축**이며 유스케이스 수로 세지 않습니다. 서술서는 한 리소스의 추가 · 조회 · 편집 · 삭제를 각각 별개의 유스케이스로 쪼개므로, 그것을 세면 리소스 하나가 피쳐 여럿으로 갈라집니다.

입구는 바깥이 시스템을 부르는 자리이며 무엇으로 식별되는지는 매체마다 다릅니다. 웹은 API 리소스 경로, 스케줄은 되풀이하는 업무, 메시지는 토픽입니다. 애너테이션은 그 입구를 선언하는 수단이지 축 자체가 아닙니다.

홀로 서는 입구는 피쳐를 만들지 않고 그것이 다루는 리소스의 피쳐에 둡니다. 딸린 서비스도 포트도 없이 파일 하나로 서는 것이 여기에 해당하며, 그것까지 승격하면 파일 하나짜리 패키지가 생깁니다.

분할 축이 다르므로 임계도 각자 셉니다. 애그리거트가 넷이어도 입구가 하나면 `application` 은 평면입니다.

분할 축이 다르므로 임계도 각자 셉니다. 애그리거트가 넷이어도 리소스가 하나면 `application` 은 평면입니다.

**BE-STY-017 (필수)** 피쳐 둘 이상이 공유하는 파일은 계층 루트에 평면으로 둡니다. `application/shared/` 나 `common/` 같은 모호한 공통 디렉터리를 만들지 않습니다.

**BE-STY-018 (권장)** 계층 루트에 파일이 쌓이는 것은 피쳐 경계 재검토의 신호입니다. 별도 공통 패키지를 만들기보다 피쳐를 합치는 쪽을 먼저 검토합니다.

**BE-STY-019 (필수)** `infrastructure` 는 피쳐로 나누지 않습니다. 구현체 클래스명이 포트 이름을 포함하므로 파일명으로 대응 관계가 드러나며, 프레임워크 확장은 목적별 패키지로 묶습니다.

**BE-STY-020 (필수)** 값 객체가 애그리거트 하나에만 속하면 그 패키지에 두고, **둘째 애그리거트가 쓰기 시작한 시점에** 계층 루트로 승격합니다. 특정 애그리거트 패키지에 잔류 시 애그리거트 간 부적절한 패키지 임포트가 발생합니다.

### 4.2 DTO

**BE-STY-021 (필수)** 요청과 응답 record 는 모듈당 하나의 묶음 클래스에 중첩 선언합니다. 묶음 클래스는 `final` 이고 `private` 기본 생성자를 갖습니다.

```java
public final class TaskRequests {
    private TaskRequests() {}

    public record CreateTask(@NotBlank @Size(max = TaskTitle.MAX) String title) {}
    public record ChangeDueDate(LocalDate dueDate) {}
}
```

개별 record 마다 파일을 생성하여 디렉터리가 파편화되는 것을 방지하고 모듈 입출력을 한눈에 파악합니다.

**BE-STY-022 (권장)** 묶음 클래스 크기가 과도하게 커지면 피쳐 단위로 분할합니다.

**BE-STY-023 (권장)** 목록과 상세 응답 구조가 동일하면 별도 record 로 분리하지 않습니다. 조기 분리로 인한 필드 추가 시 다중 수정 비용을 방지합니다.

### 4.3 메서드 배치

**BE-STY-024 (필수)** 서비스 클래스는 여섯 블록 순서로 배치하고 각 블록 앞에 구분선 주석을 둡니다. 없는 블록은 주석째 생략합니다.

| 순서 | 블록 | 대상 |
| :--- | :--- | :--- |
| 1 | 상수 | `static final` |
| 2 | 의존 | 주입 필드 |
| 3 | 생성 | 명시적 생성자 |
| 4 | 조회 | `@Transactional(readOnly = true)` |
| 5 | 명령 | `@Transactional` |
| 6 | 보조 | `private` 메서드 |

**BE-STY-025 (필수)** 조회를 명령보다 앞 블록에 둡니다. 클래스 내에서 두 경로의 물리적 경계를 시각적으로 명확히 분리합니다.

**BE-STY-026 (필수)** 구분선 주석은 `// --- ` 뒤에 블록명을 두고 대시로 120 컬럼까지 채웁니다. 들여쓰기를 포함한 폭이며 한글은 두 컬럼으로 셉니다.

**BE-STY-027 (권장)** 명령 블록 내부는 유스케이스 생애주기 순서(생성 -> 수정 -> 상태 변경 -> 삭제)로 배치합니다.

컨트롤러와 도메인은 대상이 아닙니다. 컨트롤러는 메서드가 엔드포인트 하나씩이라 구획이 생기지 않고, 도메인은 팩토리 · 상태 변경 · 접근자가 이미 형태로 갈립니다.

### 4.4 도메인 모델

**BE-STY-056 (필수)** 검증이나 정규화 규칙이 있는 필드는 값 객체로 분리합니다. 제약 상수, 검증, 정규화, 에러 문구를 값 객체에 응집하고 애그리거트는 조립만 담당합니다.

**BE-STY-057 (필수)** 표준 타입이 이미 불변식을 보장하거나 제약이 없는 필드는 값 객체를 만들지 않습니다. 불필요한 타입 파편화를 방지합니다.

| 필드의 성격 | 판정 |
| :--- | :--- |
| `String` 인데 필수 · 길이 · 정규화 규칙이 있다 | 값 객체 |
| 날짜 · 시각이며 형식 검증이 곧 파싱이다 | 표준 타입 |
| 제약이 없다 | 표준 타입 |

**BE-STY-058 (필수)** 값 객체는 검증하는 정적 팩토리(`of`)와 검증하지 않는 정규 생성자를 함께 둡니다. **정규 생성자는 저장소의 재구성 전용**이며 `ValueObject` 마커와 ArchUnit 이 호출자를 `domain` · `infrastructure` 로 제한합니다.

**BE-STY-059 (필수)** 요청 DTO 의 검증 애너테이션은 값 객체가 정의한 상수를 참조합니다. 검증 기준값과 에러 문구의 단일 진실 공급원(SSOT)을 유지합니다.

**BE-STY-060 (필수)** 애그리거트는 기본 생성자를 공개하지 않습니다. 불변식을 통과하지 않은 인스턴스가 생성되는 것을 방지합니다.

**BE-STY-061 (필수)** 도메인 메서드는 시각을 인자로 전달받고, 서비스와 어댑터는 주입된 `Clock` 에서 생성합니다. 데이터베이스 기본값 의존을 없애 테스트에서 시각 이동 검증을 가능하게 합니다.

### 4.5 조회와 명령

**BE-STY-062 (필수)** 서비스는 명령과 조회를 분리하지 않고 단일 클래스로 유지하는 것이 기본입니다. 하나의 서비스가 저장소와 조회 포트를 함께 조율하고 컨트롤러는 단일 진입점만 참조합니다.

**BE-STY-063 (권장)** 조회 전용 의존성이 둘 이상 발생하면 `<모듈>QueryService` 로 분리합니다. 자의적인 크기 기준이 아닌 필드 의존성 유무로 판정합니다.

**BE-STY-064 (필수)** 저장소는 도메인 타입(애그리거트, 값 객체)만 반환합니다. 화면 어휘 타입이 필요한 경우 조회 포트를 사용하며 ArchUnit 이 반환 타입을 정적으로 검사합니다.

**BE-STY-065 (필수)** 상태를 변경하는 명령 메서드는 저장소만 호출합니다. 조회 포트로 상태를 확인하면 애그리거트 불변식 검증이 누락되므로 코드 리뷰에서 이를 확인합니다.

**BE-STY-066 (필수)** 조회 포트 인터페이스는 유스케이스별이 아닌 모듈당 하나로 선언합니다. 인터페이스 파편화를 막고 조회 추가 비용을 최소화합니다.

**BE-STY-067 (필수)** 필터링 · 정렬 · 페이징은 데이터베이스 쿼리 내부에서 처리합니다. 전체 데이터를 메모리로 로딩하여 코드로 거르는 구조를 금지합니다.

**BE-STY-068 (권장)** 조회가 도메인 규칙을 참조할 때는 순수 함수 형태의 판정 로직만 차용합니다. SQL 중복 구현으로 인한 동기화 불일치를 방지하고 데이터 로딩은 프로젝션을 유지합니다.

### 4.6 영속성

**BE-STY-069 (필수)** 애그리거트 상태 변경 후에는 반드시 저장소의 `save` 를 명시적으로 호출합니다. 변경 감지(Dirty Checking)가 없으므로 호출이 누락되면 영속화되지 않습니다.

**BE-STY-070 (필수)** 저장소의 `save` 는 삽입과 갱신을 단일 진입점으로 처리합니다. 호출부에서 데이터 존재 여부를 분기하지 않도록 합니다.

**BE-STY-071 (필수)** 레코드와 도메인 엔티티 간 변환은 저장소 구현체 내부의 `private` 메서드가 전담합니다. **별도의 매퍼 클래스나 매퍼 패키지를 두지 않고** 저장소 내부에 캡슐화합니다.

**BE-STY-072 (필수)** SQL 구문과 jOOQ 생성 타입은 `infrastructure` 계층에만 선언합니다. 상위 계층으로의 기술 누출을 방지합니다.

**BE-STY-073 (필수)** 저장소 구현 클래스는 패키지 프라이빗(package-private) 가시성으로 선언합니다. 외부 계층은 인터페이스로만 의존합니다.

**BE-STY-074 (필수)** 마이그레이션 파일명은 `V<번호>__<설명>.sql` 형식이며 순차 번호를 부여합니다. **이미 배포·적용된 파일은 수정하지 않습니다.**

**BE-STY-075 (필수)** 롤백(다운) 마이그레이션 스크립트를 작성하지 않습니다. 스키마 되돌림은 항상 전진 마이그레이션(신규 버전 파일)으로 수행합니다.

**BE-STY-076 (필수)** 시각 컬럼의 DB 타입은 값의 시간적 특성에 따라 결정합니다.

| 성격 | 타입 |
| :--- | :--- |
| 실제로 일어난 순간 | `timestamptz` |
| 사용자가 고른 "그 날 그 시각" | `timestamp` |
| 날짜만으로 판정이 끝남 | `date` |

**BE-STY-077 (필수)** 테이블 컬럼의 길이 제약은 도메인 값 객체의 제약 상수와 동일한 값을 사용합니다. 유효성 검증을 통과한 값이 DB 저장 단계에서 실패하는 현상을 방지합니다.

**BE-STY-078 (필수)** jOOQ 코드 생성기에 도메인 값 객체를 강제 바인딩 타입으로 지정하지 않습니다. 생성물이 도메인 패키지를 임포트하여 인프라가 도메인에 역의존하는 것을 방지합니다.

### 4.7 API 계약

**BE-STY-079 (필수)** 경로에 동사를 쓰지 않습니다. 바꾸려는 것을 하위 자원으로 두면 켜고 끄는 것이 같은 경로의 값 변경입니다.

**BE-STY-080 (필수)** 응답에 봉투를 씌우지 않습니다. 성공과 실패는 상태 코드가 가르며 봉투는 그것을 본문에 한 번 더 적는 일입니다.

**BE-STY-081 (필수)** 변경 요청의 응답에 본문을 싣지 않습니다. 읽는 곳이 없는데 계약에 남으면 명세와 생성 타입과 테스트가 계속 부양합니다.

**BE-STY-082 (필수)** 값이 없는 필드의 키를 빼지 않고 `null` 을 실습니다. 키가 사라지면 오타와 미구현이 같은 모양이 됩니다.

**BE-STY-083 (필수)** 지역 시각과 절대 시각을 형식으로 구분합니다. 같은 형식으로 두면 받는 쪽이 시간대를 어떻게 다룰지 알 수 없습니다.

**BE-STY-084 (권장)** 쓰지 않는 파라미터를 계약에 미리 넣지 않습니다. 그것도 유지 대상이 됩니다.

**BE-STY-085 (필수)** 에러 코드에 사람이 읽을 문장을 요약 필드로 두지 않습니다. `detail` 과 겹쳐 같은 문장이 응답에 두 번 실립니다.

**BE-STY-086 (필수)** 사유를 나누되 그 구분이 존재 여부를 알려 주는 신호가 되지 않게 합니다. 대상이 없는 경우와 권한이 없는 경우는 같은 코드로 응답합니다.

**BE-STY-087 (필수)** 에러 응답에 입력 값을 싣지 않습니다. 민감한 입력이 되반사됩니다. 필드 이름과 메시지만 싣습니다.

**BE-STY-088 (필수)** 필드 검증 실패를 배열로 구조를 유지해 내보냅니다. 문자열 하나로 이어 붙이면 클라이언트가 파싱해야 하고 문구가 바뀌면 깨집니다.

### 4.8 인증

**BE-STY-089 (필수)** 토큰 원문을 저장하지 않습니다. 해시만 두고 조회는 들어온 값을 같은 방식으로 해싱해 비교합니다.

**BE-STY-090 (필수)** 해시에 용도를 함께 넣습니다. 수단이 다른 토큰이 같은 키로 해싱되면 한쪽 값을 다른 쪽 조회에 넣어 볼 여지가 생깁니다.

**BE-STY-091 (필수)** 인증을 거는 경로는 제외 목록으로 관리합니다. 지킬 경로를 나열하면 새 엔드포인트를 빠뜨렸을 때 조용히 열립니다.

**BE-STY-092 (필수)** 만료된 자격과 없는 자격에 같은 응답을 줍니다. 구분해 알려 주면 그 차이가 존재 여부를 노출합니다.

**BE-STY-093 (필수)** 세션 갱신에 간격을 둡니다. 요청마다 만료를 밀면 조회 하나에도 쓰기가 따라붙습니다.

**BE-STY-094 (필수)** 슬라이딩 만료에 절대 상한을 함께 둡니다. 상한이 없으면 계속 쓰는 동안 세션이 영구히 살아 있습니다.

**BE-STY-095 (필수)** 컨트롤러가 인증 여부를 판단하지 않습니다. 인터셉터가 판정하고 실패는 예외로 나갑니다.

## 5. Java 관용구

**BE-STY-028 (필수)** `@Setter` 사용을 금지합니다. `lombok.config` 가 빌드 오류로 차단하며, 도메인 상태 변경은 비즈니스 메서드가 불변식 검증과 함께 수행합니다.

**BE-STY-029 (필수)** DTO 는 [`record`](https://docs.oracle.com/en/java/javase/21/language/records.html) 로 선언합니다. 불변 객체로 다루며 접근자와 `equals` · `hashCode` 생성을 컴파일러에 위임합니다.

**BE-STY-030 (필수)** `Exception` 이나 `RuntimeException` 등 최상위 예외를 포괄적으로 잡지 않으며 빈 `catch` 블록을 금지합니다. [Checkstyle `IllegalCatch`](https://checkstyle.org/checks/coding/illegalcatch.html) 가 차단합니다.

**BE-STY-031 (필수)** 문자열 비교에 `==` 연산자를 사용하지 않고 `equals` 를 사용합니다. Checkstyle 이 차단합니다.

**BE-STY-032 (필수)** `switch` 문에는 항상 `default` 분기를 둡니다.

**BE-STY-033 (권장)** `Optional` 은 메서드 반환 타입에만 사용합니다. 필드나 파라미터로 선언 시 직렬화 불가 및 중복 분기 비용이 발생합니다.

## 6. 주석

**BE-STY-034 (필수)** 주석에 HTML 태그(`<p>`)나 인라인 태그(`{@code}`, `{@link}`)를 사용하지 않습니다. 소스 코드 자체의 가독성을 저해합니다.

**BE-STY-035 (필수)** 설계 근거와 기각된 대안은 소스 코드에 적지 않습니다. 아키텍처 문서와 결정 기록(ADR)에서 관리하며, 미채택 사유를 변호하는 주석을 남기지 않습니다.

| 뺍니다 | 남깁니다 |
| :--- | :--- |
| 설계 선택의 근거, 기각한 대안 | 이 코드가 업무에서 무엇인가 |
| 문서에 이미 있는 규칙 설명 | 유스케이스 ID 와 흐름 번호 |
| 다른 방식의 결과 예측 | 모르면 깨지는 동작상 주의 |

**BE-STY-036 (필수)** 도메인 엔티티의 필드에는 한글 단일행 주석(`//`)을 추가합니다. 영문 필드명과 비즈니스 요구사항 명세서의 한글 도메인 용어를 매핑합니다.

```java
// 나의 하루에 담은 날짜
private LocalDate myDayOn;
```

**BE-STY-037 (필수)** `TODO` 주석은 `// TODO(작성자): 내용` 형식입니다.

## 7. 에러 처리와 로깅

**BE-STY-038 (필수)** 비즈니스 실패는 반환값 대신 예외로 던집니다. 컨트롤러가 `ResponseEntity` 를 직접 조립하지 않으며 전역 핸들러가 [RFC 9457](https://www.rfc-editor.org/rfc/rfc9457.html) 응답으로 일괄 변환합니다.

| 던지는 것 | 뜻 | 문장의 성격 |
| :--- | :--- | :--- |
| `BusinessException` | 지금 상태가 이 요청을 허용하지 않는다 | 사용자 문장 |
| `DomainRuleViolation` | 들어온 값이 규칙에 맞지 않는다 | 사용자 문장 |
| `IllegalStateException` | 여기 도달하면 안 되는데 도달했다 | 개발자 문장, 로그만 |

**BE-STY-039 (필수)** 도메인 유효성 검증 실패 시 `IllegalArgumentException` 대신 `DomainRuleViolation` 을 던집니다. 표준 예외 사용 시 프레임워크 예외와 혼동되어 도메인 에러 메시지가 마스킹되는 것을 방지합니다.

**BE-STY-040 (필수)** 사용자에게 반환하는 에러 메시지에 내부 정보(테이블명, 내부 식별자, 스택 트레이스)를 포함하지 않습니다.

**BE-STY-041 (필수)** 예상된 비즈니스 실패를 `error` 레벨로 로깅하지 않습니다. 비즈니스 예외 로그로 인한 알람 노이즈를 방지하고 500 계열 서버 오류만 `error` 로 기록합니다.

**BE-STY-042 (필수)** 비밀번호 · 토큰 · 개인정보 원문을 기록하지 않습니다. 마스킹 처리나 식별자만 남깁니다.

**BE-STY-043 (필수)** 분산 추적 식별자를 비즈니스 키나 DB 식별자 용도로 쓰지 않습니다. 로그 상관관계 추적 용도로만 한정합니다.

## 8. 테스트 코드 스타일

**BE-STY-044 (필수)** 테스트 클래스명은 대상 클래스 이름 + `Test` 입니다.

**BE-STY-045 (필수)** 인수 조건의 추적 키를 **전체 계층 경로를 온전히 통과하는 테스트에만** 부여하며 `@DisplayName` 의 접두어로 둡니다. 접두어 뒤의 문장은 인수 조건 문장과 일치시키지 않습니다. 키의 형식과 부여 규약은 [결정-0007](../decisions/0007-shared-software-process.md)이 갖습니다.

```java
@DisplayName("TG-014 #1: 제목을 적으면 목록에 그 작업이 있다")
```

**BE-STY-046 (필수)** 단위 테스트에 추적 키를 붙이지 않습니다. 개별 단위 기능의 통과가 인수 조건 충족으로 오인되는 것을 방지합니다.

**BE-STY-047 (필수)** 통합 테스트의 진입점은 HTTP 엔드포인트입니다. 컨트롤러의 요청 검증, 직렬화, HTTP 상태 코드 매핑을 포함한 전체 API 계약을 검증합니다.

**BE-STY-048 (필수)** 통합 테스트는 실제 데이터베이스에 마이그레이션 스크립트를 적용하여 실행합니다. SQL 파싱 성공이 런타임 DDL 동작을 완전히 보장하지 못하는 한계를 보완합니다.

**BE-STY-049 (필수)** 각 통합 테스트는 `@Transactional` 롤백으로 데이터 격리를 유지합니다.

**BE-STY-050 (필수)** 생성 코드, 단순 위임 조회 서비스, getter 및 record 기본 동작, 프레임워크 기본 동작은 별도 테스트하지 않습니다.

**BE-STY-051 (필수)** 버그를 수정할 때는 **결함을 재현하는 실패 테스트를 먼저 작성합니다.** 수정 전 버그 재현 및 수정 후 회귀 방지를 확실히 검증합니다.

## 9. 예외 처리 절차

**BE-STY-052 (필수)** 규칙을 어겨야 하면 억제 목록이나 해당 위치에 **사유 주석과 함께** 명시합니다. 표준을 벗어난 위치와 사유의 등록부 역할을 합니다.

**BE-STY-053 (필수)** 도구 설정으로 예외를 두는 경우 **완화한 규칙의 근거가 왜 그 대상에 적용되지 않는지**를 설정 파일에 함께 적습니다.

**BE-STY-054 (필수)** 규칙 자체를 변경하려면 이 문서를 먼저 고치고 검증 도구 및 테스트를 함께 수정합니다. **테스트만 완화하는 변경은 허용하지 않습니다.**

**BE-STY-055 (권장)** 구조 · 의존성 · 인터페이스에 영향을 주는 선택이면 결정 기록(ADR)으로 발행하고 이 문서의 규칙은 그것을 가리킵니다. 아니면 근거를 이 문서 본문에 직접 적습니다.
