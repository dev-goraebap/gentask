# 백엔드 02. 코드 스타일 가이드

## 1. 목적과 적용 범위

`server/src` 하위의 Java 소스 코드에 적용한다. jOOQ 생성 코드는 대상에서 제외한다.

규칙은 세 수준으로 분류한다.

| 수준 | 의미 |
| :--- | :--- |
| **필수** | 위반 시 병합을 차단한다. 대부분 도구가 기계적으로 강제한다 |
| **권장** | 합당한 사유가 있는 경우 예외를 허용한다 |
| **취향** | 별도 규칙을 두지 않으며 코드 리뷰에서 변경을 강제하지 않는다 |

기존 코드에 소급 적용하지 않고 **수정 대상 파일에만 적용한다.** 규칙 변경 시 전체 코드를 일괄 수정하면 변경 이력이 규칙 적용으로 덮여 비즈니스 변경 맥락을 추적하기 어렵기 때문이다.

각 규칙은 `BE-STY-NNN` 식별자로 참조한다. 번호는 부여 후 불변이며 삭제 시 결번 처리하고 신규 규칙은 마지막 번호 뒤에 순차 채번한다.

## 2. 포매팅

**BE-STY-001 (필수)** 코드 포매팅은 [Spotless](https://github.com/diffplug/spotless)의 [`palantirJavaFormat`](https://github.com/palantir/palantir-java-format) 규칙을 따르며, 도구 설정이 유일한 기준이다. 들여쓰기, 줄 폭, 임포트 순서는 문서에 별도 기술하지 않고 `./gradlew spotlessApply`로 자동 교정한다.

**BE-STY-002 (필수)** 와일드카드 임포트(`*`) 및 미사용 임포트를 금지한다. Checkstyle 정적 분석으로 차단한다.

## 3. 네이밍

### 3.1 패키지

**BE-STY-003 (필수)** 모듈 패키지명은 단수형 소문자 단어를 사용한다. 모듈은 단일 애그리거트의 소유 단위이며 컬렉션 명칭을 사용하지 않는다.

**BE-STY-004 (필수)** 계층 명칭은 `application`, `domain`, `infrastructure`로 고정한다. 패키지 세그먼트에 복수형을 사용하지 않는다.

### 3.2 클래스

**BE-STY-005 (필수)** `application` 패키지 내 프레젠테이션과 애플리케이션 컴포넌트의 구분은 물리적 디렉터리가 아닌 **클래스 접미사로 구분하며 [ArchUnit](https://www.archunit.org/)으로 검증한다.**

| 역할 | 명명 및 식별 기준 | 배치 패키지 |
| :--- | :--- | :--- |
| 컨트롤러 | `@RestController` + `Controller` 접미사 | `application` |
| 서비스 · 조회 서비스 | `Service` · `QueryService` 접미사 | `application` |
| 조회 포트 | `Query` 접미사 | `application` |
| 요청 · 응답 DTO 묶음 | `Requests` · `Views` 접미사 | `application` |
| 에러 코드 | `ErrorCode` 접미사 | `application` |
| 저장소 인터페이스 | `Repository` 접미사 | `domain` |
| 포트 구현체 | 기술 접두사 + 포트 명칭 | `infrastructure` |

**BE-STY-006 (필수)** 조회 포트를 `QueryRepository`로 명명하지 않는다. 저장소는 도메인 애그리거트를 다루는 계약이고, 조회 포트는 화면 응답 전용 프로젝션을 구성하는 계약이다.

**BE-STY-007 (필수)** 포트 인터페이스 명칭은 수행하는 비즈니스 역할을 기준으로 정의한다. 특정 영속성 기술이나 인프라 위치를 명칭에 포함하지 않는다.

**BE-STY-008 (필수)** 인터페이스 명칭에 복수형을 사용하지 않는다. 복수형은 **다수의 DTO record를 포함하는 묶음 클래스**(`Requests`, `Views`) 전용 명명 규칙이다.

### 3.3 메서드와 변수

**BE-STY-009 (필수)** 도메인 엔티티 생성은 도메인 비즈니스 어휘를 반영한 정적 팩토리 메서드를 사용하고 기본 생성자를 외부에 노출하지 않는다. 영속성 데이터 재구성은 `restore` 메서드로 명명하고 저장소 구현체에서만 호출한다.

**BE-STY-010 (필수)** `find` 접두사는 데이터 부재 가능성이 있어 `Optional`을 반환함을 의미하고, `get` 접두사는 데이터 부재 시 예외를 발생시킴을 의미한다.

**BE-STY-011 (필수)** 도메인 객체 및 DTO의 필드 접근자 메서드에 `get` 접두사를 붙이지 않는다. `lombok.config`의 [`lombok.accessors.fluent`](https://projectlombok.org/features/experimental/Accessors) 설정을 통해 `@Getter`도 필드명과 동일한 메서드로 생성한다.

**BE-STY-012 (필수)** 필드 및 파라미터 식별자는 타입명의 로워 카멜케이스(lowerCamelCase)를 사용한다. 동일 타입이 둘 이상인 경우 비즈니스 역할을 접두어로 결합한다.

```java
TaskRepository taskRepository;   // Good
TaskRepository tasks;            // Bad — 컬렉션인지 포트인지 모호함
```

**BE-STY-013 (필수)** 변수명을 임의로 축약하지 않는다.

**BE-STY-014 (필수)** 컬렉션 변수명은 내부 요소 타입명의 복수형을 사용한다.

### 3.4 에러 코드 문자열

**BE-STY-015 (필수)** 에러 코드 문자열은 `<모듈>_<사유>` 형식의 SCREAMING_SNAKE_CASE를 사용한다. **요구사항 식별자는 하이픈(`-`), 에러 코드는 언더스코어(`_`)**로 구분하여 문자열 검색 시 혼선을 방지한다.

## 4. 코드 구조

모듈과 계층의 정의, 참조 방향, `shared` 진입 조건은 [5. 빌딩 블록 뷰](../05-building-block-view.md)에서 규정한다. 본 절은 **신규 코드의 세부 배치 위치**를 정의한다.

### 4.1 하위 패키지 승격

**BE-STY-016 (필수)** 신규 모듈 생성 시 각 계층 루트에 파일을 직접 배치하며 불필요한 하위 패키지를 사전 생성하지 않는다. 하위 패키지 승격은 **각 계층별 기준에 따라 독립적으로 판정**한다.

| 계층 | 분할 기준 축 | 승격 조건 |
| :--- | :--- | :--- |
| `domain` | 애그리거트 | 애그리거트 2개 이상 식별 시 |
| `application` | 인바운드 어댑터 | API 리소스 엔드포인트 2개 이상 분기 시 |

`application` 계층의 분할 축은 **인바운드 어댑터(API 리소스 경로 등) 단위**이며 유스케이스 개수를 기준으로 삼지 않는다. 단일 리소스에 대한 CRUD는 단일 피쳐 패키지로 응집한다.

단일 파일로 완결되는 단독 인바운드 어댑터는 별도 패키지를 분리하지 않고 연관 리소스 패키지에 함께 배치한다.

계층별 분할 축이 상이하므로 승격 조건도 독립적으로 평가한다. 애그리거트가 복수여도 인바운드 리소스가 단일하면 `application` 계층은 평면 구조를 유지한다.

**BE-STY-017 (필수)** 복수 피쳐가 공유하는 파일은 계층 루트에 평면으로 배치한다. `application/shared/`나 `common/`과 같은 모호한 공통 패키지를 생성하지 않는다.

**BE-STY-018 (권장)** 계층 루트에 파일이 과도하게 누적되는 경우 피쳐 경계의 재조정을 검토한다. 모호한 공통 패키지를 신설하기보다 피쳐 통합을 우선 고려한다.

**BE-STY-019 (필수)** `infrastructure` 계층은 피쳐 단위로 분할하지 않는다. 구현 클래스명이 포트 인터페이스 명칭을 포함하므로 파일명으로 대응 관계가 명확히 식별된다.

**BE-STY-020 (필수)** 단일 애그리거트에 전속되는 값 객체는 해당 애그리거트 패키지 내부에 두고, **두 번째 애그리거트에서 공통 참조가 발생하는 시점에** `domain` 계층 루트로 승격한다.

### 4.2 DTO

**BE-STY-021 (필수)** 요청 및 응답 record는 모듈당 하나의 묶음 클래스 내부에 static 중첩 클래스로 선언한다. 묶음 클래스는 `final`로 선언하고 `private` 기본 생성자를 명시한다.

```java
public final class TaskRequests {
    private TaskRequests() {}

    public record CreateTask(@NotBlank @Size(max = TaskTitle.MAX) String title) {}
    public record ChangeDueDate(LocalDate dueDate) {}
}
```

개별 record마다 독립 파일을 생성하여 디렉터리가 파편화되는 현상을 방지하고 모듈 입출력 계약을 한곳에서 파악할 수 있도록 한다.

**BE-STY-022 (권장)** 묶음 클래스의 크기가 과도하게 커지면 피쳐 단위로 분할한다.

**BE-STY-023 (권장)** 목록 조회 응답과 상세 조회 응답의 데이터 구조가 동일한 경우 별도 record로 분리하지 않는다.

### 4.3 메서드 배치

**BE-STY-024 (필수)** 서비스 클래스는 아래의 6개 블록 순서로 코드를 배치하고 각 블록 상단에 구분선 주석을 명시한다. 해당 블록에 속하는 코드가 없으면 주석을 생략한다.

| 순서 | 블록 | 대상 요소 |
| :--- | :--- | :--- |
| 1 | 상수 | `static final` 상수 |
| 2 | 의존성 | 생성자 주입 필드 |
| 3 | 생성자 | 명시적 생성자 |
| 4 | 조회 | `@Transactional(readOnly = true)` 메서드 |
| 5 | 명령 | `@Transactional` 상태 변경 메서드 |
| 6 | 보조 | `private` 헬퍼 메서드 |

**BE-STY-025 (필수)** 조회 블록을 명령 블록보다 상위에 배치하여 클래스 내에서 두 실행 경로의 물리적 경계를 시각적으로 명확히 분리한다.

**BE-STY-026 (필수)** 구분선 주석은 `// --- ` 접두어 뒤에 블록명을 표기하고 대시(`-`)를 채워 120컬럼 길이로 맞춘다.

**BE-STY-027 (권장)** 명령 블록 내부 메서드는 유스케이스 라이프사이클 순서(생성 -> 수정 -> 상태 전이 -> 삭제)로 배치한다.

컨트롤러와 도메인은 본 메서드 배치 규칙의 대상에서 제외한다.

### 4.4 도메인 모델

**BE-STY-056 (필수)** 검증이나 정규화 규칙이 있는 필드는 값 객체로 분리한다. 제약 상수, 검증, 정규화, 에러 문구를 값 객체에 응집하고 애그리거트는 조립만 담당한다.

**BE-STY-057 (필수)** 표준 타입이 이미 불변식을 보장하거나 제약이 없는 필드는 값 객체를 만들지 않는다. 불필요한 타입 파편화를 방지한다.

| 필드의 성격 | 판정 |
| :--- | :--- |
| `String` 인데 필수 · 길이 · 정규화 규칙이 있다 | 값 객체 |
| 날짜 · 시각이며 형식 검증이 곧 파싱이다 | 표준 타입 |
| 제약이 없다 | 표준 타입 |

**BE-STY-058 (필수)** 값 객체는 검증을 수행하는 정적 팩토리(`of`)와 검증을 생략하는 정규 생성자를 분리하여 제공한다. **정규 생성자는 저장소의 재구성 전용**이며 `ValueObject` 마커 인터페이스와 ArchUnit 규칙을 통해 호출자를 `domain`, `infrastructure`로 제한한다.

**BE-STY-059 (필수)** 요청 DTO의 검증 애너테이션은 값 객체가 정의한 제약 상수를 참조한다. 검증 기준값과 에러 문구의 단일 진실 공급원(SSOT)을 유지한다.

**BE-STY-060 (필수)** 애그리거트는 기본 생성자를 외부에 노출하지 않는다. 불변식을 통과하지 않은 인스턴스가 생성되는 것을 방지한다.

**BE-STY-061 (필수)** 도메인 메서드는 시각을 파라미터로 전달받고, 서비스와 어댑터는 주입된 `Clock`을 통해 생성한다. 데이터베이스 기본값 의존성을 배제하여 테스트 시 시각 제어 검증을 용이하게 한다.

### 4.5 조회와 명령

**BE-STY-062 (필수)** 서비스는 명령과 조회를 분리하지 않고 단일 클래스로 유지하는 것을 기본으로 한다. 하나의 서비스가 저장소와 조회 포트를 함께 조율하고 컨트롤러는 단일 진입점만 참조한다.

**BE-STY-063 (권장)** 조회 전용 의존성이 둘 이상 발생하면 `<모듈>QueryService`로 분리한다. 자의적인 파일 크기가 아닌 필드 의존성 유무로 분리를 판정한다.

**BE-STY-064 (필수)** 저장소는 도메인 타입(애그리거트, 값 객체)만 반환한다. 화면 어휘 타입이 필요한 경우 조회 포트를 사용하며 ArchUnit으로 반환 타입을 검증한다.

**BE-STY-065 (필수)** 상태를 변경하는 명령 메서드는 저장소만 호출한다. 조회 포트로 상태를 확인하면 애그리거트 불변식 검증이 누락될 수 있다.

**BE-STY-066 (필수)** 조회 포트 인터페이스는 유스케이스별이 아닌 모듈당 하나로 선언한다.

**BE-STY-067 (필수)** 필터링, 정렬, 페이징은 데이터베이스 쿼리 레벨에서 처리한다. 전체 데이터를 메모리로 로딩하여 코드로 필터링하는 구조를 금지한다.

**BE-STY-068 (권장)** 조회가 도메인 비즈니스 규칙을 참조할 때는 순수 함수 형태의 판정 로직만 차용한다. SQL 중복 구현으로 인한 동기화 불일치를 방지하고 데이터 로딩은 프로젝션을 유지한다.

### 4.6 영속성

**BE-STY-069 (필수)** 애그리거트 상태 변경 후에는 반드시 저장소의 `save`를 명시적으로 호출한다. jOOQ 환경에서는 변경 감지(Dirty Checking)가 지원되지 않으므로 명시적 호출이 필수이다.

**BE-STY-070 (필수)** 저장소의 `save`는 삽입과 갱신을 단일 진입점으로 처리한다. 호출부에서 데이터 존재 여부를 분기하지 않도록 한다.

**BE-STY-071 (필수)** jOOQ 레코드와 도메인 엔티티 간 매핑은 저장소 구현체 내부의 `private` 메서드가 전담한다. **별도의 매퍼 클래스나 매퍼 패키지를 두지 않고** 저장소 내부에 캡슐화한다.

**BE-STY-072 (필수)** SQL 구문과 jOOQ 생성 타입은 `infrastructure` 계층에만 선언한다. 상위 계층으로의 기술 누출을 방지한다.

**BE-STY-073 (필수)** 저장소 구현 클래스는 패키지 프라이빗(package-private) 가시성으로 선언한다. 외부 계층은 인터페이스로만 의존한다.

**BE-STY-074 (필수)** 마이그레이션 파일명은 `V<번호>__<설명>.sql` 형식이며 순차 번호를 부여한다. **이미 배포·적용된 파일은 수정하지 않는다.**

**BE-STY-075 (필수)** 롤백(다운) 마이그레이션 스크립트를 작성하지 않는다. 스키마 되돌림은 항상 신규 버전의 전진 마이그레이션으로 수행한다.

**BE-STY-076 (필수)** 시각 컬럼의 데이터베이스 타입은 시간적 특성에 따라 결정한다.

| 성격 | 타입 |
| :--- | :--- |
| 실제로 일어난 순간 | `timestamptz` |
| 사용자가 고른 "그 날 그 시각" | `timestamp` |
| 날짜만으로 판정이 끝남 | `date` |

**BE-STY-077 (필수)** 테이블 컬럼의 길이 제약은 도메인 값 객체의 제약 상수와 동일한 값을 사용한다. 유효성 검증을 통과한 값이 DB 저장 단계에서 실패하는 현상을 방지한다.

**BE-STY-078 (필수)** jOOQ 코드 생성기에 도메인 값 객체를 강제 바인딩 타입으로 지정하지 않는다. 인프라 계층이 도메인 계층에 역의존하는 결합을 방지하기 위함이다.

### 4.7 API 계약

**BE-STY-079 (필수)** URI 경로에 동사를 사용하지 않는다. 상태 변경은 하위 자원에 대한 `PATCH` 메서드로 표현한다.

**BE-STY-080 (필수)** 응답에 별도의 공통 래퍼(Envelope)를 씌우지 않는다. 성공과 실패는 HTTP 상태 코드로 분기하며, 불필요한 중복 필드 포장을 배제한다.

**BE-STY-081 (필수)** 상태 변경 요청의 응답에는 본문을 포함하지 않는다(`204 No Content`). 사용처가 없는 데이터를 응답에 포함하면 명세와 테스트의 유지보수 비용이 증가하기 때문이다.

**BE-STY-082 (필수)** 값이 없는 필드는 키를 생략하지 않고 `null`로 직렬화한다. 키 누락 시 필드명 오타와 값의 부재를 구분하기 어렵기 때문이다.

**BE-STY-083 (필수)** 지역 시각과 절대 시각을 형식으로 구분한다. 동일 형식을 사용할 경우 클라이언트에서 시간대(Timezone) 처리 방식을 명확히 판별할 수 없다.

**BE-STY-084 (권장)** 사용되지 않는 파라미터는 API 계약에 사전 추가하지 않는다.

**BE-STY-085 (필수)** 에러 응답 객체에 사람이 읽을 메시지를 위한 요약 필드를 중복 생성하지 않는다. RFC 9457 `detail` 필드와 중복되기 때문이다.

**BE-STY-086 (필수)** 리소스의 부재와 권한 없음을 동일한 에러 코드로 응답한다. 세분화된 에러 코드가 리소스 존재 여부를 노출하는 보안 취약점을 방지하기 위함이다.

**BE-STY-087 (필수)** 에러 응답 본문에 사용자가 입력한 원본 값을 포함하지 않는다. 민감 데이터 노출을 차단하며 필드명과 검증 메시지만 전달한다.

**BE-STY-088 (필수)** 필드 검증 실패 내역은 배열 구조로 유지하여 반환한다. 단일 문자열 결합 시 클라이언트의 파싱 오류를 방지한다.

### 4.8 인증

**BE-STY-089 (필수)** 인증 토큰 원문을 저장하지 않고 HMAC 해시만을 보관한다.

**BE-STY-090 (필수)** 토큰 해싱 시 용도(Purpose)를 솔트로 결합한다. 용도가 다른 토큰이 동일 해시로 생성되는 것을 방지하기 위함이다.

**BE-STY-091 (필수)** 인증 보호 경로는 화이트리스트(제외 목록) 방식으로 관리한다. 보호 경로를 개별 나열할 경우 신규 엔드포인트 등록 누락 시 비인가 접근이 허용되기 때문이다.

**BE-STY-092 (필수)** 만료된 자격 증명과 존재하지 않는 자격 증명에 동일한 실패 응답을 반환한다. 차등 응답 시 토큰 존재 여부가 노출되기 때문이다.

**BE-STY-093 (필수)** 세션 만료 갱신(Sliding Expiration)에 최소 시간 간격을 설정한다. 단순 조회 요청마다 데이터베이스 쓰기 작업이 발생하는 부하를 방지하기 위함이다.

**BE-STY-094 (필수)** 슬라이딩 세션 갱신에 최초 발급 기준 절대 상한 만료 시간을 설정한다. 지속 사용 세션이 무한정 유지되는 것을 차단한다.

**BE-STY-095 (필수)** 컨트롤러 내부에서 직접 인증 여부를 판정하지 않는다. 공통 인터셉터가 인증을 전담하며 인증 실패 시 예외를 발생시킨다.

## 5. Java 관용구

**BE-STY-028 (필수)** `@Setter` 사용을 금지한다. `lombok.config`가 빌드 오류로 차단하며, 도메인 상태 변경은 비즈니스 메서드가 불변식 검증과 함께 수행한다.

**BE-STY-029 (필수)** DTO는 [`record`](https://docs.oracle.com/en/java/javase/21/language/records.html)로 선언한다. 불변 객체로 다루며 접근자와 `equals`, `hashCode` 생성을 컴파일러에 위임한다.

**BE-STY-030 (필수)** `Exception`, `RuntimeException` 등 최상위 예외를 포괄적으로 catch하지 않으며 빈 `catch` 블록을 금지한다. Checkstyle `IllegalCatch` 규칙으로 차단한다.

**BE-STY-031 (필수)** 문자열 동등성 비교에 `==` 연산자를 금지하고 `equals`를 사용한다. Checkstyle 정적 분석으로 차단한다.

**BE-STY-032 (필수)** `switch` 문에는 항상 `default` 분기를 명시한다.

**BE-STY-033 (권장)** `Optional`은 메서드 반환 타입에만 한정하여 사용한다. 필드나 파라미터로 선언 시 직렬화 불가 및 중복 분기 비용이 발생한다.

## 7. 에러 처리와 로깅

**BE-STY-038 (필수)** 비즈니스 처리 실패는 반환값 대신 도메인 예외를 던진다. 전역 예외 처리기가 [RFC 9457](https://www.rfc-editor.org/rfc/rfc9457.html) 표준 응답으로 일괄 변환한다.

| 던지는 예외 | 상황 | 메시지 성격 |
| :--- | :--- | :--- |
| `BusinessException` | 현재 상태에서 허용되지 않는 비즈니스 요청 | 사용자 노출용 메시지 |
| `DomainRuleViolation` | 전달된 입력값이 도메인 불변식을 위반함 | 사용자 노출용 메시지 |
| `IllegalStateException` | 시스템 내부 상태의 비정상적 불일치 | 개발자 진단용 메시지 (내부 로깅 전용) |

**BE-STY-039 (필수)** 도메인 유효성 검증 실패 시 `IllegalArgumentException` 대신 `DomainRuleViolation`을 던진다. 표준 예외 사용 시 프레임워크 예외와 혼동되어 도메인 에러 메시지가 마스킹되는 것을 방지한다.

**BE-STY-040 (필수)** 사용자 응답 에러 메시지에 내부 시스템 정보(테이블명, 내부 식별자, 스택 트레이스)를 포함하지 않는다.

**BE-STY-041 (필수)** 정상적인 비즈니스 검증 실패를 `ERROR` 레벨로 로깅하지 않는다. 알람 노이즈를 방지하고 500 계열 시스템 오류만 `ERROR`로 기록한다.

**BE-STY-042 (필수)** 비밀번호, 인증 토큰, 개인정보 원문을 로그에 기록하지 않는다. 마스킹 처리 또는 식별자만 남긴다.

**BE-STY-043 (필수)** 분산 추적 식별자(Trace ID)를 비즈니스 키나 데이터베이스 식별자 용도로 사용하지 않는다. 로그 상관관계 추적 용도로만 한정한다.

## 8. 테스트 코드 스타일

**BE-STY-044 (필수)** 테스트 클래스 명칭은 대상 클래스명 + `Test` 접미사를 사용한다.

**BE-STY-045 (필수)** 인수 조건 식별자는 전체 계층 경로를 통과하는 통합/종단 테스트에만 부여하며 `@DisplayName`의 접두어로 명시한다. 세부 규약은 [결정-0007](../decisions/0007-shared-software-process.md)에 기술되어 있다.

```java
@DisplayName("GT-14 #1: 제목을 적으면 목록에 그 작업이 있다")
```

**BE-STY-046 (필수)** 단위 테스트에는 인수 조건 식별자를 부여하지 않는다. 단위 테스트 통과가 인수 조건 전체 충족으로 오인되는 것을 방지하기 위함이다.

**BE-STY-047 (필수)** 백엔드 통합 테스트의 진입점은 HTTP 엔드포인트이다. 요청 검증, 직렬화, 상태 코드 매핑을 포함한 API 계약 전체를 검증한다.

**BE-STY-048 (필수)** 통합 테스트는 Testcontainers를 통해 실제 데이터베이스에 마이그레이션 스크립트를 적용하여 실행한다.

**BE-STY-049 (필수)** 통합 테스트는 `@Transactional` 롤백을 통해 테스트 간 데이터 격리를 보장한다.

**BE-STY-050 (필수)** 자동 생성 코드, 단순 위임 서비스, getter 및 record 기본 메서드에 대한 테스트는 작성하지 않는다.

**BE-STY-051 (필수)** 결함 수정 시 결함을 재현하는 실패 테스트를 먼저 작성한 후 수정을 진행한다.

## 9. 예외 처리 절차

**BE-STY-052** (결번)

**BE-STY-053 (필수)** 정적 분석 도구 설정에서 예외를 부여하는 경우, 완화 사유와 근거를 설정 파일 주석에 명시한다.

**BE-STY-054 (필수)** 스타일 규칙을 개정할 때는 본 문서를 먼저 수정한 후 검증 도구 설정 및 테스트를 동기화한다. **테스트나 도구 설정만 임의로 완화하는 변경은 허용하지 않는다.**

**BE-STY-055 (권장)** 아키텍처 구조, 의존성 방향, 인터페이스 계약에 영향을 주는 설계 선택은 아키텍처 결정 기록(ADR)으로 발행하고 본 가이드에서는 해당 문서를 참조한다.
