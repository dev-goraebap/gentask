# 프론트엔드 01. 개발 환경

프론트엔드 애플리케이션의 구성 파일 명세, 실행 명령, 경로 별칭 및 줄바꿈 정책, 자동화 강제 수단의 적용 범위와 예외 규정을 정의합니다.

본 문서는 규칙이 빌드 및 린트 도구에서 강제되는 지점과 그 예외 기준을 명시합니다.

## 1. 구성 파일

설정값을 문서에 중복 기술하지 않고 구성 파일을 단일 진실 공급원(Single Source of Truth)으로 참조합니다. 문서는 규칙과 판정 기준을 정의하고, 구성 파일은 해당 규칙의 구체적인 실행 형태를 관리합니다.

| 파일 | 역할 |
| :--- | :--- |
| `package.json` | 의존성 및 패키지 버전 관리 |
| `tsconfig.json` | 컴파일러 옵션, 경로 별칭(`paths`) 정의 |
| `angular.json` | 빌드 설정, 번들 예산, 전역 스타일 경로 등록 |
| `steiger.config.ts` | FSD 계층 구조 및 슬라이스 의존성 규칙 강제([Steiger](https://github.com/feature-sliced/steiger)) |
| `eslint.config.js` | 코드 규약, 전역 프로바이더 위치 제한, 임포트 제한, 템플릿 접근성 검사 |
| `.postcssrc.json` | [Tailwind CSS](https://tailwindcss.com/) 플러그인 등록 |
| `.prettierrc` · `.editorconfig` | 코드 포맷팅 및 에디터 기본 서식 설정 |
| `proxy.conf.json` | 로컬 개발 서버의 백엔드 API 프록시 설정 |
| `.gitattributes` (저장소 루트) | 줄바꿈 정책(EOL) 및 바이너리/생성 파일 처리 지정 |

## 2. 명령

| 명령 | 용도 |
| :--- | :--- |
| `npm start` | 로컬 개발 서버 실행 (`proxy.conf.json`을 통해 API 요청을 백엔드로 프록시) |
| `npm run build` | 운영 빌드 수행 (번들 예산 초과 시 경고/에러 처리) |
| `npm test` | 단위 및 컴포넌트 테스트 실행 |
| `npm run lint` | ESLint 기반 코드 규약 검사 |
| `npm run lint:fsd` | Steiger 기반 FSD 계층 규칙 검사 |
| `npm run check` | 린트(`lint`, `lint:fsd`), 테스트, 빌드를 순서대로 실행 |
| `npm run api:generate -w api-types` | `server/openapi.json` 에서 계약 타입 생성. `web` 과 `mcp` 가 그 하나를 본다 |

`npm run check` 검증을 통과하지 않은 코드는 코드베이스에 병합할 수 없습니다. 지속적 통합(CI) 환경에서는 `npm run check` 단일 명령을 통해 프론트엔드 전체 검증을 수행합니다.

## 3. 경로 별칭

```json
// tsconfig.json
{ "compilerOptions": { "paths": { "@/*": ["./src/*"] } } }
```

[`baseUrl`](https://www.typescriptlang.org/tsconfig/#baseUrl) 설정의 사용을 **금지**합니다. TypeScript 컴파일러에서 폐기 예정으로 지정되어 있으며, 설정 시 `TS5101` 오류가 발생하여 빌드가 차단됩니다. `paths` 매핑만을 정의하고 상대 경로를 값으로 지정합니다.

계층 간 임포트에 상대 경로를 사용하는 것은 ESLint `no-restricted-imports` 규칙으로 차단합니다. Steiger는 상대 경로로 작성된 참조 위반도 검출하므로, 별칭 규칙 적용의 주된 목적은 **파일 이동 내성(Refactoring Resilience)** 확보입니다. 슬라이스를 다른 계층으로 이동할 때 상대 경로는 모두 수정이 필요하지만 경로 별칭은 그대로 유지됩니다.

## 4. 줄바꿈 정책

모든 텍스트 파일은 저장소와 로컬 체크아웃 환경 모두에서 **LF** 줄바꿈을 적용합니다. 저장소 루트의 `.gitattributes`에 선언된 `* text=auto eol=lf` 설정이 개발자 로컬 환경의 `core.autocrlf` 설정보다 우선합니다.

해당 정책을 명시하지 않을 경우 Windows 환경에서 체크아웃 시 CRLF로 자동 변환되어 불필요한 변경 이력이 발생하고 줄바꿈 차이로 인한 머지 충돌을 유발합니다.

| 대상 | 처리 규격 |
| :--- | :--- |
| 텍스트 파일 전반 | LF |
| `*.bat` · `*.cmd` | CRLF (`cmd.exe` 실행 환경 호환) |
| 이미지 · 폰트 · 문서 바이너리 | 개행 변환 금지 (`-text`) |
| `package-lock.json` | `linguist-generated=true` 지정 (수동 리뷰 대상에서 제외) |

**OpenAPI 생성 타입 파일은 `linguist-generated`로 지정하지 않습니다.** 생성 코드를 형상 관리에 커밋하는 목적은 API 계약 변경 사항을 풀 리퀘스트(PR)의 diff에서 명시적으로 확인하기 위함입니다. diff 표시가 축소되면 백엔드 API 변경에 따른 필드 누락이나 타입 불일치를 병합 전에 검증할 수 없습니다.

## 5. 전역 스타일 배치 및 테마 관리

전역 스타일 파일은 `src/app/styles.css`에 배치하며, `angular.json`의 `styles` 항목에 해당 경로를 등록합니다. 이는 FSD 아키텍처에서 전역 스타일을 최상위 `app` 계층에 배치하도록 규정함에 따른 조치입니다.

**`src/styles.css` 기본 파일을 루트에 잔존시키지 않습니다.** [Spartan](https://spartan.ng/) CLI의 스타일 진입점 자동 탐지 로직은 `angular.json` 설정을 우선 확인하지 않고 `<sourceRoot>/styles.{css,scss,sass,less}` 파일의 존재 여부를 먼저 검사합니다. 기본 경로에 파일이 남아 있는 경우 `angular.json`이 참조하지 않는 파일에 테마 스타일이 잘못 작성될 수 있습니다. UI 컴포넌트 생성기 실행 시 `--stylesEntryPoint` 옵션을 명시하여 탐지 순서와 무관하게 진입점 경로를 고정합니다.

**테마 스타일은 스타일시트에서 단독으로 제어합니다.** 라이트 모드 및 다크 모드 전환은 HTML 루트 요소의 클래스 속성으로 제어하므로, 스타일시트 외부에서 배경색이나 `color-scheme`을 직접 정의할 경우 시스템 테마 설정에만 종속되어 애플리케이션의 테마 전환 제어가 무효화됩니다. 따라서 진입점 문서(`index.html`) 내 인라인 스타일로 색상이나 테마를 선언하는 것을 **금지**합니다.

## 6. 강제 수단의 적용 범위

규칙의 검증 주체를 자동화 도구와 코드 리뷰로 나눕니다. 자동 강제되지 않는 규칙은 코드 리뷰 단계에서 확인합니다.

빌드와 린트가 차단하는 것

- 계층 간 임포트 방향 위반 (`fsd/forbidden-imports`)
- 공개 API 우회 참조 (`no-restricted-imports`)
- 동일 계층 슬라이스 간 크로스 임포트
- 미검증 조기 추출 슬라이스 (`insignificant-slice`)
- 번들 예산 초과
- 잘못된 계층에서의 전역 프로바이더(`providedIn: 'root'`) 선언

코드 리뷰에서 확인하는 것

- `shared` 계층에 비즈니스 로직이 들어갔는지
- 적응형 컴포넌트에 뷰포트별 테스트가 있는지
- 한 파일이 여러 도메인이나 책임을 담고 있는지
- 디자인 토큰 대신 임의의 값을 하드코딩했는지
- 시각 디자인 세부사항이 아키텍처 문서로 흘러들었는지

## 7. 규칙의 예외

도구별 완화 설정은 각 구성 파일이 소유하고, 이 절은 그 예외의 사유를 갖습니다. 예외를 더할 때는 **완화한 규칙의 근거가 왜 그 대상에 적용되지 않는지**를 함께 적습니다.

- **테스트 파일(`*.spec.ts`) — ESLint 브라우저 API 접근 제한**
  테스트는 jsdom 에서만 실행되며 서버 렌더링 경로를 거치지 않습니다. 제한의 근거가 서버 실행이므로 적용되지 않으며, 브라우저 API 를 다루는 코드를 검증하려면 그 API 에 직접 닿아야 합니다.

- **서버 진입점(`main.server.ts`) — ESLint `no-console`**
  Node 런타임 진입점은 `stdout` 이 표준 로깅 채널입니다. 브라우저 콘솔로의 정보 유출이라는 근거가 적용되지 않습니다.

- **`pages` 계층 — Steiger `excessive-slicing`**
  슬라이스 수가 적은 초기 단계에서 과분할 경고는 유효하지 않습니다. 슬라이스가 셋 이상으로 늘면 이 예외를 해제합니다.

- **OpenAPI 생성 타입 — ESLint 전체**
  생성 파일은 수동 수정이 불가능하므로 지적이 검사 노이즈가 됩니다.

- **외부 UI 킷 사본 — ESLint 선택자 접두사 · `no-input-rename` · `Injector` 임포트 제한**
  접두사는 라이브러리 규약이라 바꾸면 재생성할 때마다 되돌아옵니다. 표준 HTML 속성명을 그대로 바인딩하려면 별칭이 필요하고, 이 사본의 `Injector` 는 `runInInjectionContext` 인자이지 규칙이 막으려는 `Injector.get` 이 아닙니다.

- **외부 UI 킷 사본 — Steiger `public-api` · `no-reserved-folder-names`**
  내부 디렉터리 구조를 생성기가 정합니다.

- **프로젝트 전역 — Steiger `no-public-api-sidestep`**
  컴포넌트별 개별 진입점 참조를 우회로 오판하며 규칙 단위 예외를 둘 수 없습니다. 슬라이스 내부 파일 직접 임포트는 ESLint `no-restricted-imports` 가 대신 차단합니다.

## 8. 실측으로 확인한 도구 동작 특성

규격의 근거가 되는 도구 동작입니다. 재확인 없이 규칙의 근거로 씁니다.

**Steiger**

- 경로 별칭(`@/*`) 기반 임포트를 FSD 계층으로 정상 해석합니다.
- 역방향 참조는 `fsd/forbidden-imports`, 슬라이스 내부 직접 참조는 `fsd/no-public-api-sidestep` 으로 차단합니다.
- 상대 경로로 작성된 계층 위반도 동일하게 검출합니다.
- 그룹 디렉터리명이 `shared` 의 세그먼트 명칭과 겹치면 `fsd/ambiguous-slice-names` 로 빌드를 차단합니다.
- 프레임워크 진입점 파일을 미분류로 경고하지는 않습니다. 의도를 남기기 위해 `ignores` 에 등록합니다.

**TypeScript**

- `baseUrl` 은 사용할 수 없습니다. `TS5101` 오류가 발생합니다.

**번들 분리**

- **같은 배럴을 즉시 임포트와 지연 임포트(`loadComponent`)가 함께 참조하면 청크 분리가 무너집니다.** 라우트가 배럴에서 프로바이더를 즉시 가져오면서 같은 배럴을 `loadComponent` 로도 부르자, 지연 청크에 91 바이트 껍데기만 남고 컴포넌트 코드가 초기 번들로 들어갔습니다. 즉시 참조 심볼을 전용 진입점으로 분리하니 초기 번들이 517 kB → 377 kB, 지연 청크가 91 B → 141 kB 가 되었습니다.
- 배럴을 한쪽으로만 쓰면 간섭이 없습니다. 미사용 재수출은 트리셰이킹됩니다.
- **`@defer` 도 같은 이유로 막힙니다.** 즉시 쓰는 심볼과 `@defer` 전용 심볼을 같은 배럴에서 가져오면 모듈이 정적으로 묶입니다. 컴포넌트별 경로로 나눈 결과 초기 번들이 544 kB → 275 kB 로 줄었습니다.

**검사로 막을 수 없는 것**

- 동적 주입 토큰은 정적 구문 분석으로 검출되지 않습니다. 정상적인 `Map.get` 호출과 구분되지 않아 `Injector` 임포트 제한으로 대체합니다.
- 생성 파일의 수동 편집은 린터가 막지 못합니다. CI 의 재생성 일치 검증으로 대체합니다.

**서빙**

- 비ASCII(한글) 경로는 정적 파일이 생성되어도 **서빙 단계에서 404 가 반환됩니다.** 라우트 경로에 영문 슬러그를 씁니다.
