# 프론트엔드 01. 개발 환경

프론트엔드 애플리케이션의 구성 파일 명세, 실행 명령, 경로 별칭 및 줄바꿈 정책, 자동화 강제 수단의 적용 범위와 예외 규정을 정의한다.

본 문서는 규칙이 빌드 및 린트 도구에서 강제되는 지점과 그 예외 기준을 명시한다.

## 1. 구성 파일

설정값을 문서에 중복 기술하지 않고 구성 파일을 단일 진실 공급원(Single Source of Truth)으로 참조한다. 문서는 규칙과 판정 기준을 정의하고, 구성 파일은 해당 규칙의 구체적인 실행 형태를 관리한다.

| 파일 | 역할 |
| :--- | :--- |
| `package.json` | 의존성 및 패키지 버전 관리 |
| `tsconfig.json` | 컴파일러 옵션, 경로 별칭(`paths`) 정의 |
| `angular.json` | 빌드 설정, 번들 예산, 전역 스타일 경로 등록 |
| `steiger.config.ts` | FSD 계층 구조 및 슬라이스 의존성 규칙 강제([Steiger](https://github.com/feature-sliced/steiger)) |
| `eslint.config.js` | 코드 규약, 전역 프로바이더 위치 제한, 임포트 제한, 템플릿 접근성 검사 |
| `.postcssrc.json` | [Tailwind CSS](https://tailwindcss.com/) 플러그인 등록 |
| `.prettierrc` · `.editorconfig` | 코드 포맷팅 및 에디터 기본 서식 설정 |
| `proxy.conf.json` | 로컬 개발 서버의 백엔드 API 프록시 설정 |
| `.gitattributes` (저장소 루트) | 줄바꿈 정책(EOL) 및 바이너리/생성 파일 처리 지정 |

## 2. 명령

| 명령 | 용도 |
| :--- | :--- |
| `npm start` | 로컬 개발 서버 실행 (`proxy.conf.json`을 통해 API 요청을 백엔드로 프록시) |
| `npm run build` | 운영 빌드 수행 (번들 예산 초과 시 경고/에러 처리) |
| `npm test` | 단위 및 컴포넌트 테스트 실행 |
| `npm run lint` | ESLint 기반 코드 규약 검사 |
| `npm run lint:fsd` | Steiger 기반 FSD 계층 규칙 검사 |
| `npm run check` | 린트(`lint`, `lint:fsd`), 테스트, 빌드를 순서대로 실행 |
| `npm run api:generate -w api-types` | `server/openapi.json` 파일로부터 클라이언트 인터페이스 타입 생성 (`web`과 `cli`가 동일 타입 참조) |

`npm run check` 검증을 통과하지 않은 코드는 저장소에 병합할 수 없다. 지속적 통합(CI) 환경에서는 `npm run check` 단일 명령을 통해 프론트엔드 전체 정적 검증을 수행한다.

## 3. 경로 별칭

```json
// tsconfig.json
{ "compilerOptions": { "paths": { "@/*": ["./src/*"] } } }
```

[`baseUrl`](https://www.typescriptlang.org/tsconfig/#baseUrl) 설정의 사용을 **금지한다**. TypeScript 컴파일러에서 폐기 예정(Deprecated)으로 지정되어 있으며, 설정 시 `TS5101` 오류가 발생하여 빌드가 차단된다. `paths` 매핑만을 정의하고 상대 경로를 값으로 지정한다.

계층 간 임포트에 상대 경로를 사용하는 것은 ESLint `no-restricted-imports` 규칙으로 차단한다. Steiger는 상대 경로로 작성된 참조 위반도 검출하므로, 별칭 규칙 적용의 주된 목적은 **리팩터링 내성(Refactoring Resilience)** 확보이다. 슬라이스를 다른 계층으로 이동할 때 상대 경로는 전체 수정이 필요하지만 경로 별칭은 그대로 유지된다.

## 4. 줄바꿈 정책

모든 텍스트 파일은 저장소와 로컬 체크아웃 환경 모두에서 **LF** 줄바꿈을 적용한다. 저장소 루트의 `.gitattributes`에 선언된 `* text=auto eol=lf` 설정이 개발자 로컬 환경의 `core.autocrlf` 설정보다 우선한다.

해당 정책을 명시하지 않으면 Windows 환경 체크아웃 시 CRLF로 자동 변환되어 불필요한 변경 이력이 발생하고 줄바꿈 차이로 인한 머지 충돌을 유발하기 때문이다.

| 대상 | 처리 규격 |
| :--- | :--- |
| 텍스트 파일 전반 | LF |
| `*.bat` · `*.cmd` | CRLF (`cmd.exe` 실행 환경 호환) |
| 이미지 · 폰트 · 문서 바이너리 | 개행 변환 금지 (`-text`) |
| `package-lock.json` | `linguist-generated=true` 지정 (수동 리뷰 대상에서 제외) |

**OpenAPI 생성 타입 파일은 `linguist-generated`로 지정하지 않는다.** 생성 코드를 형상 관리에 커밋하는 목적은 API 계약 변경 사항을 풀 리퀘스트(PR)의 diff에서 명시적으로 확인하기 위함이다. diff 표시가 축소되면 백엔드 API 변경에 따른 필드 누락이나 타입 불일치를 병합 전에 검증할 수 없다.

## 5. 전역 스타일 배치 및 테마 관리

전역 스타일 파일은 `src/app/styles.css`에 배치하며, `angular.json`의 `styles` 항목에 해당 경로를 등록한다. FSD 아키텍처에서 전역 스타일을 최상위 `app` 계층에 배치하도록 규정함에 따른 조치이다.

**`src/styles.css` 기본 파일을 프로젝트 루트에 잔존시키지 않는다.** [Spartan](https://spartan.ng/) CLI의 스타일 진입점 자동 탐지 로직은 `angular.json` 설정을 우선 확인하지 않고 `<sourceRoot>/styles.{css,scss,sass,less}` 파일의 존재 여부를 먼저 검사한다. 기본 경로에 파일이 남아 있는 경우 `angular.json`이 참조하지 않는 파일에 테마 스타일이 잘못 작성될 수 있다. UI 컴포넌트 생성기 실행 시 `--stylesEntryPoint` 옵션을 명시하여 탐지 순서와 무관하게 진입점 경로를 고정한다.

**테마 스타일은 스타일시트에서 단독으로 제어한다.** 라이트 모드 및 다크 모드 전환은 HTML 루트 요소의 클래스 속성으로 제어하므로, 스타일시트 외부에서 배경색이나 `color-scheme`을 직접 정의할 경우 시스템 테마 설정에 종속되어 애플리케이션의 테마 전환 제어가 무효화된다. 진입점 문서(`index.html`) 내 인라인 스타일로 색상이나 테마를 선언하는 것을 **금지한다**.

## 6. 강제 수단의 적용 범위

규칙의 검증 주체를 자동화 도구와 코드 리뷰로 분리한다. 자동 강제되지 않는 규칙은 코드 리뷰 단계에서 확인한다.

빌드와 린트가 차단하는 항목

- 계층 간 임포트 방향 위반 (`fsd/forbidden-imports`)
- 공개 API 우회 참조 (`no-restricted-imports`)
- 동일 계층 슬라이스 간 크로스 임포트
- 미검증 조기 추출 슬라이스 (`insignificant-slice`)
- 번들 예산 초과
- 잘못된 계층에서의 전역 프로바이더(`providedIn: 'root'`) 선언

코드 리뷰에서 확인하는 항목

- `shared` 계층에 비즈니스 로직이 포함되었는지
- 적응형 컴포넌트에 뷰포트별 테스트가 존재하는지
- 단일 파일이 다중 도메인이나 책임을 복합 관리하는지
- 디자인 토큰 대신 임의의 값을 하드코딩했는지
- 시각 디자인 세부사항이 아키텍처 문서로 혼입되었는지

## 7. 규칙의 예외

도구별 완화 설정은 각 구성 파일에 선언하며, 본 절은 그 예외 사유를 기술한다. 예외를 추가할 때는 **완화한 규칙의 근거가 왜 해당 대상에 적용되지 않는지**를 함께 기술한다.

- **테스트 파일(`*.spec.ts`) — ESLint 브라우저 API 접근 제한**
  테스트는 jsdom 환경에서만 실행되며 서버 렌더링 경로를 거치지 않는다. 브라우저 API 접근 제한은 서버 사이드 렌더링 시 전역 객체 미참조를 보장하기 위한 것이므로 테스트 환경에는 적용되지 않는다.

- **서버 진입점(`main.server.ts`) — ESLint `no-console`**
  Node 런타임 진입점은 `stdout`이 표준 로깅 채널이므로 브라우저 콘솔 정보 유출 방지 제한이 적용되지 않는다.

- **`pages` 계층 — Steiger `excessive-slicing`**
  슬라이스 수가 적은 초기 단계에서 과분할 경고는 유효하지 않다. 슬라이스가 3개 이상으로 증가하면 본 예외를 해제한다.

- **OpenAPI 생성 타입 — ESLint 전체**
  생성 파일은 수동 수정이 불가능하므로 지적이 검사 노이즈가 된다.

- **외부 UI 킷 사본 — ESLint 선택자 접두사 · `no-input-rename` · `Injector` 임포트 제한**
  접두사는 외부 라이브러리 규약이므로 변경 시 재생성할 때마다 복구된다. 표준 HTML 속성명을 바인딩하기 위해 입력 별칭이 필요하며, Spartan 내부의 `Injector` 사용은 `runInInjectionContext` 파라미터 전달 목적이므로 서비스 로케이터 패턴 오용과 무관하다.

- **외부 UI 킷 사본 — Steiger `public-api` · `no-reserved-folder-names`**
  내부 디렉터리 구조를 컴포넌트 생성기가 결정한다.

- **프로젝트 전역 — Steiger `no-public-api-sidestep`**
  컴포넌트별 개별 진입점 참조를 우회로 오탐지하며 규칙 단위 예외를 둘 수 없다. 슬라이스 내부 파일의 직접 임포트는 ESLint `no-restricted-imports` 규칙으로 대체 차단한다.

## 8. 실측으로 확인한 도구 동작 특성

도구의 동작 검증 결과이며 규칙의 근거로 적용한다.

**Steiger**

- 경로 별칭(`@/*`) 기반 임포트를 FSD 계층으로 정상 해석한다.
- 역방향 참조는 `fsd/forbidden-imports`, 슬라이스 내부 직접 참조는 `fsd/no-public-api-sidestep`으로 차단한다.
- 상대 경로로 작성된 계층 위반도 동일하게 검출한다.
- 그룹 디렉터리명이 `shared`의 세그먼트 명칭과 중복되면 `fsd/ambiguous-slice-names`로 빌드를 차단한다.
- 프레임워크 진입점 파일을 미분류로 경고하지는 않는다. 명시적 예외 선언을 위해 `ignores`에 등록한다.

**TypeScript**

- `baseUrl`은 사용할 수 없다. `TS5101` 오류가 발생한다.

**번들 분리**

- **동일한 배럴 파일을 정적 즉시 임포트와 동적 지연 임포트(`loadComponent`)가 동시에 참조하면 번들 분할이 실패한다.** 라우트 모듈이 배럴에서 프로바이더를 정적으로 임포트하면서 동일 배럴을 `loadComponent`로 동적 임포트할 경우, 지연 로딩 청크에는 빈 스텁(91 B)만 남고 실제 컴포넌트 코드가 초기 번들로 흡수된다. 즉시 참조 심볼을 별도 진입점으로 분리함으로써 초기 번들을 517 kB에서 377 kB로, 지연 청크를 91 B에서 141 kB로 정상 분할하였다.
- 배럴 파일을 단일 임포트 방식으로만 사용하면 청크 분할 간섭이 발생하지 않는다. 미사용 export는 정상적으로 트리셰이킹(Tree-shaking)된다.
- **`@defer` 블록 역시 동일한 원리로 번들이 결합된다.** 즉시 로딩 심볼과 `@defer` 대상 심볼을 동일 배럴에서 임포트하면 모듈이 정적으로 번들링된다. 컴포넌트별 개별 파일 경로로 임포트를 분리하여 초기 번들을 544 kB에서 275 kB로 축소하였다.

**검사로 막을 수 없는 것**

- 동적 주입 토큰은 정적 구문 분석으로 검출되지 않는다. 정상적인 `Map.get` 호출과 구분되지 않으므로 `Injector` 직접 임포트 제한으로 대체한다.
- 생성 파일의 수동 편집은 린터로 차단할 수 없다. CI 환경에서 재생성 후 파일 일치 여부를 검증하는 절차로 대체한다.

**서빙**

- 비ASCII(한글) 경로는 정적 파일이 생성되어도 **웹 서버 서빙 단계에서 404 Not Found가 반환된다.** 라우트 경로에는 영문 소문자 케밥 케이스(kebab-case) 슬러그를 사용한다.
