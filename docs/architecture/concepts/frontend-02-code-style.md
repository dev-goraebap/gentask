# 프론트엔드 02. 코드 스타일 가이드

## 1. 목적과 적용 범위

`clients/apps/web/src` 하위의 TypeScript · HTML · CSS 소스 코드에 적용한다. 외부 UI 킷 사본은 대상에서 제외한다. 생성된 계약 타입은 `clients/packages/api-types`에 위치한다.

규칙은 세 수준으로 분류한다.

| 수준 | 의미 |
| :--- | :--- |
| **필수** | 위반 시 병합을 차단한다. 대부분 도구가 기계적으로 강제한다 |
| **권장** | 합당한 사유가 있는 경우 예외를 허용한다 |
| **취향** | 별도 규칙을 두지 않으며 코드 리뷰에서 변경을 강제하지 않는다 |

기존 코드에 소급 적용하지 않고 **수정 대상 파일에만 적용한다.** 규칙 변경 시 전체 코드를 일괄 수정하면 변경 이력이 규칙 적용으로 덮여 비즈니스 변경 맥락을 추적하기 어렵기 때문이다.

각 규칙은 `FE-STY-NNN` 식별자로 참조한다. 번호는 부여 후 불변이며 삭제 시 결번 처리하고 신규 규칙은 마지막 번호 뒤에 순차 채번한다.

## 2. 포매팅

**FE-STY-001 (필수)** 코드 포매팅은 [Prettier](https://prettier.io/) 규칙을 따르며 `.prettierrc`가 유일한 기준이다. 들여쓰기, 줄 길이, 따옴표, 세미콜론 규칙은 문서에 별도 기술하지 않는다. 도구 설정과 실행은 [프론트엔드 01. 개발 환경](./frontend-01-dev-environment.md)에서 관리한다.

## 3. 네이밍

### 3.1 파일

**FE-STY-002 (필수)** 파일명은 케밥 케이스(kebab-case)를 사용한다.

**FE-STY-003 (필수)** 단일 클래스를 내보내는 파일명은 클래스명을 케밥 케이스로 변환한 명칭을 사용한다([Angular 스타일 가이드](https://angular.dev/style-guide)). 클래스명이 변경되면 파일명도 함께 동기화한다.

| 대상 | 클래스명 | 파일명 |
| :--- | :--- | :--- |
| 컴포넌트 | `TaskRow` | `task-row.ts` |
| 라우트 진입 컴포넌트 | `TaskListPage` | `task-list-page.ts` |
| 서비스 | `SessionService` | `session-service.ts` |
| 가드 · 인터셉터(함수) | — | `auth-guard.ts` · `auth-interceptor.ts` |

**FE-STY-004 (필수)** 단일 파일에서 둘 이상의 클래스를 export하지 않는다. 파일명과 일치하지 않는 클래스는 심볼 탐색을 방해하기 때문이다.

**FE-STY-005 (필수)** `pages` 슬라이스의 라우트 진입 컴포넌트는 클래스명을 `Page` 접미사로 끝내고 파일명도 FE-STY-003 규칙에 따라 일치시킨다(`task-list-page.ts`). 컴포넌트 선택자에는 접미사를 붙이지 않는다.

**FE-STY-006 (필수)** 세그먼트 내부 파일은 도메인 비즈니스 개념으로 명명한다. 포괄적이고 모호한 명칭(`types.ts`, `utils.ts`, `api.ts`)을 금지한다.

```
model/task.ts        lib/format-due-date.ts     api/fetch-tasks.ts      // Good
model/types.ts       lib/utils.ts               api/api.ts              // Bad
```

**FE-STY-007 (필수)** API 요청 함수 파일명은 수행 동작 동사로 시작한다(`fetch-tasks.ts`, `create-task.ts`, `delete-task.ts`).

### 3.2 심볼

**FE-STY-008 (필수)** 클래스명은 파스칼 케이스(PascalCase)를 사용하며 `Component`, `Directive`, `Pipe` 접미사를 붙이지 않는다([Angular 스타일 가이드](https://angular.dev/style-guide)). 디렉터리 경로가 컴포넌트 역할을 나타내기 때문이다.

**FE-STY-009 (필수)** 서비스 클래스에만 `Service` 접미사를 부여한다. FE-STY-011에 따른 주입 필드 식별자와 일반 변수명의 충돌을 방지한다.

**FE-STY-010 (필수)** 함수명은 역할을 나타내는 접두사로 시작한다.

| 성격 | 접두사 | 예시 |
| :--- | :--- | :--- |
| 주입 헬퍼 | `inject` | `injectViewportClass` |
| 조회 요청 | `fetch` | `fetchTasks` |
| 변경 요청 · 계산 | 동사 | `completeTask` · `formatDate` |
| 판정 | `is` · `has` · `can` | `isExpired` |

**FE-STY-011 (필수)** 의존성 주입 필드는 주입 대상 클래스명의 로워 카멜 케이스로 선언하며 축약하지 않는다. 변환 결과는 의미에 맞는 식별자(`isServer`)를 부여한다.

```ts
private readonly httpClient = inject(HttpClient);   // Good
private readonly http = inject(HttpClient);         // Bad — 일관성 결여
```

**FE-STY-012 (필수)** 타입 명칭에 `I` 접두사나 `Type` 접미사를 붙이지 않는다. 생성된 API 타입은 생성기가 정의한 명칭을 유지한다.

**FE-STY-013 (필수)** 컴포넌트 선택자는 `app` 접두사와 케밥 케이스를, 디렉티브 선택자는 접두사를 붙인 카멜 케이스 속성명을 사용한다. 접두사는 `angular.json`의 `prefix` 설정을 따른다.

**FE-STY-014 (필수)** 상수는 대문자 스네이크 케이스(SCREAMING_SNAKE_CASE)로 선언한다.

### 3.3 슬라이스

**FE-STY-015 (필수)** 슬라이스 명칭은 케밥 케이스를 사용한다. 동사구는 `features`, 도메인 명사는 `entities`로 분류한다([FSD 계층](https://feature-sliced.design/docs/reference/layers)).

| 계층 | 품사 | 예시 |
| :--- | :--- | :--- |
| `pages` | 화면을 나타내는 명사구 | `task-list` |
| `features` | 사용자 동작을 나타내는 동사구 | `file-upload` |
| `entities` | 도메인 개념을 나타내는 명사 | `task` |

**FE-STY-016 (필수)** `pages` 슬라이스 명칭은 라우트 경로와 일치시키며 접미사를 `-list`, `-detail`, `-edit`, `-create`로 통일한다.

**FE-STY-017 (필수)** 계층명이 포함된 명칭, 포괄적 명칭(`common`, `misc`, `management`), 축약어, `shared` 세그먼트명과 중복되는 그룹 디렉터리명을 금지한다.

## 4. 코드 구조

계층과 슬라이스의 정의, 임포트 방향, 공개 API 규칙은 [5. 빌딩 블록 뷰](../05-building-block-view.md)에서 규정한다. 본 절은 **신규 코드의 세부 배치 위치**를 정의한다.

### 4.1 배치 판정

**FE-STY-018 (필수)** 아래 판정 순서에 따라 최초로 일치하는 위치에 배치한다.

```text
1. 애플리케이션 전역 설정인가?            → app/
2. 비즈니스 로직이 없는 인프라인가?        → shared/<세그먼트>/
3. 한 화면에서만 쓰는가?                  → pages/<화면>/
4. 여러 화면이 이미 쓰는 사용자 동작인가?   → features/<동작명>/
5. 여러 화면이 이미 쓰는 도메인 모델인가?   → entities/<도메인명>/
6. 확신이 없는 경우                       → pages/<화면>/
```

**FE-STY-019 (필수)** 기본 배치 위치는 `pages/<화면>/`이다. 화면 간 단순 코드 중복은 공통 추출의 충분한 근거가 되지 않으며, 가설적 재사용성에 기반하여 하위 계층으로 조기 선제 배치하지 않는다.

**FE-STY-020 (필수)** `features` 및 `entities` 배치는 둘 이상의 화면에서 실제 참조가 발생하는 시점에만 허용한다.

### 4.2 승격과 강등

**FE-STY-021 (필수)** 슬라이스 승격은 두 번째 화면에서 실제 호출이 발생하는 시점에 수행한다. 사용자 동작은 `features`, 도메인 모델은 `entities`로 승격한다.

**FE-STY-022 (권장)** 단일 화면에서만 사용되는 슬라이스는 해당 화면(`pages`)으로 강등한다. 재사용 가설이 불일치할 때 조기 되돌림을 권장한다.

### 4.3 클래스 멤버 순서

**FE-STY-023 (필수)** 클래스 본문은 아래 8개 블록 순서로 코드를 배치하고 각 블록 상단에 구분선 주석을 명시한다. 해당 블록에 속하는 코드가 없으면 주석을 생략한다.

| 순서 | 블록 | 대상 요소 |
| :--- | :--- | :--- |
| 1 | 상수 | `static`, 템플릿 재노출 심볼 |
| 2 | 계약 | `input`, `model`, `output` |
| 3 | 의존성 | `inject` |
| 4 | 질의 | `viewChild`, `contentChild` |
| 5 | 상태 | `signal`, `linkedSignal`, `form` |
| 6 | 파생 | `computed`, `resource`, `httpResource` |
| 7 | 생성 | 생성자 및 라이프사이클 훅 |
| 8 | 동작 | public 메서드 우선, private 메서드 후순위 |

**FE-STY-024 (필수)** 구분선은 `// --- ` 접두어 뒤에 블록명을 표기하고 대시(`-`)를 채워 100컬럼 길이로 맞춘다.

**FE-STY-025 (필수)** 동일 블록은 파일당 한 번만 선언한다. 뒤에서 앞 블록으로 되돌아가 멤버를 추가하지 않는다.

**FE-STY-026 (필수)** 템플릿에 재노출한 상수는 클래스 내부에서도 해당 필드를 통해 참조한다. 템플릿에서 참조하지 않는 상수는 필드로 선언하지 않는다.

**FE-STY-027 (권장)** 멤버 수가 과도하게 증가한 컴포넌트는 하위 컴포넌트로 책임을 분할한다.

### 4.4 데이터 접근

**FE-STY-057 (필수)** 컴포넌트 내부에서 Mock 데이터나 HTTP 호출 로직을 직접 포함하지 않는다. 데이터 접근은 `api` 세그먼트의 서비스로 위임한다.

**FE-STY-058 (필수)** 조회 결과를 시그널에 복사한 후 직접 변경하지 않는다. 서버 상태와 클라이언트 상태 간 불일치 검출이 불가능해지기 때문이다.

**FE-STY-059 (필수)** `httpResource`를 통해 데이터 변경 요청을 전송하지 않는다. `httpResource`는 읽기 전용 데이터 동기화 전용이다.

**FE-STY-060 (필수)** 동일 화면에서 동일한 데이터를 중복 조회하지 않는다. `httpResource`는 요청 중복 제거를 제공하지 않으므로 인스턴스 2개는 HTTP 요청 2회로 이어진다.

**FE-STY-061 (필수)** 라우트 스코프 조회 서비스에 복잡한 데이터 변환 로직을 포함하지 않는다. 해당 서비스는 라우트 정의에서 정적 임포트되어 초기 번들에 포함되기 때문이다.

**FE-STY-062 (필수)** 데이터 무효화 키는 `shared`의 상수로 통합 관리한다. 문자열을 호출부에 분산하면 오타 검출이 어렵다.

**FE-STY-063 (필수)** 필터, 정렬, 페이지네이션 상태는 URL 쿼리 파라미터에서 관리한다. 컴포넌트 내부 시그널에 보관하면 새로고침이나 뒤로가기 시 상태가 소실되기 때문이다.

**FE-STY-064 (필수)** 전역 스토어에 특정 화면 전용 상태를 보관하지 않는다. 화면 이탈 후에도 메모리에 잔존하기 때문이다.

**FE-STY-065 (권장)** 낙관적 업데이트(Optimistic Update)를 기본으로 적용하지 않는다. 롤백 및 충돌 조정 복잡성을 수반하므로 적용 시 아키텍처 결정 기록(ADR)을 작성한다.

### 4.5 대기와 실패의 표현

**FE-STY-066 (필수)** 데이터 조회가 완료되기 전에 빈 데이터 안내를 표시하지 않는다. 미수신 상태와 데이터 부재 상태를 명확히 구분한다.

**FE-STY-067 (필수)** 조회 실패를 빈 데이터 상태로 대체하여 표시하지 않는다. 해당 영역에서 실패 상태를 명시하고 재시도 UI를 제공한다.

**FE-STY-068 (필수)** 스켈레톤 UI를 사용하지 않는다. 치수 불확실성에 따른 레이아웃 시프트와 유지보수 비용을 방지하기 위함이다.

**FE-STY-069 (필수)** 화면 내 부분 갱신, 재조회, 오버레이, 점진적 로딩에 베일(Veil)을 적용하지 않는다. 이전 데이터가 남아 있어 전체 차단이 불필요하며 조작 중인 컨트롤이 가려지기 때문이다.

**FE-STY-070 (필수)** 명령 실행 시 전체 화면 오버레이를 적용하지 않는다. 버튼 내부 인디케이터로 진행 상태를 표시하고 비활성화한다.

**FE-STY-071 (필수)** 베일을 뷰포트 전체에 적용하지 않는다. 상단 네비게이션과 사이드바 접근성을 유지해야 하기 때문이다.

**FE-STY-072 (필수)** 화면마다 대기 시간 정책을 임의로 재정의하지 않는다.

**FE-STY-073 (필수)** 셸 컴포넌트가 하위 라우트 경로를 검사하여 베일 적용 여부를 판정하지 않는다. 셸과 개별 화면 간 관심사 분리가 훼손되기 때문이다.

**FE-STY-074 (권장)** 화면 전환 구간에 전환 애니메이션을 적용하지 않는다.

### 4.6 API 계약

**FE-STY-075 (필수)** 서버 요청 및 응답 타입을 수동으로 정의하지 않는다. OpenAPI 생성 타입을 사용하여 컴파일 시점에 계약 위반을 검출한다.

**FE-STY-076 (필수)** 생성된 계약 타입 파일을 직접 수정하지 않는다. 재실행 시 덮어쓰기되므로 CI 검증으로 무단 수정을 차단한다.

**FE-STY-077 (필수)** 생성 타입 파일을 `linguist-generated`로 지정하지 않는다. 계약 변경 내역이 PR diff에서 명확히 드러나도록 유지한다.

**FE-STY-078 (필수)** 단순 1:1 필드 대응 목적의 무의미한 DTO 변환 계층을 두지 않는다.

**FE-STY-079 (필수)** 엔드포인트 URL 경로를 호출부에 하드코딩하지 않는다.

**FE-STY-080 (필수)** 실제 API 연동 완료 후 불필요한 Mock 구현체나 임시 인터페이스를 남겨두지 않는다.

### 4.7 레이아웃

**FE-STY-087 (필수)** `pages` 슬라이스가 스스로 전역 레이아웃 구조를 결정하지 않는다. 레이아웃 책임은 `app` 계층에서 총괄한다.

**FE-STY-088 (필수)** 개별 라우트에서 셸 레이아웃 구조를 직접 지정하지 않는다.

**FE-STY-089 (필수)** 사이드바(`aside`)를 본문 콘텐츠 위에 겹치도록 배치하지 않는다.

**FE-STY-090 (필수)** 화면 밖 등장·퇴장 애니메이션 요소에 `overflow: hidden`을 사용하지 않고 `clip` 속성을 사용한다. 불필요한 스크롤 컨테이너 생성으로 하위 `position: sticky`가 해제되는 문제를 방지하기 위함이다.

**FE-STY-091 (필수)** 스크롤바 유무에 따른 레이아웃 흔들림 방지에 `overflow-y: scroll` 대신 `scrollbar-gutter: stable`을 사용한다.

**FE-STY-092 (필수)** Flex 또는 Grid 컨테이너 내부의 콘텐츠 열에 `min-width: 0`(또는 `minmax(0, 1fr)`)을 명시한다. 긴 표나 코드 블록으로 인해 열 너비가 비정상 확장되는 것을 방지한다.

**FE-STY-093 (필수)** `body { overflow: hidden }` 스타일을 직접 조작하지 않는다.

**FE-STY-094 (필수)** CDK 오버레이 호스트 요소를 Flex 또는 Grid 컨테이너 내부에 직접 배치하지 않는다. 너비가 0이어도 아이템으로 계산되어 레이아웃 간격이 왜곡되기 때문이다.

**FE-STY-095 (필수)** 고정 바 높이는 전역 토큰을 참조하고 `env(safe-area-inset-bottom)`을 반영한다.

**FE-STY-096 (필수)** 전체 화면 에러 화면에는 반드시 복구 액션(새로고침 또는 홈 이동)을 제공한다.

**FE-STY-097 (필수)** 점검 안내 화면을 클라이언트 SPA 라우트로 구성하지 않고 웹 서버(nginx) 정적 응답으로 처리한다.

**FE-STY-098 (필수)** 개별 화면 컴포넌트에서 인쇄 스타일을 임의로 정의하지 않는다.

### 4.8 적응형

**FE-STY-099 (필수)** CSS 미디어 쿼리로 해결 가능한 분기를 런타임 JavaScript 분기로 처리하지 않는다. 유지보수 및 테스트 비용을 최소화하기 위함이다.

**FE-STY-100 (필수)** 컴포넌트가 미디어 쿼리 문자열을 직접 하드코딩하지 않고 `shared/lib/adaptive/`의 시그널을 사용한다.

**FE-STY-101 (필수)** 포인터 및 호버 미디어 쿼리로 기기 유형을 판정하지 않는다. 브라우저 보고값의 신뢰성이 낮기 때문이다.

**FE-STY-102 (필수)** 적응형 컴포넌트의 내부 개별 표현 컴포넌트를 슬라이스 외부로 export하지 않는다.

**FE-STY-103 (필수)** 반응형 적응 컴포넌트의 내부 표현 컴포넌트들은 동일한 입출력 인터페이스 계약을 공유한다.

**FE-STY-104 (필수)** Spartan brain 디렉티브의 `protected` 메서드를 임의 재정의하여 위치 전략을 우회하지 않는다.

**FE-STY-105 (권장)** 정량적 번들 측정 없이 지연 로딩을 선제 적용하지 않는다.

**FE-STY-106 (필수)** 터치 타겟은 뷰포트 크기와 무관하게 최소 접근성 크기(44x44px 이상)를 준수한다.

**FE-STY-107 (필수)** 데스크톱과 모바일의 네비게이션 표현은 단일 메뉴 정의 데이터를 참조한다.

### 4.9 스타일과 토큰

**FE-STY-108 (필수)** 임의 색상값을 직접 작성하지 않는다. Tailwind 기본 팔레트(`gray-200` 등)도 대상이며, 토큰을 거치지 않으면 다크 모드에서 대비가 깨지기 때문이다.

**FE-STY-109 (필수)** 간격과 모서리 반경(Radius)도 토큰을 사용한다. `rounded-[7px]` 형태의 임의값 사용을 금지한다.

**FE-STY-110 (필수)** 반투명 표면을 임의의 알파 채널 유틸리티로 생성하지 않는다. 라이트 모드와 다크 모드의 배경 밝기 차이로 동일 불투명도가 성립하지 않으므로 모드별 토큰을 선언한다.

**FE-STY-111 (필수)** 디자인 토큰 없이 임의값을 임시로 사용하지 않는다. 필요한 값이 있으면 토큰을 먼저 등록하고 사용한다.

**FE-STY-112 (필수)** 크기와 두께 토큰을 별도로 신설하지 않고 Tailwind 기본 척도를 준용한다.

**FE-STY-113 (필수)** Spartan helm 컴포넌트에 부여하는 `class`는 외부 레이아웃 배치와 마진에만 한정하여 사용한다. 색상, 타이포그래피, 패딩을 외부 클래스로 덮어쓰지 않는다.

**FE-STY-114 (필수)** 컴포넌트가 제공하는 `variant` 입력을 우선적으로 사용하며 임의 클래스로 재정의하지 않는다.

**FE-STY-115 (필수)** 요소 간격은 `gap-*`을 사용한다. `space-x-*`, `space-y-*`는 Flex 및 Grid 컨테이너에서 예기치 않은 여백 오류를 유발할 수 있다.

**FE-STY-116 (권장)** 너비와 높이가 동일한 치수에는 `size-*` 유틸리티를 사용한다.

**FE-STY-117 (필수)** 오버레이의 `z-index`를 직접 지정하지 않는다. CDK 오버레이 스택이 쌓임 순서를 관리한다.

**FE-STY-118 (필수)** Spartan brain 디렉티브 연결을 임의로 제거하지 않는다. 웹 접근성 보장이 훼손되기 때문이다.

**FE-STY-119 (필수)** `node_modules` 소스코드를 직접 패치하지 않는다. 패키지 재설치 시 변경사항이 소실된다.

**FE-STY-120 (필수)** `shared/ui` 계층에 비즈니스 도메인 명칭을 가진 컴포넌트를 배치하지 않는다. 타 프로젝트로의 재사용성을 저해하기 때문이다.

**FE-STY-121 (필수)** SVG 마크업을 템플릿에 직접 인라인으로 삽입하지 않고 전용 아이콘 래퍼 컴포넌트를 사용한다.

**FE-STY-122 (필수)** 신규 CSS 변수 토큰 추가 시 `@theme inline`에 유틸리티 매핑을 함께 등록한다. 변수만 선언하고 클래스가 생성되지 않는 오류를 방지한다.

**FE-STY-123 (필수)** 신규 디자인 토큰은 라이트 모드와 다크 모드 값을 동시에 선언한다.

**FE-STY-124 (필수)** `-foreground` 전경색 쌍이 없는 배경 토큰을 생성하지 않는다. 텍스트 대비 검증 기준을 확보하기 위함이다.

**FE-STY-125 (필수)** 라이브러리 프리셋의 다크 모드 설정을 전역 스타일시트(`styles.css`)에서 프로젝트 기준으로 재정의한다.

**FE-STY-126 (필수)** 포인터 미디어 쿼리로 UI 요소의 치수를 임의 분기하지 않는다. 입력 컨트롤 최소 폰트 크기(16px, iOS 자동 줌 방지)에만 예외적으로 적용한다.

**FE-STY-127 (필수)** 터치 타겟 최소 크기(44px)는 컴포넌트의 기본 베이스 클래스에 적용한다.

### 4.10 라우팅

**FE-STY-128 (필수)** 화면 라우트 컴포넌트를 정적으로 임포트하지 않고 지연 로딩(`loadComponent`)으로 선언한다. 초기 번들 크기 증가를 방지하기 위함이다.

**FE-STY-129 (필수)** 라우트 경로 세그먼트에 비ASCII(한글 등) 문자를 사용하지 않는다. 서빙 환경에서 404 오류가 발생하기 때문이다.

**FE-STY-130 (필수)** 라우트 URL 경로 문자열은 상수로 정의하여 참조한다. 경로 변경 시 누락과 오타를 컴파일 시점에 검출할 수 있도록 한다.

**FE-STY-131 (필수)** 필터 변경 시 브라우저 히스토리를 적재하지 않는다(`replaceUrl`). 뒤로가기 시 이전 화면 복귀가 방해받기 때문이다.

**FE-STY-132 (필수)** 모달 오버레이가 스스로 URL 주소를 직접 조작하지 않는다. URL 변경 감지를 통해 오버레이 열림/닫힘을 단방향 동기화한다.

**FE-STY-133 (필수)** URL 쿼리나 패스 파라미터에 인증 토큰이나 개인식별정보를 포함하지 않는다.

**FE-STY-134 (필수)** 라우트 가드를 최종적인 보안 인가 수단으로 신뢰하지 않는다. 클라이언트 가드는 화면 진입 제어 편의 기능이며 백엔드 API 인가가 최종 기준이다.

**FE-STY-179 (필수)** 독립적인 목적지 화면(생성 폼, 상세 보기)은 URL 쿼리 파라미터로 열림 상태를 관리하고, 일시적 선택 조작(필터, 정렬, 피커)은 주소를 갖지 않는다. 목적지 상태를 경로(Path)가 아닌 쿼리(Query)로 관리하는 이유는 배경 페이지의 언마운트와 불필요한 번들 재로딩을 방지하기 위함이다. 세부 기준은 [프론트엔드 04. 적응형 레이아웃](./frontend-04-adaptive-layout.md)에 기술되어 있다.

**FE-STY-180 (필수)** 목적지 모달 화면 진입은 링크(`<a>`) 요소를 사용하며 버튼(`<button>`) 클릭 핸들러로 직접 열지 않는다. 주소가 화면 상태의 진실 공급원이 아니면 새로고침, 뒤로가기, URL 공유가 모두 성립하지 않기 때문이다.

**FE-STY-181 (필수)** 모달 오버레이를 열 때는 브라우저 히스토리를 푸시(push)하고, 닫을 때는 히스토리를 교체(replace)한다. 열기와 닫기 모두에 푸시를 적용하면 닫힌 후 뒤로가기 시 모달이 재오픈되고, 모두에 교체를 적용하면 뒤로가기 시 모달을 닫지 못하고 이전 페이지로 이탈하기 때문이다.

**FE-STY-182 (필수)** 모달 오버레이가 닫히는 모든 실행 경로는 동일한 URL 쿼리 제거 로직으로 수렴해야 한다. 백드롭 클릭이나 Esc 키 닫기 시 URL 정리가 누락되면 모달은 닫혔으나 URL에는 쿼리가 잔존하여 새로고침 시 모달이 다시 열린다.

**FE-STY-183 (필수)** 모달 오버레이는 URL 상태를 구독하여 동기화하며 스스로 라우팅을 직접 트리거하지 않는다. 뒤로가기에 의해 URL이 먼저 변경된 경우에는 추가 라우트 이동 없이 오버레이만 닫는다.

**FE-STY-184 (필수)** 라우트 레벨에서 생성하는 모달 오버레이에는 `ViewContainerRef` 대신 `EnvironmentInjector`를 전달한다. `ViewContainerRef` 전달 시 렌더링된 DOM이 오버레이 컨테이너 외부에 생성되어 오버레이 패널이 빈 상태로 표시되고 포커스가 `aria-hidden` 영역에 갇히는 결함이 발생한다.

**FE-STY-185 (필수)** 모달 오버레이 테스트는 CDK 오버레이 패널 컨테이너 내부에서 DOM 요소를 탐색한다. `document` 전체에서 요소를 탐색하면 오버레이 외부에 잘못 렌더링된 결함을 검출하지 못하기 때문이다.

**FE-STY-186 (필수)** 라우트 기반 모달 오버레이는 CDK 백드롭 스크롤 잠금 옵션을 비활성화한다. CDK 기본 스크롤 잠금 구현은 `<html>` 요소에 `position: fixed`를 강제하므로, 뷰포트 전체 높이를 고정하고 내부 스크롤을 사용하는 레이아웃 구조에서 전체 레이아웃이 밀리는 부작용이 발생하기 때문이다. 단위 테스트 환경에서는 CDK 잠금 조건이 충족되지 않으므로 코드 리뷰에서 이를 확인한다.

**FE-STY-187 (필수)** 모바일 뷰포트에서 팝오버를 바텀 시트로 전환하는 적응형 로직을 개별 컴포넌트마다 중복 구현하지 않는다. 공통 UI 팝오버 컴포넌트 내부에서 반응형 전환 규칙을 캡슐화하여 처리한다.

**FE-STY-188 (필수)** 팝오버 패널의 고정 너비 지정 시 반응형 접두어 `md:`를 적용한다(예: `md:w-80`). 너비를 무조건부 고정값으로 지정하면 모바일 화면에서 바텀 시트가 전체 너비를 채우지 못하고 고정 너비에 갇히는 레이아웃 깨짐이 발생한다.

**FE-STY-189 (필수)** Spartan UI 원본 컴포넌트를 상속하여 커스텀 컴포넌트로 대체할 때는 부모 컴포넌트 토큰을 `providers`의 `useExisting`으로 다시 바인딩한다. 서브클래스는 부모 타입 토큰으로 자동 등록되지 않으므로, 명시적 바인딩이 누락되면 해당 토큰을 주입받거나 ViewChild로 조회하는 상위 컴포넌트에서 `NG0951` 런타임 오류가 발생한다.

**FE-STY-190 (필수)** 뷰포트 너비에 따른 백드롭 유무를 CDK OverlayConfig의 `hasBackdrop` 옵션으로 제어하지 않는다. 해당 옵션은 오버레이 생성 시 1회만 평가되어 뷰포트 크기 변경에 반응하지 못하기 때문이다. 백드롭은 상시 활성화하고 CSS 미디어 쿼리를 통해 화면 너비별 표시 스타일을 제어한다.

### 4.11 컴포넌트

**FE-STY-135 (필수)** 컴포넌트 상태는 해당 값을 소비하는 최소 범위에서 소유한다. 단일 컴포넌트 상태는 내부에 두고, 복수 컴포넌트가 공유하면 슬라이스 `model`에서 관리한다.

**FE-STY-136 (필수)** 템플릿에서 함수를 직접 호출하지 않고 `computed` 시그널로 계산한다. 변경 감지마다 불필요하게 재실행되는 것을 방지하기 위함이다.

**FE-STY-137 (필수)** `@for` 블록에 `track` 식별자를 반드시 지정한다. 미지정 시 원소 변경 시 목록 DOM 전체가 재생성된다.

**FE-STY-138 (권장)** 컴포넌트가 백엔드 API를 직접 조회하거나 비즈니스 판단을 수행하지 않는다. 표현과 입출력에 집중하여 UI와 로직의 결합을 방지한다.

### 4.12 폼

**FE-STY-139 (필수)** 신규 폼에 Reactive Forms를 도입하지 않는다. 시그널 상태 흐름 사이에 불필요한 변환 계층이 형성되기 때문이다.

**FE-STY-140 (필수)** `<form>` 요소에 `novalidate` 속성을 명시한다. 브라우저 기본 검증이 제출 이벤트를 가로채 Angular 서브밋 핸들러 실행이 차단되는 현상을 방지하기 위함이다.

**FE-STY-141 (필수)** `(ngSubmit)` 대신 `(submit)` 표준 DOM 이벤트에 바인딩한다. Reactive Forms 디렉티브가 없으면 `(ngSubmit)` 이벤트가 발생하지 않아 제출이 동작하지 않기 때문이다.

**FE-STY-142 (필수)** 폼 검증 규칙을 단일 스키마 객체에 응집하여 관리한다.

**FE-STY-143 (필수)** 프론트엔드 유효성 검증을 완료했다고 해서 백엔드 검증을 생략하지 않는다. 클라이언트 요청은 변조될 수 있으므로 서버가 최종 검증한다.

**FE-STY-144 (필수)** 유효성 검증 실패를 이유로 제출 버튼을 비활성화(`disabled`)하지 않는다. 실패 사유 전달 및 키보드 접근성을 보장하기 위함이다.

**FE-STY-145 (필수)** 사용자 입력 도중 즉시 오류를 노출하지 않고 필드 포커스 아웃(`blur`) 이후에 표시한다. 작성 중 조기 에러 노출로 인한 입력 방해를 방지한다.

**FE-STY-146 (필수)** 서버 비동기 검증 요청 시 디바운스(Debounce) 대기 시간을 반드시 설정한다. 미지정 시 키 입력마다 불필요한 네트워크 요청이 전송된다.

**FE-STY-147 (필수)** `shared/ui` 계층 컴포넌트에 비즈니스 도메인 유효성 검증 로직을 포함하지 않는다. 인프라 계층이 비즈니스 로직에 종속되는 것을 방지하기 위함이다.

### 4.13 접근성

**FE-STY-148 (필수)** `<div>`에 클릭 핸들러를 달아 상호작용 요소를 생성하지 않고 표준 `<button>`을 사용한다. 키보드 포커스와 스크린리더 탐색을 보장하기 위함이다.

**FE-STY-149 (필수)** `placeholder` 속성을 레이블(`<label>`) 대신 사용하지 않는다. 입력 시작 시 힌트가 사라져 필드 용도를 확인할 수 없기 때문이다.

**FE-STY-150 (필수)** 시각적 대체 스타일 없이 포커스 표시를 제거하지 않는다. 키보드 탐색 시 현재 위치를 식별할 수 있어야 한다.

**FE-STY-151 (필수)** 색상만으로 상태를 전달하지 않고 텍스트 레이블이나 아이콘을 병기한다. 색각 이상 사용자의 정보 인지를 보장하기 위함이다.

**FE-STY-152 (필수)** 호버(`:hover`)로만 도달할 수 있는 필수 기능을 생성하지 않는다. 터치 기기 환경에서 접근이 불가능하기 때문이다.

**FE-STY-153 (필수)** 라우팅 후 포커스 이동이나 스크린리더 전환 알림 처리를 누락하지 않는다.

**FE-STY-154 (필수)** 글꼴 크기를 `px` 고정 단위로 지정하지 않고 상대 단위(`rem`)를 사용한다. 사용자 브라우저 글꼴 설정과의 호환성을 유지하기 위함이다.

**FE-STY-155 (필수)** 파괴적 액션(삭제 등) 버튼을 일반 액션 바로 옆에 배치하지 않는다. 모바일 터치 환경에서의 오조작을 방지한다.

### 4.14 보안

**FE-STY-156 (필수)** `bypassSecurityTrust*` 메서드 사용을 금지한다. Angular 보안 체계를 우회하여 XSS 취약점을 유발하기 때문이다.

**FE-STY-157 (필수)** 서버 응답 데이터를 `[innerHTML]`에 직접 바인딩하지 않는다.

**FE-STY-158 (필수)** 클라이언트 소스 코드에 API 비밀키나 인증 시크릿을 하드코딩하지 않는다.

**FE-STY-159 (필수)** 인증 헤더를 개별 요청에서 조립하지 않고 인터셉터로 일괄 부착한다.

**FE-STY-160 (필수)** UI 요소를 숨기는 것을 최종 보안 인가 수단으로 간주하지 않는다. 클라이언트는 변조 가능하므로 서버가 최종 권한을 검증한다.

### 4.15 성능

**FE-STY-161 (필수)** 번들 예산을 설정하고 경고가 아닌 빌드 오류로 처리한다. 초과 누적으로 인한 성능 저하를 방지하기 위함이다.

**FE-STY-162 (필수)** 번들 예산을 상향할 때 변경 사유와 근거를 명시한다.

**FE-STY-163 (필수)** 정량적 측정 없이 지연 로딩이나 가상 스크롤을 선제 적용하지 않는다.

**FE-STY-164 (필수)** `<img>` 요소에 크기(`width`, `height`)를 명시한다. 레이아웃 시프트(CLS)를 방지하기 위함이다.

**FE-STY-165 (필수)** 이미지 숨김 처리를 CSS 기본값으로 지정하지 않는다. 스크립트 오류 시 이미지 미표시 현상을 방지한다.

**FE-STY-166 (권장)** 웹 폰트를 외부 CDN에서 불러오지 않고 자체 호스팅(Self-hosting)한다.

**FE-STY-167 (필수)** 개발 모드 빌드로 성능을 측정하지 않고 프로덕션 최적화 빌드에서 측정한다.

### 4.16 실패 계약의 소비

**FE-STY-168 (필수)** 에러 메시지는 서버가 반환한 에러 코드로 우선 매핑하고, 매핑되지 않는 경우 서버 응답 메시지를 기본 노출한다.

**FE-STY-169 (필수)** HTTP 상태 코드만 보고 임의로 문구를 생성하지 않는다. 서버가 전달하는 비즈니스 맥락이 소실되기 때문이다.

**FE-STY-170 (필수)** 인증 만료(401) 외의 비즈니스 실패 처리를 인터셉터에서 일괄 가로채지 않고 개별 화면 컴포넌트에 제어권을 둔다.

**FE-STY-171 (필수)** 자동 재시도 로직은 idempotent한 조회(GET) 요청에만 한정하여 적용한다. 상태 변경 요청 재전송 시 중복 처리가 발생하기 때문이다.

**FE-STY-172 (필수)** 사용자 화면에 스택 트레이스, 데이터베이스 쿼리, 내부 식별자를 노출하지 않는다. 노출하는 내부 정보는 추적 식별자(Trace ID)로 한정한다.

### 4.17 인증

**FE-STY-173 (필수)** 클라이언트에서 인증 토큰을 저장하거나 수동 헤더로 주입하지 않는다. 브라우저 쿠키 메커니즘을 사용한다.

**FE-STY-174 (필수)** 로그인 요청 자체의 실패를 세션 만료로 처리하지 않는다.

**FE-STY-175 (필수)** 프리렌더 경로에서 라우트 가드가 빌드를 차단하지 않도록 구성한다.

## 5. TypeScript · Angular 관용구

**FE-STY-028 (필수)** `any` 타입 사용을 금지한다. 타입을 특정할 수 없으면 `unknown`으로 선언하고 타입 좁히기를 사용한다.

**FE-STY-029 (필수)** TypeScript `enum` 대신 `as const` 객체와 유니온 타입을 사용한다([TypeScript enum](https://www.typescriptlang.org/docs/handbook/enums.html)). `enum`의 런타임 코드 생성과 `isolatedModules` 제약을 방지한다.

```ts
export const TASK_STATUS = { todo: 'TODO', done: 'DONE' } as const;
export type TaskStatus = (typeof TASK_STATUS)[keyof typeof TASK_STATUS];
```

**FE-STY-030 (필수)** 템플릿과 호스트 바인딩에 노출되는 식별자는 영문을 사용한다. 템플릿 컴파일러의 `NG5002` 오류를 방지하며, 한글은 `private` 멤버와 지역 변수에만 한정한다.

**FE-STY-031 (필수)** `providedIn: 'root'`는 `shared` 및 `app` 계층 서비스에서만 선언한다. 화면 단위 서비스는 라우트 `providers`에 선언하여 컴포넌트 생명주기와 동기화한다.

**FE-STY-032 (필수)** 계층 간 임포트는 `@/*` 경로 별칭을 사용한다. 상대 경로는 동일 슬라이스 내부에서만 허용한다.

**FE-STY-033 (권장)** 데이터 조회는 라우트 스코프의 `httpResource`, 데이터 변경은 명령 전용 서비스로 분리한다.

**FE-STY-081 (필수)** `shared` 계층 코드는 모듈 최상위 스코프에서 브라우저 API를 호출하지 않는다. 프리렌더 빌드(Node 환경) 실패를 방지하기 위해 함수 내부에서 지연 호출한다.

**FE-STY-082 (필수)** `typeof window !== 'undefined'` 형태의 직접 검사를 지양하고 Angular의 `isPlatformBrowser`를 사용한다. 테스트 환경에서의 환경 주입을 용이하게 하기 위함이다.

**FE-STY-083 (필수)** `afterNextRender` 내부에서 화면 DOM 구성을 변경하지 않는다. 하이드레이션 불일치 및 화면 깜빡임을 방지한다.

**FE-STY-084 (필수)** 프리렌더 대상 경로에서는 뷰포트 반응형 적응 컴포넌트 사용을 배제한다. 빌드 시점 뷰포트 부재로 하이드레이션 깜빡임이 발생하기 때문이다.

**FE-STY-085 (필수)** 프리렌더 대상 경로에서 난수, 실시간 시각, 저장소 값으로 DOM을 결정하지 않는다. 하이드레이션 실패를 방지하기 위함이다.

**FE-STY-086 (필수)** Angular 외부에서 DOM을 직접 조작하지 않는다. 하이드레이션 정합성을 유지하기 위함이다.

## 7. 에러 처리와 로깅

**FE-STY-037 (필수)** 401 처리는 HTTP 인터셉터에서 중앙 집중식으로 수행하며 개별 화면에서 중복 처리하지 않는다.

**FE-STY-038 (필수)** HTTP 인터셉터 내부에서 토스트 알림을 직접 호출하지 않는다. UI 피드백 제어권은 화면 컴포넌트가 유지한다.

**FE-STY-039 (필수)** 조회 실패를 빈 데이터 상태로 대체하여 표시하지 않는다. 데이터 부재와 통신 실패 상태를 명확히 구분한다.

**FE-STY-040 (필수)** 데이터 변경 요청을 자동 재시도하지 않는다. 중복 처리를 방지하기 위함이다.

**FE-STY-041 (필수)** 스택 트레이스와 내부 시스템 식별자를 화면에 노출하지 않는다.

**FE-STY-042 (필수)** API 응답 객체 전체를 콘솔에 출력하지 않는다. 민감 정보 노출을 방지하기 위해 필요한 필드만 지정하여 출력한다.

**FE-STY-043 (필수)** `console.log`를 커밋하지 않는다. ESLint `no-console` 규칙으로 차단하며 `console.error`와 Node 진입점은 예외로 처리한다.

**FE-STY-044 (권장)** 400 및 403 응답을 외부 모니터링 관측 도구로 전송하지 않는다. 정상적인 클라이언트 입력 오류로 인한 경보 노이즈를 방지하기 위함이다.

## 8. 테스트 코드 스타일

**FE-STY-045 (필수)** 테스트 파일은 대상 소스 파일과 동일한 디렉터리에 배치한다. `__tests__` 디렉터리를 만들지 않으며, 종단(E2E) 테스트는 `clients/apps/web/e2e/`에 배치한다.

**FE-STY-046 (필수)** 비즈니스 분기 로직을 포함하는 코드는 반드시 테스트를 작성한다. 단순 위임 함수는 테스트 작성 대상에서 제외한다.

**FE-STY-047 (필수)** 프레임워크 기본 동작 및 자동 생성 타입을 검증하는 무의미한 테스트를 작성하지 않는다.

**FE-STY-048 (필수)** DOM 요소 탐색 시 CSS 클래스명을 사용하지 않고 ARIA 역할(role) 및 접근 가능한 이름으로 탐색한다([Testing Library 질의 우선순위](https://testing-library.com/docs/queries/about/#priority)).

**FE-STY-049 (필수)** 테스트 코드에서 고정 시간 대기(`setTimeout`)를 사용하지 않는다. 비동기 상태 완료 이벤트나 상태 대기 헬퍼를 사용한다.

**FE-STY-050 (필수)** 불안정한(Flaky) 테스트를 단순 재시도로 통과시키지 않고 비동기 타이밍 등 근본 원인을 수정한다.

**FE-STY-051 (필수)** API 응답 Mock 데이터를 임의 객체로 작성하지 않고 생성된 TypeScript 계약 타입을 적용한다.

**FE-STY-052 (권장)** 테스트 커버리지 수치를 빌드 실패 기준으로 강제하지 않는다. 세부 기준은 [결정-0008](../decisions/0008-shared-testing.md)에 기술되어 있다.

**FE-STY-176 (필수)** 인수 조건 식별자는 화면 진입부터 데이터 접근까지 전체 실행 경로를 통과하는 종단/통합 테스트에만 부여하며 `describe` 또는 `it` 명칭의 접두어로 명시한다. 세부 규약은 [결정-0007](../decisions/0007-shared-software-process.md)에 기술되어 있다.

```ts
it('GT-14 #1: 제목을 적으면 목록에 그 작업이 있다', async () => {
```

**FE-STY-177 (필수)** Mock 기반 테스트가 식별자를 갖는 것은 프론트엔드 계층 경로의 정상 동작을 검증함을 의미한다. 최종 인수 조건 충족은 실제 백엔드 연동 테스트로 확인한다.

**FE-STY-178 (필수)** 단위 테스트와 컴포넌트 단독 테스트에는 인수 조건 식별자를 부여하지 않는다. 단위 테스트 통과가 인수 조건 전체 충족으로 오인되는 것을 방지하기 위함이다.

## 9. 예외 처리 절차

**FE-STY-053** (결번)

**FE-STY-054 (필수)** 도구 설정에서 규칙 예외를 부여하는 경우, 완화 사유와 근거를 [프론트엔드 01. 개발 환경](./frontend-01-dev-environment.md) 7절에 기술한다.

**FE-STY-055 (필수)** 스타일 규칙을 개정할 때는 본 문서를 먼저 수정한 후 검증 도구 설정 및 테스트를 동기화한다. 도구 설정만 임의로 완화하는 변경은 허용하지 않는다.

**FE-STY-056 (권장)** 아키텍처 구조, 의존성 방향, 인터페이스 계약에 영향을 주는 설계 선택은 아키텍처 결정 기록(ADR)으로 발행하고 본 가이드에서는 해당 문서를 참조한다.
