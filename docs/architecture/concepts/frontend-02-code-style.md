# 프론트엔드 02. 코드 스타일 가이드

## 1. 목적과 적용 범위

`clients/apps/web/src` 아래의 TypeScript · HTML · CSS 에 적용합니다. 외부 UI 킷 사본은 대상이 아닙니다. 생성된 계약 타입은 `clients/packages/api-types` 에 있어 이 축 밖입니다.

규칙은 세 수준으로 나눕니다. 이 구분이 없으면 리뷰에서 취향 논쟁이 반복됩니다.

| 수준 | 뜻 |
| :--- | :--- |
| **필수** | 어기면 병합하지 않습니다. 대부분 도구가 막습니다 |
| **권장** | 다르게 할 이유를 말할 수 있으면 따르지 않아도 됩니다 |
| **취향** | 규칙을 두지 않습니다. 리뷰에서 지적하지 않습니다 |

기존 코드에 소급하지 않습니다. **손대는 파일만 고칩니다.** 규칙이 바뀔 때마다 전체를 훑으면 변경 이력이 규칙 적용으로 덮여 실제 변경을 찾을 수 없습니다.

각 규칙은 `FE-STY-NNN` 으로 참조합니다. 번호는 부여 뒤 바꾸지 않으며 삭제는 결번, 추가는 말번입니다.

## 2. 포매팅

**FE-STY-001 (필수)** 포매팅은 [Prettier](https://prettier.io/) 가 강제하며 `.prettierrc` 가 유일한 기준입니다. 들여쓰기 · 줄 길이 · 따옴표 · 세미콜론을 이 문서에 적지 않습니다. 도구 설정과 실행은 [프론트엔드 01. 개발 환경](./frontend-01-dev-environment.md)이 관리합니다.

## 3. 네이밍

### 3.1 파일

**FE-STY-002 (필수)** 파일명은 케밥 케이스(kebab-case)입니다.

**FE-STY-003 (필수)** 단일 클래스를 내보내는 파일명은 클래스명을 케밥 케이스로 변환한 이름입니다([Angular 스타일 가이드](https://angular.dev/style-guide)). 클래스명이 바뀌면 파일명도 함께 변경합니다.

| 대상 | 클래스 | 파일 |
| :--- | :--- | :--- |
| 컴포넌트 | `TaskRow` | `task-row.ts` |
| 라우트 진입 컴포넌트 | `TaskListPage` | `task-list-page.ts` |
| 서비스 | `SessionService` | `session-service.ts` |
| 가드 · 인터셉터(함수) | — | `auth-guard.ts` · `auth-interceptor.ts` |

**FE-STY-004 (필수)** 한 파일에서 둘 이상의 클래스를 내보내지 않습니다. 파일명과 일치하지 않는 클래스는 심볼 탐색을 방해합니다.

**FE-STY-005 (필수)** `pages` 슬라이스의 라우트 진입 컴포넌트는 클래스명을 `Page` 로 끝내고 파일명도 FE-STY-003 대로 일치시킵니다(`task-list-page.ts`). 진입점과 표현 컴포넌트의 구분을 유지하며 선택자에는 붙이지 않습니다.

**FE-STY-006 (필수)** 세그먼트 내부 파일은 다루는 도메인 개념으로 명명합니다. 포괄적인 이름에는 서로 다른 관심사가 혼재됩니다.

```
model/task.ts        lib/format-due-date.ts     api/fetch-tasks.ts      // Good
model/types.ts       lib/utils.ts               api/api.ts              // Bad
```

**FE-STY-007 (필수)** 요청 함수 파일명은 수행하는 동작의 동사로 시작합니다 — `fetch-tasks.ts` · `create-task.ts` · `delete-task.ts`.

### 3.2 심볼

**FE-STY-008 (필수)** 클래스명은 파스칼 케이스이며 `Component` · `Directive` · `Pipe` 접미사를 붙이지 않습니다([Angular 스타일 가이드](https://angular.dev/style-guide)). 파일 위치가 역할을 나타냅니다.

**FE-STY-009 (필수)** 서비스 클래스만 `Service` 접미사를 붙입니다. FE-STY-011 에 따른 주입 변수명과 일반 변수명의 충돌을 방지합니다.

**FE-STY-010 (필수)** 함수명은 역할을 나타내는 접두사로 시작합니다.

| 성격 | 접두사 | 예 |
| :--- | :--- | :--- |
| 주입 헬퍼 | `inject` | `injectViewportClass` |
| 조회 요청 | `fetch` | `fetchTasks` |
| 변경 요청 · 계산 | 동사 | `completeTask` · `formatDate` |
| 판정 | `is` · `has` · `can` | `isExpired` |

**FE-STY-011 (필수)** 의존성 주입 필드는 주입 대상 클래스명의 로워 카멜 케이스로 선언하며 축약하지 않습니다. 변환 결과는 의미에 맞는 이름(`isServer`)을 부여합니다.

```ts
private readonly httpClient = inject(HttpClient);   // Good
private readonly http = inject(HttpClient);         // Bad — 파일마다 이름이 갈립니다
```

**FE-STY-012 (필수)** 타입에 `I` 접두사나 `Type` 접미사를 붙이지 않습니다. 생성된 API 타입은 생성기가 정한 이름을 유지합니다.

**FE-STY-013 (필수)** 컴포넌트 선택자는 `app` 접두사와 케밥 케이스, 디렉티브 선택자는 접두사를 붙인 카멜 케이스 속성입니다. 접두사는 `angular.json` 의 `prefix` 설정을 따릅니다.

**FE-STY-014 (필수)** 상수는 대문자 스네이크 케이스(SCREAMING_SNAKE_CASE)입니다.

### 3.3 슬라이스

**FE-STY-015 (필수)** 슬라이스명은 케밥 케이스입니다. 동사구는 `features`, 도메인 명사는 `entities` 로 분류합니다([FSD 계층](https://feature-sliced.design/docs/reference/layers)).

| 계층 | 품사 | 예 |
| :--- | :--- | :--- |
| `pages` | 화면을 나타내는 명사구 | `task-list` |
| `features` | 사용자 동작을 나타내는 동사구 | `file-upload` |
| `entities` | 도메인 개념을 나타내는 명사 | `task` |

**FE-STY-016 (필수)** `pages` 슬라이스명은 라우트 경로와 일치시키며 접미사를 `-list` · `-detail` · `-edit` · `-create` 로 통일합니다.

**FE-STY-017 (필수)** 계층명이 포함된 이름, 포괄적인 이름(`common` · `misc` · `management`), 축약어, `shared` 세그먼트명과 중복되는 그룹 디렉터리명을 금지합니다.

## 4. 코드 구조

계층과 슬라이스의 정의, 임포트 방향, 공개 API 규칙은 빌딩 블록 뷰가 갖습니다. 이 절은 **새 코드를 어디에 두는가**를 정합니다.

### 4.1 배치 판정

**FE-STY-018 (필수)** 아래 순서대로 판정하여 최초로 일치하는 위치에 배치합니다.

```text
1. 애플리케이션 전역 설정인가?            → app/
2. 비즈니스 로직이 없는 인프라인가?        → shared/<세그먼트>/
3. 한 화면에서만 쓰는가?                  → pages/<화면>/
4. 여러 화면이 이미 쓰는 사용자 동작인가?   → features/<동작명>/
5. 여러 화면이 이미 쓰는 도메인 모델인가?   → entities/<도메인명>/
6. 확신이 없는 경우                       → pages/<화면>/
```

**FE-STY-019 (필수)** 기본 배치 위치는 `pages/<화면>/` 입니다. 화면 간 중복 자체는 공통 추출의 근거가 되지 않으며, 가설적 재사용으로 하위 계층에 선제 배치하지 않습니다. 되돌리는 비용이 승격하는 비용보다 큽니다.

**FE-STY-020 (필수)** `features` 및 `entities` 배치는 현재 둘 이상의 화면에서 실제로 호출되는 시점에만 허용합니다.

### 4.2 승격과 강등

**FE-STY-021 (필수)** 슬라이스 승격은 두 번째 화면에서 실제 호출이 발생하는 시점에 수행합니다. 사용자 동작은 `features`, 도메인 모델은 `entities` 로 승격합니다.

**FE-STY-022 (권장)** 단일 화면에서만 사용되는 슬라이스는 해당 화면(`pages`)으로 강등합니다. **강등은 규칙 위반이 아니며** 재사용 예측이 빗나갔을 때 되돌리는 것이 방치보다 낫습니다.

### 4.3 클래스 멤버 순서

**FE-STY-023 (필수)** 클래스 본문은 여덟 블록 순서로 배치하고 각 블록 앞에 구분선 주석을 둡니다. 없는 블록은 주석째 생략합니다.

| 순서 | 블록 | 대상 |
| :--- | :--- | :--- |
| 1 | 상수 | `static`, 템플릿에 재노출하는 심볼 |
| 2 | 계약 | `input` · `model` · `output` |
| 3 | 의존 | `inject` |
| 4 | 질의 | `viewChild` · `contentChild` |
| 5 | 상태 | `signal` · `linkedSignal` · `form` |
| 6 | 파생 | `computed` · `resource` · `httpResource` |
| 7 | 생성 | 생성자 · 라이프사이클 훅 |
| 8 | 동작 | 공개 메서드 먼저, `private` 나중 |

**FE-STY-024 (필수)** 구분선은 `// --- ` 뒤에 블록명을 두고 대시로 100 컬럼까지 채웁니다. 들여쓰기를 포함한 폭이며 한글은 두 컬럼으로 셉니다.

**FE-STY-025 (필수)** 동일 블록은 파일당 한 번만 선언합니다. 뒤에서 앞 블록으로 되돌아가 멤버를 추가하지 않습니다.

**FE-STY-026 (필수)** 템플릿에 재노출한 상수는 클래스 내부에서도 해당 필드를 통해 참조합니다. 템플릿이 쓰지 않는 상수는 필드로 선언하지 않습니다.

**FE-STY-027 (권장)** 멤버 수가 과도하게 늘어난 컴포넌트는 역할을 분리하여 하위 컴포넌트로 분할합니다.

### 4.4 데이터 접근

**FE-STY-057 (필수)** 컴포넌트가 Mock 데이터나 HTTP 호출을 직접 갖지 않습니다. 데이터 접근은 `api` 세그먼트의 서비스가 갖습니다.

**FE-STY-058 (필수)** 조회 결과를 신호에 복사해 직접 수정하지 않습니다. 서버와 화면의 불일치를 검출할 수 없게 됩니다.

**FE-STY-059 (필수)** `httpResource` 로 변경 요청을 보내지 않습니다. 읽기 전용이며 요청이 바뀌면 진행 중인 작업을 중단합니다.

**FE-STY-060 (필수)** 같은 화면에서 같은 데이터를 두 번 조회하지 않습니다. `httpResource` 는 요청 중복 제거를 제공하지 않으므로 인스턴스 둘은 요청 두 번입니다.

**FE-STY-061 (필수)** 라우트 스코프 조회 서비스에 변환 로직을 넣지 않습니다. 이 서비스는 라우트 정의가 즉시 임포트하므로 초기 번들에 들어갑니다.

**FE-STY-062 (필수)** 무효화 키는 `shared` 의 상수로 모읍니다. 문자열을 호출부에 흩뿌리면 오타를 검출할 수 없습니다.

**FE-STY-063 (필수)** 필터 · 정렬 · 페이지는 URL 쿼리 파라미터에 둡니다. 컴포넌트 신호에 두면 새로고침과 뒤로가기에서 소실되고, 베일과 인디케이터의 판정도 성립하지 않습니다.

**FE-STY-064 (필수)** 전역 스토어에 화면 전용 상태를 두지 않습니다. 화면을 떠나도 상태가 남습니다.

**FE-STY-065 (권장)** 낙관적 업데이트를 기본으로 쓰지 않습니다. 실패 시 되돌리는 경로와 변경 조정 경로를 함께 구성해야 하며 적용 시 결정 기록(ADR)을 남깁니다.

### 4.5 대기와 실패의 표현

**FE-STY-066 (필수)** 조회가 끝나기 전에 빈 안내를 내지 않습니다. 없는 것과 아직 모르는 것이 같은 화면이 됩니다.

**FE-STY-067 (필수)** 조회 실패를 빈 상태로 표시하지 않습니다. 사용자가 데이터 없음으로 오해하므로 그 자리에서 실패를 표시하고 재시도 수단을 둡니다.

**FE-STY-068 (필수)** 스켈레톤을 쓰지 않습니다. 최종 치수를 알 수 없는 화면에서 성립하지 않고 예약한 자리 자체가 유지보수 대상이 됩니다.

**FE-STY-069 (필수)** 화면 내 갱신 · 재조회 · 오버레이 · 덧붙는 로딩에 베일을 씌우지 않습니다. 이전 값이 남아 있어 덮을 것이 없고 방금 누른 컨트롤이 가려집니다.

**FE-STY-070 (필수)** 명령 실행에 전체 화면 덮개를 쓰지 않습니다. 피드백 범위가 실제 영향 범위와 어긋나므로 누른 버튼 안에서 진행을 표시하고 비활성화합니다.

**FE-STY-071 (필수)** 베일을 뷰포트 전체에 적용하지 않습니다. 상단 바와 사이드바가 가려져 대기 중에 이동할 수 없습니다.

**FE-STY-072 (필수)** 화면이 대기 시간 정책을 새로 정하지 않습니다. 같은 대기가 화면마다 다르게 보입니다.

**FE-STY-073 (필수)** 셸이 경로를 보고 베일 자리를 판정하지 않습니다. 셸이 어느 화면인지 알게 되어 골격 소유가 뒤집힙니다.

**FE-STY-074 (권장)** 화면 교체 구간에 애니메이션을 두지 않습니다. 완성된 화면 표시 시점을 늦추며 화면마다 전환 판단 비용을 유발합니다.

### 4.6 API 계약

**FE-STY-075 (필수)** 서버 응답과 요청의 타입을 손으로 쓰지 않습니다. 계약 위반이 컴파일을 통과해 런타임에서야 드러납니다.

**FE-STY-076 (필수)** 생성된 타입 파일을 직접 수정하지 않습니다. 다음 생성에서 소실되며 CI 의 재생성 검사가 이를 강제합니다.

**FE-STY-077 (필수)** 생성물을 `linguist-generated` 로 표시하지 않습니다. 계약 변경이 PR 차이에서 접히면 생성물을 커밋하는 목적이 사라집니다.

**FE-STY-078 (필수)** 필드 대응만 하는 변환 계층을 두지 않습니다. 판단을 담지 않는 코드를 유지하게 됩니다.

**FE-STY-079 (필수)** 엔드포인트 경로를 호출부에 직접 적지 않습니다. 경로 변경은 컴파일로 검출되지 않는 유일한 계약 변경입니다.

**FE-STY-080 (필수)** 실제 연동으로 전환한 뒤 인터페이스와 Mock 을 남기지 않습니다. 구현이 하나뿐인 간접층이 계약 변경마다 수리 대상이 됩니다.

### 4.7 레이아웃

**FE-STY-087 (필수)** `pages` 슬라이스가 자신의 레이아웃을 결정하지 않습니다. 레이아웃 소유가 `app` 에서 흩어집니다.

**FE-STY-088 (필수)** 라우트가 골격을 직접 지정하지 않습니다. 호출부가 구조를 알게 되어 골격을 바꿀 때 라우트를 전부 고쳐야 합니다.

**FE-STY-089 (필수)** aside 를 본문 위에 겹치지 않습니다. 가려진 쪽을 조작할 수 없습니다.

**FE-STY-090 (필수)** 화면 밖 등장과 퇴장을 `overflow: hidden` 으로 감추지 않습니다. 스크롤 컨테이너가 생겨 그 안의 sticky 가 풀리므로 `clip` 을 씁니다.

**FE-STY-091 (필수)** 좌우 흔들림 방지에 `overflow-y: scroll` 대신 `scrollbar-gutter: stable` 을 씁니다. 빈 트랙 노출과 오버레이 스크롤 무효화를 방지합니다.

**FE-STY-092 (필수)** flex 나 grid 의 콘텐츠 열에 `min-width: 0`(또는 `minmax(0, 1fr)`)을 빠뜨리지 않습니다. 긴 표나 코드 블록이 있는 화면에서만 열이 밀려 발견이 늦습니다.

**FE-STY-093 (필수)** `body { overflow: hidden }` 을 직접 설정하지 않습니다. 레이아웃이 흔들리고 오버레이가 중첩될 때 복원 시점이 어긋납니다.

**FE-STY-094 (필수)** 오버레이 호스트를 flex 나 grid 컨테이너 안에 두지 않습니다. 너비가 0 이어도 아이템으로 계산되어 간격이 하나 더 생기고 옆 요소가 밀립니다.

**FE-STY-095 (필수)** 고정 막대 높이는 단일 토큰을 참조하고 `env(safe-area-inset-bottom)` 을 더합니다. 막대 높이 · 본문 하단 여백 · 플로팅 오프셋 간 불일치를 방지합니다.

**FE-STY-096 (필수)** 전체 화면 에러에 복구 액션을 반드시 둡니다. 셸을 유지하지 않기로 한 결정의 전제가 무너집니다.

**FE-STY-097 (필수)** 점검 화면을 애플리케이션 라우트로 만들지 않습니다. 애플리케이션이 뜨지 않는 상황에서 보여줄 수 없습니다.

**FE-STY-098 (필수)** 개별 화면이 인쇄 스타일을 정의하지 않습니다. 인쇄 시 내부 스크롤 해제를 빠뜨리면 첫 화면 분량만 인쇄됩니다.

### 4.8 적응형

**FE-STY-099 (필수)** CSS 로 해결되는 것을 런타임 분기로 만들지 않습니다. 두 표현을 모두 유지해야 하고 테스트도 두 배가 됩니다.

**FE-STY-100 (필수)** 컴포넌트가 미디어 쿼리 문자열을 직접 갖지 않고 `shared/lib/adaptive/` 의 의미 신호를 씁니다. 판정 기준 변경 시 수정 지점을 단일화합니다.

**FE-STY-101 (필수)** 포인터와 호버 미디어 쿼리로 판정하지 않습니다. 브라우저가 이 값을 신뢰할 수 있게 보고하지 않으며 코드로 교정할 수 없습니다.

**FE-STY-102 (필수)** 표현 컴포넌트를 공개 API 로 내보내지 않습니다. 외부는 하나만 알아야 합니다.

**FE-STY-103 (필수)** 한 컴포넌트의 두 표현은 같은 입출력 계약을 갖습니다. 계약이 다르면 상위 컴포넌트가 분기를 알게 됩니다.

**FE-STY-104 (필수)** brain 의 `protected` 메서드를 재정의해 위치 전략을 우회하지 않습니다. 전역 전략 강제로 넓은 화면에서도 시트가 열리는 오동작을 방지합니다.

**FE-STY-105 (권장)** 지연 로딩을 추측으로 적용하지 않습니다. 얻는 것은 번들 감소이고 잃는 것은 첫 열기 지연입니다.

**FE-STY-106 (필수)** 터치 타겟은 표현과 무관하게 최소 크기를 지킵니다. 넓은 화면으로 판정된 터치 기기에서도 손가락 조작이 가능해야 합니다.

**FE-STY-107 (필수)** 두 레이아웃 표현이 같은 메뉴 정의를 참조합니다. 따로 선언하면 한쪽에서 항목이 누락됩니다.

### 4.9 스타일과 토큰

**FE-STY-108 (필수)** 임의 색상값을 직접 적지 않습니다. Tailwind 기본 팔레트(`gray-200` 등)도 대상이며, 토큰을 거치지 않으면 다크 모드에서 대비가 깨집니다.

**FE-STY-109 (필수)** 간격과 반경도 토큰을 씁니다. `rounded-[7px]` 형태의 임의값을 쓰지 않습니다.

**FE-STY-110 (필수)** 반투명 표면을 알파 유틸리티로 만들지 않습니다. 라이트와 다크 모드의 배경 밝기 차이로 동일 불투명도가 성립하지 않으므로 모드별 토큰을 선언합니다.

**FE-STY-111 (필수)** 토큰 없이 임의값을 임시로 쓰지 않습니다. 필요한 값이 있으면 토큰을 먼저 더하고 씁니다.

**FE-STY-112 (필수)** 크기와 두께 토큰을 새로 만들지 않습니다. Tailwind 척도와 두 벌이 됩니다.

**FE-STY-113 (필수)** helm 에 거는 `class` 는 배치와 여백에만 씁니다. 색 · 타이포그래피 · 내부 여백을 클래스로 덮으면 사용처마다 외형이 갈리고 영향 범위를 추적할 수 없습니다.

**FE-STY-114 (필수)** 컴포넌트가 노출하는 변형 입력을 먼저 씁니다. 클래스로 다시 칠하지 않습니다.

**FE-STY-115 (필수)** 간격은 `gap-*` 을 씁니다. `space-x-*` · `space-y-*` 는 flex 와 grid 에서 일관되게 동작하지 않습니다.

**FE-STY-116 (권장)** 같은 치수에는 `size-*` 를 씁니다.

**FE-STY-117 (필수)** 오버레이의 `z-index` 를 직접 지정하지 않습니다. CDK 오버레이가 쌓임 순서를 관리합니다.

**FE-STY-118 (필수)** brain 디렉티브 연결을 임의로 제거하지 않습니다. 접근성 보장이 함께 사라지며 시각적으로 드러나지 않습니다.

**FE-STY-119 (필수)** `node_modules` 를 패치하지 않습니다. 재설치 시 소실되며 추적되지 않습니다.

**FE-STY-120 (필수)** `shared/ui` 에 도메인 이름을 가진 컴포넌트를 두지 않습니다. 다른 프로젝트로 옮길 수 없게 됩니다.

**FE-STY-121 (필수)** SVG 를 템플릿에 직접 붙여 넣지 않습니다. 아이콘 래퍼를 통해서만 씁니다.

**FE-STY-122 (필수)** 토큰을 더할 때 유틸리티 등록(`@theme inline`)을 함께 합니다. 빠뜨리면 변수만 정의된 채 클래스가 생성되지 않습니다.

**FE-STY-123 (필수)** 새 토큰은 라이트와 다크 값을 동시에 정의합니다. 한쪽만 정의하면 반대 모드로 들어가기 전까지 드러나지 않습니다.

**FE-STY-124 (필수)** `-foreground` 짝이 없는 배경 토큰을 만들지 않습니다. 그 위에 올릴 텍스트 색의 판단이 갈립니다.

**FE-STY-125 (필수)** 프리셋의 `dark` 변형을 그대로 쓰지 않고 전역 스타일시트에서 재선언합니다. 클래스 판정 방식의 시스템 다크 모드 불일치를 방지합니다.

**FE-STY-126 (필수)** 포인터 쿼리로 치수를 가르지 않습니다. 유일한 예외는 입력 컨트롤 글자 크기이며 오판해도 안전한 쪽으로 기웁니다.

**FE-STY-127 (필수)** 터치 타겟의 바닥은 크기 변형이 아니라 컴포넌트의 기본 클래스에 깝니다. 일부 변형에만 붙이면 추가 변형이 기준을 벗어납니다.

### 4.10 라우팅

**FE-STY-128 (필수)** 화면 라우트를 정적으로 임포트하지 않습니다. 초기 번들에 모든 화면 코드가 포함되어 초기 로딩을 늦춥니다.

**FE-STY-129 (필수)** 경로 세그먼트에 비ASCII 문자를 쓰지 않습니다. 프리렌더는 통과하지만 서빙에서 404 가 됩니다.

**FE-STY-130 (필수)** 경로 문자열을 호출부에 직접 적지 않고 상수로 모읍니다. 경로 변경 시 누락과 오타를 검출할 수 없습니다.

**FE-STY-131 (필수)** 필터를 바꿀 때 히스토리를 쌓지 않습니다. 뒤로가기 시 필터 변경마다 멈춰 이전 화면 복귀를 방해합니다.

**FE-STY-132 (필수)** 오버레이가 자기 주소를 직접 바꾸지 않습니다. 열림 상태의 진실 공급원이 둘로 나뉘어 동기화가 깨집니다.

**FE-STY-133 (필수)** URL 에 토큰이나 개인식별정보를 두지 않습니다. 브라우저 히스토리 · 리퍼러 · 서버 로그에 민감 정보가 남습니다.

**FE-STY-134 (필수)** 라우트 가드를 인가 수단으로 신뢰하지 않습니다. 클라이언트는 변조 가능하며 가드는 화면 진입을 미리 막는 편의일 뿐입니다.

**FE-STY-179 (필수)** 목적지는 주소를 갖고 일시적 조작은 갖지 않습니다. 목적지는 그 자체로 하나의 일이며(세우기 · 상세), 일시적 조작은 값 하나를 고르고 끝나는 것입니다(거르개 · 정렬 · 고르개). 목적지의 열림 상태는 **경로가 아니라 쿼리**에 둡니다 — 경로를 바꾸면 뒤에 남아야 할 화면이 언마운트되고 셸이 베일로 그것을 가립니다. 판정 기준은 [프론트엔드 04. 적응형 레이아웃](./frontend-04-adaptive-layout.md) 4절이 갖습니다.

**FE-STY-180 (필수)** 목적지를 여는 것은 링크이며 단추로 열지 않습니다. 주소가 열림의 진실이 아니면 새로고침과 뒤로가기와 주소 건네기가 모두 성립하지 않습니다.

**FE-STY-181 (필수)** 덮개를 열 때는 히스토리를 쌓고 닫을 때는 갈아 끼웁니다. 둘 다 쌓으면 닫은 뒤의 뒤로가기가 덮개를 다시 열고, 둘 다 갈아 끼우면 뒤로가기가 덮개를 닫지 않고 그 화면을 떠납니다.

**FE-STY-182 (필수)** 덮개가 닫히는 모든 경로가 같은 자리로 갑니다. 배경을 누르거나 Esc 로 닫은 경우를 빠뜨리면 덮개는 닫혔는데 주소가 덮개를 가리킨 채 남아 새로고침에 다시 열립니다.

**FE-STY-183 (필수)** 덮개는 주소를 따라가고 스스로 주소를 바꾸지 않습니다. 열림의 진실을 주소 하나가 갖게 하기 위해서이며, 뒤로가기로 주소가 먼저 돌아간 경우에는 **이동 없이 덮개만 걷습니다.** 그때 다시 이동하면 히스토리가 한 칸 더 쌓여 어긋납니다.

**FE-STY-184 (필수)** 라우트가 띄우는 덮개에 그릇(`ViewContainerRef`)을 넘기지 않고 환경 인젝터를 넘깁니다. 그릇을 넘기면 내용의 DOM 이 오버레이 밖에 남아 판이 빈 채로 뜨고 포커스가 `aria-hidden` 이 걸린 자리에 갇힙니다.

**FE-STY-185 (필수)** 덮개의 검사는 오버레이 판 안에서 내용을 찾습니다. 문서 전체에서 찾으면 내용이 화면 안에 남아 판이 비는 어긋남을 놓칩니다.

**FE-STY-186 (필수)** 라우트가 띄우는 덮개는 배경 스크롤 잠금을 끕니다. CDK 의 기본값은 잠그는 것이고 그 구현이 `<html>` 을 `position: fixed` 로 만드는데, 셸이 화면 높이를 채우고 안쪽이 스크롤하는 골격에서는 그 순간 레이아웃이 통째로 밀립니다. **이 규칙은 강제되지 않습니다** — 단위 검사 환경에서 CDK 가 잠금 조건을 만족하지 않아 기본값이어도 통과하므로, 코드 리뷰에서 확인합니다.

**FE-STY-187 (필수)** 좁은 화면에서 팝오버로 뜨는 고르개를 자리마다 시트로 바꾸지 않습니다. 팝오버 층이 그 규칙을 갖고 있으므로 쓰는 쪽은 아무것도 하지 않습니다. 자리마다 정하면 같은 모양이 화면마다 다르게 뜨고, 새로 만드는 고르개가 규칙에서 빠집니다.

**FE-STY-188 (필수)** 팝오버 판의 고정 폭은 `md:` 를 답니다. 판의 바탕 클래스는 호출부의 클래스에 밀리므로(`hlm()` 이 뒤에 온 것을 남깁니다), 폭을 그냥 적으면 좁은 화면에서 시트가 화면을 채우지 못하고 그 폭에 갇힙니다.

**FE-STY-189 (필수)** Spartan 이 준 것을 물려받아 갈아 끼울 때는 부모 토큰을 `useExisting` 으로 다시 잇습니다. 물려받은 타입은 부모의 토큰으로 서지 않으므로, 잇지 않으면 그것을 주입하거나 뷰에서 질의하는 자리가 조용히 비거나 `NG0951` 로 터집니다.

**FE-STY-190 (필수)** 화면 폭에 따라 갈리는 것을 오버레이의 `hasBackdrop` 에 싣지 않습니다. 그 값은 입력의 초기값으로 한 번만 읽히므로 폭이 바뀌어도 그 자리에 남습니다. 뒤를 덮는 판은 항상 두고 그 **모습**을 폭에 맡깁니다 — 클래스는 열려 있는 중에도 갈아 끼울 수 있습니다.

### 4.11 컴포넌트

**FE-STY-135 (필수)** 상태는 그 값을 쓰는 최소 범위가 소유합니다. 단일 컴포넌트는 내부에, 여럿이 공유하면 슬라이스 `model` 에 둡니다.

**FE-STY-136 (필수)** 템플릿에서 함수를 직접 호출하지 않고 `computed` 로 계산합니다. 변경 감지마다 불필요하게 재실행됩니다.

**FE-STY-137 (필수)** `@for` 에 `track` 을 빠뜨리지 않습니다. 원소 변경 시 목록 DOM 전체가 재생성됩니다.

**FE-STY-138 (권장)** 컴포넌트가 서버를 직접 조회하거나 업무 규칙을 판단하지 않습니다. 표현과 입출력만 담당하여 UI 와 로직 결합을 방지합니다.

### 4.12 폼

**FE-STY-139 (필수)** 새 폼에 Reactive Forms 를 쓰지 않습니다. 시그널 상태 흐름 사이에 불필요한 변환 계층이 생깁니다.

**FE-STY-140 (필수)** 폼 요소에 `novalidate` 를 답니다. 검증 규칙이 DOM 제약 속성으로 반영되므로 없으면 브라우저 기본 검증이 제출을 가로채 **핸들러가 아예 실행되지 않습니다.**

**FE-STY-141 (필수)** `(ngSubmit)` 을 쓰지 않고 `(submit)` 에 바인딩합니다. Reactive Forms 디렉티브가 없으면 출력이 발화하지 않아 **빌드는 통과하고 제출만 조용히 동작하지 않습니다.**

**FE-STY-142 (필수)** 검증 규칙을 스키마 하나에 모읍니다. 조건부 활성화 · 표시 · 읽기 전용을 포함하며 템플릿에 분산하면 진실 공급원이 깨집니다.

**FE-STY-143 (필수)** 프론트엔드 검증을 근거로 서버 검증을 생략하지 않습니다. 클라이언트 요청은 변조될 수 있으므로 서버가 최종 검증합니다.

**FE-STY-144 (필수)** 검증 실패 시 제출 버튼을 비활성화하지 않습니다. 실패 사유를 알 수 없고 키보드 접근성이 저하됩니다.

**FE-STY-145 (필수)** 입력 중 즉시 오류를 표시하지 않고 필드를 벗어난 뒤에 보입니다. 작성 중 조기 에러 노출로 입력을 방해합니다.

**FE-STY-146 (필수)** 서버에 묻는 검증에 대기 시간을 함께 지정합니다. 미지정 시 타이핑마다 불필요한 요청이 전송됩니다.

**FE-STY-147 (필수)** `shared/ui` 에 도메인 검증을 넣지 않습니다. 인프라 계층이 비즈니스 로직에 종속되어 재사용성이 사라집니다.

### 4.13 접근성

**FE-STY-148 (필수)** `<div>` 에 클릭 핸들러를 달아 동작을 만들지 않고 `<button>` 을 씁니다. 키보드 포커스와 스크린리더 탐색이 불가능합니다.

**FE-STY-149 (필수)** `placeholder` 를 레이블 대신 쓰지 않습니다. 입력을 시작하면 사라져 필드 용도를 확인할 수 없습니다.

**FE-STY-150 (필수)** 대체 없이 포커스 표시를 제거하지 않습니다. 키보드 탐색 시 현재 위치를 파악할 수 없습니다.

**FE-STY-151 (필수)** 색상만으로 상태를 전달하지 않고 문구나 아이콘을 함께 둡니다. 색각 이상 사용자가 정보를 인지할 수 없습니다.

**FE-STY-152 (필수)** 호버로만 닿을 수 있는 필수 기능을 만들지 않습니다. 터치 환경에서 접근할 수 없습니다.

**FE-STY-153 (필수)** 라우팅 후 포커스 이동이나 알림을 빠뜨리지 않습니다. 스크린리더 사용자가 화면 전환을 인지하지 못합니다.

**FE-STY-154 (필수)** 글꼴 크기를 `px` 로 고정하지 않고 상대 단위(`rem`)를 씁니다. 브라우저 사용자 글꼴 크기 설정이 무시됩니다.

**FE-STY-155 (필수)** 파괴적 액션을 일반 액션 바로 옆에 두지 않습니다. 모바일 · 터치 환경에서 오조작이 발생합니다.

### 4.14 보안

**FE-STY-156 (필수)** `bypassSecurityTrust*` 를 쓰지 않습니다. Angular 보안 체계를 우회하여 XSS 취약점이 발생합니다.

**FE-STY-157 (필수)** 서버 응답을 `[innerHTML]` 에 바인딩하지 않습니다. 사용자 입력이 포함된 데이터로 인한 XSS 공격에 노출됩니다.

**FE-STY-158 (필수)** 소스 코드에 API 키나 비밀값을 두지 않습니다. 클라이언트 번들은 공개되므로 보호되지 않습니다.

**FE-STY-159 (필수)** 인증 헤더를 개별 요청에서 조립하지 않고 인터셉터로 일괄 부착합니다. 부착 규칙이 흩어져 누락되거나 외부로 토큰이 유출됩니다.

**FE-STY-160 (필수)** UI 를 숨기는 것을 인가 수단으로 쓰지 않습니다. 클라이언트는 변조 가능하므로 서버가 최종 판정합니다.

### 4.15 성능

**FE-STY-161 (필수)** 번들 예산을 두고 경고가 아니라 실패로 설정합니다. 경고만 두면 초과가 누적되어도 방치됩니다.

**FE-STY-162 (필수)** 예산을 올릴 때 사유를 남깁니다. 사유 없는 상향이 반복되면 예산 관리가 무력화됩니다.

**FE-STY-163 (필수)** 측정 없이 지연 로딩이나 가상 스크롤을 넣지 않습니다. 분할 복잡도 비용만 치르고 실제 성능 이득이 없을 수 있습니다.

**FE-STY-164 (필수)** 이미지에 크기(`width` · `height`)를 지정합니다. 로드 전 공간이 확보되지 않아 레이아웃이 밀립니다.

**FE-STY-165 (필수)** 이미지를 감추는 것을 CSS 기본값으로 두지 않습니다. 스크립트 실행 실패 시 이미지가 영구히 보이지 않습니다.

**FE-STY-166 (권장)** 폰트를 CDN 에서 불러오지 않고 자체 호스팅합니다. 추가 연결이 생기고 CSP 허용 목록이 넓어집니다.

**FE-STY-167 (필수)** 개발 빌드로 성능을 측정하지 않고 프로덕션 빌드에서 측정합니다. 디버그 오버헤드로 인해 수치가 왜곡됩니다.

### 4.16 실패 계약의 소비

**FE-STY-168 (필수)** 에러 문구는 서버가 준 코드로 먼저 찾고 없으면 서버 문장을 그대로 씁니다. 모르는 코드가 와도 화면이 비지 않아야 합니다.

**FE-STY-169 (필수)** 상태 코드만 보고 문구를 지어내지 않습니다. 서버가 아는 맥락이 소실됩니다.

**FE-STY-170 (필수)** 인증 만료 외의 실패를 인터셉터가 화면 대신 판단하지 않습니다. 인터셉터는 무엇이 일어났는지를 판별하고 화면이 무엇을 보여줄지 정합니다.

**FE-STY-171 (필수)** 자동 재시도는 조회 요청에만 겁니다. 변경 요청을 다시 보내면 중복 처리가 발생합니다.

**FE-STY-172 (필수)** 사용자에게 스택 트레이스와 쿼리와 내부 식별자를 보이지 않습니다. 노출하는 내부 정보는 추적 식별자 하나입니다.

### 4.17 인증

**FE-STY-173 (필수)** 클라이언트가 인증 토큰을 저장하거나 헤더에 붙이지 않습니다. 브라우저가 쿠키를 자동으로 실어 보냅니다.

**FE-STY-174 (필수)** 인증 요청 자체의 실패를 세션 만료로 처리하지 않습니다. 로그인 시도가 실패한 것을 만료로 보고 로그인 화면으로 다시 보내면 사용자에게는 아무 일도 일어나지 않은 것처럼 보입니다.

**FE-STY-175 (필수)** 프리렌더 경로에서 가드가 막지 않습니다. 빌드 시점에는 판정할 근거가 없고, 막으면 로그인 화면이 구워집니다.

## 5. TypeScript · Angular 관용구

**FE-STY-028 (필수)** `any` 사용을 금지합니다. 타입을 모르면 `unknown` 으로 선언하고 좁힙니다.

**FE-STY-029 (필수)** 열거는 `enum` 대신 `as const` 객체와 유니온 타입입니다([TypeScript enum](https://www.typescriptlang.org/docs/handbook/enums.html)). `enum` 의 런타임 코드 생성과 `isolatedModules` 제약을 방지합니다.

```ts
export const TASK_STATUS = { todo: 'TODO', done: 'DONE' } as const;
export type TaskStatus = (typeof TASK_STATUS)[keyof typeof TASK_STATUS];
```

**FE-STY-030 (필수)** 템플릿과 호스트 바인딩에 노출되는 식별자는 영문입니다. 템플릿 파서의 `NG5002` 컴파일 오류를 방지하며, 한글은 `private` 멤버와 지역 변수에만 씁니다.

**FE-STY-031 (필수)** `providedIn: 'root'` 는 `shared` 와 `app` 에서만 선언합니다. 화면 단위 서비스는 라우트의 `providers` 에 선언하여 컴포넌트 생명주기와 동기화합니다.

**FE-STY-032 (필수)** 계층 간 임포트는 `@/*` 별칭입니다. 상대 경로는 같은 슬라이스 내부에서만 씁니다. 근거는 검출 가능성이 아니라 **파일 이동 내성**입니다.

**FE-STY-033 (권장)** 데이터 조회는 라우트 스코프의 `httpResource`, 데이터 변경은 명령 전용 서비스로 분리합니다.

**FE-STY-081 (필수)** `shared` 의 코드는 모듈 최상위에서 브라우저 API 를 호출하지 않습니다. 프리렌더 빌드(Node) 시점 평가로 실패하므로 함수 내부에서 지연 호출합니다.

**FE-STY-082 (필수)** `typeof window !== 'undefined'` 형태의 검사를 쓰지 않습니다. Angular 가 제공하는 플랫폼 판별을 써야 테스트에서 환경을 주입할 수 있습니다.

**FE-STY-083 (필수)** `afterNextRender` 안에서 화면 구성을 바꾸지 않습니다. 프리렌더 결과물에서 누락되어 하이드레이션 불일치 및 화면 깜빡임이 발생합니다.

**FE-STY-084 (필수)** 프리렌더 경로에서 적응형 컴포넌트를 쓰지 않습니다. 빌드 시점 뷰포트 부재로 클라이언트 판정과 어긋나 깜빡임이 발생하며, **코드 리뷰에서 확인합니다.**

**FE-STY-085 (필수)** 프리렌더되는 경로에서 난수 · 현재 시각 · 저장소 값으로 DOM 을 결정하지 않습니다. 빌드 시점과 클라이언트의 값이 달라 하이드레이션이 실패합니다.

**FE-STY-086 (필수)** Angular 외부에서 DOM 을 직접 조작하지 않습니다. 하이드레이션이 노드 구조를 신뢰할 수 없게 됩니다.

## 7. 에러 처리와 로깅

**FE-STY-037 (필수)** 401 처리는 HTTP 인터셉터에서 중앙 집중식으로 수행하며 개별 화면에서 중복 처리하지 않습니다.

**FE-STY-038 (필수)** HTTP 인터셉터에서 토스트를 띄우지 않습니다. UI 피드백 제어권은 화면 컴포넌트가 유지합니다.

**FE-STY-039 (필수)** 조회 실패를 빈 데이터 상태로 대체하여 표시하지 않습니다. 데이터 부재와 통신 실패 상태를 명확히 구분합니다.

**FE-STY-040 (필수)** 변경 요청을 자동 재시도하지 않습니다. 중복 처리가 발생합니다.

**FE-STY-041 (필수)** 스택 트레이스와 내부 식별자를 화면에 노출하지 않습니다.

**FE-STY-042 (필수)** 응답 객체 전체를 콘솔에 출력하지 않습니다. 민감 정보 노출을 방지하기 위해 필요한 필드만 지정하여 출력합니다.

**FE-STY-043 (필수)** `console.log` 를 커밋하지 않습니다. ESLint `no-console` 이 막으며 `console.error` 와 Node 진입점은 예외입니다.

**FE-STY-044 (권장)** 400 · 403 을 관측 도구로 보내지 않습니다. 정상적인 입력 오류로 인한 경보 노이즈를 방지합니다.

## 8. 테스트 코드 스타일

**FE-STY-045 (필수)** 테스트 파일은 대상 파일 옆에 둡니다. `__tests__` 디렉터리를 만들지 않으며, 종단 테스트는 `clients/apps/web/e2e/` 에 둡니다. 화면을 띄워 검증하므로 그 축의 의존성과 명령을 그대로 씁니다.

**FE-STY-046 (필수)** 분기가 있는 코드는 테스트합니다. 분기 없는 위임 함수는 대상이 아닙니다.

**FE-STY-047 (필수)** 프레임워크 동작과 생성된 타입을 검증하지 않습니다. 외부 의존 동작의 변경에 따른 테스트 취약성을 방지합니다.

**FE-STY-048 (필수)** CSS 클래스로 요소를 선택하지 않습니다. 접근성 역할(role)과 접근 가능한 이름으로 요소를 탐색합니다([Testing Library 질의 우선순위](https://testing-library.com/docs/queries/about/#priority)).

**FE-STY-049 (필수)** 고정 시간 대기를 쓰지 않습니다. 비동기 상태 완료 이벤트나 상태 대기 헬퍼를 사용합니다.

**FE-STY-050 (필수)** 불안정한 테스트를 재시도로 통과시키지 않습니다. 비동기 타이밍 등 근본 원인을 수정합니다.

**FE-STY-051 (필수)** 응답 목을 임의 객체로 만들지 않습니다. 생성된 타입을 사용하여 API 계약 변경을 검출합니다.

**FE-STY-052 (권장)** 커버리지 수치를 빌드 통과 기준으로 강제하지 않습니다. 근거는 [결정-0008](../decisions/0008-shared-testing.md)이 갖습니다.

**FE-STY-176 (필수)** 인수 조건의 추적 키를 화면 진입부터 데이터 접근까지 경로 전체를 지나는 테스트에만 부여하며 `describe` 또는 `it` 이름의 접두어로 둡니다. 접두어 뒤의 문장은 인수 조건 문장과 일치시키지 않습니다. 키의 형식과 부여 규약은 [결정-0007](../decisions/0007-shared-software-process.md)이 갖습니다.

```ts
it('GT-14 #1: 제목을 적으면 목록에 그 작업이 있다', async () => {
```

**FE-STY-177 (필수)** 목 위에서 도는 테스트가 접두어를 갖는 것은 **프론트엔드 경로까지 참**이라는 뜻입니다. 인수 조건의 충족은 실제 백엔드 연결로 확인합니다.

**FE-STY-178 (필수)** 단위 테스트와 컴포넌트 단독 테스트에 추적 키를 붙이지 않습니다. 함수 하나의 통과가 인수 조건 충족으로 오인되는 것을 방지합니다.
