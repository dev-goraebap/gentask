# 8. 횡단 관심사 (Crosscutting Concepts)

여러 빌딩 블록에 걸치는 관행과 패턴, 규약을 정의합니다. 한곳에 모으지 않으면 각 빌딩 블록의 서술에서 반복될 주제가 이 절의 대상이며, 코드가 어디에 위치하는가는 [5. 빌딩 블록 뷰](./05-building-block-view.md)가 다룹니다.

[arc42](https://docs.arc42.org/tips/8-10/) 는 이 절에서 다룰 수 있는 주제를 목록으로 제시하되 전부를 채우지 말라고 명시합니다. 아래는 그 목록 가운데 이 저장소가 실제로 규약을 갖는 대상들이며, 규약이 생길 때마다 문서를 추가합니다.

하위 문서는 `concepts/` 디렉터리에 `<축>-<순번>-<주제>.md` 형식으로 배치합니다. 축은 `frontend` · `backend` · `shared` 이며 순번은 축마다 독립된 수열입니다. 두 축에 걸치는 주제가 생기면 디렉터리를 옮기지 않고 접두사만 `shared` 로 변경합니다.

## 8.1 개발 개념 (Development Concepts)

빌드 · 테스트 · 코드 생성 · 설정, 그리고 코드를 작성하는 방식입니다. 프론트엔드와 백엔드가 서로 다른 도구를 사용하므로 문서를 분리합니다.

| 문서 | 담는 것 |
| :--- | :--- |
| [프론트엔드 01. 개발 환경](./concepts/frontend-01-dev-environment.md) | 구성 파일, 명령, 경로 별칭, 줄바꿈 정책, 강제 수단의 적용 범위와 예외 |
| [프론트엔드 02. 코드 스타일 가이드](./concepts/frontend-02-code-style.md) | 네이밍 · 코드 구조 · TypeScript 관용구 · 주석 · 에러 처리 · 테스트 스타일 (`FE-STY-NNN`) |
| [백엔드 01. 개발 환경](./concepts/backend-01-dev-environment.md) | 구성 파일, JVM 요건, 로컬 실행, 빌드 단계, 정적 분석의 분담 |
| [백엔드 02. 코드 스타일 가이드](./concepts/backend-02-code-style.md) | 네이밍 · 코드 구조 · Java 관용구 · 주석 · 에러 처리 · 테스트 스타일 (`BE-STY-NNN`) |

스타일 가이드는 두 축이 동일한 9개 절 구성을 따릅니다. 각 규칙은 **필수 · 권장 · 취향** 중 하나로 분류하고 `<축>-STY-NNN` 식별자를 부여하여 코드 리뷰에서 번호로 지목할 수 있습니다. 규칙은 한 줄, 근거는 한 줄로 기술하며 세부 논증은 아키텍처 결정 기록(ADR)으로 분리합니다.

**포매팅 규칙은 문서에 직접 기술하지 않습니다.** 도구 설정을 기준으로 삼으며, 그 설정과 설치 방법은 개발 환경 문서가 다룹니다.

두 축의 개발 환경 문서는 동일한 원칙을 적용합니다. **설정값을 문서에 옮겨 적지 않고 설정 파일을 참조합니다.** 두 벌이 되면 한쪽이 낡기 때문이며, 문서는 규칙과 근거를, 설정 파일은 그 실행 형태를 갖습니다.

**자동 강제되지 않는 규칙은 그 사실을 함께 적습니다.** 강제되는 것과 그렇지 않은 것을 구분하지 않으면 전자만 지켜지고 후자는 지켜지는 것으로 오인됩니다.

## 8.2 내부 동작 (Under the Hood)

요청과 데이터가 시스템 내부에서 처리되는 흐름, 그리고 두 컴포넌트가 주고받는 인터페이스 계약입니다.

| 문서 | 담는 것 |
| :--- | :--- |
| [백엔드 03. 계층 구조와 요청 처리 흐름](./concepts/backend-03-layers.md) | 계층과 의존 방향, 명령과 조회의 분리, 도메인·영속 모델의 변환, 트랜잭션 경계 |
| [프론트엔드 03. 데이터 흐름과 상태 동기화](./concepts/frontend-03-data-flow.md) | 서버 상태의 조회와 명령, 무효화, 대기와 실패의 표현, URL 상태, 타입 생성 |
| [공통 01. API 계약](./concepts/shared-01-api-contract.md) | 경로와 메서드와 표현 형식, 목록 반환 정책, 명세가 전달되는 경로 |
| [공통 02. 실패 계약](./concepts/shared-02-error-contract.md) | 서버가 실패를 거르는 세 지점, 에러 코드 체계와 응답 형식, 클라이언트의 처리 경로 |
| [공통 03. 인증과 세션](./concepts/shared-03-authentication.md) | 신원을 확인하는 두 경로, 토큰의 저장 형태와 쿠키 속성, 세션 수명, 클라이언트의 몫 |

**공통 문서 둘은 두 축에 동시에 적용되는 계약입니다.** 서버가 생산하고 클라이언트가 소비하는 구조이므로 어느 한쪽에 두면 반대쪽이 이를 참조하게 되며, 같은 계약을 두 축이 각자 서술하면 반드시 어긋납니다.
