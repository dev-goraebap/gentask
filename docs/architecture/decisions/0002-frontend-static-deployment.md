# 결정-0002: 프론트엔드를 정적 산출물로 배포하고 실행 프로세스를 두지 않는다

- 상태: 승인됨
- 날짜: 2026-08-27

## 맥락 (Context)

프로젝트는 Angular 의 하이브리드 렌더링 설정(`outputMode: "server"`)으로 시작했습니다. 이 설정은 빌드 산출물에 Node 서버 번들을 포함하며, 배포 환경은 그 번들을 실행하는 컨테이너 하나를 상시 구동해야 합니다.

그러나 라우트별 렌더링 지정을 세어 보면 서버 렌더링(`RenderMode.Server`)으로 지정된 경로가 하나도 없습니다.

```typescript
export const serverRoutes: ServerRoute[] = [
  { path: '', renderMode: RenderMode.Prerender },
  { path: '**', renderMode: RenderMode.Client },
];
```

진입 경로는 빌드 시점에 프리렌더되고 나머지는 브라우저에서 렌더링됩니다. 요청 시점에 서버가 HTML 을 만드는 경로는 없으며, 구동 중인 Node 프로세스는 정적 파일을 전달하는 일만 수행합니다. 이 구조는 애플리케이션이 인증 후 개인 데이터를 다루는 화면으로만 구성된 데서 비롯합니다. 검색 엔진에 노출할 공개 문서가 없고 로그인 전 화면은 로그인과 가입 둘뿐이므로, 서버 렌더링이 제공하는 초기 HTML 의 이점이 성립할 지점이 없습니다.

**설정을 그대로 두는 길**은 서버 렌더링이 필요해질 때 라우트 지정만 바꾸면 된다는 이점이 있습니다. 그러나 렌더링하지 않는 프로세스 하나를 상시 구동하고 감시해야 하며, 컨테이너 이미지와 포트와 환경 변수(`NG_ALLOWED_HOSTS`)가 함께 따라옵니다. 그 변수가 누락되면 SSRF 방어 정책이 모든 요청을 HTTP 400 으로 종료시킵니다. 서버 렌더링 경로가 0 개인 상태에서 운영 대상이 하나 늘고 그 대가로 얻는 동작이 없습니다.

**프리렌더까지 걷고 순수 클라이언트 렌더링으로 가는 길**도 검토했습니다. 정적 진입점이 하나로 줄어 웹 서버 설정이 단순해지고 빌드에서 서버 엔트리가 불필요해집니다. 현재 프리렌더가 만드는 산출물이 252 바이트짜리 리다이렉트 문서 하나뿐이라 더 그렇습니다. 그러나 `/` 진입 시 브라우저가 하는 일이 다릅니다. 이 길에서는 63 KB 의 셸과 195 KB(전송 기준)의 초기 번들을 내려받아 부팅한 뒤에야 라우터가 `/tasks/all` 로 이동하지만, 프리렌더를 두면 252 바이트를 받고 즉시 다음 URL 을 요청합니다. 웹 서버 설정 한 줄과 번들 부팅 한 회의 교환이며 후자의 비용이 더 큽니다.

## 결정 (Decision)

`outputMode` 를 `static` 으로 지정하고 프리렌더를 유지합니다. 빌드 산출물 `dist/web/browser` 를 nginx 가 직접 제공하며, 프론트엔드는 실행 프로세스를 갖지 않습니다.

## 결과 (Consequences)

프론트엔드의 운영 대상이 파일 집합으로 축소됩니다. 실행 프로세스와 컨테이너 이미지와 포트와 환경 변수가 모두 사라지고, 배포와 롤백이 심볼릭 링크 교체로 통일되며 웹 서버 재시작을 수반하지 않습니다.

감수하는 것이 둘입니다.

- 서버 렌더링이 필요해지면 빌드 설정을 되돌리고 실행 환경을 다시 구성해야 합니다.
- 웹 서버가 정적 진입점 둘을 구분해야 합니다. 프리렌더된 `index.html` 은 애플리케이션 셸이 아니라 `<meta http-equiv="refresh">` 리다이렉트 문서이므로, 통상적인 `try_files $uri /index.html` 규칙을 적용하면 모든 경로가 이 문서를 받아 리다이렉트가 반복됩니다. 대체 경로는 `index.csr.html` 이어야 합니다.

**느린 회선에서는 그 리다이렉트 문서가 화면에 보입니다.** 즉시 다음 URL 을 요청하지만 다음 문서가 도착할 때까지 이 문서가 그려진 채 남습니다. 진입 라우트가 리다이렉트인 동안 감수하는 대가이며, 그 라우트가 실제 페이지를 갖게 되면 사라집니다.

아래 상황에서 이 결정을 다시 판단합니다.

- 검색 엔진 노출이나 소셜 미리보기가 필요한 공개 경로가 생길 때. 서버 렌더링 또는 해당 경로의 프리렌더 확장을 판단합니다.
- 로그인 전 화면이 늘어 초기 번들의 부팅 시간이 사용자 경험을 좌우하게 될 때.
