# 결정-0014: 개발용 데이터베이스와 파일 보관소를 홈서버에 두고 인가된 IP에서만 접근을 허용한다

- 상태: 승인됨
- 날짜: 2026-09-02

## 맥락 (Context)

기존에는 개발용 데이터베이스와 오브젝트 스토리지를 `compose.yaml`을 통해 로컬 머신 컨테이너로 기동했고, 데이터는 해당 로컬 머신의 Docker 볼륨에 국한되었다. 이로 인해 작업 머신을 변경할 때마다 개발 데이터가 유실되어 테스트 계정, 프로젝트, 작업 데이터를 매번 재입력해야 하는 비효율이 있었다.

**데이터 정합성 유지 필요**: 첨부 파일은 데이터베이스 메타데이터와 스토리지 바이너리가 함께 존재해야 한다. 한쪽만 동기화되면 파일 조회 및 다운로드 시점에 404/500 에러가 발생한다.

**개발 인프라 통합 환경**:

- 데이터베이스는 홈서버 공용 PostgreSQL 17.4 인스턴스(`my-postgres`) 내에 `gentask_dev` 데이터베이스를 신설하여 타 프로젝트와 공유한다. 이미 라우터 포트포워딩이 구성되어 있어 외부 개발 머신에서 즉시 접근 가능하다.
- 오브젝트 스토리지는 홈서버에 MinIO(`my-minio`) 컨테이너를 신규 배포하고 `gentask-dev` 버킷을 생성한다. 운영 Cloudflare R2에 개발 버킷을 생성하는 방안은 운영 계정 오염 및 추가 과금 위험이 있어 배제했다.
- MinIO 엔드포인트는 홈서버의 Nginx 리버스 프록시(443 HTTPS)를 경유하여 서브도메인으로 노출한다. 브라우저 Direct Upload를 위한 Presigned URL이 유효하게 서명되려면 Nginx가 `Host` 헤더를 투명하게 전달해야 한다.
- 공개 인터넷 노출에 따른 보안 위협을 차단하기 위해 Nginx 계층에서 개발자 공인 IP 화이트리스트 기반 접근 제어를 적용한다.

**테스트 데이터베이스 격리**: 원격 개발 DB를 테스트에 공유하면 [결정-0008](./0008-shared-testing.md)의 테스트 재현성과 독립성이 훼손되므로, Testcontainers를 사용하는 통합 테스트는 독립된 일회용 로컬 컨테이너를 유지한다.

## 결정 (Decision)

**인프라 배치**

- 개발 데이터베이스는 홈서버 공용 PostgreSQL 인스턴스에 `gentask_dev` 데이터베이스를 구성하고 전용 계정으로 연결한다. 해당 계정은 수퍼유저가 아니며 자기 데이터베이스 외부를 변경하지 못한다.
- 오브젝트 스토리지는 홈서버에 MinIO(`my-minio`)를 구축하고 `gentask-dev` 전용 버킷을 할당한다. 전용 사용자 계정으로 최소 권한을 부여한다.
- `compose.yaml` 및 `spring-boot-docker-compose` 의존성을 완전히 제거하여 로컬 머신의 컨테이너 기동 오버헤드를 없앤다.

**접근 제어 및 네트워크**

- 데이터베이스는 기존 라우터 포트포워딩을 통해 직접 접속한다.
- MinIO는 Nginx 443 포트를 경유하는 HTTPS 서브도메인으로 노출하며, MinIO 자체 호스트 포트는 외부 비공개(`127.0.0.1`)로 격리한다.
- Nginx 리버스 프록시에서 개발자 공인 IP 화이트리스트를 적용하여 비인가 접근을 원천 차단한다.
- Nginx 프록시 설정에서 `Host` 헤더를 원본 그대로 보존하고 `client_max_body_size`를 충분히 확보한다.
- SSL 인증서 자동 갱신은 홈서버의 일원화된 절차를 통해 관리한다.

**테스트 환경**

- 백엔드 통합 테스트는 Testcontainers 로컬 컨테이너 격리 방식을 불변으로 유지한다.

## 결과 (Consequences)

로컬 머신 변경과 무관하게 상시 가용 개발 데이터가 유지된다. `compose.yaml` 기동 없이 `.env` 설정만으로 즉시 애플리케이션을 실행할 수 있다.

감수하는 제약 사항은 다음과 같다.

- 인가되지 않은 IP 환경에서는 스토리지 접근이 차단되므로 화이트리스트 갱신이 선행되어야 한다.
- 원격 네트워크 왕복 지연(Latency)이 쿼리 및 파일 업로드 시 발생한다.
- 홈서버 장애나 정전 시 로컬 개발이 일시 중단된다.
- 동일 PostgreSQL 인스턴스를 운영과 공유하므로 고부하 쿼리가 운영 환경에 영향을 줄 수 있다.
- 개발 스토리지(MinIO)와 운영 스토리지(R2) 간의 구현체 차이가 존재한다.

다음 상황 발생 시 본 결정을 재검토한다.

- 협업 개발자가 참여하여 개발 데이터 격리가 요구될 때: 개발자별 독립 DB/버킷 분리 또는 로컬 복귀 검토.
- 작업 장소 이동이 빈번하여 IP 화이트리스트 관리가 비효율적일 때: Tailscale/VPN 기반 접근 검토.
- 개발 부하로 인해 운영 인스턴스 성능 저하가 감지될 때.
