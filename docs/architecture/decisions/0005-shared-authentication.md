# 결정-0005: 브라우저는 쿠키 세션으로, 그 밖의 클라이언트는 Bearer 토큰으로 인증한다

- 상태: 승인됨
- 날짜: 2026-08-28

## 맥락 (Context)

서버는 요청자의 신원을 판정해야 하고, 그 판정의 근거가 되는 자격 증명을 클라이언트가 보관하고 전송해야 합니다.

최초의 클라이언트는 브라우저 화면 하나였고 인증은 쿠키 세션으로 판정했습니다. 두 번째 경로는 요구사항에서 도출되었습니다. `GT-29` 이 로컬 에이전트가 사용자 계정으로 API 를 호출하는 것을 요구하면서 브라우저가 아닌 호출자가 클라이언트 집합에 추가되었고, 쿠키가 그 환경에서 성립하지 않으므로 두 번째 수단이 필요해졌습니다.

**단일 수단으로 통일하는 방안**은 클라이언트 환경의 특성 차이로 인해 제한됩니다. 쿠키는 브라우저가 자동으로 전송하며 그 자동 전송이 `HttpOnly` 속성의 전제입니다. 브라우저가 아닌 클라이언트에는 그 자동화가 없습니다. 반대로 브라우저에 Bearer 토큰을 사용하면 토큰을 어딘가에 보관해야 하고, 보관하는 순간 스크립트가 읽을 수 있게 됩니다.

**토큰의 저장 형태**는 원문과 해시 중 하나입니다. 원문을 저장하면 조회가 단순하지만 저장소가 유출되었을 때 그 값으로 즉시 인증할 수 있습니다. 해시를 저장하면 유출된 값으로 인증할 수 없으나, 인입된 토큰을 매번 해싱해 비교해야 하고 원문을 되찾을 수 없습니다.

**세션 수명**은 고정 만료와 슬라이딩 갱신 중 하나입니다. 고정 만료는 사용 중에도 만료되어 재인증을 요구합니다. 슬라이딩 갱신은 사용할 때마다 만료를 연장하므로 사용 중 만료가 없는 대신, 계속 사용하는 세션이 영구히 유지될 수 있고 요청마다 세션 저장소에 쓰기가 발생합니다.

**인터셉터의 적용 범위**는 보호 대상 나열과 예외 대상 나열 중 하나입니다. 보호할 경로를 나열하면 신규 엔드포인트를 추가할 때 목록 등록을 누락한 경로가 인증 없이 열립니다. 예외만 나열하면 누락된 경로는 닫힌 상태로 남습니다.

## 결정 (Decision)

**인증 수단**: 동일한 인터셉터가 두 요청 경로를 모두 처리합니다. `Authorization: Bearer` 헤더가 있으면 API 토큰으로, 없으면 세션 쿠키로 판정합니다. 검증을 통과하면 요청 속성에 사용자 식별자를 설정하고, 이후의 업무 코드는 어느 수단으로 인증되었는지 구분하지 않습니다.

**쿠키 속성**: `HttpOnly`를 활성화하고, `SameSite`는 `Lax`, `Path`는 `/`로 설정합니다. `Secure`는 환경별 설정으로 주입합니다.

**토큰 저장**: 서버는 토큰 원문을 저장하지 않습니다. 발급 시점에만 원문을 생성해 클라이언트에 전달하고 저장소에는 HMAC 해시를 보관합니다. 해시 계산에는 토큰의 용도를 함께 결합하여, 세션과 API 토큰의 동일한 원문이 서로 다른 해시를 생성하도록 합니다. 해시 키는 애플리케이션 설정이 소유하며 길이가 미달하면 기동이 실패합니다.

**세션 수명**: 슬라이딩 갱신을 사용하되 절대 상한과 갱신 간격을 함께 둡니다. 상한은 최초 발급 시점을 기준으로 하며, 갱신 간격 이내의 재사용은 유효성만 확인하고 갱신 쓰기를 생략합니다. 만료된 세션은 존재하지 않는 세션과 동일한 실패 응답을 받습니다.

**적용 범위**: 인터셉터가 API 경로 전체를 보호하고 자격을 아직 갖지 못한 자리만 예외로 제외합니다. 가입과 로그인, 그리고 가입의 이메일 확인과 비밀번호 재설정이 그 자리입니다. 재설정은 비밀번호를 모르는 상태에서 지나므로 세션을 요구할 수 없고, 대신 [결정-0012](./0012-shared-credential-policy.md)의 일회용 코드가 그 자리에서 신원을 판정합니다. 비밀번호 변경은 로그인 상태에서 수행하므로 예외가 아닙니다.

**클라이언트 처리**: 클라이언트는 토큰 원문을 다루지 않고 브라우저의 자동 쿠키 전송에 위임합니다. 화면 진입 시의 인증 확인은 라우트 가드가, 세션이 끊긴 응답의 처리는 HTTP 인터셉터가 전담합니다. 인증 요청 자체의 실패는 인터셉터의 처리 대상에서 제외합니다. 프리렌더 경로에서는 가드가 통과시킵니다.

## 결과 (Consequences)

세션 토큰이 스크립트에 노출되지 않습니다. `HttpOnly` 쿠키는 스크립트가 읽을 수 없으므로 XSS로 세션이 탈취되지 않으며, 저장소가 유출되어도 보관된 해시로는 인증할 수 없습니다.

감수하는 것이 일곱입니다.

- 인증 수단이 둘이므로 판정 경로도 둘입니다. 인증과 관련한 변경은 두 경로 모두에서 검토해야 합니다.
- 자격 증명의 저장 구조가 두 벌입니다. 두 토큰은 형태와 해시 방식과 조회 방식이 동일하고 수명 정책의 유무만 다른데도 테이블과 도메인 타입과 저장소를 각각 갖습니다.
- API 토큰에는 세션의 수명 정책이 적용되지 않습니다. 만료와 범위 제한이 없으므로 유출되면 사용자가 직접 삭제하거나 비밀번호를 재설정할 때까지 소유자 전권으로 유효합니다.
- `SameSite=Lax` 는 화면과 API 가 같은 출처라는 전제 위에 섭니다. 다른 출처에서 API 를 호출하면 쿠키가 전송되지 않으므로, 배포 환경에서 화면과 API 를 단일 도메인 아래 두는 구성이 이 설정과 맞물립니다.
- 화면 진입에 왕복이 하나 더 붙습니다. 쿠키만으로는 그것이 아직 유효한지 클라이언트가 알 수 없어 가드가 조회를 한 번 보냅니다.
- 가드는 인가 수단이 아닙니다. 클라이언트 코드는 조작 가능하므로 가드를 통과했다는 사실이 권한을 보장하지 않으며, 실제 판정은 매 요청마다 서버가 다시 수행합니다.
- 만료와 부재를 구분해 알려 줄 수 없습니다. 구분해 응답하면 그 차이가 곧 해당 토큰이 존재했다는 정보가 되기 때문입니다.

아래 상황에서 이 결정을 다시 판단합니다.

- 화면과 API 를 서로 다른 출처에 배치해야 할 때. `SameSite` 설정과 쿠키 전송 조건을 다시 판단합니다.
- 세션 저장소의 쓰기 부하가 드러날 때. 갱신 간격과 세션 저장 위치를 다시 판단합니다.
