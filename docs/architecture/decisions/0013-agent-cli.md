# 결정-0013: 에이전트가 붙는 자리를 명령줄 도구로 두고 자격을 파일과 환경에서 받는다

- 상태: 승인됨
- 날짜: 2026-08-31

## 맥락 (Context)

[AGT-001](<../../spec/agent/AGT-001(에이전트로 작업 다루기).md>)이 로컬 에이전트를 액터로 올리면서 그 도구가 붙을 자리가 필요해졌습니다. 다루는 것은 이미 있는 작업 API 이며 서버에 더할 기능은 없습니다 — 필요한 것은 그 API 를 에이전트가 알아듣는 모양으로 옮기는 껍데기입니다.

**모델 컨텍스트 프로토콜(MCP)로 두는 길**은 도구의 이름과 설명과 JSON 스키마를 프로토콜이 넘겨 주므로 에이전트가 무엇을 부를 수 있는지 따로 배우지 않습니다. 인자 검증도 프로토콜 층에서 끝납니다. 대가는 **그 정의가 대화가 시작될 때 전부 실린다**는 것입니다. 쓰지 않을 도구의 스키마도 함께 올라가며 도구를 더할수록 그 값이 커집니다.

이 저장소의 도구 여덟을 실측하면 스키마가 3,166자, 대략 1,000 토큰입니다. 지금 규모에서는 감당되는 값입니다. 다만 다루는 것을 작업에서 이슈(에픽 · 스토리 · 태스크 · 버그)로 넓히면 도구가 스물을 넘고, MCP 의 도구 목록은 평면이라 그 전부가 매번 함께 실립니다.

**명령줄 도구(CLI)로 두는 길**은 그 값을 쓰는 만큼만 냅니다. `--help` 가 곧 발견 수단이고 하위 명령마다 나뉘어 있어, 작업을 다루려는 에이전트는 작업 쪽 도움말만 읽습니다. 셸이 있는 곳이면 어디서나 서므로 MCP 를 모르는 에이전트도 부르고, 사람과 스크립트와 예약 실행도 같은 것을 부릅니다.

**가장 강한 반박은 학습 데이터입니다.** CLI 가 MCP 보다 낫다는 주장의 핵심 근거는 `git` 과 `gh` 와 `jq` 가 학습 데이터에 수없이 나와 모델이 이미 안다는 것인데, **우리가 만드는 명령은 거기 없습니다.** 모델은 `gentask add` 를 모르며 `--help` 를 읽어야 하고, 그 도움말은 결국 스키마와 비슷한 양입니다. 이 결정이 얻는 것은 "모델이 이미 아는 것을 쓴다"가 아니라 **"필요한 가지만 읽는다"** 하나입니다.

MCP 가 이기는 자리도 남습니다. 인자 검증이 프로토콜 층에서 끝나고, 클라이언트가 프로세스 수명과 자격 주입을 맡으며, 원격 전송으로 옮겨 OAuth 로 여러 사용자를 받는 길이 사양에 이미 있습니다. 지금은 토큰 하나짜리 단일 사용자라 이 셋이 모두 놀고 있습니다.

**언어**는 Java 와 TypeScript 를 놓고 보았습니다. Java 로 쓰면 백엔드와 도구를 공유하지만 산출물이 jar 이고, 사용자 기계에서 그것을 띄우려면 JVM 이 있어야 합니다. 명령줄 도구를 배포하는 관례는 `npx` 와 `pipx` 이며, 저장소에는 이미 npm 툴체인이 있고 [결정-0003](./0003-shared-api-contract.md)이 만드는 타입도 TypeScript 입니다.

## 결정 (Decision)

**형태와 자격**

- 에이전트가 붙는 자리는 명령줄 도구이며 사용자의 기계에서 돕니다. 원격으로 서비스하지 않습니다.
- 자격은 설정 파일과 환경변수에서 받습니다. 사용자가 [USR-003](<../../spec/user/USR-003(프로필 관리).md>)의 A3 에서 발급한 에이전트 토큰을 `gentask auth login` 으로 저장하거나 `GENTASK_TOKEN` 으로 넘깁니다.
- 설정 파일은 `~/.config/gentask/config.json` 이며 소유자만 읽을 수 있게(`0600`) 만듭니다. 환경변수가 있으면 그것이 파일을 이깁니다.
- **토큰을 인자로 받는 옵션을 두지 않습니다.** 명령줄에 실린 자격은 셸 이력과 프로세스 목록에 남아, 편의 하나를 위해 노출 경로 둘을 엽니다.
- 토큰이 없으면 부르기 전에 멈추고 무엇을 어디서 해야 하는지 알립니다. 없는 채로 보내면 거절만 돌아오고 사용자는 이유를 알 자리가 없습니다.

**출구**

- 사람이 읽는 것을 기본으로 내고 `--json` 이 기계가 읽는 것을 냅니다. 에이전트와 `jq` 가 같은 출구를 씁니다.
- 사람에게 하는 말은 표준오류로, 기계가 읽는 것은 표준출력으로 냅니다. 성공과 실패는 종료 코드가 가릅니다.

**자리와 언어**

- `clients/apps/cli/` 에 두고 TypeScript 로 씁니다. 자기 빌드와 자기 검증 명령을 갖는 세 번째 축입니다([결정-0001](./0001-shared-monorepo.md)).
- 인자 해석은 Node 내장 `util.parseArgs` 를 씁니다. 명령이 여남은이고 옵션이 단순해 의존을 하나 더 들일 값어치가 없습니다.
- API 의 요청과 응답 타입은 [결정-0003](./0003-shared-api-contract.md)이 만드는 생성물을 씁니다. 손으로 다시 적지 않습니다.

**발행**

- npm 에 `gentask` 로 발행하며 사용자는 `npx gentask` 로 부르거나 전역으로 설치합니다. 내려받아 빌드하게 하면 도구 하나를 붙이려고 저장소를 clone 해야 합니다.
- 꾸러미에는 `dist/` 와 README 와 라이선스만 담깁니다. 소스와 시험은 저장소가 갖습니다.
- `prepublishOnly` 가 검증을 돌립니다. 검증을 지나지 않은 것이 밖으로 나가지 않게 하는 자리이며, 배포 스크립트가 서버 산출물에 대해 하는 일과 같은 것을 여기서는 npm 이 합니다.
- 버전은 이 축만의 것입니다. 저장소의 이력은 하나지만 발행되는 물건은 이 디렉터리뿐이므로, [결정-0001](./0001-shared-monorepo.md)이 "축마다 독립된 릴리스 주기를 갖지 못한다"고 적은 감수 항목이 이 축에서만 풀립니다.

**명령의 경계**

- 명령은 작업 API 가 이미 여는 것만 덮습니다. 스스로 판정하거나 저장하는 것은 없으며, 규칙은 모두 서버가 갖습니다.
- 실패는 서버가 낸 것을 그대로 옮깁니다. 다시 시도할지 사용자에게 물을지는 부르는 쪽이 정합니다.
- 이름은 화면이 쓰는 말을 따릅니다. 작업 · 추가 · 편집 · 삭제 · 완료 · 중요 · 나의 하루입니다.

## 결과 (Consequences)

서버에 아무것도 더하지 않고 에이전트가 붙습니다. 인증도 인가도 이미 있는 것을 그대로 쓰며, 작업 API 가 바뀌면 생성된 타입이 그 변화를 컴파일 오류로 드러냅니다. 부르는 쪽이 셸을 가지기만 하면 되므로 특정 클라이언트의 지원 여부에 매이지 않고, 사람과 예약 실행도 같은 것을 씁니다.

감수하는 것이 다섯입니다.

- **모델이 이 명령을 모릅니다.** `git` 이나 `gh` 와 달리 학습 데이터에 없어 도움말을 읽어야 하며, 그 도움말이 곧 계약입니다. 도움말이 부실하면 잘못 부릅니다.
- **인자 검증을 스스로 해야 합니다.** 프로토콜이 스키마로 걸러 주던 것을 명령이 직접 판정하고, 틀린 인자에 무엇이 틀렸는지 말해야 합니다.
- **사용자가 토큰을 손으로 옮깁니다.** 화면에서 발급해 `gentask auth login` 에 붙여넣어야 하며, 다시 발급하면 그 자리도 함께 고쳐야 합니다.
- **토큰에 범위가 없습니다.** 에이전트 토큰은 그 계정의 전권이므로 이 도구에 준 토큰으로 작업 말고 다른 것도 부를 수 있습니다. 결정-0005 가 이미 감수 항목으로 적은 자리이며, 이 결정이 그 토큰을 쓰는 두 번째 소비자를 더합니다.
- **에이전트가 실제로 부르는 경로를 자동 검사가 덮지 못합니다.** 다른 프로세스가 이 명령을 띄우고 출력을 읽는 대목은 우리 검증 밖이며, 명령이 API 를 바르게 부르는지까지만 검사가 닿습니다.

아래 상황에서 이 결정을 다시 판단합니다.

- 쓰는 사람이 우리 밖으로 늘 때. 토큰을 손으로 옮기게 하는 것이 그 시점에 처음으로 비싸지며, 원격 전송과 OAuth 가 그 대가를 갚습니다.
- 토큰에 범위를 두게 될 때. 작업만 부를 수 있는 토큰이 생기면 네 번째 감수 항목이 사라집니다.
- 부르는 쪽이 도움말을 읽지 못해 잘못 부르는 일이 실제로 쌓일 때. 그때는 스키마를 넘겨 주는 프로토콜이 값을 하며, 이 결정이 판 근거가 뒤집힙니다.
