# 결정-0013: 에이전트 연동 인터페이스를 명령줄 도구로 두고 자격 증명을 파일과 환경 변수로 관리한다

- 상태: 승인됨
- 날짜: 2026-08-31

## 맥락 (Context)

로컬 에이전트 연동 요구사항([AGT-001](<../../spec/agent/AGT-001(에이전트로 작업 다루기).md>))이 도출되면서 에이전트 인터페이스가 필요해졌다. 대상 API는 기존 백엔드 REST API를 그대로 활용하며, 핵심 과제는 에이전트 환경에 최적화된 어댑터를 구축하는 것이다.

**Model Context Protocol(MCP) 도입 방안**: 도구 명칭, 설명, JSON Schema를 표준 프로토콜로 자동 제공하여 에이전트의 도구 발견과 인자 검증이 프로토콜 계층에서 완결된다. 그러나 대화 세션 시작 시 모든 도구 스키마가 컨텍스트 윈도우에 일괄 적재되므로, 기능 확장에 따라 컨텍스트 토큰 소비량이 급증하는 트레이드오프가 있다.

실측 결과 8개 도구의 스키마만으로 약 3,166자(1,000 토큰)를 차지했다. 향후 백로그 관리 전반으로 도구를 확장할 경우 스키마 크기가 선형 증가하여 매 턴마다 불필요한 토큰 비용이 발생한다.

**명령줄 도구(CLI) 도입 방안**: `--help`를 통한 계층적 탐색을 지원하므로 에이전트가 당장 필요한 명령의 도움말만 동적으로 조회하여 토큰 효율을 극대화할 수 있다. 또한 셸 환경이 지원되는 모든 에이전트 런타임에서 범용 실행 가능하며 사람과 CI 스크립트에서도 동일하게 활용할 수 있다.

**개발 언어**: 백엔드와 동일한 Java 대신 TypeScript를 채택했다. 사용자 머신에 별도 JRE 설치를 요구하지 않고 Node.js 생태계(`npx`)로 즉시 배포 가능하며, OpenAPI 명세로부터 자동 생성된 TypeScript 타입을 클라이언트와 공유할 수 있기 때문이다([결정-0003](./0003-shared-api-contract.md)).

## 결정 (Decision)

**인터페이스 형태 및 인증**

- 에이전트 인터페이스를 로컬 CLI 도구로 구축하며 사용자의 로컬 환경에서 직접 실행된다.
- 인증 자격 증명은 설정 파일(`~/.config/gentask/config.json`, 파일 권한 `0600`) 또는 `GENTASK_TOKEN` 환경 변수로 주입받는다. 환경 변수 값이 설정 파일 값보다 우선한다.
- 프로세스 목록 및 셸 이력 노출로 인한 보안 취약점을 방지하기 위해 CLI 명령행 옵션으로 토큰을 직접 전달받지 않는다.
- 토큰 미설정 시 네트워크 요청 전에 즉시 실행을 중단하고 설정 안내 메시지를 표준 오류(`stderr`)로 출력한다.

**출력 형식**

- 기본 출력은 가독성 높은 텍스트 형식을 지원하고, `--json` 플래그 지정 시 기계 판독용 정형 JSON을 표준 출력(`stdout`)으로 발행한다.
- 안내 메시지 및 에러는 표준 오류(`stderr`)로 분리 출력한다.

**패키지 위치 및 의존성**

- `clients/apps/cli/`에 배치하고 TypeScript로 작성한다. 독자적인 빌드/검증 명령을 갖는 독립 축으로 구성한다([결정-0001](./0001-shared-monorepo.md)).
- 인자 파싱은 Node.js 표준 라이브러리 `util.parseArgs`를 활용하여 외부 런타임 의존성을 최소화한다.
- API 통신 타입은 OpenAPI 생성 타입을 직접 참조한다.

**배포 방식**

- npm 저장소에 `gentask` 패키지로 배포하여 `npx gentask` 실행을 지원한다.
- `dist/` 산출물과 문서만 패키징하며 `prepublishOnly` 훅으로 빌드 및 테스트 통과를 강제한다.
- 패키지 버전은 CLI 축 독자적으로 관리한다.

**명령의 책임 한계**

- CLI 명령은 백엔드 REST API를 1:1 매핑하는 씬 클라이언트(Thin Client)로 동작하며 독자적인 비즈니스 규칙을 갖지 않는다.
- 에러 발생 시 서버 RFC 9457 응답 메시지를 가공 없이 투명하게 전달한다.

## 결과 (Consequences)

기존 백엔드 API 변경 없이 에이전트 친화적인 명령줄 인터페이스가 제공된다. OpenAPI 타입 동기화를 통해 컴파일 타임 안정성이 보장되며 토큰 소비 효율이 최적화된다.

감수하는 제약 사항은 다음과 같다.

- 모델의 사전 학습 데이터에 포함되지 않은 도구이므로 `--help` 출력 명세에 전적으로 의존한다.
- 입력 인자 유효성 검증을 CLI 코드에서 직접 처리해야 한다.
- 사용자가 초기 1회 API 토큰을 발급받아 CLI 설정에 직접 등록해야 한다.
- 발급된 에이전트 토큰이 계정 전권 권한을 갖는다.
- 외부 에이전트 프로세스가 CLI를 구동하는 상호작용 전체는 종단 자동화 테스트 범위에 포함되지 않는다.

다음 상황 발생 시 본 결정을 재검토한다.

- 외부 일반 사용자 배포가 확장되어 OAuth 기반 원격 인증이 요구될 때.
- API 토큰의 세부 스코프 제어가 도입될 때.
- 에이전트의 CLI 파싱 실패율이 증가하여 스키마 기반 MCP 전환이 유리해질 때.
