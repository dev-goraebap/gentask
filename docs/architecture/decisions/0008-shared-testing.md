# 결정-0008: 테스트의 소유를 나누고 인수 테스트를 인수 조건에 대응시킨다

- 상태: 승인됨
- 날짜: 2026-08-28

## 맥락 (Context)

- 구현 코드와 테스트 코드를 에이전트가 작성하며 작업자는 테스트 코드를 열람하지 않습니다. 검증 코드를 직접 읽지 않는 환경에서는 테스트가 통과하더라도 무엇을 보호하는지 명확히 전달되지 않습니다.
- 에이전트는 구현을 읽고 테스트를 씁니다. 그래서 테스트가 코드가 해야 하는 일이 아니라 코드가 하는 일을 단언하는 동어반복이 되기 쉽고, 결함이 있어도 통과합니다.
- 작성 시점 기준 전체 테스트 250건 중 인수 조건과 연결된 테스트는 64건입니다. 작업자가 직접 명시한 문장과 연결되지 않은 테스트는 명칭만으로 실패 원인을 판별할 수 없습니다.
- 작업자가 매일 화면을 직접 조작하므로 가시적인 결함은 자동화 테스트보다 작업자가 먼저 발견합니다. 서버 계층은 이 수단이 없으며 API 를 직접 호출해야 확인됩니다.
- 테스트 피라미드(Test Pyramid)는 UI 자동화가 느리고 깨지기 쉽던 도구 사정을 전제합니다. 테스트 트로피(Testing Trophy)는 그 비용이 떨어진 뒤의 배분입니다. 둘은 같은 원리에 다른 수치를 넣은 결과이므로, 이 저장소에서 어느 계층이 싼지가 배분을 정합니다.
- **커버리지 수치를 판정 기준으로 삼는 방안**은 도구가 값을 측정하고 빌드가 강제할 수 있습니다. 대가는 그 수치가 무엇을 덮었는지가 아니라 몇 줄을 지났는지를 세는 것입니다. 작업자가 인지하는 대상이 되지 못합니다.
- **모든 테스트를 유지하는 방안**은 기존 검증을 보존합니다. 대가는 인지 범위 밖의 테스트가 계속 늘어나고, 리팩터링에서 깨질 때마다 에이전트가 고치며, 그 수정도 읽히지 않는 것입니다.
- **단위 테스트를 걷고 종단 테스트만 두는 방안**은 검증 위치를 하나로 모읍니다. 대가는 월말을 넘기는 기한 계산이나 정오와 자정의 12시간제 표기 같은 경계를 브라우저에서 재현할 수 없고, 로그인 없는 접근처럼 UI 가 보내지 않는 요청을 만들 수 없는 것입니다.
- **종단 테스트 도구**로 Cypress 와 Selenium 을 함께 검토했습니다. Playwright 는 브라우저를 한 번 띄우고 테스트마다 브라우저 컨텍스트만 새로 만들며, 병렬 실행에 별도 비용이 없고, `route.abort()` 로 실제 네트워크 실패를 만들며, 실패한 실행의 타임라인과 DOM 스냅숏과 네트워크 기록을 파일로 남깁니다. Cypress 는 병렬 실행이 유료 서비스에 묶이고, Selenium 은 WebDriver 왕복 때문에 느립니다.
- **변이 테스트(Mutation Testing)로 무효한 테스트를 기계가 판정하는 방안**은 구현을 일부러 망가뜨려 테스트의 검출 여부를 확인하므로 동어반복 테스트를 사후에 식별하는 수단입니다. 대가는 실행 시간이 크게 늘고, 낮은 점수를 받은 테스트를 고칠지 지울지는 여전히 사람이 정하는 것입니다. 이번 결정에서는 채택하지 않습니다.

## 결정 (Decision)

**소유의 구분**

- 테스트를 소유로 나눕니다. **작업자가 소유하는 것은 둘입니다.** 인수 조건을 지탱하는 인수 테스트와, 백엔드 애플리케이션 계층 및 도메인 계층의 단위 테스트입니다. 작업자는 이것을 읽고 판단합니다.
- **그 밖의 테스트는 에이전트가 소유합니다.** 작업자는 그 내용을 알지 못하며 깨져도 읽지 않습니다. 에이전트가 고치거나 지웁니다.
- 에이전트가 소유한다고 해서 무엇이든 둘 수 있는 것은 아닙니다. 아래 "층과 각 층이 갖는 것"에 열거한 종류에 속해야 합니다.

**판정 기준**

- 테스트명은 관찰 가능한 사실을 기술합니다. 구현의 내부 구조가 아니라 밖에서 확인되는 결과를 적습니다.
- 작업자의 화면 조작으로 결함을 식별할 수 있는 UI 요소는 자동화 테스트를 작성하지 않고 작업자의 직접 확인으로 대체합니다. 작업자의 확인 범위와 테스트 검증 범위가 중복되면 자동화 테스트를 두지 않습니다.

**층과 각 층이 갖는 것**

- 인수 테스트는 Playwright 기반의 종단 테스트(End-to-End Test)로 구현하며, 브라우저부터 실제 서버와 데이터베이스까지 전체 실행 경로를 검증합니다.
- 종단 테스트는 워커마다 계정을 하나 만들고 그 세션을 재사용합니다. 워커 사이에 데이터가 섞이지 않으므로 목록 전체를 단언해도 병렬 실행이 안전하며, 각 테스트가 로그인 화면을 지나지 않습니다.
- 준비 데이터는 화면 조작이 아니라 API 호출로 만듭니다. 검증하려는 경로만 화면으로 지납니다.
- 백엔드 통합 테스트는 HTTP 엔드포인트부터 실제 데이터베이스까지 검증하며, 종단 테스트가 지나지 못하는 경로를 담당합니다. 대상은 권한 경계, Bearer 토큰 인증, 비정상 클라이언트 요청, 상태 코드 및 실패 응답 본문, 마이그레이션 스크립트 실행입니다.
- 백엔드 단위 테스트는 애플리케이션 계층과 도메인 계층에만 작성합니다.
- 프론트엔드 단위 테스트는 순수 계산의 경계값, 시간 정책, 세션을 넘어 복원되는 상태, 접근성 속성, HTTP 요청 형태의 다섯 범주로 한정합니다.
- 프론트엔드 화면 테스트는 종단 테스트가 지나지 못하거나 실행 비용이 과도한 항목으로 한정합니다. 입력기(IME) 조합 상태, 내부 서비스 상태, 데이터 조회가 끝나기 전의 과도기 상태, 요청이 나가지 **않는다**는 사실, 그리고 브라우저에서 조작 횟수가 많은 시각 선택기의 축 조작이 이에 해당합니다.
- 반응형 분기는 자동화 테스트로 검증하지 않습니다. 테스트는 분기 발생 여부만 확인할 뿐 결과의 유효성을 판별하지 못하므로, 작업자가 화면 조작으로 검증합니다.
- 디자인 토큰의 명도 대비비는 자동화 테스트로 실측 검증합니다. 라이트·다크 모드와 색상 조합 수가 수동 확인 범위를 초과하기 때문입니다.

**중복의 처리**

- 동일한 사실을 복수 계층이 검증하는 경우 하위 계층 테스트를 제거합니다.
- 상위 계층 테스트가 해당 사실의 일부만 단언하는 경우에는 하위 계층 테스트를 유지합니다. 테스트명의 동일 여부가 아니라 단언(assertion) 대상을 기준으로 중복 여부를 판정합니다.
- **삭제의 단위는 개별 테스트입니다.** 추적 키를 가진 그룹 블록을 통째로 지우면 그 안의 대체 불가능한 테스트까지 사라지므로, 그룹은 키만 떼고 남깁니다.

**추적**

- 추적 키의 형식과 부여 규약은 [결정-0007](./0007-shared-software-process.md)을 따릅니다.
- **화면 폭에 따른 배치 분기는 인수 조건으로 적지 않습니다.** 넓은 화면과 좁은 화면이 무엇을 어느 자리에 두는가는 사용자의 목표가 아니라 그 목표를 이루는 수단이며, 반응형 분기를 자동화 검증에서 제외한 이상 지정할 검증 계층도 없어 Story 가 닫히지 못합니다. 배치의 의도는 Story 의 메모나 화면 설계에 남깁니다. 화면 폭과 무관하게 고정된 자리는 브라우저에서 도달하므로 인수 조건이 됩니다.
- **인수 조건마다 검증 계층을 하나만 지정합니다.** 브라우저에서 도달할 수 있으면 종단 테스트가, 도달할 수 없으면 백엔드 통합 테스트가 갖습니다. 두 계층이 같은 인수 조건을 함께 지탱하면 인수 테스트가 둘이 되어 대응이 깨집니다.
- 브라우저에서 도달할 수 없는 인수 조건은 문장 앞에 `[서버]` 를 답니다. 이 표기는 이 저장소의 것이며, 검증 방법을 묻는 ISO/IEC/IEEE 29148 의 속성과 달리 검증 계층을 가리킵니다.
- 검증 계층을 잃은 통합 테스트는 접두어를 떼고 API 계약 테스트로 남기거나, 종단 테스트가 같은 사실을 단언하면 지웁니다.
- 추적 검사기는 각 인수 조건별 검증 계층을 함께 보고하며 `[서버]` 표기가 있으면 종단 테스트를 면제합니다.
- Story 는 `[서버]` 가 아닌 인수 조건을 종단 테스트가 모두 검증했을 때 닫습니다. `[서버]` 인수 조건은 백엔드 통합 테스트가 검증하면 충족된 것으로 봅니다. 이는 결정-0007 의 "실제 백엔드 연결로 확인했을 때 닫는다"는 규칙을 구체화한 규격입니다.

**불안정성**

- 종단 테스트의 재시도(retry) 횟수는 0으로 설정합니다. 재시도로 통과시키는 방식은 무효화된 테스트를 은폐합니다.
- 간헐적으로 실패하는 종단 테스트는 원인을 수정하거나 제거하며, 대기 시간을 추가하여 통과시키지 않습니다.
- 실패한 종단 테스트는 실행의 타임라인과 각 단계의 DOM 스냅숏과 네트워크 기록을 파일로 남깁니다. 작업자는 테스트 코드가 아니라 이 기록을 읽습니다. **이 결정이 테스트 코드를 읽지 않는다는 전제 위에 서므로, 실패를 되감아 볼 수단이 없으면 성립하지 않습니다.**

## 결과 (Consequences)

인수 조건마다 인수 테스트가 하나씩 대응하므로 추적 검사기의 보고가 요구사항의 검증 상태와 일치합니다. Story 완료 여부를 기계적으로 판정할 수 있습니다.

인수 조건과 연결되지 않은 테스트는 그대로 남습니다. 경계 계산, 대비비, 시간 정책, HTTP 요청 형태, 계층 규칙이 그것이며 사용자의 목표가 아니므로 인수 조건이 될 수 없습니다. 이 테스트들이 정당한 근거는 위에 열거한 종류에 속한다는 것뿐이고, **그 판정은 기계가 하지 못하며 작업자도 하지 않습니다.** 에이전트가 소유하는 테스트이기 때문입니다.

감수하는 것이 일곱입니다.

- 실패 지점의 지목을 잃습니다. 하위 계층 테스트를 제거함에 따라 실패가 상위 계층에서만 발생하며, 어느 계층이 깨졌는지는 실행 추적을 읽어야 확인됩니다.
- 조합 폭발에 대한 방어가 약해집니다. 통합 테스트로는 아래 계층의 분기 조합을 다 덮을 수 없는데, 통합 테스트가 많으면 덮였다고 오인하게 됩니다.
- 예외 경로의 확인이 종단 테스트에만 남습니다. 종단 테스트가 없는 인수 조건의 예외 경로는 작업자가 브라우저에서 확인해야 하며, 변경할 때마다 반복되지 않습니다.
- 갱신 시각(`updatedAt`)의 검증이 대표 하나로 줄었습니다. 인수 조건에 없는 사실이므로 본 결정의 기준으로는 제외 대상이나, 서버가 그 값을 내보내므로 어긋나도 드러나지 않습니다.
- 반응형 분기의 회귀를 기계가 잡지 못합니다. 작업자가 좁은 화면을 열지 않는 기간만큼 결함 발견이 지연됩니다. 요구사항 문서도 그 분기를 붙들지 않으므로 배치가 바뀌거나 사라져도 어긋남이 드러나는 자리가 없습니다.
- 종단 테스트가 검증 시간을 늘립니다. 애플리케이션 기동과 브라우저 실행이 추가됩니다.
- 에이전트가 소유하는 테스트가 변경 저항이 될 수 있습니다. 리팩터링에서 깨질 때마다 에이전트가 고치고 그 수정은 읽히지 않으므로, 테스트가 안전망이 아니라 마찰로 바뀌어도 드러나지 않습니다.

다음 상황에서 이 결정을 다시 판단합니다.

- 두 번째 작업자가 참여할 때 이 결정을 다시 판단합니다. 화면을 조작하는 것이 회귀 검출 수단이라는 전제가 그 사람에게는 성립하지 않습니다. 이 결정의 판정 기준 전체가 작업자가 매일 제품을 쓴다는 사실에 기대고 있습니다.
- 종단 테스트가 간헐적으로 실패하기 시작할 때 다시 판단합니다. 재시도를 금지했으므로 검증이 통과하지 않는 상태가 지속됩니다.
- 지속적 통합을 도입할 때 다시 판단합니다. 지금 검증은 작업자의 기기에서만 돌며, 재시도를 금지한 대가는 종단 테스트가 불안정한 환경에서 처음으로 비싸집니다.
- 변이 테스트를 도입할 때 다시 판단합니다. 무효한 테스트를 기계가 판정하게 되면 인지 범위로 한정하는 근거가 약해집니다.
