# 결정-0006: arc42 를 채택하고 참조 아키텍처를 저장소 루트 한 트리에 배치한다

- 상태: 승인됨
- 날짜: 2026-08-28

## 맥락 (Context)

이 저장소는 제품을 개발하는 동시에 후속 프로젝트로 이식할 참조 아키텍처를 축적한다. 문서의 배치 위치와 목차 구조를 결정해야 한다.

**축마다 각 패키지 내부에 문서를 배치하는 방안**은 문서가 해당 규칙을 적용하는 코드 디렉터리에 위치한다. 프론트엔드 규칙은 `clients/apps/web/` 하위, 백엔드 규칙은 `server/` 하위에 두면 축 하나만 다른 저장소로 옮길 때 문서가 함께 이동한다. 그러나 두 축에 걸치는 공통 규약의 소속을 정하기 어렵다. API 계약, 실패 응답, 인증 명세를 어느 한쪽에 두면 반대쪽이 이를 교차 참조해야 하고, 양쪽에 두면 동일한 계약이 분산되어 동기화가 깨진다.

**루트 단일 문서 트리에 통합하는 방안**은 공통 규약의 분산 문제가 발생하지 않는다. 트레이드오프로 아키텍처 이식 단위가 축 단위에서 저장소 단위로 변경된다. 프론트엔드만 타 저장소로 분리 이식할 경우 필요한 문서를 선별 복사해야 한다.

**목차 구조**: 자체 정의와 국제 표준 템플릿 중 하나이다. 자체 정의 방식은 현재 필요한 절만 유연하게 구성할 수 있으나 신규 문서 추가 시 분류 기준을 매번 판단해야 한다. [arc42](https://arc42.org/) 템플릿은 소프트웨어 아키텍처의 12개 핵심 뷰와 구조를 명문화하고 있으므로 문서 배치 기준이 템플릿 표준으로 정형화된다. 트레이드오프로 당장 내용이 없는 절도 목차 골격에 남는다.

## 결정 (Decision)

**축 분리**: 저장소의 문서를 요구사항 축과 참조 아키텍처 축으로 분리한다. 요구사항 축은 프로젝트마다 달라지고, 참조 아키텍처 축은 프로젝트 간에 이식된다.

```text
docs/spec/           요구사항 축 — 유스케이스 서술서
docs/prd.md          요구사항 축 — 제품 요구사항
docs/architecture/   참조 아키텍처 축
```

**목차**: 참조 아키텍처는 arc42의 12개 절 구조를 따르며, 각 절이 독립 마크다운 파일로 구성되고 `index.md`는 목차 진입점 역할만 수행한다.

**하위 문서**: 세부 관심사는 해당 절의 하위 디렉터리에 배치하고 파일명 접두사로 축을 식별한다.

- 횡단 관심사는 `concepts/<축>-<순번>-<주제>.md`로 명명하며 축은 `frontend`, `backend`, `shared` 중 하나이다.
- 아키텍처 결정 기록(ADR)은 `decisions/NNNN-<축>-<슬러그>.md`로 명명하며 순번은 축과 무관한 단일 수열로 채번한다.

**백로그**: 저장소 내부에 파일로 두지 않는다. 원본은 트래커 운영 환경에 위치하며 `gentask issue` CLI와 웹 인터페이스로 일원화하여 관리한다([결정-0007](./0007-shared-software-process.md)).

**참조 방향**: 하위 개념 문서는 상위 arc42 개요 문서를 역참조하지 않는다. 하위 문서 간의 참조는 허용하되 순환 참조를 배제하고 단방향으로 유지한다.

**공통 관심사**: 두 축에 걸치는 주제는 접두사를 `shared`로 부여한다. 단일 축에서 시작된 관심사가 맞은편 축의 변경을 요구하는 공통 규약으로 확장될 경우 접두사를 `shared`로 변경한다.

## 결과 (Consequences)

두 축에 걸치는 공통 규약이 단일 문서 트리에 통합된다. API 계약, 에러 응답, 인증 메커니즘이 각각 단일 원본 문서를 가지므로 문서 불일치가 원천 방지된다.

감수하는 제약 사항은 다음과 같다.

- 아키텍처 이식 단위가 축 단위에서 저장소 단위로 확장된다.
- 규칙 문서가 실제 소스 코드 디렉터리와 물리적으로 분리된다.
- 현재 내용이 없는 arc42 절도 표준 골격 유지를 위해 목차에 빈 상태로 유지된다.
- 문서의 축 분류(`frontend`, `backend`, `shared`)를 작업자의 판단에 의존한다.

다음 상황 발생 시 본 결정을 재검토한다.

- 특정 축을 독립 저장소로 영구 분리할 때.
- arc42 표준 12개 절 구조가 시스템의 아키텍처 표현에 명확한 한계를 보일 때.
