# 결정-0006: arc42 를 채택하고 참조 아키텍처를 저장소 루트 한 트리에 배치한다

- 상태: 승인됨
- 날짜: 2026-08-28

## 맥락 (Context)

이 저장소는 제품을 개발하는 동시에 후속 프로젝트로 이식할 참조 아키텍처를 축적합니다. 문서의 배치 위치와 목차 구조를 결정해야 합니다.

**축마다 자기 패키지 안에 두는 방안**은 문서가 해당 문서를 적용하는 코드 디렉터리에 위치합니다. 프론트엔드 규칙은 `clients/apps/web/` 하위, 백엔드 규칙은 `server/` 하위에 두면 축 하나만 다른 저장소로 옮길 때 문서가 함께 따라갑니다. 그러나 두 축에 걸치는 규약은 소속을 정할 수 없습니다. API 계약과 실패 응답과 인증은 어느 한쪽에 두면 반대쪽이 그것을 참조하게 되고, 양쪽에 두면 같은 계약을 두 축이 각자 서술하다 어긋납니다.

**루트 한 트리에 모으는 방안**은 두 축에 걸치는 규약의 소속 문제가 발생하지 않습니다. 대가는 이식 단위가 축에서 저장소로 바뀌는 것입니다. 프론트엔드만 다른 저장소로 옮기면 문서는 따라가지 않으며, 필요한 문서를 골라 복사해야 합니다.

**목차 구조**는 자체 정의와 표준 템플릿 중 하나입니다. 자체 정의는 이 프로젝트에 필요한 절만 구성할 수 있으나, 절을 추가할 때마다 소속 위치를 매번 판단해야 합니다. [arc42](https://arc42.org/) 는 아키텍처 문서의 12개 절과 각 절이 담을 내용을 규정하므로, 새 문서가 생겼을 때 배치 판단이 템플릿의 규정으로 대체됩니다. 대가는 이 프로젝트에 해당하지 않는 절도 목차에 남는다는 것입니다.

## 결정 (Decision)

**축 분리**: 저장소의 문서를 요구사항 축과 참조 아키텍처 축으로 분리합니다. 요구사항 축은 프로젝트마다 달라지고, 참조 아키텍처 축은 프로젝트 사이에서 이식됩니다.

```text
docs/spec/           요구사항 축 — 유스케이스 서술서
docs/prd.md          요구사항 축 — 제품 요구사항
backlog/tasks/       요구사항 축 — Epic · Story · Task
docs/architecture/   참조 아키텍처 축
```

**목차**: 참조 아키텍처는 arc42 의 12개 절 구조를 따르며, 각 절이 파일 하나를 구성하고 `index.md` 는 목차만 갖습니다.

**하위 문서**: 절이 하위 문서를 갖는 경우 해당 절의 하위 디렉터리에 배치하고 파일명으로 소속을 표시합니다.

- 횡단 관심사는 `concepts/<축>-<순번>-<주제>.md` 이며 축은 `frontend` · `backend` · `shared` 입니다.
- 결정 기록은 `decisions/NNNN-<축>-<슬러그>.md` 이며 순번은 축과 무관한 단일 수열입니다.

**백로그**: `backlog/` 아래의 구조는 [Backlog.md](https://github.com/MrLesk/Backlog.md) 가 정의하며 이 결정이 규정하지 않습니다. 항목은 유형과 무관하게 `tasks/` 하나에 들어가고 `type` 필드가 Epic · Story · Task 를 가릅니다. 오래 닫힌 항목은 `completed/` 로 옮겨지며 지워지지 않습니다.

**참조 방향**: 하위 문서는 상위 문서를 참조하지 않습니다. 하위 문서 사이의 참조는 허용하되 단방향으로 유지합니다.

**두 축에 걸치는 주제**: 접두사를 `shared` 로 두고 디렉터리를 이동하지 않습니다. 한쪽 축에서 시작한 주제가 반대쪽 축의 규칙을 함께 변경해야 성립하면 그 시점에 접두사를 변경합니다.

## 결과 (Consequences)

두 축에 걸치는 규약이 단일 위치에 통합됩니다. API 계약과 실패 응답과 인증이 각각 문서 하나를 가지므로, 서버와 클라이언트가 같은 계약을 각자 서술하다 어긋나는 경우가 발생하지 않습니다.

감수하는 것이 넷입니다.

- 이식 단위가 축에서 저장소로 바뀝니다. 프론트엔드만 다른 저장소로 옮기면 문서는 따라가지 않으며, 필요한 문서를 골라 복사해야 합니다.
- 문서가 적용 대상 코드에서 멀어집니다. 코드를 수정하는 작업자가 같은 디렉터리에서 규칙을 발견할 수 없고 문서 트리를 별도로 열어야 합니다.
- 이 프로젝트에 해당하지 않는 절도 목차에 남습니다. arc42 의 12개 절을 모두 유지하므로 내용이 없는 절이 "작성 전" 상태로 표시됩니다.
- 축 접두사의 판정을 사람이 수행합니다. 어떤 주제가 `shared` 인지 한쪽 축인지를 기계가 판정할 수 없으므로, 잘못 분류된 문서는 검토에서만 드러납니다.

아래 상황에서 이 결정을 다시 판단합니다.

- 축 하나를 다른 저장소로 분리할 때. 문서를 어느 범위까지 복사할 것인지 그 시점에 결정합니다.
- arc42 의 절 구조가 이 저장소의 문서를 담지 못할 때. 절을 추가하거나 템플릿 이탈을 기록합니다.
