# 결정-0012: 비밀번호에 구성 규칙을 걸고 이메일 소유를 일회용 코드로 확인한다

- 상태: 승인됨
- 날짜: 2026-08-30

## 맥락 (Context)

기존에는 비밀번호에 대해 길이 제약(8자 이상 72자 이하, bcrypt 알고리즘의 최대 바이트 수 제한 기반)만 검증했다. 이메일 주소 역시 정규식 형식 검증만 수행하고 실제 수신 가능 여부를 검증하지 않아 타인의 이메일로 계정을 생성할 수 있는 결함이 있었으며 비밀번호 재설정([USR-005](<../../spec/user/USR-005(비밀번호 재설정).md>)) 흐름을 성립시킬 수 없었다.

**비밀번호 복잡도 규칙 적용에 대한 고려**: NIST SP 800-63B는 특정 문자 조합 요구가 사용자로 하여금 예측 가능한 패턴(`Password1!`)을 유도하여 실제 엔트로피를 향상시키지 못하므로 복잡도 규칙 대신 충분한 길이 확보와 유출 비밀번호 사전 대조를 권고한다. 그러나 현재 시스템은 외부 유출 비밀번호 데이터베이스 연동 인프라가 부재하므로 최소한의 구성 규칙을 적용하기로 결정했다.

**인증 수단**: 매직 링크 방식은 메일 클라이언트 및 보안 게이트웨이의 사전 URL 프리페치(Prefetch) 동작으로 인해 사용자 클릭 전에 토큰이 조기 만료되는 결함이 발생할 수 있다. 반면 숫자 6자리 일회용 인증 코드는 사용자가 직접 입력해야 하므로 사전 소비 문제가 없으며 가입과 재설정 절차에 일관되게 적용할 수 있다.

**저장 구조**: 가입과 재설정을 별도 테이블로 분리하지 않고 단일 `verification_codes` 테이블로 통합한다. 가입 시 임시 비밀번호 해시를 보관한다는 점을 제외하면 코드 발급, 해시 검증, 시도 횟수 제한, 만료 처리가 동일하기 때문이다([결정-0005](./0005-shared-authentication.md)의 중복 방지 원칙).

## 결정 (Decision)

**비밀번호 복잡도 규칙**

- 8자 이상 72자 이하 길이를 요구하며 영문자, 숫자, 특수문자를 각각 최소 1자 이상 포함해야 한다.
- 대문자와 소문자를 구분하여 강제하지 않는다.
- 공백 문자를 허용하며 전후 트리밍(trim)을 수행하지 않는다.
- 본 규칙은 회원가입([USR-001](<../../spec/user/USR-001(계정 회원가입).md>)), 비밀번호 재설정([USR-005](<../../spec/user/USR-005(비밀번호 재설정).md>)), 비밀번호 변경([USR-006](<../../spec/user/USR-006(비밀번호 변경).md>))에 동일하게 적용된다.
- 서버가 최종 검증을 강제하며 클라이언트 폼도 동일한 유효성 검사를 수행한다.
- 검증 실패 시 충족되지 않은 세부 조건을 명확히 피드백한다.

**일회용 인증 코드 정책**

- 암호학적으로 안전한 난수로 생성된 6자리 숫자를 사용한다.
- 유효 시간은 발급 시점으로부터 10분이다.
- 최대 검증 시도 횟수는 5회로 제한하며, 초과 시 해당 코드를 즉시 폐기한다.
- 코드 재요청 시 기존 코드는 무효화 처리하고 신규 코드를 발급한다.
- 토큰 원문은 저장하지 않고 HMAC 해시 값으로 보관하며 해시 생성 시 용도(Scope)를 결합한다.
- 인증이 완료된 코드는 즉시 만료 처리한다.

**저장 구조**

- 단일 테이블(`verification_codes`)에서 관리하며 `purpose` 컬럼으로 용도(`SIGNUP`, `PASSWORD_RESET`)를 구분한다.
- 가입 대기 중인 사용자의 비밀번호 해시는 해당 행에 임시 보관하며 계정 생성 완료 시 엔티티로 이전된다.
- `(email, purpose)` 복합 유니크 제약 조건을 적용하여 재발급 시 기존 행을 갱신(Upsert)한다.
- 만료 레코드 정리는 주기적 백그라운드 배치 작업으로 처리한다.

## 결과 (Consequences)

이메일 실소유권이 검증된 계정만 생성된다.

인증 코드를 다루는 처리 흐름이 단일 메커니즘으로 표준화된다.

감수하는 제약 사항은 다음과 같다.

- 복잡도 규칙이 실제 엔트로피 향상에 미치는 영향이 제한적일 수 있다.
- 비밀번호 유효성 검사 규칙이 프론트엔드와 백엔드에 각각 중복 정의된다.
- 6자리 숫자 코드는 100만 개의 공간을 가지므로 무차별 대입 공격을 완벽히 차단하기 위해 IP/계정별 발급 요청 횟수 제한(Rate Limiting)이 요구된다.
- 가입 전 임시 비밀번호 해시가 `verification_codes` 테이블에 일시 보관된다.

다음 상황 발생 시 본 결정을 재검토한다.

- HIBP(Have I Been Pwned) 등 유출 비밀번호 대조 API 연동이 가능해질 때: 복잡도 규칙을 폐기하고 사전 대조로 전환.
- 발급 요청 Rate Limiting을 고도화할 때.
- 다중 요소 인증(MFA)을 도입할 때.
