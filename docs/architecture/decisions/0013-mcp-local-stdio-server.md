# 결정-0013: MCP 서버를 로컬 stdio 로 두고 자격을 환경에서 받는다

- 상태: 승인됨
- 날짜: 2026-08-30

## 맥락 (Context)

[AGT-001](<../../spec/agent/AGT-001(에이전트로 작업 다루기).md>)이 로컬 에이전트를 액터로 올리면서 그 도구가 붙을 자리가 필요해졌습니다. 다루는 것은 이미 있는 작업 API 이며 서버에 더할 기능은 없습니다 — 필요한 것은 그 API 를 에이전트가 알아듣는 모양으로 옮기는 껍데기입니다.

**MCP 는 전송을 둘로 나눕니다.** stdio 는 클라이언트가 서버를 자식 프로세스로 띄우고 표준입출력으로 말하는 방식이고, HTTP 는 원격에 떠 있는 서버에 붙는 방식입니다. 인가 사양은 이 둘을 다르게 다룹니다 — HTTP 전송은 OAuth 2.1 을 따르는 것을 권하고, **stdio 전송은 그 사양을 따르지 말고 환경에서 자격을 가져오라고 적습니다**(SHOULD NOT / retrieve credentials from the environment).

**원격 HTTP 로 두고 OAuth 를 붙이는 길**은 사용자가 토큰을 손으로 옮기지 않아도 됩니다. 클라이언트가 브라우저를 열고 승인만 받으면 토큰이 내려옵니다. 대가는 인가 서버 한 벌입니다 — 보호 자원 메타데이터(RFC 9728, 필수), 인가 서버 메타데이터(RFC 8414 또는 OIDC Discovery), 승인 화면, PKCE 토큰 교환, 자원 지시자(RFC 8707), 발급자 검증(RFC 9207), 클라이언트 등록. 지금 저장소는 쿠키 세션과 API 토큰만 갖고 있어([결정-0005](./0005-shared-authentication.md)) 이 전부가 새로 서는 자리이며, 작업자가 한 명이고 쓰는 사람도 한 명인 지금 그 일이 사는 것은 편의 하나입니다.

**언어**는 Java 와 TypeScript 를 놓고 보았습니다. Java 로 쓰면 백엔드와 도구를 공유하지만 산출물이 jar 이고, 사용자 기계에서 그것을 띄우려면 JVM 이 있어야 합니다. MCP 클라이언트들이 서버를 띄우는 관례는 `npx` 와 `python -m` 이며, 저장소에는 이미 npm 툴체인이 있고 [결정-0003](./0003-shared-api-contract.md)이 만드는 타입도 TypeScript 입니다.

## 결정 (Decision)

**전송과 자격**

- MCP 서버는 stdio 전송으로 서며 사용자의 기계에서 돕니다. 원격 HTTP 로 서비스하지 않습니다.
- 자격은 환경변수로 받습니다. 사용자가 [USR-003](<../../spec/user/USR-003(프로필 관리).md>)의 A3 에서 발급한 에이전트 토큰을 그 도구의 MCP 설정에 둡니다.
- 서버는 그 토큰을 `Authorization: Bearer` 로 실어 API 를 부릅니다. 토큰을 파일에 쓰거나 어딘가에 보관하지 않습니다 — 프로세스가 사는 동안 환경변수로만 있습니다.
- 토큰이 없으면 붙기 전에 멈추고 무엇을 해야 하는지 알립니다. 없는 채로 보내면 거절만 돌아오고 사용자는 이유를 알 자리가 없습니다.

**자리와 언어**

- `mcp/` 에 두고 TypeScript 로 씁니다. 자기 빌드와 자기 검증 명령을 갖는 세 번째 축입니다([결정-0001](./0001-shared-monorepo.md)).
- API 의 요청과 응답 타입은 [결정-0003](./0003-shared-api-contract.md)이 만드는 생성물을 씁니다. 손으로 다시 적지 않습니다.

**도구의 경계**

- 도구는 작업 API 가 이미 여는 것만 덮습니다. MCP 서버가 스스로 판정하거나 저장하는 것은 없으며, 규칙은 모두 서버가 갖습니다.
- 실패는 서버가 낸 것을 그대로 옮깁니다. 에이전트가 다시 시도할지 사용자에게 물을지는 그 도구가 정합니다.

## 결과 (Consequences)

서버에 아무것도 더하지 않고 에이전트가 붙습니다. 인증도 인가도 이미 있는 것을 그대로 쓰며, 작업 API 가 바뀌면 생성된 타입이 그 변화를 컴파일 오류로 드러냅니다.

감수하는 것이 넷입니다.

- **사용자가 토큰을 손으로 옮깁니다.** 화면에서 발급해 설정 파일에 붙여넣어야 하며, 다시 발급하면 그 자리도 함께 고쳐야 합니다.
- **토큰에 범위가 없습니다.** 에이전트 토큰은 그 계정의 전권이므로 MCP 서버에 준 토큰으로 작업 말고 다른 것도 부를 수 있습니다. 결정-0005 가 이미 감수 항목으로 적은 자리이며, 이 결정이 그 토큰을 쓰는 두 번째 소비자를 더합니다.
- **실제로 에이전트가 붙는 경로를 자동 검사가 덮지 못합니다.** MCP 클라이언트가 프로세스를 띄우고 표준입출력으로 말하는 대목은 우리 검증 밖이며, 도구가 API 를 바르게 부르는지까지만 검사가 닿습니다.
- 축이 하나 늘어 검증과 배포 절차에 한 줄씩 붙습니다.

아래 상황에서 이 결정을 다시 판단합니다.

- 쓰는 사람이 우리 밖으로 늘 때. 토큰을 손으로 옮기게 하는 것이 그 시점에 처음으로 비싸지며, 원격 HTTP 와 OAuth 가 그 대가를 갚습니다.
- 토큰에 범위를 두게 될 때. 작업만 부를 수 있는 토큰이 생기면 이 결정의 두 번째 감수 항목이 사라집니다.
- MCP 사양의 인가가 stdio 전송을 다루기 시작할 때.
