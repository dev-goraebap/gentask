# 결정-0001: 제품을 이루는 축들을 한 저장소에 둔다

- 상태: 승인됨
- 날짜: 2026-08-17

## 맥락 (Context)

이 시스템은 화면과 API 를 모두 필요로 합니다. 두 축은 언어도 빌드 도구도 산출물도 겹치지 않습니다. 프론트엔드는 TypeScript 와 npm 으로 정적 파일을 만들고, 백엔드는 Java 와 Gradle 로 실행 가능한 아카이브를 만듭니다. 배포 대상과 시점도 다릅니다.

뒤에 세 번째 축이 붙었습니다. [AGT-001](<../../spec/agent/AGT-001(에이전트로 작업 다루기).md>)이 요구하는 MCP 서버이며, 사용자의 기계에서 도는 프로그램이라 배포 대상이 우리 서버가 아닙니다. 앞의 둘과 언어도 산출물도 배포처도 다르지만 API 를 소비한다는 점에서 프론트엔드와 같은 자리에 섭니다.

**저장소를 축마다 나누는 길**에서는 각 축이 독립된 버전과 릴리스 주기를 갖고, 권한과 CI 도 독립적으로 운영됩니다. 축별 담당자가 나뉜 조직에서는 이 구조가 자연스럽습니다.

그러나 이 프로젝트는 한 사람이 개발합니다. 독립 릴리스, 권한 분리, 작업 격리와 같은 분리의 이점은 여러 작업자가 동시에 다른 축을 다룰 때 발생하는 문제를 해결하기 위한 것이며, 현재 환경에서는 해당 문제가 존재하지 않습니다.

반면 저장소를 분리하면 즉시 발생하는 비용이 있습니다. 축들의 유일한 연결점은 OpenAPI 명세에서 생성하는 타입인데, 저장소가 나뉘면 API 변경 작업 하나가 여러 저장소의 변경으로 분할됩니다. 명세를 먼저 반영하고 생성 타입을 나중에 갱신하는 순서를 작업자가 관리해야 하며, 그사이의 불일치는 어느 쪽 CI 도 검증하지 못합니다. 단일 저장소에서는 같은 변경이 한 커밋의 diff 에 담겨 즉시 대조 검증됩니다.

또한 이 저장소는 참조 아키텍처 축적을 목적으로 합니다. 상당수 규칙이 여러 축에 걸치거나 상호 비교되므로, 저장소가 분리되면 공통 문서의 배치 위치를 매번 판단해야 합니다.

## 결정 (Decision)

한 저장소에 `server/` 와 `clients/` 를 나란히 두고, 축에 걸치는 문서와 백로그는 루트에 둡니다. `clients/` 는 npm 워크스페이스이며 `apps/` 가 축을 담고 `packages/` 가 축들이 나눠 쓰는 것을 담습니다. 빌드와 검증은 축마다 각자의 도구가 수행하며 저장소 차원의 통합 빌드를 두지 않습니다. 워크스페이스가 합치는 것은 의존성과 잠금 파일이지 빌드가 아닙니다.

**축이 되는 기준은 산출물입니다.** 자기 빌드와 자기 검증 명령을 갖고 따로 배포되는 것이 축입니다. 그 셋을 갖지 않는 것은 축이 아니라 어느 축의 일부입니다.

## 결과 (Consequences)

API 계약을 바꾸는 변경이 한 커밋에 담깁니다. 명세와 그것을 소비하는 축들이 같은 diff 에 있어 어긋난 채로 병합되지 않습니다. 소비자가 둘이 된 뒤 이 이점이 커졌습니다 — 계약 하나를 고치면 화면과 에이전트 도구가 같은 커밋에서 함께 드러납니다. 참조 아키텍처는 축들을 한자리에서 서술하고 비교할 수 있으며, 어느 규칙이 한쪽에만 해당하는지도 같은 트리 안에서 드러납니다.

감수하는 것이 셋입니다.

- 축마다 독립된 릴리스 주기와 버전 태그를 갖지 못합니다. 배포는 산출물을 각각 전달하는 것으로 분리되어 있으나 저장소의 이력은 하나입니다.
- 한 축만 바뀌어도 저장소 전체를 내려받습니다. 신규 참여자의 첫 체크아웃과 CI 캐시가 그만큼 커집니다.
- **이식 단위가 축 단위에서 저장소 단위로 바뀝니다.** 프론트엔드 규칙만 다른 프로젝트로 옮기려 해도 문서가 루트 트리에 있어 함께 따라오지 않습니다.

아래 상황에서 이 결정을 다시 판단합니다.

- 개발자가 둘 이상이 되어 축별로 작업이 갈리기 시작할 때.
- MCP 서버를 남이 갖다 쓸 수 있게 패키지로 발행하게 될 때. 그때는 그 축만 따로 버전과 릴리스 주기를 갖게 되므로 분리의 이점이 처음으로 실재합니다.
- 한 축을 다른 프로젝트에서 독립적으로 재사용하려는 요구가 실제로 생길 때.

그때 저장소를 나누는 비용은 이력을 분리하는 작업이므로 지금 나누는 비용보다 크지만 일회성으로 끝납니다.
