# 결정-0006: 에이전트 자산은 개방 표준 위치(.agents/skills)를 정본으로 한다

- 상태: 승인됨
- 날짜: 2026-07-24

## 맥락

검토 페르소나 4종을 `.claude/agents/`(Claude 전용)에 두는 PR #10이 반려되었다.
반려 사유: 키트는 Claude 외 에이전트(Codex, Antigravity, Gemini 등)에서도 동작해야 하며,
에이전트별 폴더에 동일 내용을 복붙하는 관리비용과 이를 개선하는 스크립트 비용을 비교해
더 나은 방식을 찾아야 한다.

당시 전제(2026-07 리서치): Agent Skills(SKILL.md)는 20여 개 에이전트가 지원하는 개방
표준이고, `.agents/skills/`가 universal layout으로 수렴해 Codex·Gemini·Cursor 등이 직접
읽는다. Claude Code만 `.claude/skills/`를 읽으며, skills.sh CLI도 "정본은 `~/.agents/skills`,
필요한 에이전트에만 심링크/복사"로 동작한다. 서브에이전트 정의 파일은 여전히 벤더별로 다르다.

## 검토한 대안

- **에이전트별 복붙**: 페르소나 4 × 에이전트 N = 사본 4N개. 즉시 썩는다
- **원본 + 전체 변환 스크립트**: 우리만의 원본 포맷에서 벤더별 전체 파일 생성. 벤더 포맷 변경마다 변환 로직 수선, 제3의 포맷 추가
- **스킬 정본 + Claude 서브에이전트 래퍼 생성**: 격리는 유지되나 Claude에게만 래퍼를 제공하는 비대칭 발생 (검토 중 기각)
- **스킬 정본 단일화 + 격리는 법전 규칙으로 (선택)**: 아래

## 결정

1. **정본은 `.agents/skills/`** (개방 표준 레이아웃) 하나뿐이다. 스킬 이름·본문은 영문
   (스펙상 name은 소문자+하이픈 ASCII 필수), 프로젝트 문서 경로는 한글 그대로 참조한다.
2. **서브에이전트 래퍼는 만들지 않는다.** 컨텍스트 격리는 법전(AGENTS.md) 규칙
   "검토 페르소나는 별도 컨텍스트에서 SKILL.md를 읽어 수행한다"로 해결한다 —
   각 에이전트가 자기 서브에이전트 기능으로 이행하므로 벤더 중립이다.
3. **벤더별 보정은 그 벤더의 진입 파일에 둔다.** Claude Code가 `.agents/skills`를 직접
   읽지 못하는 동안 `scripts/sync-agent-assets.mjs`(정본 → `.claude/skills` 복사)로 동등화하며,
   실행 지시는 법전이 아니라 CLAUDE.md에 둔다.
4. `.gitignore`는 `.claude/`(전부 어댑터·로컬 설정)만 제외한다. `.agents`와
   `skills-lock.json`(설치 스킬의 출처·버전 기록)은 형상 항목으로 추적한다 —
   이로써 페르소나 외의 스킬(angular-developer 등)도 같은 위치에 두는 것만으로 키트 자산이 된다.

## 재검토 조건

- Claude Code가 `.agents/skills`를 직접 지원하면: 동기화 스크립트와 CLAUDE.md 보정 절을 제거한다
- 서브에이전트 정의에도 개방 표준이 생기면: 격리 규칙의 이행 방식을 재평가한다

## 결과

- 내용 수정은 정본 1곳. 에이전트가 늘어도 관리비용이 늘지 않는다
- Claude 외 에이전트는 클론 즉시 동작, Claude는 첫 세션에서 CLAUDE.md 지시로 자가 동기화
- 감수하는 것: Claude에서 페르소나가 네이티브 서브에이전트 목록에 나타나지 않음 (법전 규칙 기반 호출로 갈음)
