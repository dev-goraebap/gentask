# 결정-0013: 마이그레이션은 Flyway, jOOQ 코드는 DDLDatabase로 DB 없이 생성한다

- 상태: 승인됨
- 날짜: 2026-07-26

## 맥락

jOOQ는 스키마가 먼저 있어야 코드를 생성한다. 따라서 마이그레이션 도구 결정이 코드 생성 전략보다
선행하며, 둘을 함께 정해야 빌드가 성립한다.

키트의 성격이 판단에 결정적이었다 — **파생 프로젝트가 클론 직후 빌드할 수 있어야 한다.**
빌드에 Docker가 필요해지면 그 자체가 진입 장벽이 된다.

당시 전제: Spring Boot 4.1(jOOQ 3.21.5 관리), Gradle 9.5.1, PostgreSQL, Java 21.

## 검토한 대안

**마이그레이션 도구**: Flyway 채택. SQL 파일이 곧 마이그레이션이라 jOOQ의 SQL 파서로 그대로 읽을 수
있다는 점이 아래 코드 생성 전략과 맞물린다.

**코드 생성 방식**

| | DDLDatabase (선택) | Testcontainers로 실 DB 기동 후 생성 |
|---|---|---|
| Docker | **불필요** | 필요 |
| 정확도 | jOOQ 파서 + 인메모리 H2 — Postgres 고유 문법 일부 한계 | 실제 Postgres = 100% |
| 속도 | 빠름 | 컨테이너 기동 비용 |

Testcontainers 방식이 더 정확하지만, **빌드가 Docker에 묶인다.** DDLDatabase를 택하면
`./gradlew build`는 Docker 없이, 통합 테스트만 Docker로 갈린다 — 키트의 진입 장벽이 낮아진다.

## 결정

1. **Flyway** — 마이그레이션은 `src/main/resources/db/migration/V*.sql`.
2. **jOOQ 공식 Gradle 플러그인 + DDLDatabase** — 마이그레이션 SQL을 정렬 옵션 `flyway`로 읽어
   실행 중인 DB 없이 코드를 생성한다. 런타임 jOOQ 버전을 생성기와 맞춘다(`ext['jooq.version']`).
3. **생성 코드는 커밋하지 않는다.** `build/generated-sources/jooq`에만 두고 소스셋에 추가한다.
   Docker가 필요 없어 어디서든 즉시 생성되므로, 스키마와 어긋날 여지를 원천 차단하는 쪽을 택했다.
4. **생성 코드는 코딩 표준의 대상이 아니다** — Spotless 타깃과 Checkstyle에서 제외하고,
   SpotBugs 필터에서 `dev.goraebap.devkit.jooq` 패키지를 제외한다.
5. **Gradle 데몬 JVM 요구사항을 저장소에 고정한다**(`gradle/gradle-daemon-jvm.properties`,
   `toolchainVersion=21`). jOOQ 코드 생성 플러그인이 빌드스크립트 클래스패스에서 JVM 21을 요구하는데,
   Java 툴체인 설정은 컴파일에만 적용되고 데몬에는 적용되지 않는다. 로컬 기본 JDK가 더 낮은
   환경에서도 클론 직후 빌드되도록 하기 위함이다.

## 재검토 조건

- jOOQ 파서가 Postgres 고유 문법에서 막히면: 먼저 `[jooq ignore start]`/`[jooq ignore stop]` 주석으로
  해당 구문만 건너뛴다. 그래도 안 되면 Testcontainers 기반 생성으로 전환한다 — 마이그레이션 파일은
  그대로이므로 전환 비용은 빌드 설정에 한정된다.

## 결과

- 클론 직후 `./gradlew build`가 Docker 없이 동작한다. 통합 테스트(`test`)만 Docker를 요구한다
- 마이그레이션 파일이 스키마의 단일 원본이 되고, 생성 코드는 항상 그로부터 파생된다
- 감수하는 것: 인메모리 H2 파서의 문법 지원 범위. 스키마가 복잡해지면 위 재검토 조건이 발동할 수 있다
