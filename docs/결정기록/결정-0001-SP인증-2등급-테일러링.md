# 결정-0001: 프로세스 기준으로 SP인증 2등급을 테일러링하여 채택

- 상태: 승인됨
- 날짜: 2026-07-23

## 맥락

이 키트는 파생 프로젝트들의 출발점이 되므로, 키트 자체와 파생 프로젝트 모두가
"계획·추적되고 산출물이 형상관리되는" 수준(SPICE 레벨 2 / SP인증 2등급)을 갖추길 원했다.
운영 주체는 1인(devgo) + AI 에이전트이며, 인증 심사를 받는 것이 목적이 아니라
심사 기준을 실질적 품질 장치로 쓰는 것이 목적이다.

당시 전제: SP인증 기준(과기정통부 고시 제2025-21호), 5개 영역 중 2등급은
프로젝트관리·개발·지원 3개 영역. 기준 전문은 `docs/참고/` 보관.

## 검토한 대안

- 형식 없이 진행: 초기 속도는 빠르나 1인 프로젝트 특성상 프로세스가 형해화되고, 파생 프로젝트에 물려줄 자산이 남지 않음
- CMMI 기반: 조직 성숙도 중심이라 1인 프로젝트에 과함
- SP인증 2등급 테일러링: 프로젝트 단위 기준이라 규모에 맞고, 국내 제도라 참조 자료가 풍부함

## 결정

SP인증 2등급의 3개 영역을 다음 원칙으로 테일러링한다:

1. 사람의 결정이 담기는 원본 문서만 손으로 유지하고, 파생 가능한 산출물은 자동 생성한다
2. 역할 분담: 사람=승인자, 에이전트=수행자, CI=측정자
3. 프로세스 정의의 원본은 `AGENTS.md`(법전)이며, 에이전트가 매 세션 로드한다
4. 협력업체 관리(1.3)는 해당 없음, 공수·비용 견적은 상대 크기로 갈음
5. 베이스라인은 git 태그로, 태그 전 형상감사를 수행한다

## 결과

- 문서 7종(법전, 계획, 요구사항, 설계, 결정기록, CHANGELOG, 린터 설정)만 유지하면 2등급 증적이 남는다
- 키트를 복제한 파생 프로젝트는 첫날부터 같은 프로세스를 갖춘다
- 감수하는 것: 기능 개발 전 문서 선행 비용, 페르소나·CI 자산의 유지 비용
