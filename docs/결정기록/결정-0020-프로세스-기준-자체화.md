# 결정-0020: 프로세스 기준에서 SP인증 참조 제거

- 상태: 승인됨
- 날짜: 2026-07-28

## 맥락

결정-0001은 프로세스 기준으로 SP인증 2등급 테일러링을 채택했다. 이후 프로세스 점검
인터뷰(2026-07-28)에서 승인자가 실제 의도를 확인했다: 인증 심사를 받을 계획은 없고,
원했던 것은 소프트웨어 프로세스의 확립 자체이지 특정 인증 기준의 충족이 아니다.

인증 기준을 명분으로 유지하면 부작용이 있다. 에이전트가 매 세션 법전의 "2등급 대비"
문구를 로드하므로, 심사 기준 충족을 근거로 산출물·절차를 과잉 제안할 정당한 근거가
계속 남는다. 프로세스가 승인자의 의도보다 무거워지는 방향으로 압력이 걸린다.

## 검토한 대안

- 현행 유지: 이미 확립된 장치의 출처 설명으로는 유효하나, 위의 과잉 제안 압력이 계속됨
- 등급만 낮춰 표기: 등급 표기가 남는 한 "심사 대비"라는 오해와 기준 대조 비용도 남음
- 참조 제거: 실질 장치는 유지하고 명분만 자체 규칙으로 교체. 프로세스의 근거가
  "기준 충족"에서 "실제로 겪는 문제의 방지"로 바뀜

## 결정

프로세스 기준에서 SP인증 참조를 제거하고, 프로세스를 이 프로젝트의 자체 규칙으로 선언한다.

1. 실질 장치는 전부 유지한다 — 요구사항 상태 관리, 결정기록, CI 게이트,
   검토 페르소나, 베이스라인 감사, 역할 분담(사람=승인자, 에이전트=수행자, CI=측정자).
2. AGENTS.md·README·계획.md에서 SP인증 용어를 제거한다.
3. `docs/참고/`의 인증 기준 자료 3건(기준 전문 txt·pdf, 커버리지 맵)을 삭제한다.
4. 결정-0001은 대체됨으로 표시한다.
5. 외부 심사·제출 요구가 실제로 생기면 그때 산출물 목록을 받아
   원본(직접 작성)/파생(자동 생성)으로 분류해 대응한다.

## 결과

- 프로세스의 존재 이유가 자체 규칙으로 명확해지고, 인증 기준을 근거로 한
  과잉 산출물 제안의 여지가 사라진다.
- 감수하는 것: 인증 제도가 주던 외부 준거(커버리지 맵) 상실 — 심사 요구가
  생기면 분류·대응 비용이 그때 발생한다.
