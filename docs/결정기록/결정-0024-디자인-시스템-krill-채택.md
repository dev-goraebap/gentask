# 결정-0024: 디자인 시스템을 Krill로 교체한다 — 토큰 3계층을 버린다

- 상태: 승인됨
- 날짜: 2026-08-03
- 대체: [결정-0017](결정-0017-디자인-토큰-아키텍처.md) (디자인 토큰 아키텍처)

## 맥락

당시 전제: Angular 22, Tailwind CSS 4, Storybook(`@storybook/angular-vite`),
컴포넌트 8종(`web/src/shared/ui`), Pretendard 자체 호스팅.

**Krill(https://krill.goraebap.xyz)은 이 저장소의 소유자가 직접 만든 Tailwind 기반 디자인
시스템이고, 자기 대부분의 프로젝트에 공통으로 적용하려고 만든 것이다.** 키트가 그것을 쓰면
파생 프로젝트도 같은 기반을 물려받는다.

교체 대상인 기존 시스템은 [결정-0017](결정-0017-디자인-토큰-아키텍처.md)이 정한 3계층 토큰
구조다 — 프리미티브(`themes/halo.css`) → 시맨틱(`tokens.css`, Tailwind `@theme`) → 컴포넌트.
팔레트 교체가 파일 한 줄 바꾸기가 되도록 설계했고, 대비 검증 테스트 33건이 붙어 있었다.

**둘은 생각보다 많이 겹쳤다.** 둘 다 Tailwind 4 `@theme` 기반이고, 타이포 토큰을 역할 이름으로
부르며(`text-headline-lg`·`text-body-md`), 크기·굵기·자간·행간을 한 세트로 묶고, 간격 토큰을
만들지 않고 Tailwind 기본 스케일을 쓴다. 그래서 교체 비용이 겉보기보다 훨씬 작았다.

부딪친 것은 넷이다.

| 항목 | 결정-0017 | Krill |
|---|---|---|
| 토큰 계층 | 3계층 | 1장(`krill.css`)에 OKLCH 직접 |
| 다크 전환 | `light-dark()` + `color-scheme` + `[data-theme]` | `.dark` 클래스 + `@custom-variant` |
| 깊이 표현 | 라이트는 그림자가, 다크는 표면색이 층위를 만든다 | **선이 구조를 그린다** — 그림자는 실제로 떠 있는 것만 |
| 반경 이름 | 역할 기반(`rounded-control`) | 크기 기반(`rounded-md`) |

## 검토한 대안

- **Krill 값을 프리미티브 계층에 넣고 3계층 유지**: `--prim-*`로 옮겨 심고 시맨틱 계층을 그대로
  둔다. `light-dark()`와 역할 기반 반경 이름이 살아남는다. 기각 — **Krill이 갱신될 때마다 값을
  손으로 옮겨 심어야 한다.** 그러면 "붙여넣으면 끝"이라는 Krill의 이점이 사라지고, 옮겨 심는
  과정에서 어긋날 여지가 매번 생긴다.
- **색 토큰만 Krill, 나머지는 현행 유지**: 변경 범위가 가장 작다. 기각 — 두 체계가 섞여
  "Krill을 쓴다"고 말하기 애매해지고, 어느 쪽 규칙을 따를지 매번 판단해야 한다.
- **krill.css를 그대로 넣고 3계층을 버린다(채택)**.

## 결정

**1. `krill.css` 한 장이 토큰의 정본이다.** `themes/halo.css`와 `tokens.css`를 제거한다.

**2. `krill.css`는 손으로 고치지 않는다. 통째로 갈아끼운다.** 이것이 3계층을 버린 대가로 얻는
것이며, 동시에 지켜야 하는 규율이다. 고쳐야 할 값이 있으면 **우리 진입점(`web/src/styles.css`)
에서 덮어쓴다** — 벗어난 지점이 우리 파일에만 모여 있어야 업스트림이 갱신됐을 때 무엇을 지울지
알 수 있다.

**3. 다크 전환은 `.dark` 클래스로 한다.** `light-dark()`를 버린다.

  `light-dark()`는 OS 선호를 공짜로 따라왔지만 `.dark`는 그렇지 않다. 그대로 두면 OS를 다크로
  설정한 사용자가 라이트 화면을 받으므로, **`index.html`의 인라인 스크립트**가 첫 페인트 전에
  `.dark`를 결정한다. 앱 코드에서 붙이면 라이트로 한 번 그렸다가 어두워지는 깜빡임이 생긴다.
  `localStorage`가 OS 선호를 이긴다 — 사용자가 직접 고른 것이 뒤에 온 의사 표시이기 때문이다.

  **잃는 것**: 밝은 페이지 안의 어두운 영역처럼 하위 트리만 다른 모드로 두는 것이 공짜가
  아니게 된다. Storybook에서 두 모드를 나란히 보여주는 배치는 여전히 가능하다 — 프리뷰 루트에
  `.dark`가 없으므로 라이트가 기본이고 다크 패널에만 클래스를 건다.

**4. 깊이는 선이 낸다.** 같은 평면에서 영역을 가르는 것은 헤어라인 보더이고, 그림자는 **실제로
떠 있는 것**(모달·팝오버·드롭다운)에만 쓴다. 정적 카드에 그림자를 얹으면 "떠 있음"이라는 신호가
값싸져서 진짜 떠 있는 것과 구분되지 않는다.

**5. 폰트는 현행을 유지한다.** Krill 문서는 CDN `@import`를 보여주지만 채택하지 않는다 —
외부 의존이 생기고 서브셋 없이 통째로 받게 된다. Pretendard 변수 폰트를 자체 호스팅 + 92개
유니코드 범위 동적 서브셋으로 계속 쓴다. `krill.css`의 `--font-sans`가 `'Pretendard Variable'`을
첫 후보로 두고 있어 그대로 맞물린다.

  `--font-mono`(Geist Mono)는 자체 호스팅하지 않는다. 수치 표시에만 쓰이고 시스템 모노스페이스로
  떨어져도 `tabular-nums`가 유지되어 자릿수 정렬이라는 목적은 달성된다. 폰트 하나를 더 지고
  갈 만한 이득이 아니다.

**6. 대비 검증 테스트는 지우지 않고 Krill의 계약에 맞게 다시 쓴다.** 이 결정의 핵심 중 하나다.

  기존 테스트는 "모든 경계선이 3:1"을 강제했다. Krill은 **장식선(`border`·`border-strong`)에
  WCAG 1.4.11을 의도적으로 면제**하고 폼 컨트롤용 `border-control`에만 3:1을 요구한다.
  **이것은 느슨해진 것이 아니라 더 정교하게 나눈 것이다** — 장식선은 사라져도 컴포넌트를
  식별하지 못하게 되지 않지만, 입력란의 테두리는 "여기가 입력란"임을 알리는 유일한 단서다.
  장식선을 진하게 만들어 미감을 깨는 대신 필요한 곳에만 진한 선을 둔다.

  그래서 테스트를 이렇게 바꿨다.
  - 색 파서를 OKLCH → OKLab → 선형 sRGB → 감마 sRGB로 다시 쓴다
  - 반투명 값(다크의 보더들)은 뒤에 깔린 면 위에 합성한 뒤 계산한다
  - **`border-control`의 3:1을 새로 강제한다**
  - 장식선은 검증하지 않되 그 근거를 파일 머리말에 남긴다
  - `krill.css`뿐 아니라 **`styles.css`의 오버라이드까지 읽는다** — 앱이 실제로 싣는 값을
    검증해야 하기 때문이다

  검증 건수는 33건에서 58건으로 늘었다.

## 결과

- 토큰을 고칠 곳이 한 곳으로 줄었다. 팔레트 교체가 "파일 한 줄 바꾸기"에서 "파일 한 장
  갈아끼우기"가 됐다 — 계층이 사라진 만큼 옮겨 심을 것도 없다.
- 여러 프로젝트가 같은 시스템을 공유한다. 키트에서 익힌 클래스 조합이 다른 프로젝트에서 그대로 쓰인다.
- **[결정-0018](결정-0018-컴포넌트-워크벤치.md)(Storybook)과 [결정-0019](결정-0019-컴포넌트-동작-조달.md)
  (컴포넌트 직접 제작·속성 선택자·접근성 배선)는 대체하지 않는다.** Krill과 충돌하지 않고,
  Krill도 Angular에는 CDK를 권장해 결정-0019 §5와 일치한다. 컴포넌트 8종은 **내부 클래스만**
  바뀌었고 계약은 그대로다.
- 버튼의 `quiet` 변형을 `tertiary`로 바꿨다. Krill의 어휘를 따르는 편이 카탈로그를 그대로 복사해
  쓸 수 있어 이롭다. 호출부가 아직 없어 지금이 바꿀 수 있는 시점이다.
- 감수하는 것:
  - **하위 트리 부분 다크가 공짜가 아니다**(§3).
  - **린터가 이 규율을 강제하지 못한다.** "krill.css를 손대지 않는다"와 "색·간격·반경을
    하드코딩하지 않는다"는 검토로만 지켜진다.

## 채택 과정에서 발견한 Krill 자체의 문제

교체하며 대비를 측정하다 두 가지를 찾았다. 상세와 재현 절차는
[`docs/참고/krill-대비-보고.txt`](../참고/krill-대비-보고.txt)에 있다.

1. **다크 모드 `border-control`이 3:1에 못 미친다**(2.67·2.71). 라이트는 3.02·3.24로 통과하므로
   다크만 놓친 것으로 보인다. **`styles.css`에서 알파를 0.34로 덮어썼다**(3.09·3.12).
   업스트림에 반영되면 그 블록을 지운다.
2. **`fg-faint`가 라이트에서 AA에 못 미친다**(3.20·3.44). 값을 올리면 3단 전경 스케일의 폭이
   좁아지므로, 값 대신 **용도를 좁혔다** — 플레이스홀더 전용으로 쓰고 본문·캡션에는 `fg-muted`를
   쓴다. 테스트가 3:1로 고정한다.

## 재검토 조건

- **Krill이 새 판을 내면** `krill.css`를 갈아끼우고 `npm test`를 돌린다. 대비 테스트가 값을
  하드코딩하지 않으므로 새 팔레트가 기준을 넘는지 그 자리에서 판정된다. 위 오버라이드가
  불필요해졌는지도 함께 확인한다.
- **테마 토글 UI가 생길 때** — `index.html`의 스크립트가 이미 `localStorage`의 `theme` 키를
  읽으므로, 그 키에 쓰기만 하면 맞물린다.
- **Tailwind가 메이저를 올릴 때** — `@theme`·`@custom-variant`·`@utility`의 동작이 바뀌면
  Krill 쪽 대응을 기다린 뒤 갈아끼운다.
