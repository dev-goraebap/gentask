# gentask 제품 요구사항 정의서 (Product Requirements Document)

## 1. 개요 (Overview)

gentask는 개인용 할 일 관리(Todo) 기능에서 출발하여, 필요에 따라 동일 계정 내에서 경량 트래커(Tracker)로 전환하여 사용할 수 있는 개인용 관리 서비스입니다. 사용자는 필요에 따라 모드를 전환하며, 두 모드는 단일 사용자 계정과 공통 웹 UI 셸(Shell)을 공유합니다.

제품은 다음 세 가지 핵심 특성을 갖습니다.

- **모드 전환성 (Dual Mode Transition)**: 투두 모드는 개인의 할 일을 스마트 목록(오늘·중요·기한) 기반으로 관리하는 공간이며, 트래커 모드는 프로젝트 단위의 작업 아이템과 문서를 관리하는 공간입니다. 사용자는 사이드바 하단에서 모드를 전환할 수 있습니다. 트래커 모드를 사용하지 않는 사용자는 투두 모드 단독으로 서비스를 완결성 있게 활용할 수 있습니다.
- **에이전트 협업 (Agent Collaboration)**: 명령줄 도구(CLI, `gentask`)를 통해 작업 아이템 및 문서 데이터에 직접 접근할 수 있습니다. 로컬 코딩 에이전트가 로컬 저장소(Repository) 외부에서 프로젝트의 맥락(Context)을 조회하고 갱신할 수 있도록 지원하는 것이 트래커 모드의 핵심 목적입니다.
- **게이미피케이션 (반려 팻)**: 할 일 또는 작업 아이템을 완료하면 보상으로 반려 팻(Pet)이 성장합니다. 완료가 단순한 목록 삭제로 끝나지 않고 지속적인 피드백으로 연결되도록 설계되었습니다. (세부 성장 규격은 미정 상태입니다.)

### 1.1 대상 사용자 (Target Users)

- **기본 대상**: 1인 개발자를 기본 대상으로 설계합니다.
- **확장 대상**: 소규모 팀까지 확장 가능한 구조를 고려하되, 멤버 및 권한 관리 기능은 현재 구현 범위에서 제외되므로(2.3 참조) 현재 버전은 1인 사용자 환경을 기준으로 정의합니다.

### 1.2 배경 및 문제 정의 (Background & Problem Statement)

- **기존 이슈 관리 도구의 한계**: Jira 등의 기존 도구는 개인 프로젝트에 도입하기에 기능 및 운영 측면에서 과도하게 무겁습니다.
- **로컬 마크다운 백로그의 한계**: 로컬 마크다운 파일로 백로그를 관리할 경우 구조가 단순하여 에이전트가 저장소 열람만으로 쉽게 읽을 수 있으나, 사람 관점에서는 가독성이 떨어지고 소스 코드와 프로젝트 관리 관심사가 혼재되어 문서에 집중하기 어렵습니다.
- **도구 파편화 문제**: 마크다운 파일에 별도 시각화 도구를 추가 도입할 경우 관리해야 할 도구의 수가 늘어나며 플랫폼 일원화가 저해됩니다.
- **해결 방안**: gentask는 이러한 문제를 해결하기 위해 사람은 웹 인터페이스를 통해 직관적으로 열람/편집하고, 코딩 에이전트는 CLI를 통해 접근하며, 양측이 동일한 원격 데이터 저장소를 일관되게 참조하는 통합 환경을 제공합니다.

### 1.3 기능 범위 기준점 (Benchmark)

- **투두 모드**: Microsoft To Do의 핵심 기능 범위와 도메인 용어를 기준점으로 정의합니다.
- **트래커 모드**: Jira 와 Plane 의 작업 아이템 유형 체계를 기준점으로 정의합니다.

### 1.4 도메인 용어 정의 (Terminology)

두 모드가 각각 다루는 항목을 다음과 같이 구분합니다.

| 용어 | 영문 | 정의 및 설명 |
| :--- | :--- | :--- |
| **할 일** | Todo | 투두 모드의 기본 항목. 오늘·중요·기한 속성을 갖는 개인의 할 일입니다. |
| **작업 아이템** | Work item | 트래커 모드의 기본 항목. 프로젝트에 귀속되며 유형, 계층, 상태를 갖습니다. |
| **태스크** | Task | 작업 아이템의 4개 유형(에픽, 스토리, 태스크, 버그) 중 하나입니다. |
| **문서** | Document | 트래커 모드의 위키 항목. 프로젝트에 귀속되며 폴더 구조로 계층화됩니다. |

트래커의 항목을 `이슈`가 아닌 `작업 아이템`으로 표기합니다. `이슈`는 결함을 연상시키나 실제로 담기는 것은 기능과 잡일과 에픽을 포함하며, Jira 와 Plane 이 동일한 이유로 `Work item` 으로 전환했습니다. 투두 모드의 항목을 `할 일`로 표기하는 것은 `작업`이 `작업 아이템` 및 `태스크` 유형과 겹쳐 읽히기 때문입니다.

### 1.5 작업 아이템의 상태 (Work item states)

상태는 5개이며 이름과 구분 기준은 Plane 및 Linear 의 상태 그룹을 따릅니다.

| 상태 | 영문 | 정의 |
| :--- | :--- | :--- |
| **백로그** | `BACKLOG` | 아직 하기로 정하지 않은 것. 더 논의하거나 준비해야 합니다. |
| **예정** | `UNSTARTED` | 하기로 정했으나 아직 시작하지 않은 것. |
| **진행 중** | `STARTED` | 현재 진행 중인 것. |
| **닫힘** | `COMPLETED` | 인수 조건이 참임을 확인한 것. |
| **취소** | `CANCELED` | 근거를 잃어 더 이상 유효하지 않은 것. |

`백로그`와 `예정`을 가르는 기준은 착수 여부가 아니라 **하기로 정했는가**입니다. 두 상태 모두 시작되지 않은 상태입니다.

## 2. 서비스 범위 (Scope)

### 2.1 포함 범위 (In Scope)

**공통 (Common)**

- 계정 관리: 회원가입, 로그인, 로그아웃, 프로필 관리, 비밀번호 변경/재설정, 회원 탈퇴
- 알림 관리: 미리 알림 발송 및 사용자 통지
- 파일 관리: 파일 업로드 및 항목 첨부
- 외부 인터페이스: 명령줄 도구(CLI)를 통한 데이터 접근
- 게이미피케이션: 반려 팻

**투두 모드 (Todo Mode)**

- 할 일 관리: 등록, 조회, 수정, 완료 처리, 삭제
- 스마트 목록: 오늘, 중요, 기한 조건에 따른 할 일 필터링 및 선별

**트래커 모드 (Tracker Mode)**

- 프로젝트 관리: 계정 생성 시 기본 프로젝트 1개 자동 생성, 프로젝트 선택 및 전환
- 작업 아이템 관리: 에픽·스토리·태스크·버그 유형 지원, 계층 구조 및 상태 관리(1.5)
- 문서 관리: 폴더 기반 계층화, 마크다운 본문 편집(이미지 및 다이어그램 지원), 문서 단위 파일 첨부, 작업 아이템과 문서 간 링크 연동
- 프로젝트 설정: 프로젝트명 수정, 원격 저장소(Git) 연동 (원격 저장소 연동은 선택 사항이며 미연동 시에도 작업 아이템 관리 가능)

### 2.2 제외 범위 (Out of Scope)

시스템 설계 및 구현의 명확성을 유지하기 위해 다음 항목은 서비스 범위에서 명시적으로 제외합니다.

- **일정 관리 도메인**: 캘린더 및 달력 뷰는 제공하지 않습니다. 기한 및 미리 알림은 할 일 및 작업 아이템에 부속된 속성으로만 관리합니다.
- **원격 저장소 코드 열람 및 편집**: 저장소 연동은 커밋 메시지와 참조된 작업 아이템 간의 연결에 한하며, gentask 내에서 저장소 코드를 직접 열람하거나 편집하지 않습니다.
- **고가용성 및 대규모 처리량**: 단일 서버 배포 환경을 전제로 하므로 고가용성(High Availability) 및 대규모 처리량(High Throughput)은 목표 아키텍처 범위에서 제외합니다. (근거: [1.2 품질 목표](./architecture/01-introduction-and-goals.md))

### 2.3 향후 검토 범위 (Future Scope / Backlog)

현재 구현 범위에는 포함되지 않으나 향후 확장 대상으로 식별된 기능은 백로그의 Draft 상태로 관리합니다.

- **멤버 및 권한 관리**: 향후 소규모 팀 확장을 고려하여 프로젝트 데이터 모델이 단일 계정에 강결합되지 않도록 설계하되, 사용자 초대 및 역할 기반 권한 분리는 현재 범위에서 제외합니다.
- **반려 팻 성장 규격**: 성장을 유발하는 조건 및 시각적 표현 방식에 대한 세부 규격 확정
- **프로젝트 관리 계측**: 추정치, 사이클(스프린트), 번다운, 시간 추적. 경량을 유지하는 것이 트래커 모드의 전제이므로 기본으로 두지 않되, 필요해지는 시점에 필요한 것만 차용합니다.
- **반복 할 일 관리**: 할 일의 주기적 반복 생성 및 규칙 관리
- **뽀모도로**: 시간 집중 관리 타이머 기능
- **사용자 정의 목록(List) 관리**: 할 일을 분류하고 그룹화하기 위한 사용자 정의 목록 관리 기능

### 2.4 데이터 격리 원칙 (Data Isolation)

모든 데이터는 사용자 계정 단위로 엄격히 격리되며, 타 계정의 리소스에 대해서는 존재 여부 자체를 노출하지 않습니다. 프로젝트와 그에 속한 작업 아이템 및 문서 역시 사용자 계정에 귀속됩니다. (해당 원칙은 향후 멤버 관리 기능 도입 시 재검토합니다.)

### 2.5 에이전트 접근 원칙 (Agent Access)

트래커 모드의 작업 아이템과 문서는 CLI를 통해 원격으로 조회 및 변경할 수 있어야 합니다. 에이전트가 로컬 마크다운 파일 전체를 순회 탐색하던 방식을 대체할 검색 기능이 제공되어야 합니다.

- **서버 사이드 검색 원칙**: 검색 기능은 서버가 직접 수행합니다. CLI가 데이터를 로컬로 내려받아 검색하는 방식은 로컬에 데이터를 다시 분산시키는 결과를 초래하여 데이터 일원화 원칙에 위배되므로 배제합니다.

문서는 개정 이력을 갖습니다. 본문은 문서가 아니라 개정이 소유하며, 문서는 현재 참인 개정을 가리킵니다. 개정은 남긴 뒤 변경하지 않고, 되돌리기 역시 새 개정을 만듭니다.

폴더 계층·첨부·작업 아이템 링크·검색(DOC-008~011)은 화면 프로토타입이 목 데이터 위에 있는 상태에서 작성했습니다. 실제 흐름을 확인한 뒤 개정될 가능성이 나머지보다 높습니다.
