계획 문서와 실제 게이트 사이에 어긋남이 남아 있다.

## 어긋남 전수 목록 (심각도 구분 없이 전부)

1. **M0 완료 조건 미충족(부분)**: server 테스트가 CI 게이트에서 제외됨. 계획.md는 수정되지 않음.
2. **열린 이슈 #7이 M0 마일스톤에 잔존**: bug 라벨. 마일스톤을 닫으려면 이관 또는 해결 필요.
3. **server 테스트의 DoD 형해화**: 테스트가 "존재"하지만 로컬 DB 없이는 실행 불가 — DoD 3항
   (빌드·테스트·린트 통과)을 server에서 증명할 수단이 현재 없다.
4. **Windows 로컬에서 `format:check` 실패 (재현성 결함)**: 저장소에 `.gitattributes`가 없고
   prettier `endOfLine` 설정도 없어, `core.autocrlf=true`인 Windows 체크아웃은 CRLF가 되고
   prettier 기본값(lf)에 걸려 9파일이 실패한다. CI(Linux, LF)는 통과하므로 게이트는 뚫리지
   않지만, "린터 설정 파일이 곧 표준" 원칙에 비추면 로컬과 CI의 판정이 갈리는 것 자체가 결함.
5. **Windows 로컬에서 npm 스크립트 실행 불가**: 저장소 상위 경로의 `&` 문자 때문에 npm의
   cmd 셸 호출이 깨진다(`npm run lint` 실패). 저장소 자체의 결함은 아니고 로컬 폴더명 문제지만,
   개발키트의 "복제해서 바로 쓴다"는 정체성상 파생 프로젝트 경로 제약으로 기록해 둔다.

## 잘된 것

- **이슈 → 브랜치 → PR → CI → squash 머지** 흐름이 5건의 PR에서 예외 없이 지켜졌다 (결정-0003).
- CI 도입 이후 실행 11회 전부 성공 — 게이트가 머지를 막은 적은 없지만, 로컬에서 미리 맞추고
  올리는 습관이 작동했다는 뜻이기도 하다.
- 결정기록 4건(0003~0006)이 결정 시점에 작성되어 근거가 유실되지 않았다.
- CHANGELOG가 머지 이력과 완전히 정합 — 문서 부채 없이 마일스톤을 마감한다.
- 결함(#7)을 발견 즉시 이슈로 등록하고 CI 주석에 유예 사유를 남겨 추적성을 유지했다.

## M1에 반영할 것

1. **#7을 M1으로 이관**하고, M1의 DB 설계 결정(결정기록)에 테스트 전략(Testcontainers / H2 /
   프로파일 분리)을 포함시킨다. 해결 시 `ci.yml`의 `-x test`를 제거해 server 테스트를 게이트에 편입.
2. **계획.md의 M0 완료 조건을 실제에 맞게 수정** (수정안은 회고와 함께 제안, 승인은 사람).
3. **라인엔딩 표준화**: 루트에 `.gitattributes`(`* text=auto eol=lf` 등)를 추가하거나 prettier에
   `endOfLine` 명시 — 어느 쪽이든 로컬과 CI의 판정을 일치시킨다. 소규모 설정 변경이므로 이슈
   등록 후 처리.
4. **테스트 자산이 생기는 M1부터** 커버리지 수집을 CI에 추가한다 (AGENTS.md 역할 분담에 예고됨).
   테스트 이름의 요구사항 ID 참조(AUTH-* 등) 규칙이 실제로 지켜지는지 QA 심사 대상에 포함.
5. 파생 프로젝트 안내(부트스트랩 문서 또는 README)에 **경로에 `&` 등 특수문자 금지** 제약을 명시.
