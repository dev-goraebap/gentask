# ADM-002 알림 발송 실패 관리

- **목표:** 알림 발송 실패 내역을 조회하고 처리하여 실패 원인을 규명하고 무효화된 구독 엔드포인트를 정리한다.
- **주 액터:** 관리자
- **지원 액터:** 없음
- **선행 조건:** 관리자 권한을 가진 계정으로 로그인되어 있어야 한다.
- **트리거:** 알림 미수신 문의를 접수했거나 발송 시스템의 정상 동작 여부를 점검한다.

## 기본 흐름 (Basic Flow)

1. 관리자가 알림 발송 실패 관리 화면으로 진입한다.
2. 시스템이 발송 실패 내역을 최신순으로 표시한다 (사용자 정보, 실패 사유, 발생 시각 포함).
3. 관리자가 특정 항목을 처리 완료로 지정한다.
4. 시스템이 해당 항목을 처리 완료 상태로 갱신하고 기본 미처리 목록에서 제외한다.

## 대체 흐름 (Alternate Flows)

### A1 무효한 구독 엔드포인트를 해제한다

- **시작 조건:** 3단계에서 실패 원인이 영구적인 엔드포인트 무효화인 경우다.
- **경로:**
  1. 관리자가 해당 엔드포인트의 구독 해제를 요청한다.
  2. 시스템이 해당 기기의 푸시 구독 레코드를 삭제하고 항목을 처리 완료로 변경한다.

사용자가 기기에서 알림을 재활성화하면 신규 구독 엔드포인트가 등록된다.

### A2 처리 완료된 내역을 포함하여 조회한다

- **시작 조건:** 2단계에서 관리자가 기처리된 내역 조회를 요청한다.
- **경로:**
  1. 시스템이 처리 완료된 내역을 포함하여 전체 목록을 표시한다.

## 예외 흐름 (Exception Flows)

### E1 탈퇴한 사용자의 발송 실패 내역

- **시작 조건:** 2단계에서 대상 사용자가 이미 계정을 삭제했다.
- **경로:**
  1. 시스템이 사용자 식별 정보를 '탈퇴한 사용자'로 표시한다.

## 실패 기록 적재 흐름

발송 실패 기록은 예약 시각 발송 배치 작업이 실패할 때 시스템이 자동으로 적재한다([NTF-001](<../notification/NTF-001(알림 받기).md>) A4, Story `GT-34`).

실패 사유 유형:

- **일시 발송 실패** — 푸시 서비스 장애 또는 네트워크 오류로 인한 전송 실패 (재시도 가능)
- **엔드포인트 만료** — 푸시 서비스가 해당 구독 엔드포인트의 무효화(`410 Gone` 등)를 응답함 (구독 해제 대상)

## 미결

- 장기 누적 실패 기록의 보관 주기 및 자동 파기 정책
- 동일 엔드포인트의 반복 실패 건에 대한 그룹화 및 집계 뷰 제공

## 범위 밖

알림 본문 구성 및 스케줄링 발송 로직은 본 유스케이스 범위에 포함하지 않는다.
