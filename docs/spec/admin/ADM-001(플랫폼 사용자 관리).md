# ADM-001 플랫폼 사용자 관리

- **목표:** 누가 이 서비스를 쓰고 있는지 보고 관리할 사람을 정해, 운영을 혼자 짊어지지 않는다.
- **주 액터:** 관리자
- **지원 액터:** 없음
- **선행 조건:** 관리자 권한을 가진 계정으로 로그인해 있어야 한다.
- **트리거:** 누가 가입했는지 확인해야 하거나, 다른 사람에게 관리를 맡겨야 한다.

## 기본 흐름 (Basic Flow)

1. 관리자가 사용자 관리를 연다.
2. 시스템이 가입한 사용자를 최근 가입 순으로 보여 준다.
3. 관리자가 어떤 사용자를 관리자로 올린다.
4. 시스템이 그 사용자의 권한을 바꾸고 바뀐 자리를 보여 준다.

## 대체 흐름 (Alternate Flows)

### A1 사람을 찾는다

- **시작 조건:** 2단계에서 목록이 길어 원하는 사람이 한눈에 보이지 않는다.
- **경로:**
  1. 관리자가 찾을 말을 넣는다.
  2. 시스템이 이메일과 별명에서 그 말을 가진 사용자만 남긴다.
  3. **기본 흐름 3으로 복귀.**

이메일과 별명을 함께 보는 것은 관리자가 둘 중 무엇으로 기억하는지 알 수 없기 때문이다.

### A2 관리자를 일반 사용자로 내린다

- **시작 조건:** 3단계에서 대상이 이미 관리자다.
- **경로:**
  1. 시스템이 그 사용자의 권한을 일반 사용자로 바꾼다.

## 예외 흐름 (Exception Flows)

### E1 자기 자신의 권한을 바꾸려 한다

- **시작 조건:** 3단계에서 대상이 관리자 자신이다.
- **경로:**
  1. 시스템이 바꾸지 않고 사유를 알린다.

마지막 관리자가 스스로를 내리면 관리 화면에 들어갈 사람이 아무도 없게 되고, 그 상태는 화면으로 되돌릴 수단이 없다. 자신을 올리는 것도 함께 막는 것은 이미 관리자만 이 자리에 오기 때문이며, 가를 실익이 없다.

### E2 관리자가 아닌 사람이 들어오려 한다

- **시작 조건:** 1단계에서 액터의 권한이 일반 사용자다.
- **경로:**
  1. 시스템이 관리 화면과 그 API 를 거절한다.

화면 쪽 판정은 빈 화면 대신 자기 자리를 보여 주기 위한 것이며, 접근을 막는 근거는 서버가 갖는다. 화면만으로 막으면 API 를 직접 부르는 길이 열린 채로 남는다.

## 미결

- **첫 관리자를 화면에서 정하는 길.** 지금은 서버 설정값이 가리키는 계정을 기동 시와 가입 시에 올린다. 화면으로 여는 순간 누구나 첫 관리자가 될 수 있으므로 열지 않았다. 운영자가 서버 설정에 닿지 못하는 상황이 생기면 올린다
- **권한을 자원별로 나누는 것.** 지금 가르는 것이 "관리 화면에 들어갈 수 있는가" 하나뿐이라 역할 둘로 족하다. 가를 것이 늘면 역할과 권한을 분리한다
- **권한 변경의 이력.** 누가 언제 누구를 올렸는지 남기지 않는다. 관리자가 여럿이 되어 서로의 조치를 확인해야 할 때 올린다
- **계정 정지와 삭제.** 관리자가 남의 계정을 없애는 것은 되돌릴 수 없으므로 두지 않았다. [USR-006](<../user/USR-006(계정 탈퇴).md>)이 본인의 탈퇴를 갖는다

## 범위 밖

사용자의 작업과 파일은 보지 않는다. 관리자가 남의 목록을 열 수 있으면 이 서비스에 적은 내용이 본인만의 것이 아니게 된다. 운영에 필요한 것은 누가 쓰고 있는가이지 무엇을 적었는가가 아니다.
