# USR-001 계정 회원가입

- **목표:** 신규 사용자 계정을 생성하여 시스템 이용을 시작한다.
- **주 액터:** 사용자
- **지원 액터:** 메일 발송 서비스
- **트리거:** 시스템에 신규 가입하고자 한다.

## 기본 흐름 (Basic Flow)

1. 사용자가 이메일과 비밀번호를 입력한다.
2. 시스템이 이메일 형식과 중복 여부를 검증하고, 비밀번호가 복잡도 정책에 부합하는지 검증한다.
3. 시스템이 일회용 인증 코드를 해당 이메일로 발송하고 코드 입력 폼을 활성화한다.
4. 사용자가 수신한 인증 코드를 입력한다.
5. 시스템이 인증 코드를 검증한다.
6. 시스템이 사용자 계정을 생성하고 세션을 발급하여 로그인 처리한다.
7. 사용자가 기본 프로젝트의 작업 목록 화면으로 이동한다.

가입 완료 즉시 인증 세션을 발급하여 추가 로그인 절차 없이 서비스 이용을 개시한다.

계정 엔티티는 이메일 인증 코드가 검증된 6단계에서 생성된다.

## 대체 흐름 (Alternate Flows)

### A1 이미 등록된 이메일이다

- **시작 조건:** 2단계에서 해당 이메일로 등록된 계정이 이미 존재한다.
- **처리 절차:**
  1. 시스템이 이미 등록된 이메일임을 안내한다.
  2. **실패로 종료.** [USR-002 계정 로그인](<./USR-002(계정 로그인).md>)으로 유도한다.

### A2 이메일 형식이 올바르지 않다

- **시작 조건:** 2단계에서 입력된 이메일이 표준 형식에 부합하지 않는다.
- **처리 절차:**
  1. 시스템이 형식 오류 메시지를 안내한다.
  2. **기본 흐름 1로 복귀.**

### A3 비밀번호 정책에 부합하지 않는다

- **시작 조건:** 2단계에서 비밀번호 복잡도 규칙을 충족하지 못한다.
- **처리 절차:**
  1. 시스템이 미충족 비밀번호 규칙을 안내한다.
  2. **기본 흐름 1로 복귀.**

비밀번호 복잡도 정책은 [결정-0012](../../architecture/decisions/0012-shared-credential-policy.md)를 따른다.

### A4 인증 코드가 일치하지 않는다

- **시작 조건:** 5단계에서 입력된 인증 코드가 발송된 코드와 일치하지 않는다.
- **처리 절차:**
  1. 시스템이 인증 코드 불일치를 안내한다.
  2. **기본 흐름 4로 복귀.**

연속 입력 실패 한도 초과 시 코드를 무효화하고 재발급을 요구한다.

### A5 인증 코드가 만료되었다

- **시작 조건:** 5단계에서 인증 코드 유효 시간이 만료되었다.
- **처리 절차:**
  1. 시스템이 코드 만료를 안내하고 재발송 수단을 제공한다.
  2. **A6으로 이어진다.**

### A6 인증 코드를 재요청한다

- **시작 조건:** 3단계 후, 사용자가 인증 코드를 수신하지 못했거나 만료되어 재발송을 요청한다.
- **처리 절차:**
  1. 시스템이 기존 코드를 만료 처리하고 신규 인증 코드를 발송한다.
  2. **기본 흐름 4로 복귀.**

## 미결

- 인증 코드 재발송 요청 횟수 제한(Rate Limiting) 정책
