# USR-006 비밀번호 변경

- **목표:** 쓰던 비밀번호를 갈아, 계정에 들어오는 길을 나만 갖는 상태로 되돌린다.
- **주 액터:** 사용자
- **지원 액터:** 없음
- **트리거:** 쓰던 비밀번호를 더 믿을 수 없게 되었다.

## 기본 흐름 (Basic Flow)

1. 사용자가 프로필에서 비밀번호를 바꾸겠다고 한다.
2. 사용자가 현재 비밀번호와 새 비밀번호를 제공한다.
3. 시스템이 현재 비밀번호를 검증하고, 새 비밀번호가 규칙에 맞으며 지금 것과 다름을 검증한다.
4. 시스템이 비밀번호를 바꾸고, 지금 쓰는 자리를 뺀 나머지 세션을 거둔다.
5. 사용자가 바뀐 사실을 확인하고 하던 일을 계속한다.

1단계의 자리는 [USR-003 프로필 관리](<./USR-003(프로필 관리).md>)의 화면이다.

**현재 비밀번호를 다시 받는다.** 로그인 상태만으로 바꾸게 하면, 자리를 비운 사이 남이 그 화면을 열어 비밀번호를 갈고 주인을 밀어낼 수 있다.

**4단계는 지금 쓰는 자리를 남긴다.** 이 경로는 현재 비밀번호를 아는 채로 지나므로 조작하는 사람이 주인임이 확인되며, 자기 자리까지 거두면 방금 바꾼 사람이 다시 로그인해야 한다. 나머지를 거두는 것은 바꾸는 이유가 대개 다른 자리를 믿을 수 없게 된 것이기 때문이다. API 토큰은 남긴다. 그것을 거두는 자리는 [USR-005 비밀번호 재설정](<./USR-005(비밀번호 재설정).md>)이며, 비밀번호를 모르는 채로 지나는 경로만이 앞선 자리들을 의심할 근거를 갖는다.

## 대체 흐름 (Alternate Flows)

### A1 현재 비밀번호가 맞지 않는다

- **시작 조건:** 3단계에서 제공한 현재 비밀번호가 계정의 것과 다르다.
- **처리 절차:**
  1. 시스템이 현재 비밀번호가 맞지 않음을 알리고 아무것도 바꾸지 않는다.
  2. **기본 흐름 2로 복귀.**

기억나지 않으면 [USR-005 비밀번호 재설정](<./USR-005(비밀번호 재설정).md>)으로 간다.

### A2 새 비밀번호가 규칙에 맞지 않는다

- **시작 조건:** 3단계에서 새 비밀번호가 규칙을 충족하지 않는다.
- **처리 절차:**
  1. 시스템이 충족하지 못한 규칙을 알린다.
  2. **기본 흐름 2로 복귀.**

규칙의 내용은 [결정-0012](../../architecture/decisions/0012-shared-credential-policy.md)가 갖는다.

### A3 새 비밀번호가 지금 것과 같다

- **시작 조건:** 3단계에서 새 비밀번호가 현재 비밀번호와 같다.
- **처리 절차:**
  1. 시스템이 달라야 함을 알리고 아무것도 바꾸지 않는다.
  2. **기본 흐름 2로 복귀.**

## 미결

- 바꾼 사실을 메일로 알릴지. 계정이 이미 남에게 넘어간 뒤라면 주인이 그것을 알아챌 자리가 여기밖에 없다
