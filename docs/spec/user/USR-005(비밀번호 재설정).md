# USR-005 비밀번호 재설정

- **목표:** 비밀번호가 기억나지 않아 들어가지 못하는 상태에서 벗어나, 다시 내 계정으로 들어간다.
- **주 액터:** 사용자
- **지원 액터:** 메일 발송 서비스
- **트리거:** 로그인하려 했으나 비밀번호가 기억나지 않는다.

## 기본 흐름 (Basic Flow)

1. 사용자가 가입한 이메일을 제공한다.
2. 시스템이 일회용 코드를 그 이메일로 보내고, 코드를 받을 자리를 보인다.
3. 사용자가 받은 코드와 새 비밀번호를 제공한다.
4. 시스템이 코드를 검증하고 새 비밀번호가 규칙에 맞음을 검증한다.
5. 시스템이 비밀번호를 바꾸고 그 계정의 세션과 API 토큰을 모두 거둔다.
6. 사용자가 새 비밀번호로 로그인한다.

6단계는 [USR-002 계정 로그인](<./USR-002(계정 로그인).md>)이다.

**2단계의 응답은 그 이메일의 등록 여부와 무관하게 같다.** 구분해 알리면 그 차이가 곧 가입 여부를 알려 주는 신호가 된다([결정-0004](../../architecture/decisions/0004-shared-error-contract.md)).

**5단계는 세션만이 아니라 API 토큰까지 거둔다.** 이 경로는 비밀번호를 모르는 상태에서 지나므로, 그것을 지난 사람이 계정의 주인이라는 것 말고 앞서 열린 자리들이 정당하다고 볼 근거가 남지 않는다. 대가는 에이전트를 다시 연결해야 하는 것이며, 재설정이 드물게 일어나는 일이라 그 쪽을 택했다.

## 대체 흐름 (Alternate Flows)

### A1 등록되지 않은 이메일이다

- **시작 조건:** 1단계의 이메일로 만들어진 계정이 없다.
- **처리 절차:**
  1. 시스템이 메일을 보내지 않고, 보낸 경우와 같은 응답을 낸다.
  2. **기본 흐름 2로 복귀.**

사용자에게는 이 흐름과 기본 흐름이 구분되지 않는다. 코드를 받지 못한 채 3단계에 이르면 A5 로 끝난다.

### A2 재설정 수단이 만료되었다

- **시작 조건:** 4단계에서 코드의 수명이 지났다.
- **처리 절차:**
  1. 시스템이 코드가 만료되었음을 알리고 다시 받을 수단을 보인다.
  2. **A3 으로 이어진다.**

### A3 재설정 수단을 다시 요청한다

- **시작 조건:** 2단계 뒤, 사용자가 코드를 받지 못했거나 코드가 만료되었다.
- **처리 절차:**
  1. 시스템이 앞서 보낸 코드를 거두고 새 코드를 보낸다.
  2. **기본 흐름 3으로 복귀.**

### A4 새 비밀번호가 규칙에 맞지 않는다

- **시작 조건:** 4단계에서 새 비밀번호가 규칙을 충족하지 않는다.
- **처리 절차:**
  1. 시스템이 충족하지 못한 규칙을 알리고 코드는 그대로 둔다.
  2. **기본 흐름 3으로 복귀.**

규칙의 내용은 [결정-0012](../../architecture/decisions/0012-shared-credential-policy.md)가 갖는다.

### A5 코드가 맞지 않는다

- **시작 조건:** 4단계에서 제공한 코드가 보낸 코드와 다르거나, 보낸 코드가 없다.
- **처리 절차:**
  1. 시스템이 코드가 맞지 않음을 알린다.
  2. **기본 흐름 3으로 복귀.**

정해진 횟수를 넘겨 틀리면 그 코드를 거두고 A2 와 같은 자리에 둔다. 등록되지 않은 이메일로 요청한 경우도 이 흐름을 탄다.

## 미결

- 코드 요청의 반복에 대한 제한. [USR-001](<./USR-001(계정 회원가입).md>)과 같은 자리다
