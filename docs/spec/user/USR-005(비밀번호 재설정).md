# USR-005 비밀번호 재설정

- **목표:** 비밀번호가 기억나지 않아 들어가지 못하는 상태에서 벗어나, 다시 내 계정으로 들어간다.
- **주 액터:** 사용자
- **지원 액터:** 메일 발송 서비스
- **트리거:** 로그인하려 했으나 비밀번호가 기억나지 않는다.

> 초안이다. 기본 흐름은 단계까지 쓰고 대체 흐름은 조건 이름만 둔다. 세부 절차는 그 흐름을 지나는 슬라이스에 착수할 때 쓴다.

## 기본 흐름 (Basic Flow)

1. 사용자가 가입한 이메일을 제공한다.
2. 시스템이 재설정 수단을 그 이메일로 보낸다.
3. 사용자가 받은 수단으로 새 비밀번호를 제공한다.
4. 시스템이 비밀번호를 바꾸고 기존 로그인 상태를 거둔다.
5. 사용자가 새 비밀번호로 로그인한다.

5단계는 [USR-002 계정 로그인](<./USR-002(계정 로그인).md>)이다.

## 대체 흐름 (Alternate Flows)

- **A1 등록되지 않은 이메일이다**
- **A2 재설정 수단이 만료되었다**
- **A3 재설정 수단을 다시 요청한다**
- **A4 새 비밀번호가 규칙에 맞지 않는다**

## 미결

- 2단계의 응답은 그 이메일의 등록 여부와 무관하게 같아야 한다. 구분해 알리면 그 차이가 곧 가입 여부를 알려 주는 신호가 된다([결정-0004](../../architecture/decisions/0004-shared-error-contract.md))
- 재설정 수단의 형태와 수명. 일회용이며 저장은 [결정-0005](../../architecture/decisions/0005-shared-authentication.md)의 해시 방식을 따르는 것을 전제한다
- 4단계에서 거두는 범위. 세션만 거둘지 API 토큰까지 거둘지
- 메일 발송 서비스의 선정. 이 유스케이스는 그것이 붙어야 성립한다
