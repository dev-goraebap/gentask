# USR-005 비밀번호 재설정

- **목표:** 비밀번호 분실 시 이메일 인증을 통해 비밀번호를 재설정하고 계정 접근 권한을 복구한다.
- **주 액터:** 사용자
- **지원 액터:** 메일 발송 서비스
- **트리거:** 비밀번호를 분실하여 로그인이 불가능하다.

## 기본 흐름 (Basic Flow)

1. 사용자가 가입된 이메일을 입력한다.
2. 시스템이 일회용 인증 코드를 해당 이메일로 발송하고 코드 입력 폼을 활성화한다.
3. 사용자가 수신한 인증 코드와 새 비밀번호를 입력한다.
4. 시스템이 인증 코드를 검증하고 새 비밀번호가 복잡도 규칙에 부합하는지 검증한다.
5. 시스템이 비밀번호를 갱신하고 해당 계정의 모든 활성 세션과 API 토큰을 일괄 만료 처리한다.
6. 사용자가 새 비밀번호로 로그인을 진행한다([USR-002 계정 로그인](<./USR-002(계정 로그인).md>)).

이메일 존재 여부 유출을 방지하기 위해 2단계 응답은 이메일 가입 여부와 무관하게 동일하게 반환한다([결정-0004](../../architecture/decisions/0004-shared-error-contract.md)).

보안을 위해 비밀번호 재설정 시 기존 세션과 API 토큰을 전체 만료 처리한다.

## 대체 흐름 (Alternate Flows)

### A1 미등록 이메일로 요청한다

- **시작 조건:** 1단계에서 입력된 이메일의 계정이 존재하지 않는다.
- **처리 절차:**
  1. 시스템이 실제 메일을 발송하지 않고 정상 발송과 동일한 응답을 반환한다.
  2. **기본 흐름 2로 복귀.**

### A2 인증 코드가 만료되었다

- **시작 조건:** 4단계에서 인증 코드 유효 시간이 경과했다.
- **처리 절차:**
  1. 시스템이 코드 만료를 안내하고 재발송 수단을 제공한다.
  2. **A3으로 이어진다.**

### A3 인증 코드를 재요청한다

- **시작 조건:** 2단계 후, 사용자가 인증 코드를 수신하지 못했거나 만료되어 재발송을 요청한다.
- **처리 절차:**
  1. 시스템이 기존 코드를 만료 처리하고 신규 인증 코드를 발송한다.
  2. **기본 흐름 3으로 복귀.**

### A4 새 비밀번호가 규칙에 부합하지 않는다

- **시작 조건:** 4단계에서 새 비밀번호가 복잡도 규칙을 충족하지 못한다.
- **처리 절차:**
  1. 시스템이 미충족 규칙을 안내하고 인증 코드는 유효하게 유지한다.
  2. **기본 흐름 3으로 복귀.**

비밀번호 복잡도 규칙은 [결정-0012](../../architecture/decisions/0012-shared-credential-policy.md)를 따른다.

### A5 인증 코드가 일치하지 않는다

- **시작 조건:** 4단계에서 입력한 인증 코드가 발송된 코드와 일치하지 않는다.
- **처리 절차:**
  1. 시스템이 인증 코드가 올바르지 않음을 안내한다.
  2. **기본 흐름 3으로 복귀.**

연속 입력 실패 한도 초과 시 코드를 무효화하고 재발급을 요구한다.

## 미결

- 인증 코드 재발송 요청 횟수 제한(Rate Limiting) 정책
