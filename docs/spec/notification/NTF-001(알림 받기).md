# NTF-001 알림 받기

- **목표:** 현재 기기에 푸시 알림을 수신 등록하여 앱을 직접 열람하지 않고도 예정된 작업 일정을 인지할 수 있도록 한다.
- **주 액터:** 사용자
- **지원 액터:** 웹 푸시 서비스 (브라우저 벤더 운영)
- **선행 조건:** iOS 환경의 경우 홈 화면에 웹앱(PWA)으로 설치되어 있어야 한다.
- **트리거:** 기기에서 작업 미리 알림을 푸시 알림으로 수신하고자 한다.

## 기본 흐름 (Basic Flow)

1. 사용자가 현재 기기에서 알림 수신 활성화를 요청한다.
2. 시스템이 브라우저 알림 권한을 요청한다.
3. 사용자가 알림 권한을 허용한다.
4. 시스템이 현재 기기의 푸시 구독 엔드포인트를 서버에 등록한다.
5. 시스템이 기기의 알림 수신 활성화 상태를 화면에 표시한다.

## 대체 흐름 (Alternate Flows)

### A1 알림 권한을 거절한다

- **시작 조건:** 3단계에서 사용자가 권한을 허용하지 않는다.
- **경로:**
  1. 시스템이 알림 비활성화 상태를 유지한다.
  2. 시스템이 브라우저 설정에서 권한을 직접 재허용할 수 있음을 안내한다.

브라우저 정책상 거절된 권한은 스크립트로 재요청할 수 없으므로 사용자 수동 변경을 안내한다.

### A2 알림을 비활성화한다

- **시작 조건:** 알림 활성화 상태에서 사용자가 현재 기기의 알림 수신 중단을 요청한다.
- **경로:**
  1. 시스템이 서버에 등록된 해당 기기의 푸시 구독 정보를 삭제한다.
  2. 시스템이 알림 비활성화 상태를 표시한다.

브라우저 권한은 유지되며 서버의 푸시 구독 정보만 해제된다.

### A3 다른 기기에서 알림을 등록한다

- **시작 조건:** 기존 기기에 알림이 등록된 상태에서 새로운 기기로 기본 흐름을 진행한다.
- **경로:**
  1. 시스템이 신규 기기의 푸시 구독 엔드포인트를 추가 등록한다.

구독 엔드포인트는 기기별로 독립 관리되므로 한 기기에서 비활성화하더라도 타 기기의 수신 상태는 유지된다.

### A4 구독 엔드포인트가 만료된다

- **시작 조건:** 등록된 엔드포인트로 푸시 발송 시 웹 푸시 서비스로부터 엔드포인트 만료(`410 Gone`)가 반환된다.
- **경로:**
  1. 시스템이 해당 구독 엔드포인트를 서버에서 삭제한다.
  2. 사용자가 이후 화면에 접속하면 시스템이 알림 비활성화 상태로 표시한다.

알림 활성화 여부는 브라우저 로컬 저장소가 아닌 서버에 등록된 유효 구독 엔드포인트를 기준으로 판정한다.

### A5 iOS 환경에서 알림을 활성화한다

- **시작 조건:** 1단계에서 접속 기기가 iOS이며 홈 화면에 설치되어 있지 않다.
- **경로:**
  1. 시스템이 홈 화면 추가(PWA 설치) 필요성 및 절차를 안내한다.
  2. 사용자가 브라우저 공유 메뉴를 통해 홈 화면에 웹앱을 추가한다.
  3. 사용자가 홈 화면 아이콘을 통해 앱을 다시 실행한다.
  4. **기본 흐름 1로 복귀.**

iOS 정책상 홈 화면에 설치된 웹앱에서만 푸시 알림 API 호출이 허용된다.

## 예외 흐름 (Exception Flows)

### E1 브라우저가 웹 푸시를 미지원한다

- **시작 조건:** 1단계에서 브라우저 환경이 웹 푸시 API를 지원하지 않는다.
- **경로:**
  1. 시스템이 해당 기기에서 알림 수신이 불가함을 안내한다.

## 미결

- 알림 유형별 선택적 수신 설정
- 방해 금지 시간대 설정

## 범위 밖

PWA 매니페스트 및 아이콘 에셋 구성, 스케줄링 발송 워커 로직은 본 유스케이스 범위에 포함하지 않는다.
