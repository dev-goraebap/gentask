# DOC-005 개정 되돌리기

- **목표:** 문서를 이전 특정 개정 시점의 상태로 복원하여 변경 사항의 가역성을 확보한다.
- **주 액터:** 사용자
- **지원 액터:** 없음
- **트리거:** 최근 수정된 내용보다 이전 개정의 내용이 더 적합하다고 판단되었다.

## 기본 흐름 (Basic Flow)

1. 사용자가 문서 개정 이력 화면으로 진입한다.
2. 사용자가 복원 대상 개정을 선택한다.
3. 시스템이 해당 개정의 본문 내용을 표시하고 복원 확인을 요청한다.
4. 사용자가 복원을 확인한다.
5. 시스템이 해당 개정의 본문을 복사한 **신규 개정**을 등록하고 문서의 최신 개정 참조를 갱신한다.

개정 되돌리기는 중간 개정을 삭제하지 않고 대상 시점의 본문을 새로운 개정으로 추가 등록하는 방식이다.

되돌리기 작업 자체도 새로운 개정으로 기록되므로 언제든 재복원이 가능하다.

확인 절차를 두어 사용자가 복원 시점을 명확히 검토할 수 있도록 한다.

## 대체 흐름 (Alternate Flows)

### A1 되돌리기를 취소한다

- **시작 조건:** 3단계 확인 화면에서 사용자가 작업을 취소한다.
- **처리 절차:**
  1. 시스템이 신규 개정을 생성하지 않는다.
  2. **실패로 종료.**

### A2 현재 개정과 동일한 버전으로 되돌린다

- **시작 조건:** 5단계에서 선택한 개정의 본문이 현재 유효한 개정과 동일하다.
- **처리 절차:**
  1. 시스템이 새 개정을 생성하지 않고 상세 조회 화면으로 이동한다.
  2. **다른 성공으로 종료.**

[DOC-003](<./DOC-003(문서 편집).md>)의 변경 없는 저장 방지 정책과 동일하게 적용한다.

### A3 되돌리기 사유를 기록한다

- **시작 조건:** 4단계 후, 사용자가 복원 사유를 입력한다.
- **처리 절차:**
  1. 사용자가 단문 사유를 입력한다.
  2. **기본 흐름 5로 복귀.**

사유 미입력 시 시스템이 복원 대상 개정 번호를 사유 필드에 자동 기록한다.

### A4 문서가 존재하지 않는다

- **시작 조건:** 5단계에서 대상 문서가 이미 삭제되었다.
- **처리 절차:**
  1. 시스템이 해당 리소스가 존재하지 않음을 알린다.
  2. **실패로 종료.**

### A5 타인 프로젝트의 문서 복원

- **시작 조건:** 5단계에서 대상 문서가 사용자의 프로젝트에 속하지 않는다.
- **처리 절차:**
  1. 시스템이 해당 리소스가 존재하지 않음을 알린다.
  2. **실패로 종료.**

보안을 위해 권한 없음 대신 리소스 부재로 응답한다.

### A6 CLI에서 되돌린다

- **시작 조건:** 2단계에서 CLI(`gentask`)로 되돌리기를 개시한다.
- 처리 절차는 해당 슬라이스 착수 시 기술한다.
