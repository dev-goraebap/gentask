# DOC-009 문서 첨부 관리

- **목표:** 본문에 직접 포함하기 어려운 원본 자료를 문서에 첨부하여 관련 자료의 접근성을 보장한다.
- **주 액터:** 사용자
- **지원 액터:** 오브젝트 스토리지
- **트리거:** 텍스트로 기술하기 어려운 파일이나 참고 자료를 문서에 연계해야 한다.

## 기본 흐름 (Basic Flow)

1. 사용자가 문서 상세 화면으로 진입한다.
2. 사용자가 첨부할 파일을 선택한다.
3. 시스템이 파일 형식과 크기가 업로드 정책에 부합하는지 검증하고 Presigned Upload URL을 발급한다.
4. 클라이언트 브라우저가 발급받은 URL을 통해 오브젝트 스토리지에 직접 업로드한다.
5. 시스템이 오브젝트 스토리지의 실제 저장 크기를 재검증한 후 해당 문서에 첨부 관계를 등록한다.
6. 시스템이 첨부 파일 목록에 추가된 파일을 표시한다.

서버 부하를 방지하기 위해 클라이언트-스토리지 직업로드 방식을 채택한다.

업로드 중 파일 변조를 방지하기 위해 스토리지 실측 크기로 2차 검증을 수행한다.

본문 인라인 이미지와 달리 첨부 파일은 문서의 메타데이터 목록으로 관리한다.

문서 삭제 시 연결된 첨부 파일도 함께 삭제 처리한다.

## 대체 흐름 (Alternate Flows)

### A1 정책에 부합하지 않는 형식 또는 크기

- **시작 조건:** 3단계에서 파일 확장자가 허용되지 않거나 최대 허용 크기를 초과한다.
- **처리 절차:**
  1. 시스템이 업로드 URL을 발급하지 않고 거절 사유를 알린다.
  2. **실패로 종료.**

### A2 최대 첨부 개수 초과

- **시작 조건:** 5단계에서 해당 문서의 첨부 파일 개수가 한도를 초과한다.
- **처리 절차:**
  1. 시스템이 첨부 등록을 거절하고 스토리지에 임시 업로드된 객체를 삭제한다.
  2. 시스템이 실패 사유를 알린다.
  3. **실패로 종료.**

### A3 업로드 취소 또는 네트워크 단절

- **시작 조건:** 4단계에서 사용자가 취소하거나 네트워크 연결이 끊긴다.
- **처리 절차:**
  1. 시스템이 문서에 첨부를 등록하지 않는다.
  2. **실패로 종료.**

### A4 첨부 파일을 다운로드한다

- **시작 조건:** 1단계 후, 사용자가 첨부 파일 다운로드를 요청한다.
- **처리 절차:**
  1. 시스템이 시한부 접근 URL(Presigned Download URL)을 생성하여 반환한다.
  2. 클라이언트 브라우저가 해당 URL을 통해 파일을 다운로드한다.
  3. **다른 성공으로 종료.**

무단 공유를 방지하기 위해 다운로드 URL에는 만료 시간을 설정한다.

### A5 첨부 파일을 삭제한다

- **시작 조건:** 1단계 후, 사용자가 특정 첨부 파일의 삭제를 요청한다.
- **처리 절차:**
  1. 시스템이 대상 파일을 표시하고 삭제 재확인을 요청한다.
  2. 사용자가 삭제를 확정한다.
  3. 시스템이 문서와의 첨부 관계를 해제하고 스토리지의 객체를 삭제한다.
  4. **다른 성공으로 종료.**

### A6 타인 프로젝트의 문서 첨부 접근

- **시작 조건:** 5단계 또는 A4·A5 단계에서 대상 문서가 사용자의 프로젝트에 속하지 않는다.
- **처리 절차:**
  1. 시스템이 해당 리소스가 존재하지 않음을 알린다.
  2. **실패로 종료.**

보안을 위해 권한 없음 대신 리소스 부재로 응답한다.

### A7 타인이 발급받은 스토리지 키로 등록 시도

- **시작 조건:** 5단계에서 업로드 키 발급자와 첨부 등록 요청자가 일치하지 않는다.
- **처리 절차:**
  1. 시스템이 리소스 부재로 응답한다.
  2. **실패로 종료.**

### A8 에이전트의 파일 첨부

- **시작 조건:** 2단계에서 CLI를 통해 첨부를 개시한다.
- 처리 절차는 해당 슬라이스 착수 시 기술한다.
