# DOC-001 문서 작성

- **목표:** 프로젝트 관련 의사결정과 명세를 중앙 저장소에 기록하여 팀원과 에이전트가 동일한 정보를 참조할 수 있도록 한다.
- **주 액터:** 사용자
- **지원 액터:** 없음
- **트리거:** 프로젝트에 기록할 지식이나 결정 사항이 발생했다.

## 기본 흐름 (Basic Flow)

1. 사용자가 문서 작성 화면으로 진입한다.
2. 사용자가 문서 생성을 요청한다.
3. 시스템이 제목 및 본문 입력 폼을 활성화한다.
4. 사용자가 제목을 입력한다.
5. 시스템이 제목이 비어 있지 않음을 검증한다.
6. 시스템이 문서를 생성하고 초기 개정을 등록한 후 상세 조회 화면으로 이동한다.

문서 생성과 초기 개정 등록은 단일 트랜잭션으로 처리한다. 문서는 유효한 최신 개정을 참조하며, 상세 이력 구조는 [DOC-004](<./DOC-004(개정 이력 보기).md>)를 따른다.

본문은 빈 상태로 등록할 수 있으며 필수 검증 대상은 제목이다.

## 대체 흐름 (Alternate Flows)

### A1 제목이 비어 있다

- **시작 조건:** 5단계에서 제목이 비어 있다.
- **처리 절차:**
  1. 시스템이 제목 입력이 필요함을 알린다.
  2. 사용자가 제목을 다시 입력한다.
  3. **기본 흐름 5로 복귀.**

### A2 폴더 내에 생성한다

- **시작 조건:** 2단계에서 사용자가 특정 폴더 화면에 위치한다.
- **처리 절차:**
  1. 시스템이 해당 폴더를 저장 위치로 지정한다.
  2. **기본 흐름 3으로 복귀.**

현재 진입 중인 폴더 위치를 저장 위치로 지정하며, 위치 변경은 [DOC-006](<./DOC-006(문서 옮기기).md>)을 이용한다.

### A3 작성을 취소한다

- **시작 조건:** 3–5단계에서 사용자가 작성을 취소한다.
- **처리 절차:**
  1. 시스템이 문서를 저장하지 않는다.
  2. **실패로 종료.**

### A4 동일한 제목의 문서가 이미 존재한다

- **시작 조건:** 6단계에서 동일 폴더 내 동일한 제목의 문서가 이미 존재한다.
- **처리 절차:**
  1. 시스템이 문서를 정상 생성한다.
  2. **기본 흐름 6으로 복귀.**

문서 식별자가 고유하므로 동일 위치 내 제목 중복을 허용한다.

### A5 타인의 프로젝트에 생성을 시도한다

- **시작 조건:** 6단계에서 해당 프로젝트가 사용자의 소유가 아니다.
- **처리 절차:**
  1. 시스템이 해당 리소스가 존재하지 않음을 알린다.
  2. **실패로 종료.**

프로젝트 존재 여부 노출을 방지하기 위해 권한 없음 대신 리소스 부재로 응답한다.

### A6 CLI에서 작성한다

- **시작 조건:** 2단계에서 CLI(`gentask`)로 요청을 개시한다.
- 처리 절차는 해당 슬라이스 착수 시 기술한다.
