# DOC-002 문서 조회

- **목표:** 프로젝트에서 정의한 의사결정과 명세를 확인하여 불필요한 중복 논의를 방지한다.
- **주 액터:** 사용자
- **지원 액터:** 없음
- **트리거:** 기결정 사항이나 명세 내용의 확인이 필요하다.

## 기본 흐름 (Basic Flow)

1. 사용자가 프로젝트 문서 목록 화면으로 진입한다.
2. 시스템이 해당 위치의 폴더 및 문서 목록을 표시한다.
3. 사용자가 문서를 선택한다.
4. 시스템이 유효한 최신 개정의 본문을 렌더링하여 표시한다.

문서 조회를 독립적인 목표로 분리하여 정의한다.

상세 조회는 현재 유효한 최신 개정만 표시하며, 이전 이력은 [DOC-004](<./DOC-004(개정 이력 보기).md>)에서 조회한다.

보안 취약점을 방지하기 위해 마크다운 본문은 안전하게 렌더링한다.

## 대체 흐름 (Alternate Flows)

### A1 하위 폴더로 진입한다

- **시작 조건:** 3단계에서 사용자가 폴더를 선택한다.
- **처리 절차:**
  1. 시스템이 해당 폴더 내 하위 폴더 및 문서 목록을 표시한다.
  2. 시스템이 탐색 경로(Breadcrumbs)를 표시한다.
  3. **기본 흐름 3으로 복귀.**

### A2 문서 목록이 비어 있다

- **시작 조건:** 2단계에서 해당 위치에 폴더와 문서가 존재하지 않는다.
- **처리 절차:**
  1. 시스템이 빈 상태 안내 메시지와 문서 작성 링크를 표시한다.
  2. **다른 성공으로 종료.**

### A3 문서가 존재하지 않는다

- **시작 조건:** 4단계에서 조회 대상 문서가 이미 삭제되었다.
- **처리 절차:**
  1. 시스템이 해당 리소스가 존재하지 않음을 알린다.
  2. **실패로 종료.**

### A4 타인 프로젝트의 문서 조회

- **시작 조건:** 4단계에서 해당 문서가 사용자의 프로젝트에 속하지 않는다.
- **처리 절차:**
  1. 시스템이 해당 리소스가 존재하지 않음을 알린다.
  2. **실패로 종료.**

보안을 위해 권한 없음 대신 리소스 부재로 응답한다.

### A5 CLI에서 조회한다

- **시작 조건:** 1단계에서 CLI(`gentask`)로 요청을 개시한다.
- **처리 절차:**
  1. 시스템이 마크다운 원본 텍스트를 출력한다.
  2. **다른 성공으로 종료.**

### A6 본문에 이미지 또는 다이어그램 포함

- **시작 조건:** 4단계에서 본문에 이미지 또는 다이어그램이 포함되어 있다.
- 처리 절차는 해당 슬라이스 착수 시 기술한다.
