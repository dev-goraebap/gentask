# DOC-004 개정 이력 조회

- **목표:** 문서의 변경 이력을 확인하여 특정 내용이 작성된 시점과 변경 맥락을 파악한다.
- **주 액터:** 사용자
- **지원 액터:** 없음
- **트리거:** 문서의 과거 버전 내용이나 변경 사유 확인이 필요하다.

## 기본 흐름 (Basic Flow)

1. 사용자가 문서 상세 화면으로 진입한다.
2. 사용자가 개정 이력 조회를 요청한다.
3. 시스템이 개정 목록을 최신순으로 정렬하여 표시한다 (개정 번호, 변경 시각, 작성자, 사유 포함).
4. 사용자가 특정 개정을 선택한다.
5. 시스템이 해당 개정 시점의 본문을 렌더링하여 표시한다.

개정 이력 조회를 독립적인 목표로 분리하여 정의한다. 개정 되돌리기는 [DOC-005](<./DOC-005(개정 되돌리기).md>)에서 다룬다.

각 개정 레코드는 당시 본문 전체의 스냅샷을 영속화한다. 조회 성능을 최적화하기 위해 diff 누적 방식 대신 전체 본문 저장 방식을 채택한다.

개정 간 차이(diff)는 별도 저장하지 않고 조회 시점에 동적으로 계산한다.

개정 레코드는 불변 데이터이므로 개별 수정이나 삭제를 허용하지 않는다.

## 대체 흐름 (Alternate Flows)

### A1 두 개정을 비교한다

- **시작 조건:** 4단계에서 사용자가 두 개의 개정을 선택한다.
- **처리 절차:**
  1. 시스템이 두 개정 본문 간의 diff를 계산하여 표시한다.
  2. **다른 성공으로 종료.**

### A2 개정이 하나만 존재한다

- **시작 조건:** 3단계에서 문서 작성 후 수정 이력이 존재하지 않는다.
- **처리 절차:**
  1. 시스템이 초기 생성 개정 1건만 목록에 표시한다.
  2. **기본 흐름 4로 복귀.**

### A3 개정 이력이 다수 존재한다

- **시작 조건:** 3단계에서 개정 목록이 단일 화면 표시 한도를 초과한다.
- **처리 절차:**
  1. 시스템이 최신 항목부터 페이징 처리하여 표시한다.
  2. **기본 흐름 4로 복귀.**

### A4 문서가 존재하지 않는다

- **시작 조건:** 3단계에서 대상 문서가 이미 삭제되었다.
- **처리 절차:**
  1. 시스템이 해당 리소스가 존재하지 않음을 알린다.
  2. **실패로 종료.**

### A5 타인 프로젝트의 문서 조회

- **시작 조건:** 3단계에서 대상 문서가 사용자의 프로젝트에 속하지 않는다.
- **처리 절차:**
  1. 시스템이 해당 리소스가 존재하지 않음을 알린다.
  2. **실패로 종료.**

보안을 위해 권한 없음 대신 리소스 부재로 응답한다.

### A6 CLI에서 조회한다

- **시작 조건:** 2단계에서 CLI(`gentask`)로 조회를 개시한다.
- 처리 절차는 해당 슬라이스 착수 시 기술한다.

### A7 오래된 개정 정리

- **시작 조건:** 3단계에서 보관 정책에 따른 이전 개정 정리 요구가 발생한다.
- 처리 절차는 해당 슬라이스 착수 시 기술한다.
