# TSK-001 작업 추가

- **목표:** 할 일을 등록하여 기억에 의존하지 않고 체계적으로 관리한다.
- **주 액터:** 사용자
- **지원 액터:** 없음
- **트리거:** 새로운 할 일이 발생했다.

## 기본 흐름 (Basic Flow)

1. 사용자가 신규 작업 추가를 요청한다.
2. 시스템이 입력 폼을 활성화한다.
3. 사용자가 작업 제목을 입력한다.
4. 시스템이 제목이 비어 있지 않음을 검증한다.
5. 시스템이 작업을 목록에 등록한다.
6. 사용자가 목록에서 추가된 작업을 확인한다.

## 대체 흐름 (Alternate Flows)

선택적 단계(A2–A4, A7)는 상호 조합될 수 있으며 조합마다 별도의 대체 흐름을 생성하지 않는다.

### A1 제목이 비어 있다

- **시작 조건:** 4단계에서 제목이 비어 있다.
- **처리 절차:**
  1. 시스템이 제목 입력이 필요함을 알린다.
  2. 사용자가 제목을 다시 입력한다.
  3. **기본 흐름 4로 복귀.**
- 사용자가 추가를 취소하면 A5로 이동한다.

### A2 기한을 설정한다

- **시작 조건:** 3단계 후, 사용자가 완료 기한을 설정한다.
- **처리 절차:**
  1. 사용자가 기한 일자를 지정한다.
  2. 시스템이 기한을 작업 속성에 바인딩한다.
  3. **기본 흐름 4로 복귀.**

### A3 미리 알림을 설정한다

- **시작 조건:** 3단계 후, 사용자가 미리 알림을 설정한다.
- **처리 절차:**
  1. 사용자가 알림 시각을 지정한다.
  2. 시스템이 미리 알림 시각을 작업 속성에 바인딩한다.
  3. **기본 흐름 4로 복귀.**

알림 수신 환경 구성은 [NTF-001](<../notification/NTF-001(알림 받기).md>)에서 정의하며, 예약 시각 발송 처리는 백로그 스토리의 인수 조건으로 검증한다.

기한(A2)과 미리 알림(A3)은 독립 속성이며 상호 배타적이지 않다.

### A4 반복 주기를 설정한다

- **시작 조건:** 3단계 후, 사용자가 반복 주기를 설정한다.
- 처리 절차는 해당 슬라이스 착수 시 기술한다.

### A5 추가를 취소한다

- **시작 조건:** 1–4단계에서 사용자가 추가를 취소한다.
- **처리 절차:**
  1. 시스템이 작업을 목록에 등록하지 않는다.
  2. **실패로 종료.**

### A6 (결번)

### A7 스마트 목록 화면에서 추가한다

- **시작 조건:** 1단계에서 사용자가 특정 스마트 목록(TSK-002 A2–A4)을 조회 중인 상태에서 추가를 요청한다.
- **처리 절차:**
  1. 시스템이 해당 스마트 목록의 속성(나의 하루, 중요, 기한)을 작업에 자동 적용한다.
  2. **기본 흐름 4로 복귀.**
