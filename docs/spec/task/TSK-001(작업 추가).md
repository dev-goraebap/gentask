# TSK-001 작업 추가

- **목표:** 떠오른 일을 목록에 남겨, 기억에 의존하지 않는다.
- **주 액터:** 사용자
- **지원 액터:** 없음
- **트리거:** 할 일이 떠올랐다.

## 기본 흐름 (Basic Flow)

1. 사용자가 새 작업을 추가하겠다고 한다.
2. 시스템이 적을 수 있게 한다.
3. 사용자가 제목을 적는다.
4. 시스템이 제목이 비어 있지 않음을 검증한다.
5. 시스템이 작업을 목록에 넣는다.
6. 사용자가 목록에서 방금 적은 작업을 확인한다.

## 대체 흐름 (Alternate Flows)

선택(A2–A4, A7)은 서로 조합될 수 있다. 조합마다 대체 흐름을 두지 않는다.

### A1 제목이 비어 있다

- **시작 조건:** 4단계에서 제목이 비어 있다.
- **처리 절차:**
  1. 시스템이 제목이 필요함을 알린다.
  2. 사용자가 제목을 다시 적는다.
  3. **기본 흐름 4로 복귀.**
- 사용자가 추가를 그만두면 A5로 간다.

### A2 기한을 붙인다

- **시작 조건:** 3단계 뒤, 사용자가 기한을 붙이겠다고 한다.
- **처리 절차:**
  1. 사용자가 기한을 정한다.
  2. 시스템이 기한을 작업에 붙인다.
  3. **기본 흐름 4로 복귀.**

### A3 미리 알림을 붙인다

- **시작 조건:** 3단계 뒤, 사용자가 미리 알림을 붙이겠다고 한다.
- **처리 절차:**
  1. 사용자가 알릴 시각을 정한다.
  2. 시스템이 미리 알림을 작업에 붙인다.
  3. **기본 흐름 4로 복귀.**

붙이는 데까지가 이 유스케이스다. 정해진 시각에 무엇이 일어나는지는 사용자가 시작하는 흐름이 아니므로 여기 담기지 않고, 알림을 시스템이 직접 울릴지 바깥(지원 액터)에 맡길지도 그쪽에서 정한다. 지원 액터가 생기면 이 유스케이스가 아니라 그 유스케이스에 붙는다.

기한(A2)과 함께 붙일 수는 있다. 그때는 A2와 A3를 잇달아 지나는 경로이지, 새 대체 흐름이 아니다. 기한은 날짜만 갖고 미리 알림은 시각까지 갖는다. 하나를 정해도 다른 하나는 정해지지 않는다.

### A4 반복 주기를 붙인다

- **시작 조건:** 3단계 뒤, 사용자가 반복 주기를 붙이겠다고 한다.
- 처리 절차는 착수할 때 쓴다. 완료한 뒤 다음 회차가 어떻게 생기는지(TSK-004 와의 접점)가 먼저 정해져야 한다.

### A5 추가를 그만둔다

- **시작 조건:** 1–4단계 어디서든, 사용자가 추가를 그만둔다.
- **처리 절차:**
  1. 시스템이 작업을 목록에 넣지 않는다.
  2. **실패로 종료.** 기존 목록은 그대로다.

### A6 (결번)

식별 가능한 사유가 아니어서 걷었다.

### A7 스마트 목록 안에서 적는다

- **시작 조건:** 1단계에서 사용자가 특정 스마트 목록(TSK-002 A2–A4)을 보는 중에 적겠다고 한다.
- **처리 절차:**
  1. 시스템이 그 스마트 목록의 성질(나의 하루 추가됨 · 중요 · 기한)을 작업에 붙인다.
  2. **기본 흐름 4로 복귀.**

추가한 작업이 보고 있던 스마트 목록에 나타나지 않으면 사용자는 사라진 것으로 본다. 작업 목록(전체)에서는 붙일 성질이 없으므로 기본 흐름과 같다.
