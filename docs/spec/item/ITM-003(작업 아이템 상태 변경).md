# ITM-003 작업 아이템 상태 변경

- **목표:** 어디까지 왔는지를 항목에 남겨, 목록이 지금의 사실을 낸다.
- **주 액터:** 사용자
- **지원 액터:** 없음
- **트리거:** 어떤 작업 아이템의 처지가 달라졌다.

## 기본 흐름 (Basic Flow)

1. 사용자가 작업 아이템 하나를 연다.
2. 사용자가 옮길 상태를 고른다.
3. 시스템이 그 상태를 항목에 남긴다.
4. 사용자가 바뀐 상태를 확인한다.

상태는 다섯이다 — 백로그 · 예정 · 진행 중 · 완료 · 취소. 가르는 축이 착수 여부가 아니라 **하기로 정했는가**이며, 이름과 자리는 [결정-0007](../../architecture/decisions/0007-shared-software-process.md)이 갖는다.

## 대체 흐름 (Alternate Flows)

### A1 더 손댈 것이 없는 자리로 옮긴다

- **시작 조건:** 3단계에서 고른 상태가 완료이거나 취소다.
- **처리 절차:**
  1. 시스템이 그 순간을 닫힌 때로 남긴다.
  2. **기본 흐름 4로 복귀.**

완료와 취소가 닫힌 때를 함께 갖는 것은 둘 다 더 손대지 않는 자리이기 때문이다. 둘을 가르는 것은 인수 조건이 참임을 확인했는가이며, 취소는 근거를 잃어 더 이상 유효하지 않은 것이다.

### A2 닫힌 것을 되돌린다

- **시작 조건:** 3단계에서 닫혀 있던 항목을 닫히지 않은 상태로 옮긴다.
- **처리 절차:**
  1. 시스템이 닫힌 때를 지운다.
  2. **기본 흐름 4로 복귀.**

닫힌 때를 남겨 두면 목록의 닫힘 판정과 상세의 날짜가 서로 다른 것을 가리킨다.

### A3 이미 그 상태다

- **시작 조건:** 2단계에서 고른 상태가 지금 상태와 같다.
- **처리 절차:**
  1. 시스템이 아무것도 바꾸지 않는다.
  2. **성공으로 종료.** 닫힌 때도 그대로다.

### A4 남의 프로젝트의 항목이다

- **시작 조건:** 3단계에서 그 항목이 사용자의 프로젝트에 속하지 않는다.
- **처리 절차:**
  1. 시스템이 그 자리가 없음을 알린다.
  2. **실패로 종료.**

있으나 권한이 없다고 알리지 않는다. 그렇게 알리면 어떤 번호가 존재하는지가 새어 나간다.

### A5 자식이 남아 있는데 부모를 닫는다

- **시작 조건:** 3단계에서 닫으려는 항목에 닫히지 않은 자식이 있다.
- 처리 절차는 착수할 때 쓴다. 막을 것인지 알리기만 할 것인지가 정해지지 않았다.
