# ITM-005 작업 아이템 삭제

- **목표:** 잘못 생성되었거나 불필요한 작업 아이템을 삭제하여 백로그 목록을 정돈한다.
- **주 액터:** 사용자
- **지원 액터:** 없음
- **트리거:** 작업 아이템을 상태 변경(취소)이 아닌 영구 삭제로 제거해야 한다.

## 기본 흐름 (Basic Flow)

1. 사용자가 작업 아이템 상세 화면으로 진입한다.
2. 사용자가 작업 아이템 삭제를 요청한다.
3. 시스템이 삭제 대상 정보를 표시하고 삭제 재확인을 요청한다.
4. 사용자가 삭제를 확정한다.
5. 시스템이 해당 작업 아이템을 삭제하고 작업 아이템 목록 화면으로 이동한다.

취소 상태([ITM-003](<./ITM-003(작업 아이템 상태 변경).md>)의 `CANCELED`)와 구분한다. 작업 수행 취소 이력을 보존해야 하는 경우 상태 변경을 사용한다.

삭제된 작업 아이템의 식별 번호는 재사용하지 않는다. 커밋 메시지나 테스트 코드의 참조 무결성을 유지하기 위해 식별 번호는 영구 불변이다([결정-0007](../../architecture/decisions/0007-shared-software-process.md)).

## 대체 흐름 (Alternate Flows)

### A1 삭제를 취소한다

- **시작 조건:** 3단계 확인 화면에서 사용자가 삭제를 취소한다.
- **처리 절차:**
  1. 시스템이 작업 아이템을 삭제하지 않는다.
  2. **실패로 종료.**

### A2 하위 자식 항목이 존재한다

- **시작 조건:** 5단계에서 삭제 대상 작업 아이템을 부모로 참조하는 하위 항목이 존재한다.
- **처리 절차:**
  1. 시스템이 하위 자식 항목들을 최상위 계층으로 승격한다 (부모 참조 null 설정).
  2. **기본 흐름 5로 복귀.**

상위 항목 삭제 시 하위 항목은 연쇄 삭제하지 않고 최상위 계층으로 보존한다.

### A3 타인 프로젝트의 항목 삭제

- **시작 조건:** 5단계에서 대상 항목이 사용자의 프로젝트에 속하지 않는다.
- **처리 절차:**
  1. 시스템이 해당 리소스가 존재하지 않음을 알린다.
  2. **실패로 종료.**

보안을 위해 권한 없음 대신 리소스 부재로 응답한다.

### A4 이미 삭제된 항목을 삭제 시도한다

- **시작 조건:** 5단계에서 대상 식별자가 이미 존재하지 않는다.
- **처리 절차:**
  1. 시스템이 해당 리소스가 존재하지 않음을 알린다.
  2. **실패로 종료.**

### A5 삭제된 작업 아이템 복원

- **시작 조건:** 5단계 후, 사용자가 삭제된 작업 아이템의 복원을 요청한다.
- 처리 절차는 해당 슬라이스 착수 시 기술한다.
