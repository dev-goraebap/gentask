# ITM-002 작업 아이템 보기

- **목표:** 프로젝트에 무엇이 남아 있고 무엇이 어디에 속하는지를 한 자리에서 읽는다.
- **주 액터:** 사용자
- **지원 액터:** 없음
- **트리거:** 무엇을 할 차례인지 알아야 한다.

## 기본 흐름 (Basic Flow)

1. 사용자가 지금 프로젝트의 작업 아이템 목록을 연다.
2. 시스템이 아직 닫히지 않은 것을 계층 순으로 낸다.
3. 시스템이 각 줄에 번호 · 유형 · 상태 · 제목을 낸다.
4. 사용자가 목록에서 찾는 것을 확인한다.

닫힌 것을 기본으로 감추는 것은 목록이 할 일을 고르는 자리이기 때문이다. 감춘 개수를 함께 내어 사용자가 목록이 전부가 아님을 안다.

## 대체 흐름 (Alternate Flows)

거르개(A1, A2)는 서로 조합될 수 있다. 조합마다 대체 흐름을 두지 않는다.

### A1 유형으로 거른다

- **시작 조건:** 2단계 뒤, 사용자가 어떤 유형만 보겠다고 한다.
- **처리 절차:**
  1. 사용자가 유형을 켜고 끈다.
  2. 시스템이 켜진 유형만 남긴다.
  3. **기본 흐름 3으로 복귀.**

### A2 상태로 거른다

- **시작 조건:** 2단계 뒤, 사용자가 어떤 상태만 보겠다고 한다.
- **처리 절차:**
  1. 사용자가 상태를 켜고 끈다.
  2. 시스템이 켜진 상태만 남긴다.
  3. **기본 흐름 3으로 복귀.**
- 사용자가 전부 끄면 시스템은 남은 일로 되돌린다. 아무것도 보이지 않는 목록은 고를 것이 없는 화면과 구분되지 않기 때문이다.

거르개는 조합할 수 있으므로 자리가 아니라 주소의 쿼리가 갖는다. 이름 붙은 자리와 조합하는 거르개를 가르는 기준은 [결정-0007](../../architecture/decisions/0007-shared-software-process.md)이 갖는다.

### A3 하나를 열어 본다

- **시작 조건:** 4단계에서 사용자가 한 줄을 고른다.
- **처리 절차:**
  1. 시스템이 그 작업 아이템의 자리로 옮긴다.
  2. 시스템이 본문과 인수 조건과 자식을 낸다.
  3. **성공으로 종료.**

인수 조건의 수와 아직 확인되지 않은 수는 본문을 세어 낸다. 따로 저장하지 않는 것은 두 자리가 어긋났을 때 어느 쪽이 참인지 판정할 근거가 없기 때문이다.

### A4 목록이 비어 있다

- **시작 조건:** 2단계에서 낼 것이 하나도 없다.
- **처리 절차:**
  1. 시스템이 비어 있음과 세우는 길을 함께 낸다.
  2. **성공으로 종료.** 목표는 달성되지 않았으나 시스템은 정상이다.

### A5 없는 번호를 연다

- **시작 조건:** 사용자가 지금 프로젝트에 없는 번호의 자리를 곧바로 연다.
- **처리 절차:**
  1. 시스템이 그 자리가 없음을 알린다.
  2. **실패로 종료.**

다른 프로젝트의 번호도 여기에 해당한다. 번호는 프로젝트 안에서만 유일하므로, 지금 프로젝트에 그 번호가 없으면 없는 것이다.

### A6 검색한다

- **시작 조건:** 2단계 뒤, 사용자가 제목이나 본문으로 찾겠다고 한다.
- 처리 절차는 착수할 때 쓴다. 찾는 자리가 화면에 아직 없다.
