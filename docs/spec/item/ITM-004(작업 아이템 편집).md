# ITM-004 작업 아이템 편집

- **목표:** 변경된 요구사항을 작업 아이템에 반영하여 최신 작업 명세를 유지한다.
- **주 액터:** 사용자
- **지원 액터:** 없음
- **트리거:** 작업 내용, 인수 조건, 유형 등의 변경이 필요하다.

## 기본 흐름 (Basic Flow)

1. 사용자가 작업 아이템 상세 화면으로 진입한다.
2. 사용자가 작업 아이템 수정을 요청한다.
3. 시스템이 제목 및 본문 입력 폼을 활성화한다.
4. 사용자가 제목 또는 본문을 수정한다.
5. 시스템이 제목이 비어 있지 않음을 검증한다.
6. 시스템이 수정 사항을 저장하고 상세 조회 화면으로 이동한다.

인수 조건은 본문 내 체크박스 항목으로 관리하므로 본문 수정 시 함께 갱신된다. 식별 번호는 부여 후 불변이며 삭제 시 `(결번)`으로 표시한다([결정-0007](../../architecture/decisions/0007-shared-software-process.md)).

식별자와 상태 변경은 본 흐름의 대상이 아니다. 식별자는 불변이며 상태 변경은 [ITM-003](<./ITM-003(작업 아이템 상태 변경).md>)을 따른다.

## 대체 흐름 (Alternate Flows)

### A1 제목이 비어 있다

- **시작 조건:** 5단계에서 제목이 비어 있다.
- **처리 절차:**
  1. 시스템이 제목 입력이 필요함을 알린다.
  2. 사용자가 제목을 다시 입력한다.
  3. **기본 흐름 5로 복귀.**

### A2 수정을 취소한다

- **시작 조건:** 3–5단계에서 사용자가 수정을 취소한다.
- **처리 절차:**
  1. 시스템이 변경 사항을 저장하지 않고 기존 상태를 유지한다.
  2. **실패로 종료.**

### A3 유형을 변경한다

- **시작 조건:** 4단계 후, 사용자가 유형 변경을 요청한다.
- **처리 절차:**
  1. 사용자가 Epic · Story · Task · Bug 중 하나를 선택한다.
  2. **기본 흐름 5로 복귀.**

유형을 변경하더라도 작업 아이템 식별 번호는 변경되지 않는다.

### A4 타인 프로젝트의 항목 수정

- **시작 조건:** 6단계에서 대상 항목이 사용자의 프로젝트에 속하지 않는다.
- **처리 절차:**
  1. 시스템이 해당 리소스가 존재하지 않음을 알린다.
  2. **실패로 종료.**

보안을 위해 권한 없음 대신 리소스 부재로 응답한다.

### A5 동일 항목 동시 수정 충돌

- **시작 조건:** 6단계에서 화면 조회 시점 이후 다른 세션에서 이미 수정이 완료되었다.
- 처리 절차는 해당 슬라이스 착수 시 기술한다.
