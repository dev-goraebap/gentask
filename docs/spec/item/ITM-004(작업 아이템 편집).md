# ITM-004 작업 아이템 편집

- **목표:** 적어 둔 것을 지금 아는 것에 맞춰, 항목이 사실과 어긋난 채로 남지 않는다.
- **주 액터:** 사용자
- **지원 액터:** 없음
- **트리거:** 적어 둔 것과 지금 아는 것이 달라졌다.

## 기본 흐름 (Basic Flow)

1. 사용자가 작업 아이템 하나를 연다.
2. 사용자가 고치겠다고 한다.
3. 시스템이 제목과 본문을 적을 수 있게 한다.
4. 사용자가 고친다.
5. 시스템이 제목이 비어 있지 않음을 검증한다.
6. 시스템이 고친 것을 담고 읽는 자리로 되돌린다.

**인수 조건은 따로 고치지 않는다.** 본문 안의 체크 항목이므로 본문을 고치는 것이 곧 인수 조건을 고치는 것이다. 번호는 부여 뒤 불변이며 지운 자리는 `(결번)` 으로 남긴다 — 규약은 [결정-0007](../../architecture/decisions/0007-shared-software-process.md)이 갖는다.

**번호와 유형과 상태는 이 흐름이 다루지 않는다.** 번호는 불변이고, 상태는 [ITM-003](<./ITM-003(작업 아이템 상태 변경).md>)이 갖는다.

## 대체 흐름 (Alternate Flows)

### A1 제목이 비어 있다

- **시작 조건:** 5단계에서 제목이 비어 있다.
- **처리 절차:**
  1. 시스템이 제목이 필요함을 알린다.
  2. 사용자가 제목을 다시 적는다.
  3. **기본 흐름 5로 복귀.**

### A2 고치기를 그만둔다

- **시작 조건:** 3–5단계 어디서든, 사용자가 그만둔다.
- **처리 절차:**
  1. 시스템이 고치기 전의 것을 그대로 둔다.
  2. **실패로 종료.**

적던 것은 사라진다. 되살릴 자리를 두려면 어디에 얼마나 남길지가 먼저 정해져야 한다.

### A3 유형을 바꾼다

- **시작 조건:** 4단계 뒤, 사용자가 유형을 바꾸겠다고 한다.
- **처리 절차:**
  1. 사용자가 Epic · Story · Task · Bug 중 하나를 고른다.
  2. **기본 흐름 5로 복귀.**

유형을 바꿔도 번호는 바뀌지 않는다. 넷이 한 표에 있어 옮길 자리가 없기 때문이다.

### A4 남의 프로젝트의 항목이다

- **시작 조건:** 6단계에서 그 항목이 사용자의 프로젝트에 속하지 않는다.
- **처리 절차:**
  1. 시스템이 그 자리가 없음을 알린다.
  2. **실패로 종료.**

있으나 권한이 없다고 알리지 않는다. 그렇게 알리면 어떤 번호가 존재하는지가 새어 나간다.

### A5 두 사람이 같은 것을 동시에 고친다

- **시작 조건:** 6단계에서 그 항목이 연 뒤에 다른 곳에서 이미 바뀌었다.
- 처리 절차는 착수할 때 쓴다. 나중에 담은 것이 앞의 것을 덮는 것이 지금의 동작이며, 공유가 생기기 전까지는 그 자리가 드러나지 않는다(PRD 2.3).
