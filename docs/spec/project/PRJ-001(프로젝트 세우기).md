# PRJ-001 프로젝트 생성

- **목표:** 작업 영역을 프로젝트 단위로 분리 생성하여 상이한 작업이 단일 목록에 혼재되지 않도록 격리한다.
- **주 액터:** 사용자
- **지원 액터:** 없음
- **트리거:** 기존 프로젝트와 분리된 새로운 작업 공간이 필요하다.

## 기본 흐름 (Basic Flow)

1. 사용자가 프로젝트 생성을 요청한다.
2. 시스템이 프로젝트 생성 입력 폼을 활성화한다.
3. 사용자가 프로젝트 이름과 작업 아이템 접두어를 입력한다.
4. 시스템이 이름이 비어 있지 않음과 접두어 형식(영문, 숫자)을 검증한다.
5. 시스템이 프로젝트를 생성하고 해당 프로젝트 작업 공간으로 이동한다.

프로젝트 식별 체계는 세 가지 요소로 구성된다:

| 구분 | 예시 | 정의 주체 | 주요 용도 |
| :--- | :--- | :--- | :--- |
| 이름 | 내 프로젝트 | 사용자 | UI 화면 표시 명칭 |
| 식별자 | `V1StGXR8_Z5j` | 시스템 | URL 주소, API 경로, CLI 매개변수 |
| 접두어 | `GT` | 사용자 | 작업 아이템 식별자 접두어 (`GT-43`) |

식별자는 시스템이 난수(NanoID)로 발급하며 전역적으로 고유하다.

접두어는 사용자가 정의하며 영문과 숫자로만 구성된다. 프로젝트 식별자가 고유하므로 접두어 중복은 허용한다.

## 대체 흐름 (Alternate Flows)

### A1 이름이 비어 있다

- **시작 조건:** 4단계에서 프로젝트 이름이 비어 있다.
- **처리 절차:**
  1. 시스템이 이름 입력이 필요함을 알린다.
  2. 사용자가 이름을 다시 입력한다.
  3. **기본 흐름 4로 복귀.**

### A2 접두어 형식이 올바르지 않다

- **시작 조건:** 4단계에서 접두어가 비어 있거나 영문 및 숫자가 아닌 문자를 포함한다.
- **처리 절차:**
  1. 시스템이 허용되는 접두어 형식을 안내한다.
  2. 사용자가 접두어를 다시 입력한다.
  3. **기본 흐름 4로 복귀.**

### A3 회원가입 시 기본 프로젝트 자동 생성

- **시작 조건:** 사용자가 신규 계정을 생성한다.
- **처리 절차:**
  1. 시스템이 기본 프로젝트를 자동으로 생성한다.
  2. **성공으로 종료.**

초기 진입 시 빈 화면 노출을 방지하기 위해 계정 가입과 동시에 기본 프로젝트를 자동 구성한다([PRD 2.1](../../prd.md)). 시스템 기본 접두어를 적용한다.

### A4 생성을 취소한다

- **시작 조건:** 1–4단계에서 사용자가 프로젝트 생성을 취소한다.
- **처리 절차:**
  1. 시스템이 프로젝트를 생성하지 않는다.
  2. **실패로 종료.**
