# 슬라이스 예제 (TK-001)

흐름이 정해지면 슬라이스 후보가 보입니다. 흐름 하나가 슬라이스 하나는 아닙니다. 같은 자리에서 갈라지고 같은 장치로 처리되는 흐름은 묶고, 아직 결정이 안 난 흐름은 자르지 않습니다.

| ID | 슬라이스 | 흐름 | 묶은 근거 |
| :--- | :--- | :--- | :--- |
| S1 | 제목만으로 할일 적기 | BF, A1, A5, A7 | 입력란 하나에서 일어나는 일 전부입니다 |
| S2 | 마감일 있는 할일 적기 | A2 | 새 입력 요소가 생깁니다 |
| S3 | 할일 적기 실패 | A6 | 저장소 거부. 토스트와 재시도라는 다른 장치입니다 |
| — | (자르지 않음) | A3 알림, A4 반복 | 지원 액터와 TK-004 접점이 정해진 뒤 자릅니다 |

이 표는 자르는 과정을 보이기 위한 것입니다. 실제로는 행 하나가 이슈 하나가 되고 서술서에는 남기지 않습니다.

이름은 유스케이스의 목적어와 동사에 그 흐름의 조건을 얹어 짓습니다. `빈 제목` 이 아니라 `제목 없는 할일 적기` 이고, 기본 흐름에 합쳐졌으면 `제목만으로 할일 적기` 입니다.

## 성공 조건

묶인 흐름마다 한 문장입니다. S1 은 넷입니다.

- 제목을 적으면 목록에 그 할일이 있다
- 제목이 비면 목록에 들어가지 않는다
- 그만두면 목록은 그대로다
- 묶음을 보며 적으면 그 묶음의 성질이 붙은 채로 목록에 남는다

기본 흐름에 확정 단계가 없으므로 `등록하면` 을 넣지 않습니다. `등록 버튼을 누르면` 은 조작이라 성공 조건이 아니라 확인 절차에 들어갑니다.

이 문장은 **그 경로**가 액터 앞에서 닫히는지를 봅니다. 단위 테스트(`addTask`)만으로 검증됨이 되지 않습니다. 프론트와 백엔드가 나뉘면 둘을 붙여 확인합니다.

## 이슈

마일스톤은 `TK-001 할일 적어두기`, 제목은 `TK-001 S1 제목만으로 할일 적기` 이고 본문 양식은 [작성지침](../작성지침.md)의 이슈 구성 절에 있습니다. 화면과 API 는 이슈 하나의 프론트 · 백엔드 절이지 별개 이슈가 아닙니다. 진행 상태는 open · closed 가 갖습니다.
