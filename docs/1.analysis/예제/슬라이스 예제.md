# 슬라이스 예제 (TK-001)

흐름이 정해지면 슬라이스 후보가 보입니다. 흐름 하나가 슬라이스 후보입니다. 이름은 유스케이스의 목적어와 동사에 그 흐름의 조건을 얹어 짓습니다. `빈 제목` 이 아니라 `제목 없는 할일 적기` 입니다. 관련 길은 묶을 수 있고, 지금 안 만들 길은 이슈만 열어 두어도 됩니다. 아래 표는 자르는 과정을 보이기 위한 것이며, 실제로는 행 하나가 이슈 하나가 되고 서술서에는 남기지 않습니다.

| ID | 슬라이스 | 흐름 | 성공 조건 | 이슈 |
| :--- | :--- | :--- | :--- | :--- |
| S1 | 제목만으로 할일 적기 | BF | 제목을 적으면 목록에 그 할일이 있다 | — |
| S2 | 제목 없는 할일 적기 | BF, A1 | 제목이 비면 목록에 들어가지 않는다 | — |
| S3 | 마감일 있는 할일 적기 | BF, A2 | 마감일과 함께 목록에 남는다 | — |
| S4 | 알림 있는 할일 적기 | BF, A3 | 알림이 붙은 채로 목록에 남는다 | — |
| S5 | 반복하는 할일 적기 | BF, A4 | 반복 주기와 함께 목록에 남는다 | — |
| S6 | 할일 적기 그만두기 | A5 | 그만두면 목록은 그대로다 | — |
| S7 | 할일 적기 실패 | BF, A6 | 넣기에 실패하면 목록에 없고, 기존 할일은 남는다 | — |

S4에 A2를 넣지 않습니다. 알림은 자기 시점만 있으면 됩니다. 마감일과 알림을 같이 붙이는 것은 S3와 S4가 지나는 경로이지, 새 대체 흐름·새 슬라이스가 아닙니다.

## 성공 조건

S1의 `제목을 적으면 목록에 그 할일이 있다`는 기본 흐름과 맞습니다. 기본 흐름에 확정 단계가 없으므로 `등록하면`을 넣지 않습니다. `등록 버튼을 누르면`은 조작입니다.

이 문장은 **그 경로**가 액터 앞에서 닫히는지를 봅니다. 단위 테스트(`addTask`)만으로 검증됨이 되지 않습니다. 프론트와 백엔드가 나뉘면 둘을 붙여 확인합니다. 시스템 전체(다른 유스케이스까지)를 도는 테스트는 아닙니다.

## 이슈

행 하나가 이슈 하나입니다. 마일스톤은 `TK-001 할일 적어두기`, 제목은 `TK-001 S1 제목만으로 할일 적기` 이고 본문은 다음과 같습니다.

```markdown
서술서: [TK-001 할일 적어두기](../작업/TK-001(할일 적어두기).md)
흐름: BF

## 성공 조건

제목을 적으면 목록에 그 할일이 있다

## task

- [x] 지나는 대체 흐름 구체화
- [ ] 프론트: 화면 (목 계층 위)
- [ ] 백엔드: API 와 연결
- [ ] 성공 조건 확인
```

화면과 API 는 이슈 하나의 task 이지 별개 이슈가 아닙니다. 진행 상태는 체크박스와 open · closed 가 갖습니다.
