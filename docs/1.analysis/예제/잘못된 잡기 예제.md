# 잘못된 잡기 예제 (TK-001)

할일 목록을 CRUD나 화면으로 나누면 이렇게 됩니다. 오른쪽이 TK-001이 잡은 자리입니다.

| 이렇게 쓰면 | 문제 | TK-001에서 |
| :--- | :--- | :--- |
| 할일 생성 / 조회 / 수정 / 삭제 | 목표 없음. 기능 분해 | 생성에 해당하는 목표만 `할일 적어두기`. 조회는 `지금 할 일 보기`, 수정·포기는 `손보기` |
| 상세 패널 열기, 저장하기 | UI | 흐름에 패널·저장이 없다. 시스템이 목록에 넣는다 |
| 오늘 보기, 종료 보기, 전체 보기 | 한 목표의 경로를 승격 | 이 유스케이스가 아님. `지금 할 일 보기`의 대체 흐름 |
| 로그인, 검색 | 대부분 하위 기능 | 적어두기의 전제나 단계로 올리지 않음 |
| 제목 수정, 메모 수정, 기한 수정 | `손보다`를 필드로 쪼갬 | 적는 순간의 마감일·알림·반복은 A2–A4. 나중에 고치는 일은 `손보기` |

`할일 생성`은 상사 테스트에 실패합니다. `할일 적어두기`는 잊지 않으려고 목록에 남기는 목표입니다.

마감일·알림·반복을 `할일 생성`, `알림 등록`, `반복 설정` 세 유스케이스로 올리는 것도 같은 종류의 오류입니다. TK-001에서는 대체 흐름 세 이름입니다.
