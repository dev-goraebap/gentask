# 잘못된 잡기 예제 (TK-001)

작업 목록을 CRUD나 화면으로 나누면 이렇게 됩니다. 오른쪽이 TK-001이 잡은 자리입니다.

| 이렇게 쓰면 | 문제 | TK-001에서 |
| :--- | :--- | :--- |
| 작업 생성 / 조회 / 수정 / 삭제 | 목표 없이 데이터 조작으로 쪼갬 | 목표 하나에 유스케이스 하나. `작업 추가`의 목표는 "떠오른 일을 남겨 기억에 의존하지 않는다"이고, 보기·편집·완료는 각각 다른 목표라 따로 둔다. 이름이 동사인 것은 문제가 아니다 |
| 상세 패널 열기, 저장하기 | UI | 흐름에 패널·저장이 없다. 시스템이 목록에 넣는다 |
| 오늘 보기, 종료 보기, 전체 보기 | 한 목표의 경로를 승격 | 이 유스케이스가 아님. `작업 보기`의 대체 흐름 |
| 로그인, 검색 | 대부분 하위 기능 | 추가의 전제나 단계로 올리지 않음 |
| 제목 수정, 메모 수정, 기한 수정 | `편집`을 필드로 쪼갬 | 추가하는 순간의 기한·알림·반복은 A2–A4. 나중에 바꾸는 일은 `작업 편집` |

`작업 생성`이 실패하는 것은 레코드를 만드는 것 자체가 목표가 아니기 때문입니다. `작업 추가`는 같은 동사처럼 보여도 "잊지 않으려고 목록에 남긴다"는 목표를 제품의 말로 부른 것입니다.

기한·알림·반복을 `작업 생성`, `알림 등록`, `반복 설정` 세 유스케이스로 올리는 것도 같은 종류의 오류입니다. TK-001에서는 대체 흐름 세 이름입니다.
