# 설계 — 디자인 시스템

이 문서는 **디자인 언어의 원칙**을 담는다. 값의 정본은 토큰 파일
(`web/src/app/styles/`)이며, 이 문서는 그 값들이 왜 그렇게 생겼고 어떻게 써야
하는지를 기록한다.

**자족적으로 쓴다.** 톤 & 매너의 출처는 구매한 상용 팩이지만 그 문서는 저장소
밖의 추적되지 않는 위치에 있다. 사라져도 이 문서만으로 판단할 수 있어야 하므로
원칙을 우리 문장으로 다시 쓴다.

## 1. 무엇을 지향하는가

**조용한 구조. 정보가 빛이다.**

이 키트로 만드는 것은 제품 UI다 — 폼, 목록, 설정, 상태 표시. 랜딩 페이지도
에디토리얼도 아니다. 그래서 화면의 표현 예산을 **내용**에 쓰고 크롬(뼈대)에는
쓰지 않는다. 배경은 거의 무채색이고, 색은 사용자가 알아야 할 것에만 얹힌다.

지향하는 감각:

1. **밀도는 높지만 답답하지 않다.** 여백으로 구분하고 선은 최소로 쓴다.
2. **깊이는 얕다.** 표면은 세 단계이며, 그 이상은 사용자가 층위를 읽지 못한다.
3. **모든 컨트롤이 같은 문법을 쓴다.** 같은 반경, 같은 전환 시간, 같은 포커스 링.
4. **색은 신호다.** 장식으로 쓰지 않는다. 화면에 초록이 있으면 무언가 성공한 것이다.

피하는 것:

- 그라디언트 배경, 글로우, 파티클, 유리 효과
- 실제 기능이 없는 배지·카운터·타임스탬프
- 한 컴포넌트 안에서 반경 섞기, 2px 이상의 테두리
- 액센트 색을 넓은 면적에 채우기 — 액센트가 흔해지면 강조가 아니게 된다

## 2. 색

### 2.1 역할 체계

색은 **역할 이름**으로만 쓴다. 컴포넌트는 `--prim-*`(원시 값)을 직접 읽지 않는다.
이 규칙 하나가 테마 교체를 파일 한 줄 교체로 만든다.

| 묶음 | 토큰 | 용도 |
|---|---|---|
| 표면 | `background` · `surface` · `elevated` · `overlay` | 페이지 → 카드·필드 → 모달·팝오버 → 딤 |
| 전경 | `foreground` · `muted` · `subtle` | 본문 → 보조 → 비활성·메타 |
| 경계선 | `line` · `line-strong` | 헤어라인 → 선택 행 강조 |
| 액센트 | `accent` · `accent-ink` · `accent-soft` · `on-accent` | 채움 · 잉크 · 선택 배경 · 채움 위 텍스트 |
| 의도 | `success` · `warning` · `info` · `danger` (+ `-soft`) | 상태 |

### 2.2 액센트가 둘인 이유

**채움(`accent`)과 잉크(`accent-ink`)는 요구 대비가 다르다.** 채움은 그 위에 얹힌
흰 텍스트가 AA를 넘어야 하고, 잉크는 캔버스 위에서 AA를 넘어야 한다. 한 값으로
두 조건을 동시에 만족할 수 없다.

팔레트의 원래 액센트에 흰 텍스트를 얹으면 4.21:1로 AA(4.5)에 미달했다. 그래서
채움에는 한 단계 어두운 값을 쓴다. **선명함을 조금 내주고 읽을 수 있음을 얻은
거래다** — 되돌리려면 대비 검증을 다시 통과시켜야 한다.

### 2.3 `-soft`는 배경 전용

`success`와 `success-soft`를 서로 바꿔 쓰면 대비가 무너진다. 기본형은
텍스트·아이콘·테두리, `-soft`는 배경이다. 배너는 `bg-*-soft` 위에 `text-*`를 얹는다.

### 2.4 대비 기준

- 본문·보조 텍스트: **AA 4.5:1**
- 비활성·메타데이터·경계선·채움 구분: **UI 3:1** (WCAG 1.4.11)
- `subtle`은 AA를 넘지 않는다. **본문에 쓰지 않는다** — 비활성 상태와 보조
  메타데이터 전용이다.

수치는 문서에 적어두는 것으로 끝내지 않는다. `contrast.spec.ts`가 실제 CSS를
파싱해 계산하므로, 팔레트 값이나 매핑을 바꾸면 그 자리에서 실패한다.

## 3. 타이포그래피

### 3.1 역할 스케일

크기가 아니라 **역할**로 부른다: `display` · `headline-lg` · `headline-md` ·
`title` · `body` · `body-sm` · `label` · `mono` · `metric`.

**굵기·행간·자간이 토큰에 함께 들어 있다.** 호출부가 네 값을 매번 고르면 반드시
어긋난다. `text-headline-lg` 하나가 36px·600·1.12·-0.02em을 모두 들고 온다.

### 3.2 한글과 라틴을 한 서체로

라틴 전용 서체를 기준으로 잡으면 한글이 시스템 폰트로 떨어져 굵기와 리듬이
어긋난다. 섞인 문장에서 그것이 바로 보인다. 그래서 두 문자를 함께 덮는 서체를
쓰고 자체 호스팅한다(외부 CDN 의존·프라이버시·오프라인 문제를 피한다).

모노는 웹폰트를 싣지 않고 시스템 스택을 쓴다 — 지표와 코드 라벨 몇 곳에만
쓰여서 서체를 하나 더 내려받을 값을 하지 못한다.

### 3.3 규칙

- 본문 한 줄은 너무 길어지지 않게 폭을 제한한다. 줄 끝에서 다음 줄 머리를
  찾지 못하면 그것만으로 피로해진다.
- **대문자화는 유틸리티로 붙인다.** 토큰이 강제하면 한글 라벨에서 무의미해진다.
  `label` 토큰은 자간만 넓혀 두고, 대문자화가 의미 있는 곳에서만 `uppercase`를 쓴다.
- 제목 아래 부제는 하나까지. 둘을 쌓지 않는다.

## 4. 공간과 형태

### 4.1 간격

**별도 토큰을 만들지 않는다.** 간격 스케일(4·8·12·16·20·24·32·40·48·64·80px)이
Tailwind 기본 스케일과 정확히 같아서 `p-6` = 24px가 이미 성립한다. 없어도 되는
층을 만들지 않는다.

여백이 기본 구분 수단이다. 선은 여백만으로 부족할 때 꺼낸다.

### 4.2 반경

크기가 아니라 **역할**로 고정한다.

| 토큰 | 값 | 용도 |
|---|---|---|
| `rounded-tight` | 6px | 체크박스, 작은 표식 |
| `rounded-control` | 10px | 버튼, 입력, 셀렉트 |
| `rounded-surface` | 16px | 카드, 필드셋 |
| `rounded-panel` | 24px | 모달, 시트 |
| `rounded-pill` | 999px | 배지, 칩, 스위치 |

컨트롤과 표면이 같은 반경을 쓰면 위계가 사라진다. **한 컴포넌트 안에서 반경을
섞지 않는다** — 조립된 느낌이 난다.

테두리는 1px이다. 2px 외곽선이나 이중 테두리를 쓰지 않으며, 색 있는 테두리는
포커스와 오류에만 쓴다.

## 5. 깊이

**두 모드가 깊이를 다른 수단으로 표현한다.** 이것이 라이트/다크를 단순 반전으로
만들 수 없는 핵심 이유다.

- **밝은 배경에서는 그림자가 보인다.** 표면은 흰색으로 두고 그림자가 층위를 만든다.
- **어두운 배경에서는 그림자가 보이지 않는다.** 표면 색이 올라갈수록 밝아지고,
  안쪽 하이라이트가 면이 서 있다는 느낌을 만든다.

같은 그림자를 두 모드에 쓰면 한쪽에서 평평해진다. 그래서 그림자 토큰도 모드별로
갈린다(`raised` · `floating` · `modal`).

정적 콘텐츠 카드에는 그림자를 쓰지 않는다. 반경과 헤어라인으로 충분하다.

## 6. 모션

- `duration-fast` 120ms — 누름, 색 변화
- `duration-base` 150ms — 대부분의 상태 전환
- `duration-slow` 240ms — 진입·퇴장
- `ease-standard` — 모든 전환이 같은 이징을 쓴다

**`prefers-reduced-motion`을 존중한다.** 전역 기반 스타일에서 전환을 걷어내므로
컴포넌트가 따로 처리하지 않아도 된다.

모션은 상태 변화를 설명할 때만 쓴다. 주의를 끌기 위해 움직이지 않는다.

## 7. 라이트 / 다크

- 기본은 **OS 선호**를 따른다.
- 명시적 전환은 `[data-theme="light" | "dark"]`이며 OS 선호를 이긴다.
- `:root`에 한정하지 않아 **하위 트리에도** 걸 수 있다 — 밝은 페이지 안의 어두운
  영역이 공짜로 얻어진다.
- 색상은 `light-dark()`로 두 값을 한 줄에 선언한다. 모드별 블록을 따로 두면 한쪽만
  고치는 실수가 생기는데, 이 방식은 구조적으로 어긋날 수 없다.

**양쪽 모드를 항상 함께 본다.** 워크벤치의 토큰·컴포넌트 화면은 두 모드를 나란히
띄운다. 한 번에 하나만 보면 한쪽이 깨진 것을 늦게 발견한다.

## 8. 컴포넌트 규칙

### 8.1 토큰만 읽는다

컴포넌트는 시맨틱 토큰만 읽는다. 원시 값을 직접 쓰거나 색을 새로 만들지 않는다.
필요한 역할이 없으면 **토큰을 추가하는 것이 맞다** — 컴포넌트에 임시값을 박으면
테마 교체가 그 컴포넌트에서 멈춘다.

### 8.2 완성의 기준

컴포넌트는 다음을 갖춘 상태에서만 "완성"이다.

- 키보드로 도달·조작 가능
- 포커스가 보인다(공용 `--focus-ring`을 쓴다. 컴포넌트가 바꾸지 않는다)
- 접근가능한 이름이 있다
- 필요한 ARIA 역할·상태가 붙어 있다
- 비활성·로딩·오류 상태가 정의되어 있다

### 8.3 네이티브 요소 위에 얹는다

버튼은 `<button>`, 입력은 `<input>`이다. 속성 선택자로 스타일과 동작을 얹어
네이티브 의미와 폼 연동을 공짜로 얻는다. `<div>`에 역할을 붙여 컨트롤을 만들지
않는다.

### 8.4 동작 조달

포커스 트랩·포지셔닝·리스트 키보드 내비 같은 어려운 동작은 직접 만들지 않고
조달한다. 다만 **필요해지는 시점에 고른다** — 1차 컴포넌트(버튼·입력·필드·카드·
배너 등)는 그런 동작이 없어 직접 만들고, 2차(다이얼로그·셀렉트·드롭다운·툴팁)를
시작할 때 라이브러리를 결정한다. 쓰지 않는 채로 선택을 굳히지 않는다.

## 9. Do / Don't

**Do**

- 여백으로 구분하고, 부족할 때만 선을 꺼낸다
- 색을 신호로만 쓴다 — 상태가 아니면 무채색으로 둔다
- 역할 토큰을 쓴다. 값이 필요하면 토큰을 추가한다
- 두 모드를 함께 보고 함께 고친다
- 대비를 눈으로 확인하고, 수치는 테스트에 맡긴다

**Don't**

- 그라디언트 배경·글로우·유리 효과를 넣지 않는다
- `subtle`을 본문에 쓰지 않는다
- `-soft`를 텍스트에, 기본형을 배경에 쓰지 않는다
- 정적 카드에 그림자를 얹지 않는다
- 한 컴포넌트 안에서 반경을 섞지 않는다
- 액센트를 넓은 면적에 채우지 않는다

## 10. 값을 바꿀 때

1. 프리미티브(`themes/*.css`)를 바꾼다. 시맨틱 매핑은 웬만해선 건드리지 않는다.
2. `npm test`로 대비 검증을 통과시킨다. 실패하면 값을 다시 고른다.
3. 워크벤치에서 **두 모드를 나란히** 확인한다.
4. 새 역할이 필요해졌다면 시맨틱 토큰을 추가하고 이 문서의 표를 갱신한다.

테마를 교체하려면 프리미티브 파일 하나를 바꾼다. 새 팔레트는 기존 `--prim-*`
이름을 전부 정의해야 하며, 그 목록이 팔레트와 시맨틱 계층 사이의 계약이다.
