# 19. 용어집

본 문서는 참조 아키텍처 전반이 쓰는 용어의 뜻을 정의합니다. 같은 낱말을 문서마다 다르게 쓰지 않기 위한 기준입니다.

## 구조

| 용어 | 정의 | 원본 |
| :--- | :--- | :--- |
| **FSD (Feature-Sliced Design)** | 프론트엔드 코드를 계층·슬라이스·세그먼트로 분할하고 계층 간 단방향 임포트를 강제하는 아키텍처 방법론 | [fsd.how](https://fsd.how/) |
| **계층 (Layer)** | FSD 의 최상위 분할 단위. `app`, `pages`, `features`, `entities`, `shared` | [02. 패키지 배치](02-package-structure.md) |
| **슬라이스 (Slice)** | 계층 내부의 도메인 단위 분할. `pages/task-list` 등 | [02. 패키지 배치](02-package-structure.md) |
| **세그먼트 (Segment)** | 슬라이스 내부의 기술적 목적별 분할. `ui`, `model`, `api`, `lib`, `config` | [02. 패키지 배치](02-package-structure.md) |
| **공개 API (Public API)** | 슬라이스가 `index.ts` 로 노출하는 진입점. 외부는 이것을 통해서만 접근합니다 | [02. 패키지 배치](02-package-structure.md) |
| **슬라이스 그룹** | 탐색 목적으로만 슬라이스를 묶는 폴더. 세그먼트도 공개 API 도 갖지 않습니다 | [08. 라우팅](08-routing.md) |
| **승격 · 강등** | `pages` 의 코드를 하위 계층으로 옮기는 것과 그 반대. 재사용이 실제로 확인된 뒤에 수행합니다 | [02. 패키지 배치](02-package-structure.md) |

## 렌더링과 상태

| 용어 | 정의 | 원본 |
| :--- | :--- | :--- |
| **하이드레이션 (Hydration)** | 서버가 생성한 HTML 에 클라이언트가 이벤트와 상태를 결합해 상호작용 가능한 상태로 만드는 과정 | [05. 렌더링 전략](05-rendering.md) |
| **증분 하이드레이션** | 화면 전체가 아니라 필요한 블록만 선택적으로 하이드레이션하는 방식. Angular 22 에서 기본 활성화 | [05. 렌더링 전략](05-rendering.md) |
| **전송 상태 (Transfer State)** | 서버 렌더링 시 조회한 데이터를 HTML 에 실어 클라이언트로 전달해 중복 요청을 막는 기법 | [05. 렌더링 전략](05-rendering.md) |
| **서버 상태** | 원본이 서버에 있고 화면은 언제든 낡을 수 있는 사본만 가진 데이터 | [09. 상태](09-state.md) |
| **클라이언트 상태** | 원본이 화면에 있는 데이터. 선택된 탭, 열린 아코디언 등 | [09. 상태](09-state.md) |
| **URL 상태** | 원본이 브라우저 히스토리에 있는 데이터. 필터·정렬·페이지가 해당합니다 | [09. 상태](09-state.md) |
| **무효화 신호** | 변경을 수행한 곳과 조회를 소유한 곳의 계층이 달라 직접 참조할 수 없을 때, `shared` 의 문자열 키로 재조회를 촉발하는 장치 | [09. 상태](09-state.md) |

## 화면

| 용어 | 정의 | 원본 |
| :--- | :--- | :--- |
| **반응형 (Responsive)** | 레이아웃만 바뀌고 DOM 은 같은 방식. CSS 미디어 쿼리로 해결됩니다 | [07. 적응형 UI](07-adaptive-ui.md) |
| **적응형 (Adaptive)** | 뷰포트 폭에 따라 컴포넌트와 상호작용 모델 자체를 교체하는 방식. 런타임 분기가 필요합니다 | [07. 적응형 UI](07-adaptive-ui.md) |
| **의미 신호** | 컴포넌트가 미디어 쿼리 문자열을 직접 갖지 않도록 `shared/lib/adaptive` 가 노출하는 판정 결과. 현재는 `wide` 와 `compact` 를 가르는 `injectViewportClass()` 하나입니다 | [07. 적응형 UI](07-adaptive-ui.md) |
| **바텀시트** | 화면 하단에서 올라오는 오버레이 컨테이너. Select · Dropdown menu · Date picker · Toast 의 `compact` 표현 | [07. 적응형 UI](07-adaptive-ui.md) |
| **액션시트** | 항목을 나열하는 오버레이 표현. 컨텍스트 메뉴에만 씁니다. 그리드나 임의 콘텐츠의 컨테이너가 아닙니다 | [07. 적응형 UI](07-adaptive-ui.md) |
| **골격 (Frame)** | 화면의 상위 구조를 가르는 축. 실질적 차이는 스크롤 컨테이너의 위치입니다 | [06. 레이아웃](06-layout.md) |
| **표면 (Surface)** | 콘텐츠와 네비게이션의 시각적 구분 방식. 경계선이거나 여백입니다 | [06. 레이아웃](06-layout.md) |
| **베일 (Veil)** | 화면 전환 중 콘텐츠 영역을 덮어 이전 화면을 유지하는 표시. 스켈레톤을 대신합니다 | [10. 로딩 전략](10-loading.md) |

## 디자인 시스템

| 용어 | 정의 | 원본 |
| :--- | :--- | :--- |
| **brain · helm** | Spartan 의 두 층. brain 은 접근성과 동작을 담당하는 헤드리스 프리미티브이며 npm 의존성입니다. helm 은 시각 층이며 프로젝트로 복사해 소유합니다 | [04. 디자인 시스템](04-design-system.md) |
| **토큰 이름 집합** | 아키텍처가 고정하고 DESIGN.md 가 전부 채워야 하는 목록. 둘 사이의 계약입니다 | [04. 디자인 시스템](04-design-system.md) |
| **DESIGN.md** | 시각 언어를 소유하는 문서. YAML 프런트매터에 토큰 값, 본문에 근거를 담습니다 | [결정-0001](../decisions/0001-design-outside-architecture.md) |
