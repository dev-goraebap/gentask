# 04. 디자인 시스템

본 문서는 UI 킷의 구성 방식, 디자인 토큰의 **그릇**, 그리고 `shared/ui` 의 경계를 정의합니다.

**토큰에 담기는 값은 이 문서가 소유하지 않습니다.** 팔레트·곡률·표면 처리·타이포는 [DESIGN.md](../../design/DESIGN.md)가 소유하며 프로젝트마다 새로 작성합니다. 분리의 근거는 [결정-0001](../decisions/0001-design-outside-architecture.md)에 있습니다.

## 1. 구성

UI 는 두 층으로 구성합니다. 각 층의 소유권이 다릅니다.

| 층 | 패키지 | 소유 | 담당 |
| :--- | :--- | :--- | :--- |
| **brain** | `@spartan-ng/brain` (npm) | 외부 | 접근성, 포커스 관리, 키보드 조작, ARIA, 오버레이 |
| **helm** | `shared/ui/` (소스) | 프로젝트 | 마크업, 클래스, 시각적 표현 |
| **기반** | `@angular/cdk` (npm) | 외부 | brain 이 사용하는 프리미티브 |

`@spartan-ng/brain` 은 `@angular/cdk` 를 peer 로 요구합니다. brain 과 CDK 는 대체 관계가 아니라 **brain 이 CDK 위에 세워진 층**입니다.

helm 컴포넌트는 npm 패키지가 아니라 CLI 로 소스를 복사해 옵니다.

```bash
# --stylesEntryPoint 를 명시하는 이유는 01. 개발 환경 4절을 참조합니다.
ng g @spartan-ng/cli:init --stylesEntryPoint=src/app/styles.css
ng g @spartan-ng/cli:ui         # 컴포넌트 선택 후 소스 복사
ng g @spartan-ng/cli:ui-theme   # 테마 변수 생성
```

`init` 은 `@angular/cdk`·`@spartan-ng/brain`·`tailwind-merge`·`tw-animate-css` 를 설치하고 전역 스타일에 Tailwind 계층, Spartan 프리셋 임포트, 테마 변수, `@layer base` 기본 규칙을 기록합니다. `angular.json` 은 수정하지 않습니다.

복사된 소스는 `shared/ui/` 아래에 배치합니다. 배치 경로와 스타일은 `components.json` 이 원본입니다.

```json
{ "componentsPath": "src/shared/ui", "style": "vega", "importAlias": "@/shared/ui" }
```

> **중요: `style` 축은 컴포넌트를 추가하기 전에 확정합니다**
>
> `style` 은 helm 의 마크업과 클래스 형태를 정하는 축이며 색 팔레트와 별개입니다. 나중에 바꾸면 이미 복사된 사본을 재생성해야 하고, 2절에 따라 자유롭게 수정한 내용이 덮입니다.

### 1.1 helm 사본의 구조와 공개 API

생성기는 컴포넌트마다 다음 구조를 만듭니다.

```text
src/shared/ui/
└── button/
    └── src/
        ├── index.ts
        └── lib/
            └── hlm-button.ts
```

`src/index.ts` 가 컴포넌트 진입점이며 `tsconfig` 가 이 경로를 `@/shared/ui/button` 으로 매핑합니다.

**사용처는 컴포넌트별 경로를 임포트합니다.** 세그먼트 배럴을 두지 않습니다.

```ts
import { HlmButton } from '@/shared/ui/button';
import { HlmSheet } from '@/shared/ui/sheet';
```

배럴을 두지 않는 이유는 `@defer` 때문입니다. 같은 배럴에서 즉시 쓰는 심볼과 지연 대상 심볼을 함께 가져오면 배럴 모듈이 정적 의존으로 확정되어 지연 청크가 만들어지지 않습니다. 선행 저장소에서 배럴을 제거한 결과 초기 번들이 544kB 에서 275kB 로 줄었습니다.

이 구조는 FSD 규칙 셋과 부딪히며 해소 방식은 다음과 같습니다.

| 충돌 | 해소 |
| :--- | :--- |
| 컴포넌트 폴더에 `index.ts` 가 없음 (`fsd/public-api`) | `steiger.config.ts` 에서 해당 경로만 해제합니다 |
| `lib` 폴더명이 세그먼트명과 겹침 (`fsd/no-reserved-folder-names`) | 같은 방식으로 해제합니다 |
| 컴포넌트별 경로를 우회로 판정 (`fsd/no-public-api-sidestep`) | 규칙을 해제하고 ESLint `no-restricted-imports` 로 대체합니다 |

앞의 둘을 해제하는 이유는 구조를 수동으로 평탄화할 경우 컴포넌트 추가 및 재생성 시마다 반복적인 수정 작업이 발생하기 때문입니다.

세 번째는 성격이 다릅니다. `@/shared/ui/button` 은 tsconfig 가 `button/src/index.ts` 로 매핑하는 **그 컴포넌트의 공개 API** 이며 내부 파일이 아닙니다. Steiger 가 경로 문자열만 보고 판정하는데 규칙 단위로 예외를 둘 수 없어 전역 해제하고, 슬라이스 내부 파일 직접 임포트 금지는 ESLint 패턴이 대신합니다.

## 2. helm 수정 정책

**복사해 온 helm 컴포넌트는 자유롭게 수정합니다.** 마크업 구조, 클래스, 입출력 API 모두 대상입니다.

이 정책의 근거는 [07. 적응형 UI](07-adaptive-ui.md)입니다. 같은 논리적 컴포넌트가 상호작용 특성에 따라 다른 DOM 과 다른 상호작용 모델을 가져야 하므로, 토큰과 클래스만 바꾸는 방식으로는 구현할 수 없습니다.

대가는 **업스트림의 시각적 개선이 자동으로 오지 않는다**는 점입니다. API 수준의 갱신은 `ng g @spartan-ng/cli:healthcheck --autoFix` 가 폐기된 API 를 조정하므로 시각적 개선만 수동 대상입니다.

이 대가가 감당 가능한 이유는 층이 분리되어 있기 때문입니다. **접근성과 동작은 brain 이 소유하며 helm 은 시각 층**입니다. helm 을 고쳐도 포커스 트랩, 키보드 조작, ARIA 속성 연결은 brain 이 계속 담당합니다. 사본이 낡아서 잃는 것은 시각적 개선이지 접근성이 아닙니다.

| 구분 | 준수 지침 (Do) | 금지 지침 (Don't) |
| :--- | :--- | :--- |
| **helm 수정** | 마크업과 클래스를 목적에 맞게 고칩니다 | brain 디렉티브 연결을 임의로 제거합니다 |
| **brain** | 제공하는 디렉티브를 그대로 사용합니다 | `node_modules` 를 패치합니다 |

brain 디렉티브를 제거하면 접근성 보장이 함께 상실되며, 이는 시각적으로 드러나지 않아 결함 감지가 지연됩니다.

## 3. 디자인 토큰

### 3.1 원본과 소유

| 대상 | 원본 | 소유 |
| :--- | :--- | :--- |
| **토큰 이름의 집합** | 본 문서 3.2절 | 아키텍처 |
| **각 이름에 담기는 값** | `src/app/styles.css` | DESIGN.md 의 규칙을 따라 채웁니다 |
| **값을 그렇게 정한 근거** | `web/docs/design/DESIGN.md` | 디자인 |

**토큰 값을 본 문서에 중복 기재하지 않습니다.** 값의 원본은 `styles.css` 이며 런타임 해석 파일과 개발 참조 파일이 단일하므로 불일치가 발생하지 않습니다.

전역 스타일시트는 Tailwind 계층과 함께 Spartan 프리셋을 임포트합니다. 이 프리셋이 애니메이션 유틸리티와 **CDK 오버레이 스타일**을 함께 제공하므로 누락하면 다이얼로그와 팝오버가 깨집니다.

```css
@import '@spartan-ng/brain/hlm-tailwind-preset.css';
```

### 3.2 토큰 이름의 집합

**이 목록이 아키텍처와 디자인 사이의 계약입니다.** DESIGN.md 는 이 이름을 전부 채워야 하며, 빠진 이름은 그 자리를 쓰는 컴포넌트에서 드러납니다.

| 짝을 이루는 토큰 | 용도 |
| :--- | :--- |
| `background` / `foreground` | 화면 기본 |
| `card` / `card-foreground` | 카드 표면 |
| `popover` / `popover-foreground` | 오버레이 표면 |
| `primary` / `primary-foreground` | 주 동작 |
| `secondary` / `secondary-foreground` | 보조 동작 |
| `muted` / `muted-foreground` | 약화된 영역 |
| `accent` / `accent-foreground` | 강조 |
| `destructive` / `destructive-foreground` | 파괴적 동작 |

짝이 없는 단독 토큰은 `border`, `input`, `ring` 이며 `--radius` 와 `sidebar*` 계열이 추가로 존재합니다.

**`-foreground` 짝이 없는 배경 토큰을 만들지 않습니다.** 그 위에 어떤 색 텍스트를 올릴지 판단이 갈려 대비 문제를 만듭니다.

폰트 패밀리는 `--font-sans` 와 `--font-mono` 두 자리를 둡니다. **크기와 두께에는 토큰을 두지 않습니다.** Tailwind 의 유틸리티에 척도가 이미 정의되어 있어 별도 토큰을 두면 두 벌이 됩니다.

### 3.3 토큰 사용 규칙

```html
<!-- 허용 -->
<div class="bg-background text-foreground border-border">

<!-- 금지 -->
<div class="bg-white text-gray-900 border-gray-200">
<div class="bg-[#ffffff]">
<div style="color: #333">
```

임의 색상값의 직접 기재를 **금지**합니다. Tailwind 의 기본 팔레트(`gray-200`, `blue-500`)도 금지 대상입니다. 토큰을 거치지 않으면 다크 모드에서 대비가 깨지고 브랜드 색상 변경이 전역 치환 작업이 됩니다.

간격과 반경도 같습니다. `--radius` 계열 토큰을 사용하고 `rounded-[7px]` 형태의 임의값을 쓰지 않습니다.

**반투명 표면을 알파 유틸리티(`bg-background/85`)로 만드는 것을 금지합니다.** 라이트와 다크에 같은 불투명도가 걸리는데, 뒤 요소가 비쳐 보이는 정도는 배경과의 밝기 차이에 비례하므로 두 모드에 같은 값이 맞을 수 없습니다. 모드별로 다른 값이 필요하면 토큰을 새로 만듭니다.

### 3.4 토큰 추가

기존 토큰으로 표현할 수 없는 값이 필요하면 **토큰을 먼저 추가하고 사용합니다.** 컴포넌트에 임의값을 임시 적용하는 방식을 금지합니다. 임의값을 방치하면 스타일 불일치와 기술 부채가 누적됩니다.

두 가지를 함께 정의합니다.

```css
:root {
  --warning: /* 라이트와 다크 값 */;
  --warning-foreground: /* 라이트와 다크 값 */;
}

@theme inline {
  --color-warning: var(--warning);
  --color-warning-foreground: var(--warning-foreground);
}
```

`@theme inline` 등록을 빠뜨리면 `bg-warning` 같은 유틸리티 클래스가 생성되지 않아 변수만 정의된 채 쓸 수 없습니다.

**새 토큰은 라이트와 다크 값을 동시에 정의합니다.** 한쪽만 정의하면 반대 모드에서 색상 대비가 훼손되며, 해당 모드로 진입하기 전에는 결함이 인지되지 않습니다.

### 3.5 치수와 밀도

컨트롤의 크기는 **뷰포트 폭에 따라 갈립니다.** helm 기본값은 마우스 환경을 전제하므로, 좁은 화면에서는 접근성 최소 기준에 미달합니다.

**치수 조정에는 런타임 판정이 필요 없습니다.** `max-md:` 변형이 미디어 쿼리로 컴파일되므로 CSS 만으로 해결되며 정적 생성 경로에서도 그대로 동작합니다. `injectViewportClass()` 는 컴포넌트를 교체할 때 쓰는 것이고 크기를 바꿀 때 쓰는 것이 아닙니다.

임계값은 [07. 적응형 UI](07-adaptive-ui.md) 2절의 판정 축과 같은 `md` 경계를 씁니다. 두 자리에 다른 값을 두면 컴포넌트가 교체되는 지점과 치수가 바뀌는 지점이 어긋납니다.

| 항목 | `md` 이상 | `md` 미만 |
| :--- | :--- | :--- |
| **상호작용 컨트롤의 최소 크기** | helm 기본값 | **44 × 44** |
| **인접 타겟 간격** | helm 기본값 | **8px 이상** |

**포인터 쿼리로 치수를 가르는 것을 금지합니다.** [07. 적응형 UI](07-adaptive-ui.md) 2.1절의 실측이 보여주듯 브라우저는 마우스가 연결된 기기를 coarse 로 보고하기도 하며, 그 경우 데스크탑 전체가 터치 치수로 커집니다. 이 결함은 실제로 발생했습니다.

#### 3.5.1 입력 글자 크기의 예외

**글자를 입력하는 컨트롤의 글자 크기만 포인터로 판정합니다.** `text-base`(16px) 를 기본으로 두고 `pointer-fine:text-sm` 으로 좁힙니다.

폭으로 판정할 수 없는 이유는 실패의 성격이 다르기 때문입니다. 태블릿 가로는 `md` 를 넘으므로 폭으로 보면 14px 이 되는데, iOS Safari 는 16px 미만 입력에 포커스가 가면 화면을 확대하며 **사용자가 그 배율을 직접 되돌려야 합니다.** 다른 치수의 오판은 크기가 어긋나는 것으로 끝나지만 이것은 사용자가 손으로 수습해야 하는 동작 결함입니다.

포인터 쿼리의 오판도 이 자리에서는 안전한 쪽으로 기웁니다. 정밀 포인터가 없다고 보고되면 16px 이 유지되어 확대가 일어나지 않습니다.

**크기 변형마다 값을 흩지 않고 컴포넌트의 기본 클래스에 바닥을 깝니다.** `sm` 과 `icon-sm` 에만 붙이면 나중에 추가되는 변형이 조용히 기준을 벗어납니다.

```ts
// 크기 변형과 무관하게 좁은 화면의 바닥을 보장합니다.
const TOUCH_TARGET = 'max-md:min-h-11 max-md:min-w-11';
```

밀도가 촘촘해야 하는 자리, 예컨대 표의 행 안 조작 버튼처럼 44px 을 시각적으로 확보할 수 없는 경우에는 보이는 크기를 유지하고 누를 수 있는 영역만 넓힙니다. **기본은 시각 치수를 함께 키우는 것이며 예외를 기본으로 쓰지 않습니다.**

### 3.6 대비 하한

| 대상 | 기준 |
| :--- | :--- |
| **본문·보조·삼차 텍스트** | 4.5:1 |
| **큰 텍스트** | 3:1 |
| **폼 컨트롤 경계(`input`)와 포커스 링(`ring`)** | 3:1 |
| **장식선(`border`)** | **면제** |

라이트와 다크 **양쪽에서** 충족해야 합니다.

**두 경계선의 기준이 다릅니다.** `border` 는 같은 평면에서 면을 가르는 장식선이며, 사라져도 컴포넌트를 식별하지 못하게 되지 않으므로 WCAG 1.4.11 의 대상이 아닙니다. 여기에 3:1 을 걸면 모든 면 사이에 중간 회색 선이 그어져 헤어라인으로 구조를 그린다는 표현 자체가 성립하지 않습니다. 반대로 `input` 은 "여기가 입력란"임을 알리는 유일한 단서이므로 강제합니다.

이것은 기준을 느슨하게 한 것이 아니라 **더 정교하게 나눈 것**입니다. 장식선을 진하게 만들어 미감을 깨는 대신 필요한 곳에만 진한 선을 둡니다.

**수치를 문서에 적어 두는 것으로 끝내지 않습니다.** 토큰 정의를 파싱해 대비를 계산하는 자동화 테스트를 통해 검증하므로, 팔레트 교체나 오버라이드 삭제 시 즉시 실패를 감지합니다. 문서에만 적힌 기준은 팔레트가 바뀌는 순간 조용히 어긋납니다.

이 테스트는 **아키텍처가 소유합니다.** 디자인은 하한 위에서 자유롭고 아래로는 내려갈 수 없습니다.

> **주의: Spartan 기본 테마는 이 기준을 충족하지 않습니다**
>
> 실측 결과 라이트에서 `muted-foreground` 가 `muted` 위 4.34:1, `input` 이 배경 위 1.26:1, `ring` 이 2.59:1 입니다. 생성기가 넣은 값을 그대로 두면 세 항목이 기준 아래에 있습니다.

## 4. 스타일 작성 규칙

| 규칙 | 내용 |
| :--- | :--- |
| **내장 변형 우선** | 컴포넌트가 노출하는 `variant`·`size` 입력을 사용합니다. 클래스로 다시 칠하지 않습니다 |
| **helm 에 거는 `class` 는 레이아웃 전용** | 배치와 여백(flex, grid, gap, margin, width)에만 씁니다. 색·타이포그래피·내부 여백을 덮어쓰려면 복사한 helm 파일이나 CSS 변수를 고칩니다 |
| **간격은 `gap-*`** | `space-x-*`·`space-y-*` 를 쓰지 않습니다 |
| **동일 치수는 `size-*`** | `w-4 h-4` 대신 `size-4` 를 씁니다 |
| **z-index 직접 관리 금지** | 다이얼로그·시트·팝오버·툴팁·메뉴는 CDK 오버레이가 쌓임 순서를 관리합니다 |

`class` 로 컴포넌트 내부 표현을 덮어쓰면 같은 컴포넌트가 사용처마다 다르게 보이고, 나중에 helm 파일을 고칠 때 어느 사용처가 영향을 받는지 알 수 없게 됩니다.

이 제한은 **helm 컴포넌트에 클래스를 걸 때** 적용됩니다. `<a>`·`<ul>` 같은 순수 HTML 요소를 Tailwind 클래스로 꾸미는 것은 대상이 아니며, 그 자리에는 덮어쓸 컴포넌트 표현이 존재하지 않습니다. 다만 같은 조합이 세 곳 이상에서 반복되면 `shared/ui` 로 승격할 시점입니다.

## 5. shared/ui 의 경계

| 들어가는 것 | 들어가지 않는 것 |
| :--- | :--- |
| 버튼, 입력, 선택, 다이얼로그, 표, 배지 | 특정 도메인의 카드나 행 |
| 레이아웃 프리미티브 (스택, 그리드) | 화면 전용 조합 |
| 로딩 표시, 빈 상태 표시 | 업무 규칙이 담긴 표시 로직 |
| 아이콘 래퍼 | 서버 조회 |

`shared/ui` 의 컴포넌트는 **도메인 이름을 갖지 않습니다.** `TaskCard` 는 `shared/ui` 에 들어갈 수 없습니다. `Card` 는 들어갈 수 있고, 할일 카드는 `Card` 를 조합해 `pages` 에서 만듭니다.

판정 기준은 하나입니다. **다른 프로젝트에 그대로 옮겨도 의미가 통하는가.** 통하면 `shared/ui` 이고, 통하지 않으면 도메인 지식이 섞인 것입니다.

## 6. 아이콘

아이콘은 `shared/ui/icon/` 에 래퍼를 두고 그것을 통해서만 사용합니다. SVG 를 템플릿에 직접 붙여 넣는 것을 **금지**합니다.

래퍼를 두는 이유는 크기·색상 토큰 적용을 한 곳에서 보장하고, 아이콘 세트를 교체할 때 사용처를 수정하지 않기 위함입니다.

장식용 아이콘은 `aria-hidden="true"` 를 갖고, 아이콘만으로 동작을 표현하는 버튼은 접근 가능한 이름을 갖습니다. 상세는 [13. 접근성](13-accessibility.md)에 있습니다.

어느 아이콘 세트를 쓰는지는 DESIGN.md 가 정합니다. 본 문서는 **하나로 고정하고 굵기를 섞지 않는다**는 규칙만 둡니다.

## 7. 색상 모드 전환

라이트와 다크 전환의 **수단**은 이 문서가, 각 모드의 **값**은 DESIGN.md 가 정합니다.

전환 판단의 원본은 `color-scheme` 이며, 기본값은 시스템 설정을 따르고 사용자가 고르면 문서 루트의 클래스가 덮습니다. 클래스 부여 로직은 `app` 계층이 소유합니다.

**첫 페인트 전에 결정되어야 합니다.** 앱 코드에서 붙이면 한 모드로 그렸다가 바뀌는 깜빡임이 생깁니다. 색 토큰이 두 값을 한 자리에 함께 선언하면 스크립트 실행 전에도 CSS 만으로 시스템 설정이 반영되므로 이 문제가 발생하지 않습니다.

사용자 선택을 저장한다면 `localStorage` 를 사용하며, 이는 브라우저 API 이므로 [05. 렌더링 전략](05-rendering.md) 2절의 격리 규칙을 따릅니다.

> **주의: 문서 루트에만 걸리는 선택자는 부분 다크를 지원하지 않습니다**
>
> `:root.dark` 형태는 하위 요소에 클래스를 붙여도 재정의가 일어나지 않아 두 모드를 한 화면에 나란히 띄울 수 없습니다. 선택자를 `.dark` 로 넓히면 가능해지지만 부분 영역의 의도치 않은 재정의를 부릅니다. 두 모드 병렬 표시가 필요해지면 이것이 첫 번째 검토 대상입니다.

## 8. 금지 사항

| 금지 | 사유 |
| :--- | :--- |
| 임의 색상값 직접 기재 | 다크 모드 대비가 깨지고 변경이 전역 치환이 됩니다 |
| Tailwind 기본 팔레트 사용 | 토큰 체계를 우회합니다 |
| 반투명 표면을 알파 유틸리티로 생성 | 라이트와 다크에 같은 값이 걸립니다 |
| brain 디렉티브 제거 | 접근성 보장이 함께 사라집니다 |
| `node_modules` 패치 | 재설치 시 소실되며 추적되지 않습니다 |
| `shared/ui` 에 도메인 이름 컴포넌트 | 다른 프로젝트로 옮길 수 없게 됩니다 |
| SVG 를 템플릿에 직접 삽입 | 토큰 적용과 세트 교체가 어려워집니다 |
| `class` 로 컴포넌트 내부 색·타이포그래피 덮어쓰기 | 같은 컴포넌트가 사용처마다 다르게 보입니다 |
| `space-x-*` · `space-y-*` 사용 | `gap-*` 이 flex·grid 와 일관되게 동작합니다 |
| 오버레이의 z-index 직접 지정 | CDK 가 관리하는 쌓임 순서와 충돌합니다 |
| `@theme inline` 없이 토큰만 추가 | 유틸리티 클래스가 생성되지 않습니다 |
| 토큰 없이 임의값을 쓰고 나중에 정리 | 정리 시점이 오지 않습니다 |
| 크기·두께 토큰 신설 | Tailwind 척도와 두 벌이 됩니다 |
| 본 문서에 팔레트 값 기재 | 결정-0001 이 금지한 구성입니다 |
