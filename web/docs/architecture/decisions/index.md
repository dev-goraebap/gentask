# 결정 기록 목차

본 문서는 이 저장소의 프론트엔드 아키텍처 결정을 시간순으로 나열합니다. 결정의 본문은 각 파일이 소유하고 여기에는 상태와 한 줄 요약만 둡니다.

**결정 기록은 승인 후 불변입니다.** 결론이 바뀌면 새 결정을 발행해 이전 것을 대체하며, 옛 문서를 고치지 않습니다. 기록의 역사성이 사라지면 다음 작업자가 같은 논의를 반복합니다.

## 작성 판별식

**검토한 대안과 트레이드오프를 한 문단 이상 진지하게 쓸 수 있는가.** 쓸 수 있으면 결정 기록이고, 쓸 수 없으면 참조 문서 본문에 직접 적습니다. 업계 표준, 취향, 앞선 결정에서 자동으로 따라오는 규칙은 대상이 아닙니다.

템플릿은 [adr.template.md](../../templates/adr.template.md)입니다.

## 대체 절차

한 커밋으로 처리합니다.

1. **새 결정 작성**: 대체 대상을 머리말의 `대체` 항목에 적습니다.
2. **목차 갱신**: 아래 표에서 이전 결정의 상태를 `대체됨 (→ NNNN)`으로 바꿉니다.
3. **참조 교체**: 참조 문서가 걸어 둔 링크를 새 결정으로 바꿉니다.

## 발행 예정

아래는 판별식을 통과하지만 아직 작성되지 않은 결정입니다. 해당 참조 문서를 이식할 때 함께 발행합니다.

| 주제 | 무엇이 갈림길인가 |
| :--- | :--- |
| **모듈 분할 방법론** | FSD 채택과 계층 구성. 대안은 기능별 폴더, 도메인 주도 배치 |
| **UI 킷 조달 방식** | 헤드리스 프리미티브 + 사본 소유. 대안은 직접 제작, 의견 키트 채택 |
| **적응형 판정 축** | 뷰포트 폭 기반 판정. 대안은 포인터·호버 기반이며, 브라우저가 마우스 연결 여부를 미디어 쿼리로 신뢰성 있게 보고하지 않아 기각했습니다 |
| **서버 상태 조회 수단** | 프레임워크 내장 수단. 대안은 외부 상태 라이브러리 |
| **데이터 로딩 모델** | 리졸버와 베일. 대안은 스켈레톤, 화면 우선 렌더 |
| **폼 구현 수단** | 시그널 기반 폼. 대안은 리액티브 폼 |
| **문서 배치와 도입 순서 번호** | 참조 아키텍처를 `web/docs` 에 두고 파일명에 순서를 새기는 선택 |
