## Overview

이 시스템은 **읽는 화면**을 위해 만들어졌습니다. 글과 문서가 중심이고, 화면은 그것을 담는 종이입니다.

세 가지가 성격을 정합니다.

**선이 구조를 그립니다.** 영역을 나누는 것은 헤어라인 경계이고, 그림자는 실제로 떠 있는 것에만 씁니다. 정적인 카드에 그림자를 얹으면 "떠 있음"이라는 신호가 값싸져서 진짜 떠 있는 것과 구분되지 않습니다.

**강조는 하나뿐입니다.** 파랑이 링크·활성 표시·포커스 링·검색 하이라이트를 전부 맡습니다. 강조가 여럿이면 어느 것도 강조가 아닙니다.

**모서리는 크고 부드럽습니다.** 기준 반경 1rem에 초타원 곡률을 얹어, 직선에서 곡선으로 넘어가는 꺾임을 없앴습니다.

라이트와 다크는 **한쪽이 본체가 아닙니다.** 모든 색 토큰이 `light-dark()`로 두 값을 한 줄에 선언하므로 한쪽만 고치는 실수가 구조적으로 불가능합니다. 기본값은 시스템 설정을 따르고, 사용자가 고르면 문서 루트의 클래스가 `color-scheme`을 덮습니다. 스크립트가 돌기 전에도 CSS만으로 시스템 설정이 반영되어 잘못된 모드가 잠시 보이는 일이 없습니다.

프런트매터의 색 값이 `light-dark(...)` 문자열인 것은 그 성질을 잃지 않기 위함입니다. 한쪽 모드만 뽑아 적으면 이 시스템의 핵심 장치가 문서에서 사라집니다.

## Colors

배경은 **순백이 아닙니다.** 라이트는 순백에서 한 단계 내린 흰색이고, 채도가 있는 색을 얹었을 때 더 선명하게 보이며 장시간 읽을 때 눈이 덜 부십니다. 다크는 중성 회색이며 검정이 아닙니다.

**텍스트 위계는 세 단계입니다.**

| 단계 | 토큰 | 쓰는 자리 |
| :--- | :--- | :--- |
| **본문** | `foreground` | 읽는 글 전부 |
| **보조** | `foreground-secondary` | 카드 설명, 비활성 내비 항목 |
| **삼차** | `muted-foreground` | 캡션, 메타 정보 |

`secondary`라는 이름을 텍스트에 쓰지 않는 이유는 그것이 버튼 변형용 배경이고 `secondary-foreground`와 짝을 이루기 때문입니다. 역할이 다릅니다.

**표면을 밝기로 쌓지 않습니다.** 라이트에서 `card`와 `popover`는 `background`와 같은 값이며 오직 경계선으로 구분됩니다. 다크에서만 카드가 배경보다 반 단계 밝은데, 어두운 화면에서는 경계선만으로 면이 분리되어 보이지 않기 때문입니다. 이 차이는 의도된 비대칭입니다.

**강조는 `primary` 하나입니다.** 링크, 활성 내비 항목, 포커스 링(`ring`), 검색 하이라이트(`mark`)가 모두 같은 계열을 씁니다. 걸린 자리가 링크나 활성 항목과 같은 의미로 읽히게 하려는 것입니다.

`warning`·`info`·`success`는 문서 본문의 강조 블록 전용입니다. 화면 컴포넌트의 상태 표시에 끌어다 쓰지 않습니다.

`toolbar`는 상단 바 전용의 반투명 표면입니다. **알파 유틸리티(`bg-background/85`)로 대신하지 않습니다.** 그렇게 하면 라이트와 다크에 같은 불투명도가 걸리는데, 뒤로 지나가는 요소가 비쳐 보이는 정도는 배경과의 밝기 차이에 비례합니다. 다크에서 흰 요소가 지나갈 때 툴바 밝기는 불투명도 75%면 800%, 85%면 약 370% 오릅니다. 그래서 라이트 65%, 다크 85%로 나눠 둡니다. **이 제약은 앞으로 모든 반투명 표면에 동일하게 적용됩니다.**

대비 기준은 본문·보조 텍스트 4.5:1, 비활성·경계선·채움 3:1이며 라이트와 다크 **양쪽에서** 충족해야 합니다. 이것은 서술이 아니라 테스트가 판정합니다.

## Typography

서체는 **두 종에 로고 하나의 예외**입니다.

| 용도 | 서체 | 사유 |
| :--- | :--- | :--- |
| **본문** | Pretendard Variable | 한글과 라틴을 함께 담고 라틴이 한글과 어울리도록 조정되어 있습니다 |
| **코드** | JetBrains Mono Variable | 라틴 식별자의 가독성을 우선했습니다. 한글은 본문 서체로 떨어집니다 |
| **로고** | Caveat 500 | 상단 바의 사이트 이름 하나. 이 이름은 서체가 곧 내용의 일부입니다 |

**본문에 영문 전용 폰트를 겹치지 않습니다.** Pretendard가 라틴 글리프를 이미 다듬어 갖고 있으므로, 다른 영문 폰트를 앞에 두면 그 조정이 무효가 되고 한 문장 안에서 x-height와 획 두께가 어긋납니다.

**코드 블록 안에서 공백으로 열을 맞추지 않습니다.** 한글 구간에서 고정폭이 깨집니다. 계층은 tree 기호로 그리고, 정렬이 의미를 갖는 내용은 블록 밖 표로 옮깁니다.

**크기 스케일에 토큰을 두지 않습니다.** Tailwind의 유틸리티를 그대로 쓰며, 별도 토큰을 두면 척도가 두 벌이 됩니다. 실제 사용은 `text-sm`이 압도적인 기본값이고 제목이 `text-2xl`, 메타 정보가 `text-xs`입니다. 화면이 조밀한 대신 기준 배율 자체를 올립니다.

**기준 배율이 뷰포트 폭에 연동됩니다.** 1920px에서 100%, 2560px에서 125%이며 상·하한을 둡니다. 27인치 QHD는 24인치 FHD보다 픽셀 밀도가 높아 같은 CSS 픽셀이 작게 보이므로, 고정 배율로 올리면 노트북에서 과해집니다. 단위는 `rem`이며 `px`를 쓰지 않습니다 — 브라우저 기본 글꼴을 키워 둔 사용자의 설정을 존중해야 합니다.

## Layout

폭이 세 단계입니다.

| 이름 | 값 | 쓰는 자리 |
| :--- | ---: | :--- |
| **shell-max** | 90rem | 상단 바, 문서 셸의 바깥 한계 |
| **content-max** | 66rem | 읽기 화면과 푸터의 본문 폭 |
| **reading-measure** | 40rem | 글 본문 한 줄의 길이 |

읽기 화면은 본문 40rem과 보조 열 17.5rem을 4rem 간격으로 나란히 둡니다. 좁은 화면에서는 한 열로 접힙니다.

세로 리듬은 좁은 화면 `py-8`, 넓은 화면 `py-12`입니다. 가로 여백은 `px-4`로 고정합니다.

**고정 요소는 자기 높이를 토큰으로 노출합니다.** 하단 내비의 높이(`bottom-nav-height`)를 막대 자신과 본문의 아래 여백, 그리고 그 위에 놓이는 요소가 함께 읽습니다. 세 곳에 숫자를 적어 두면 하나를 고칠 때 나머지가 어긋나고, 그 어긋남은 그 폭에서만 드러나 발견이 늦습니다. `env(safe-area-inset-bottom)`을 반드시 더합니다.

스크롤바 자리를 상시 확보합니다(`scrollbar-gutter: stable`). 화면마다 스크롤 유무가 달라 폭이 변하면 전환 때 레이아웃이 좌우로 흔들립니다.

## Elevation & Depth

**깊이는 선이 냅니다.** 같은 평면에서 영역을 가르는 것은 헤어라인 경계이고, 그림자는 **실제로 떠 있는 것** — 모달·시트·팝오버·드롭다운 — 에만 씁니다.

| 층 | 표현 |
| :--- | :--- |
| **면** | 배경과 같은 색. 경계선으로만 구분 |
| **카드** | 1px 링과 아주 옅은 그림자. 들어 올리지 않습니다 |
| **떠 있는 것** | 큰 그림자. 여기서만 층위가 시각적으로 드러납니다 |

정적 카드에 그림자를 얹지 않습니다. 그러면 "떠 있음"이라는 신호가 값싸져서 진짜 떠 있는 것과 구분되지 않습니다.

**종이 질감은 선택 항목이며 기본값은 꺼짐입니다.** 화면 전체에 옅은 노이즈를 덮어 색면이 균일하게 비어 보이지 않게 합니다. 읽는 화면에는 어울리지만 표와 폼이 빽빽한 업무 화면에서는 작은 글자의 가독성을 떨어뜨리고, 데이터 그리드가 있는 화면에서는 고정 레이어가 부담이 됩니다.

> **주의: 질감을 켜면 대비 여유를 더 확보해야 합니다**
>
> 노이즈가 전경과 배경 양쪽에 얹혀 대비를 낮춥니다. 실측으로 라이트에서 0.24, 다크에서 0.63 하락합니다. 4.5:1을 겨우 넘는 색은 질감을 켠 화면에서 기준 아래로 내려갑니다.

질감의 층위는 상단 바 위, 오버레이 아래입니다. 모달과 시트는 질감 없는 표면을 유지합니다.

## Shapes

기준 반경 하나가 체계 전체를 만듭니다. `base`를 1rem으로 두면 배지 9.6px, 알약 16px, 커버 22.4px, 카드 28.8px가 파생됩니다. **개별 값을 손으로 고치지 않고 기준값을 바꿉니다.**

모서리는 **초타원**으로 그립니다. 원호는 직선에서 곡선으로 넘어가는 지점이 눈에 띄는데 초타원은 곡률이 연속이라 그 꺾임이 없습니다. 반경이 클수록 차이가 드러나므로 기본값으로 둡니다.

`corner-shape`는 아직 Baseline이 아닙니다. `@supports`로 감싸므로 미지원 브라우저에서는 일반 원호로 그려지며 레이아웃과 크기는 달라지지 않습니다. 완전한 원이 필요한 자리는 명시적으로 되돌립니다.

임의 반경값(`rounded-[7px]`)을 쓰지 않습니다. 체계를 우회합니다.

## Components

컴포넌트의 **표현 원본은 문서가 아니라 코드**입니다. `shared/ui`의 사본이 그것이며, 이 절은 그 사본이 지켜야 할 시각 규칙만 서술합니다.

컴포넌트는 **동작과 표현이 분리되어 있습니다.** 접근성·포커스 관리·키보드 조작·ARIA는 헤드리스 층이 소유하고, 마크업과 클래스만 우리가 소유합니다. 표현을 아무리 고쳐도 헤드리스 층과의 연결은 유지합니다. 연결을 떼면 접근성 보장이 함께 사라지며, 이는 화면상으로 드러나지 않아 발견이 늦습니다.

**버튼**은 낮은 높이(기본 36px)에 작은 글자, 중간 굵기입니다. 채워진 것은 `primary` 하나뿐이고 나머지는 외곽선·투명·연한 배경입니다. 누르면 1px 내려앉습니다. 포커스는 3px 링입니다. 터치 환경에서는 크기 변형과 무관하게 44×44의 바닥이 깔립니다.

**카드**는 들어 올리지 않습니다. 1px 링과 아주 옅은 그림자만 갖고, 내부 여백은 하나의 값(`card-inset`)이 정하며 조밀한 변형은 그 값만 줄입니다.

**입력**은 경계선이 "여기가 입력란"임을 알리는 유일한 단서이므로 장식선보다 진합니다. 글자를 입력하는 컨트롤은 터치 환경에서 16px 이상이어야 합니다. 미관이 아니라 동작 문제입니다 — iOS Safari는 16px 미만 입력에 포커스가 가면 화면을 확대하고 사용자가 그 배율을 직접 되돌려야 합니다.

**상단 바**는 반투명에 블러를 겁니다. 불투명도는 반드시 `toolbar` 토큰이 정합니다.

**아이콘**은 래퍼를 거쳐서만 씁니다. SVG를 템플릿에 직접 붙여 넣지 않습니다. 장식용은 접근성 트리에서 숨기고, 아이콘만으로 동작을 표현하는 버튼은 접근 가능한 이름을 갖습니다.

**터치 기준**은 최소 타겟 44×44 CSS 픽셀, 인접 타겟 간격 8 픽셀 이상입니다. 기본은 시각 치수를 함께 키우는 것이며, 밀도가 촘촘해야 하는 자리에 한해 보이는 크기를 유지하고 누를 수 있는 영역만 넓힙니다.

## Motion

움직임은 **적습니다.** 기본값이 "효과 없음"입니다.

| 자리 | 처리 |
| :--- | :--- |
| **화면 교체** | 효과를 두지 않습니다 |
| **이미지 등장** | 다 받아진 뒤 700ms 페이드 |
| **버튼 누름** | 1px 내려앉음 |
| **호버·포커스** | 색 전환만 |

화면 교체에 효과를 두지 않는 이유는 그것이 완성된 화면이 드러나는 시각을 뒤로 미루기 때문입니다. 무엇이 움직이고 무엇이 제자리에 남는지가 화면마다 판단 대상이 되고, 빠뜨린 요소는 오류 없이 그 요소만 다르게 움직입니다.

이미지 등장은 `transition`이 아니라 `animation`으로 만듭니다. `transition`으로 구현하면 이미지에 붙은 `transition-transform` 같은 유틸리티가 `transition-property`를 통째로 덮어 페이드가 사라지며, **그 이미지에서만 조용히 동작하지 않습니다.**

`prefers-reduced-motion`을 존중합니다. 움직임을 줄이도록 설정한 사용자에게는 전환 없이 곧바로 드러냅니다.

## Do's and Don'ts

**Do**

- 색·간격·반경은 토큰 이름으로 씁니다.
- 모드별로 다른 값이 필요하면 토큰을 새로 만들고 `light-dark()`로 두 값을 함께 선언합니다.
- 새 토큰은 라이트와 다크 값을 동시에 정의하고, 배경 토큰에는 그 위에 얹을 전경 토큰을 짝으로 만듭니다.
- 반경을 바꿀 때는 기준값 하나를 바꿉니다.
- 강조가 필요하면 `primary`를 씁니다. 새 강조색을 만들지 않습니다.
- 컴포넌트에 거는 클래스는 배치와 여백에만 씁니다.

**Don't**

- 임의 색상값(`#ffffff`, `bg-white`, `text-gray-900`)을 쓰지 않습니다. Tailwind 기본 팔레트도 대상입니다.
- 반투명 표면을 알파 유틸리티로 만들지 않습니다. 라이트와 다크에 같은 값이 걸립니다.
- 정적인 카드에 그림자를 얹지 않습니다.
- 텍스트에 `secondary`를 쓰지 않습니다. 그것은 버튼 변형용 배경입니다.
- 본문에 영문 전용 폰트를 겹치지 않습니다.
- 크기·굵기 토큰을 새로 만들지 않습니다. Tailwind 척도가 이미 있습니다.
- 오버레이의 쌓임 순서를 직접 지정하지 않습니다.
- 색만으로 상태를 전달하지 않습니다. 아이콘과 문구를 함께 둡니다.
- 호버로만 접근 가능한 기능을 두지 않습니다.
- 종이 질감을 업무 화면의 기본값으로 켜지 않습니다.
