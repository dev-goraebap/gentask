## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
> 사용자로서, 내가 실제로 받는 이메일로 가입하고 싶다. 남이 내 주소로 계정을 만들지 못하게 하고, 비밀번호를 잊었을 때 되찾을 길을 남기기 위해.

서술서: USR-001 · 흐름: 기본 · A1 · A3 · A4 · A5 · A6

## 메모

- 계정은 코드를 확인한 뒤에 만든다. 먼저 만들고 확인 여부를 표시로 가르면 확인되지 않은 계정이 이메일을 차지하고, 남의 주소로 가입을 시작해 그 사람의 가입을 막을 수 있다
- 코드와 가입 재료(이메일 · 비밀번호 해시)를 `verification_codes` 한 행이 함께 든다. 계정이 되기 전까지 그 재료를 갖는 자리가 그것뿐이다
- 종단 테스트가 코드를 알아야 진행한다. 시험 프로파일의 가짜 발송이 마지막 코드를 들고 그것을 꺼내는 경로는 그 프로파일에서만 선다. 운영 프로파일에는 그 빈이 없어 경로도 없다
- 코드 길이와 수명과 시도 한도는 결정-0012 가 갖는다
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 [서버] When 사용자가 이메일과 비밀번호를 제출하면, 시스템은 그 주소로 일회용 코드를 보낸다
- [ ] #2 When 사용자가 받은 코드를 제출하면, 시스템은 계정을 만들고 로그인 상태로 작업 목록을 보여 준다
- [ ] #3 [서버] While 코드를 확인하기 전에는, 시스템은 그 이메일로 계정을 만들지 않는다
- [ ] #4 If 비밀번호가 규칙에 맞지 않으면, then 시스템은 충족하지 못한 조건을 알린다
- [ ] #5 If 제출한 코드가 맞지 않으면, then 시스템은 코드가 맞지 않음을 알린다
- [ ] #6 [서버] If 코드의 수명이 지났으면, then 시스템은 만료를 알린다
- [ ] #7 [서버] When 사용자가 코드를 다시 요청하면, 시스템은 앞서 보낸 코드를 거두고 새 코드를 보낸다
- [ ] #8 [서버] If 코드를 정해진 횟수보다 많이 틀리면, then 시스템은 그 코드를 거둔다
<!-- AC:END -->
