## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
> 사용자로서, 비밀번호가 기억나지 않아도 내 계정으로 돌아가고 싶다. 계정을 새로 만들고 그동안 쌓은 것을 버리지 않기 위해.

서술서: USR-005 · 흐름: 기본 · A1 · A2 · A3 · A4 · A5

## 메모

- 요청의 응답은 그 이메일의 등록 여부와 무관하게 같다. 구분해 알리면 그 차이가 곧 가입 여부를 알려 주는 신호가 된다
- 세션과 API 토큰을 모두 거둔다. 비밀번호를 모르는 채 지나는 경로라, 그것을 지난 사람이 주인이라는 것 말고 앞서 열린 자리들이 정당하다고 볼 근거가 남지 않는다
- 코드를 다루는 절차는 가입과 한 벌이며, 해시에 용도를 결합해 같은 여섯 자리가 서로 다른 값이 된다
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 [서버] When 사용자가 가입한 이메일로 재설정을 요청하면, 시스템은 그 주소로 일회용 코드를 보낸다
- [ ] #2 When 사용자가 코드와 새 비밀번호를 제출하면, 시스템은 비밀번호를 바꾸고 새 비밀번호로 로그인하게 한다
- [ ] #3 [서버] When 비밀번호를 바꾸면, 시스템은 그 계정의 세션과 API 토큰을 모두 거둔다
- [ ] #4 [서버] If 등록되지 않은 이메일로 요청하면, then 시스템은 메일을 보내지 않고 보낸 경우와 같은 응답을 낸다
- [ ] #5 If 새 비밀번호가 규칙에 맞지 않으면, then 시스템은 충족하지 못한 조건을 알린다
- [ ] #6 If 제출한 코드가 맞지 않으면, then 시스템은 코드가 맞지 않음을 알린다
- [ ] #7 [서버] If 코드의 수명이 지났으면, then 시스템은 만료를 알린다
- [ ] #8 [서버] When 사용자가 코드를 다시 요청하면, 시스템은 앞서 보낸 코드를 거두고 새 코드를 보낸다
<!-- AC:END -->
