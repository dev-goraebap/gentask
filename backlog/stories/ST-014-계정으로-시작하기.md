# 계정으로 시작하기

> 사용자로서, 내 계정으로 들어가 내 작업만 보고 싶다. 어느 자리에서든 내 목록으로 돌아오기 위해.

서술서: [USR-001 계정 회원가입](<../../docs/spec/user/USR-001(계정 회원가입).md>) · [USR-002 계정 로그인](<../../docs/spec/user/USR-002(계정 로그인).md>) · [USR-004 계정 로그아웃](<../../docs/spec/user/USR-004(계정 로그아웃).md>)

## 인수 조건

- [ ] When 사용자가 이메일과 비밀번호로 등록하면, 시스템은 계정을 만들고 곧바로 로그인 상태로 작업 목록을 보여 준다
- [ ] When 이미 등록된 이메일로 등록하려 하면, 시스템은 이미 등록된 이메일임을 알린다
- [ ] When 사용자가 맞는 자격으로 로그인하면, 시스템은 그 계정의 작업 목록을 보여 준다
- [ ] When 자격이 맞지 않으면, 시스템은 어느 쪽이 틀렸는지 구분하지 않고 알린다
- [ ] When 로그아웃하면, 이후 작업 화면 접근은 로그인 자리로 안내된다
- [ ] 로그인 없이 작업 API 에 닿을 수 없고, 다른 계정의 작업은 보이지 않는다

## 메모

백엔드:

- 테이블(users · accounts · sessions)과 세션 방식은 devkit auth 준용. 세션 토큰은 256bit 난수를 HMAC-SHA256 으로 해시해 저장하고, `session_token` HttpOnly · SameSite=Lax 쿠키로 나른다. 30일 슬라이딩 · 90일 상한 · 1시간 touch 간격
- 이메일 인증 · 비밀번호 재설정 · 소셜 로그인은 넣지 않는다(서술서 미결). Spring Security 는 들이지 않고 BCrypt 만 `spring-security-crypto` 로 뽑아 쓴다
- 기존 tasks 에 user_id 를 붙이고 조회 · 명령을 계정 스코프로 좁힌다. 계정 도입 전의 데이터는 지운다

프론트:

- /login · /signup 은 셸 밖의 화면이다. 성공하면 /tasks 로 이동한다
- 인증이 필요한 라우트는 가드가 지키고, 세션이 도중에 풀리면 401 인터셉터가 로그인 자리로 보낸다
