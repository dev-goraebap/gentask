# 부자연스러운 문체 패턴 치환 사전 (Bad Patterns Lookup)

본 문서는 LLM이 한국어 기술 문서를 작성할 때 빈번히 발생하는 부자연스러운 표현을 식별하고, 이를 올바른 공학적 표준 어휘 및 자연스러운 문장 구조로 치환하거나 과감히 덜어내기(삭제) 위한 사전입니다.

---

## 1. 낱말 수준 치환 사전 (다의어 고유어 -> 표준 공학 용어)

한자어나 외래어 전문 용어를 순우리말로 억지로 대체하면 단어의 다의성으로 인해 의미가 흐려지고 정밀도가 손상됩니다. 아래 기준에 따라 치환합니다.

| 부자연스러운 표현 | 가리키는 실제 의미 | 권장 표준 공학 용어 |
| :--- | :--- | :--- |
| **세우다** | 생성, 등록, 정의, 작성, 초기화 | **작성한다**, **생성한다**, **정의한다**, **초기화한다** |
| **잇다 / 이음** | 연결, 연동, 매핑, 관계 맺기 | **연결한다**, **연동한다**, **매핑한다**, **링크** |
| **걷다** | 제거, 회수, 해제, 비활성화 | **제거한다**, **해제한다**, **삭제한다** |
| **거두다** | 삭제, 회수, 만료, 철회 | **삭제한다**, **회수한다**, **만료 처리한다** |
| **내다** | 발급, 반환, 응답, 출력, 게시 | **발급한다**, **반환한다**, **출력한다**, **응답한다** |
| **매다 / 붙이다** | 연결, 바인딩, 귀속, 첨부 | **연결한다**, **바인딩한다**, **귀속시킨다**, **첨부한다** |
| **자리** | 위치, 디렉터리, 계층, 엔드포인트, 화면 | **위치**, **경로**, **계층**, **엔드포인트**, **화면** (대상 명칭 직접 기술) |
| **떠 있는 자리** | 상시 가용 환경, 활성 인스턴스 | **상시 가용 환경**, **운영 환경**, **활성 프로세스** |
| **껍데기** | 래퍼, 레이아웃, 어댑터, 셸 | **래퍼(Wrapper)**, **레이아웃(Layout)**, **어댑터(Adapter)** |
| **보다** | 조회, 판정, 참조, 확인 | **조회한다**, **판정한다**, **참조한다**, **확인한다** |
| **띄우다** | 실행, 기동, 구동, 배포 | **실행한다**, **기동한다**, **배포한다** |
| **두 층 / 두 겹** | 2단계 계층, 2중 구조 | **2단계 계층**, **2중 구조** |
| **고치다 / 지우다** | 수정, 변경, 삭제 | **수정한다**, **변경한다**, **삭제한다** |
| **밀어 넣다** | 전송, 전달, 큐잉, 삽입 | **전송한다**, **전달한다**, **삽입한다** |
| **떨어뜨리다** | 실패, 라우팅, 폴백, 중단 | **실패 처리한다**, **폴백 라우팅한다**, **중단한다** |
| **평평하게 매기다** | 단일 수열 채번, 계층 없는 ID | **단일 수열로 채번한다**, **계층 없이 순차 발급한다** |

## 2. 문장 구조 안티패턴 치환 가이드

### 2.1 소유·발화 의인화 안티패턴
문서, 소스 파일, 테스트, 도구 등 무생물 객체에 소유(`갖는다`) 및 발화(`말한다`, `떠받친다`) 동사를 사용하는 패턴입니다.

| 안티패턴 | 결함 분석 | 올바른 서술 |
| :--- | :--- | :--- |
| "이 결정의 근거는 아키텍처 문서-001이 갖습니다." | 문서가 근거를 소유할 수 없음 | **"이 결정의 근거는 아키텍처 문서-001에 기술되어 있습니다."** |
| "테스트는 지금의 명세를 말하고, 항목과의 연결은 커밋 트레일러가 갖습니다." | 테스트가 발화하고 트레일러가 소유함 | **"테스트는 현재 시스템 명세를 기술하며, 작업 항목 연결은 커밋 트레일러에 기록합니다."** |
| "이 제약조건이 하위 아키텍처 결정들을 떠받칩니다." | 제약조건을 물리적 기둥으로 의인화 | **"이 제약조건은 하위 아키텍처 결정의 기본 전제가 됩니다."** |
| "접속 자격 증명은 서버의 `.env` 파일만 갖습니다." | 설정 파일이 소유 주체가 됨 | **"접속 자격 증명은 서버의 `.env` 파일에만 단일 정의하여 보관합니다."** |

### 2.2 인과 후치 도치 (`~하기 때문입니다`) 안티패턴
결론을 먼저 말하고 뒤에 이유를 부록 형태로 종속시키는 패턴입니다.

| 안티패턴 | 결함 분석 | 올바른 서술 |
| :--- | :--- | :--- |
| "검사는 커밋 절차에서 제거했습니다. 검사 비용이 이득을 넘어섰기 때문입니다." | 결론 뒤에 인과문 종속 | **"검사 실행 비용이 결함 검출 이득을 초과하므로, 커밋 절차에서 검사를 제외합니다."** |
| "상태 변경 응답 본문은 비웁니다. 클라이언트가 읽지 않는 본문이 남으면 테스트 비용이 늘어나기 때문입니다." | 이유를 후치 종속절로 연결 | **"클라이언트가 변경 후 재조회를 수행하므로, 불필요한 유지보수 부하를 줄이기 위해 응답 본문은 생략합니다."** |
| "슬라이딩 갱신에 간격을 두는 이유는 쓰기 때문입니다." | 모호한 이유와 구어체 종속 | **"불필요한 데이터베이스 쓰기 I/O를 방지하기 위해 세션 만료 시각 갱신에 최소 간격을 설정합니다."** |

### 2.3 억지 대구 및 대칭 수사 안티패턴
긍정과 부정을 짝지어 운율을 만들기 위해 실질적 정보가 없는 문장을 끼워 넣는 패턴입니다.

| 안티패턴 | 결함 분석 | 올바른 서술 |
| :--- | :--- | :--- |
| "어느 층에 무엇을 두고 무엇을 두지 않는가가 여기 있습니다." | 운율을 위한 긍·부정 나열 | **"계층별 테스트 배치 기준과 대상 범위를 규정합니다."** |
| "접두어는 이름에 쓰고 주소에는 쓰지 않습니다." | 부정 대구로 글자 수 채움 | **"접두어는 작업 항목의 이름에만 사용하며 URL 주소에는 고유 식별자를 사용합니다."** |
| "문서를 저장소 파일로 두지 않으며, 읽고 쓰는 것은 CLI와 웹 화면입니다." | 부정문과 접속절의 불필요한 결합 | **"문서 관리는 저장소 파일 대신 전용 CLI와 웹 인터페이스를 통해 일원화하여 수행합니다."** |

### 2.4 부정 서술로 가치 포장하기 안티패턴
시스템이 수행하는 실제 기능을 진술하지 않고, 수행하지 않는 조작으로 에둘러 가치를 설명하는 패턴입니다.

| 안티패턴 | 결함 분석 | 올바른 서술 |
| :--- | :--- | :--- |
| "화면을 열지 않고도 할 일을 남기고 고친다." | 하지 않는 행위로 기능 표현 | **"CLI 도구를 통해 작업 항목을 직접 조회, 등록, 수정한다."** |
| "누가 이 서비스를 쓰고 있는지 보아, 서버에 들어가지 않고 운영 사실을 확인한다." | 부정적 표현으로 우회 | **"관리자 웹 콘솔에서 사용자 목록과 주요 운영 지표를 조회한다."** |

## 3. 개선이 아닌 '완전 삭제(덜어내기)' 판정 패턴

문장을 다듬어서 살려둘 것이 아니라, **문장 자체를 통째로 지워야 하는 대표 패턴**입니다.

| 사족 유형 | 부자연스러운 원문 | 결함 원인 | 조치 및 결과 |
| :--- | :--- | :--- | :--- |
| **코드 반향 주석** | `// id가 없으면 에러를 낸다` | 코드가 이미 `if (id == null) throw ...`를 명시함 | **[완전 삭제]** (주석 불필요) |
| **자명한 동어반복** | `원문 그대로 옮기며 문체를 고치지 않는다.` | '원문 그대로'에 문체 불변이 이미 포함됨 | **"원문 그대로 옮긴다."** (후반부 삭제) |
| **도메인 상식 사족** | `지우면 데이터가 사라진다. 복구할 수 없기 때문이다.` | 삭제 시 데이터 소멸은 도메인의 자명한 전제 | **[완전 삭제]** |
| **사고 과정 중계** | `그것이 이 명령이 서 있는 이유입니다.` | 모델의 감정적 혼잣말이자 메타 진술 | **[완전 삭제]** |
| **방어적 변명** | `대안 A를 쓰면 너무 무겁기 때문에 이렇게 했습니다.` | 구체적 벤치마크나 제약 없는 막연한 변명 | **[완전 삭제]** |
| **비행동성 소음** | `나중에 필요해지면 다시 바꿀 수 있습니다.` | 독자의 구현 행동에 아무 영향을 주지 않음 | **[완전 삭제]** |
