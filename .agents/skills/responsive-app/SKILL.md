# responsive-app

UI를 무엇으로 띄우고 URL을 줄지 결정하고, 화면·입력 모드에 맞춰 반응형으로 적응시킨다.
다루는 범위: 결정 프레임(정체성 vs 표현), 반응형 적응, 모바일 디테일, 제스처(옵트인).

## 언제 활성화하나

- 모바일 웹앱 / PWA / 웹뷰 화면을 "네이티브 앱처럼" 만들어 달라는 요청
- "이걸 모달로 띄울까 페이지로 만들까", "URL을 줘야 하나", "새로고침·공유·뒤로가기가 깨진다"
- 목록에서 클릭하면 모달, 직접 접속하면 풀페이지(라우티드 모달), 멀티스텝 폼/위저드의 뒤로가기
- "모바일에서 모달이 어색하다", "휴대폰에서 바텀시트로", "테이블이 폰에서 깨진다"
- 시트/드로어를 뒤로가기로 닫기, safe-area·노치·100vh 잘림
- 끌어서 닫는 시트·스와이프 액션 같은 제스처 추가
- 위 결정·코드에 대한 리뷰

## 운영 메모

필요한 값(브레이크포인트·색·타이포 토큰 등)이 프로젝트에 있으면 그대로 쓴다. 없으면 진행을
막지 말고 최소 임시값을 정해 **값 옆에 한 줄로 `(임시)`만 표시**한다. 분업·소관은 언급하지 않는다.

## 규칙 0 — 직접 구현 전에 리서치한다

먼저 사용 중인 프레임워크/버전을 탐지하고(`package.json` 등), 그 프레임워크에서 필요한 패턴을
충족하는 라이브러리를 웹 검색한다. 적합한 것이 있으면 쓰고, 없을 때만 직접 구현한다.
후보가 UI를 강제로 끌고 오면(예: Ionic) 탈락시킨다.

검색 시작점(2026-06 기준 — 메모리에 의존하지 말고 현재 정보를 다시 검색할 것):
- 반응형 시트/제스처 — React: vaul / @use-gesture / Motion. Svelte: vaul-svelte. Vue: vaul 유사.
- 라우티드 모달(1.4) — Next.js: Parallel Routes + Intercepting Routes로 1급 지원.
  일반 SPA 라우터(React Router 등): 라우터 상태에 background location을 얹어 구현.

## 1. 결정 프레임 (정체성 vs 표현)

무엇으로 띄울지 고르기 전에 두 축을 **따로** 판단한다. 전체 절차·패턴별 상세는
`references/routing-decisions.md`.

**두 축은 직교한다.**
- **정체성** — 이건 *무엇*인가? 목적지(destination) ↔ 일시적 오버레이(transient overlay).
  → **URL을 줄지 여부를 결정한다.**
- **표현** — 이걸 *어떻게* 보여주는가? 인라인 · 팝오버 · 액션시트 · 바텀시트 · 전체페이지 다이얼로그 · 페이지.
  → 플랫폼·화면 크기에 따라 갈린다.

**핵심 규칙 [MUST]: 표현이 정체성을 결정하게 두지 마라.** "모달이니까 URL 없어도 된다",
"모바일이니까 페이지"는 두 축을 혼동한 것이다. URL 유무는 오직 정체성이 정하고, 같은 정체성을
플랫폼별로 다른 표현으로 렌더한다.

### 1.1 먼저 묻는다 — 목적지인가?

셋 중 하나라도 Yes면 **목적지 → 모든 브레이크포인트에서 URL(라우트) 부여** [MUST]:
- 직접 링크로 진입(공유 URL·새 탭·북마크)하는 것이 의미 있는가?
- 새로고침해도 이 화면이 유지되어야 하는가?
- 뒤로가기로 이 화면을 빠져나가는 것이 자연스러운가?

전부 No면 **일시적 오버레이 → URL 없음.** 선행 화면에 종속적이고 잠깐 떴다 사라지는 액션
(확인 다이얼로그·선택 메뉴·값 선택). 모바일에서 풀스크린/바텀시트로 키워도 여전히 오버레이다.

### 1.2 표현은 무게의 스펙트럼에서 고른다

`인라인 → 팝오버 → 액션시트 → 바텀시트 → 전체페이지 다이얼로그 → 라우티드 페이지`
(왼쪽=가벼움, 오른쪽=무거움. 오른쪽 끝만 URL 보유). 데스크탑은 왼쪽, 모바일은 같은 콘텐츠라도
한 칸 오른쪽이 관용적인 경우가 많다. 구체 매핑은 2장.

### 1.3 공유하는 것은 UI 껍데기가 아니라 로직·데이터·동작이다

플랫폼별로 표현이 갈릴 때 단일 소스로 두는 것: 선택지/항목 정의, 액션 핸들러, 동작·상태·접근성 로직.
표현은 갈아끼우되 그 안의 동작·데이터는 한 곳에서 온다.

### 1.4 패턴별 상세는 참조 문서로

`references/routing-decisions.md`에 다음이 전문으로 있다:
- **라우티드 모달 / 인터셉팅 라우트(4.3)** — 목적지를 목록 위 모달로 띄우되 직접 진입 시 풀페이지.
  URL 하나 · 배경 위치 보존 · 뒤로가기=닫기 · 닫기 경로(X·백드롭·Esc·뒤로가기) 수렴 · 직접 진입 fallback.
- **멀티스텝 흐름(4.4)** — 흐름=1 라우트, 스텝=히스토리 엔트리, 콜드 진입 가드. 각 스텝이 공유용
  목적지라서가 아니라 뒤로가기·새로고침 복구·퍼널 분석 때문.
- **진입점이 다른 트리거(4.5) vs 셀렉트 모핑(4.6)** — 진입점·표현이 다르면 억지로 한 컴포넌트로
  모핑하지 말고 별개 컴포넌트 + 공유 로직(과설계 방지). 진입점·책임이 하나면 정당한 모핑.

## 2. 반응형 적응

화면 크기·입력 모드에 따라 같은 의도를 다른 컴포넌트로 바꾼다. 전체 결정 가이드:
`references/responsive-patterns.md`. 핵심 매핑:

- **모달/다이얼로그** → **바텀 시트**(빠른 액션·짧은 폼·컨텍스트 유지) 또는 **전체 페이지**(복잡·다단계·긴 폼, 자체 백스택 항목)
- **hover 메뉴/팝오버/툴팁** → 탭 기반 **시트/드로어/인라인** (터치엔 hover 없음)
- **밀집 데이터 테이블** → 쌓인 **카드/리스트**
- **사이드바 내비** → **드로어 + 하단 탭 바**(자주 쓰는 목적지는 엄지 영역)

하나의 컴포넌트 API 뒤에서 형태를 전환한다(데스크톱=다이얼로그, 모바일=시트). 호출부는 분기하지 않는다.
브레이크포인트는 너비만이 아니라 입력 능력(`hover: none and pointer: coarse`)으로 판단한다.
브레이크포인트 토큰이 있으면 쓰고, 없으면 최소값을 정해 값 옆에 `(임시)`로 표시한다.

## 3. 모바일 디테일

- **뒤로가기로 오버레이 닫기 [MUST].** 시트·드로어·전체페이지 모달은 오버레이 열릴 때
  `history.pushState`로 항목을 쌓고 `popstate`에서 닫는다. 닫기 버튼으로 닫을 땐 쌓은 항목을 정리한다.
  전체 페이지 형태가 목적지라면 자체 라우트(백스택 항목)를 갖는다 — 정체성/URL 판단은 1장을 따른다.
- **safe-area / 뷰포트.** `100vh` 대신 `100dvh`. `viewport-fit=cover` + `env(safe-area-inset-*)`로
  하단 고정 바·시트 핸들에 여백.
- **배경 스크롤 잠금/복원.** 오버레이 열 때 배경 스크롤을 잠그고(`position: fixed` + top 오프셋),
  닫을 때 원래 위치로 복원. `overflow:hidden` 토글만 하면 닫을 때 맨 위로 점프.

상세: `references/responsive-patterns.md`의 "자주 놓치는 함정".

## 4. 제스처 & 모션 (옵트인)

명시적으로 제안하고 사용자가 원한다고 가정하지 않는다. 대상: 끌어서 닫는 시트, 스냅 포인트,
스와이프 액션, 당겨서 새로고침, 관성, push/pop 전환 모션. 라이브러리/구현: `references/gestures-motion.md`.

가드레일:
- 모든 swipe/drag에 비제스처 폴백(보이는 버튼 + 키보드 경로)을 둔다.
- `prefers-reduced-motion`이면 모션을 줄이거나 끈다.
- 시트 열린 동안 배경 스크롤을 잠근다.
- 제스처 시트도 포커스 트랩·접근가능 이름·escape/뒤로닫기를 유지한다.

## 결정 기록 — ADR

다음 선택은 짧은 ADR로 남긴다: URL 부여 여부(목적지 vs 오버레이), 라우티드 모달·멀티스텝 히스토리
방식, 반응형 형태 매핑(시트 vs 전체페이지), 제스처 도입 여부, 라이브러리 vs 직접 구현.
`assets/adr.template.md`를 쓰고 번호를 매겨 `docs/adr/` 또는 `decisions/`에 저장한다.
기각한 선택지도 사유와 함께 적는다.

## 적용 체크리스트

1. [ ] 프레임워크/버전 탐지 → 라이브러리 리서치 (규칙 0)
2. [ ] 정체성 판단: 목적지면 URL 부여, 오버레이면 URL 없음 (1.1)
3. [ ] 표현이 정체성을 결정하지 않게 — 모달/모바일이라고 URL 생략 금지 (1장)
4. [ ] 해당 시: 라우티드 모달(배경 보존·뒤로가기=닫기·직접진입 fallback), 멀티스텝(스텝=히스토리·콜드진입 가드) (1.4)
5. [ ] 공유는 UI가 아니라 선택지 정의·핸들러·동작 로직 (1.3)
6. [ ] 반응형 형태 매핑: 모달↔시트↔전체페이지, 테이블↔카드 (2장)
7. [ ] 모바일 디테일: 뒤로가기로 닫기, dvh/safe-area, 배경 스크롤 복원 (3장)
8. [ ] (옵트인) 제스처: 비제스처 폴백 + reduced-motion (4장)
9. [ ] 결정을 ADR로 기록
