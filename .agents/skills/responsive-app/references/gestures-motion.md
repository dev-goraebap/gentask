# 제스처 & 모션 — 딥 모바일 (선택 적용)

이 단계는 **선택 적용**입니다. 명시적으로 제안하고, 사용자가 원한다고 가정하지
마세요. 헤드리스 프리미티브와 CDK 스타일 유틸리티가 보통 *제공하지 않는*
네이티브 느낌의 상호작용을 다룹니다: 끌어서 닫는 시트, 스냅 포인트, 스와이프
액션, 당겨서 새로고침, 관성/물리.

> **추천 전 검증하세요.** 도입을 확정하기 전에 빠른 웹 검색으로 현재 유지보수
> 상태, 라이선스, 프레임워크 호환성을 확인하세요.

## 의사결정 순서: 목적 전용 → 제스처 라이브러리 → 물리 엔진

**적합한 가장 높은 수준의 도구**를 먼저 선택하고, 상호작용이 진정으로 커스텀일
때에만 아래 수준으로 내려가세요.

1. **목적 전용 시트/드로어 라이브러리** — 필요한 것이 "스냅 포인트와 함께 스와이프로
   닫히는 끌 수 있는 바텀 시트"라면, 제스처를 직접 조립하기보다 정확히 그 용도로
   만들어진 라이브러리를 사용하세요:
   - **React**: **vaul** (Emil Kowalski 제작) — 제스처 기반 드로어/시트, 스냅
     포인트, 배경 스케일링. 사실상의 표준 선택이며 주요 앱에서 프로덕션에
     사용됩니다. shadcn의 Drawer가 이를 래핑합니다.
   - **Svelte**: **vaul-svelte** — Svelte 포트.
   - **Vue**: aioli / Reka 기반 바텀 시트(vaul 유사) — 현재 가장 잘 유지보수되는
     옵션을 검증하세요.
   - **Angular**: CDK drag + overlay로 만들 수 있습니다. 직접 만들기 전에 유지보수되는
     커뮤니티 시트가 있는지 확인하세요.

2. **범용 제스처 라이브러리** — 시트 라이브러리가 다루지 않는 커스텀 drag/swipe/pinch
   로직이 필요할 때:
   - **@use-gesture** — pointer/touch/wheel을 drag/pinch/swipe 핸들러로
     정규화합니다. 애니메이션 라이브러리와 잘 어울립니다. React 우선이며, 다른 곳에서
     사용 가능한 바닐라 코어를 제공합니다.
   - 더 단순한 경우에는 가능한 경우 프레임워크 네이티브 drag(Angular CDK DragDrop,
     Svelte actions)를 사용하세요.

3. **애니메이션 / 물리 엔진** — 제스처가 만들어내는 모션을 구동하기 위해:
   - **Motion** (이전에 Framer Motion으로 알려진 라이브러리. "Motion for React"와
     바닐라 `motion` 패키지) — 스프링 물리, 제스처 인식 애니메이션. 선언적 모션의
     강력한 기본값입니다.
   - **GSAP** — 강력한 타임라인/트윈 엔진. 2025년 기준으로 전체 플러그인
     스위트(이전에 유료였던 **Draggable**과 **Inertia** 포함)가 **무료**입니다.
     관성과 스냅이 있는 복잡하고 명령형이며 물리적인 drag에 적합하고,
     프레임워크에 구애받지 않고 동작합니다.
   - 스프링 라이브러리(예: react-spring)도 대안적인 물리 소스입니다.

## 흔한 상호작용과 구현 방법

| 상호작용 | 권장 접근법 |
| --- | --- |
| 스냅 포인트가 있는 끌어서 닫는 바텀 시트 | 목적 전용 시트 라이브러리(vaul / vaul-svelte)를 먼저. 커스텀: @use-gesture (drag) + Motion/GSAP (spring + snap). |
| 스와이프로 액션하는 리스트 행 (드러내기/삭제) | 스와이프 + transform용 제스처 라이브러리. 액션 임계값으로 clamp + snap. 보이는 버튼 폴백을 유지하세요. |
| 당겨서 새로고침 | 스크롤 최상단에서 제스처 drag + 임계값 + 스프링 백. 네이티브 스크롤을 존중하세요. |
| 관성/모멘텀 drag, 스냅 캐러셀 | GSAP Draggable + Inertia, 또는 이미 모멘텀을 처리하는 Embla(캐러셀). |
| 공유 요소 / 라우트 전환 | Motion(레이아웃 애니메이션) 또는 지원되는 경우 View Transitions API. |

## 타협 불가 가드레일

- **항상 제스처가 아닌 폴백을 제공하세요.** 모든 swipe/drag 상호작용에는 보이는
  버튼과 키보드 경로가 필요합니다. 제스처는 향상이지, 무언가를 하는 유일한
  방법이 결코 아닙니다.
- **`prefers-reduced-motion`을 존중하세요.** 이를 요청하는 사용자에게는 물리와
  전환을 줄이거나 비활성화합니다.
- **네이티브 스크롤과 싸우지 마세요.** 의도적인 drag와 스크롤을 구별하고, 시트가
  열려 있는 동안 배경 스크롤을 잠그세요.
- **접근성을 온전히 유지하세요.** 제스처 기반 시트도 여전히 포커스 트랩, 접근
  가능한 이름, escape/뒤로 가기로 닫기가 필요합니다.
- **번들 비용을 유의하세요.** 하나의 상호작용을 위한 물리 엔진은 과할 수
  있습니다. 그것만 필요하다면 목적 전용 시트 라이브러리를 선호하세요.

## 이 단계를 건너뛸 때

앱이 주로 데스크톱이거나, 반응형 형태(drag 없는 탭 기반 시트/드로어,
→ `references/responsive-patterns.md`)가 이미 기대를 충족한다면, 딥 모바일 제스처를 전부 건너뛸 수 있습니다.
responsive-dialog 패턴은 drag 물리 없이도 잘 동작합니다.

결정(딥 모바일이 범위에 있는지, 그리고 어떤 라이브러리를 쓰는지)을 ADR로
기록하세요. 의도적으로 미룬 경우 명시적인 주석을 포함하세요.
